# 对话流式呈现稳定性验证

日期：2026-10-26  
变更：`stabilize-conversation-streaming`  
范围：PWA 对话中栏、时间线正文、滚动补偿与输入区悬浮提示；未修改 Sync/ACP/Node Link 协议、权威排序、认证或持久化。

## 1. 结论与范围

本次保留用户要求的即时流式输出：每个正文片段到达后直接更新可见正文，没有加入正文节流、定时积攒、字数阈值或下一绘制帧批量提交。优化集中在七处：

- 时间线条目、正文块和时间文案会复用未变化的输入，避免一个新片段令全部历史条目重新渲染。
- 本地用户回显与原位正式消息使用同一稳定键；只有收到已确认的 `messageId`/`turnId` 关联后才接替，并在同一个 store 状态更新中移除回显。
- 滚动几何只在内容高度、可视高度或宽度实际变化时处理；同行追加保持位置，换行、媒体、宽度变化与折叠按实际布局补偿。
- 快捷收起、回到底部与发送/停止切换不会因短暂过程状态反复闪现；真实错误、授权和不可用原因仍可见或可访问。
- `turn.delta_compacted` 不再先删除正文；它只阻止迟到增量并触发权威读取，成功的读取结果在同一个 store 状态更新中替换或移除相应易失正文，读取失败则保留已收到内容。
- 正式用户增量早于命令受理结果时，使用事件携带的 `causationRequestId` 与本机输入 `requestId` 精确关联，在同一次状态更新中把本地回显原位换成正式消息。
- 新会话的分配、恢复、保存和等待正式接管不再生成临时阻塞原因行。此前首次回车后该行额外占用 21px，使输入区增高、时间线上移；现在正常流程保持同一布局，真实失败与不可用原因仍会显示。新会话页同时完全移除「放弃新会话」和「尚未转正」入口及文案。

用户已否决的第 3 项“正文节流”没有实施。`requestAnimationFrame` 和短 `setTimeout` 只用在与正文显示解耦的绘制后几何复核中，正文本身仍在收到片段时立即提交。

现场基线已直接抓到本次追加修复的两个窗口：

- 回车后，本地 `sent:<requestId>` 回显先出现；早期 `user.message.delta` 在受理结果补齐 `turnId` 前另起 `message:<messageId>`，随后才清理，造成第二条用户气泡短暂进入布局。
- 回复完成时，`turn.delta_compacted` 在 `1457.1ms` 先删除用户与 Agent 正文，时间线高度从 `5450` 降到 `5290`；权威读取在 `1472.9ms` 回填后恢复到 `5450`，形成约一帧的空缺。

修复后的自动化断言把这两个窗口变成可控顺序：`CR-12b` 验证受理结果到达前已由 causation 完成原位接替；`SCROLL-COMPACT` 扣住压缩后的 `session.read`，确认读取返回前两个原 DOM 节点仍挂载、页面仍贴底，并在同一个权威结果返回后原位接管。

关键浏览器断言包括：

- `CR-7`：单个文字片段到达即呈现，不等待后续片段、定时器或下一绘制帧。
- `CR-8`、`CR-12`：权威读取与轮次归属补齐沿用同一正文 DOM 节点。
- `CR-12b`：用户实时消息先于受理结果到达时，依靠 `causationRequestId` 在受理结果之前原位接替，始终只有一个用户气泡。
- `SCROLL-COMPACT`：压缩通知到达后正文保持挂载；权威读取返回前节点连接且仍贴底，返回后同节点原位接管。
- `CR-9`：权威消息页为空时，已作废的流式正文只在读取返回后退出，本地回显不重新出现。
- 状态层回归：权威消息页先于受理结果到达时，受理后同样按已确认的 `turnId` 建立稳定关联。
- `CR-10`、`CR-11`：流式增长不重写已完成历史条目；工具、授权、媒体、Markdown 与降级条目的真实变化仍会渲染。
- `SCROLL-SAME-LINE`、`SCROLL-WRAP`、`SCROLL-REWRAP`：同行追加不写滚动，真实换行会跟随，宽度重排与历史前置保持阅读位置。
- `FOLD-HYSTERESIS`、`FOLD-MANUAL-ANCHOR`、`COMPOSER-SWITCH`：快捷收起边界稳定，手动收起保留位置，发送/停止切换不闪现通用禁用提示。

# 对话区域需求讨论

状态：需求访谈进行中；本记录不是已接受的协议设计或实现完成声明。确定后的要求应通过 OpenSpec 进入正式变更，并同步对应权威文档。

## 已确认的范围

2026-10-19，用户确认：

- 内容范围包含用户消息、智能体回复、思考、工具调用及结果、审批、向用户提问、计划、终端、文件改动、本轮执行结果、多媒体与资源、异常与不可用提示。
- 图片、文件等输入也纳入本次目标，不再沿用仅文本输入的交付范围。具体类型、传递方式、限额与保留方式仍待确定；现有权威文档在正式变更前仍描述仅文本输入。
- 以 ACP 标准能力为统一基础，验证 Codex 和 Oh My Pi；不根据普通文本猜造结构化能力。
- 每类内容验收覆盖实时呈现、状态更新、重新进入后的历史恢复，以及失败或不支持时的明确说明；审批与提问还覆盖应答提交及多设备处理。
- 本地会话和经 Node Link 导入的远程会话均纳入上述支持范围；远程附件正文由资源所属节点保存，中转节点不持久保存远程正文。
- 输入支持选择或粘贴图片、选择文件、选择已有音频文件；录音、录像和视频专用预览留待后续。仅向明确支持对应类型的 Agent 发送；不支持时保留草稿并说明原因，不自动转换或静默删除附件后提交文字。
- 上传附件传递用户选择的文件内容；工作目录文件引用仅限当前会话目录内；外部链接作为消息内容传给 Agent，客户端和服务端不因展示链接而自动下载目标内容。
- 点击发送后才上传附件，选择阶段仅在当前设备预览；全部附件传输完成后才提交整条消息。部分失败保留完整草稿，不提交文字或部分附件；上传可取消，未提交给 Agent 不触发执行。
- 已发送附件与所属消息保留期一致，历史可查看或下载，消息清理时关联清理；未成功提交的临时上传自动过期清理。远程附件仅在所属节点长期保存，中转节点不落盘。
- 用户随后修订：首版不设附件数量、单个大小或每条消息总大小的产品上限，撤回此前 10 个 / 20 MiB / 50 MiB 的建议值。传输仍采用分块方式；Agent 实际限制与资源耗尽时的行为、必要的运行保护边界待确认，不得宣称 Agent 可接收无限内容。
- 刷新或换设备后允许重新取得当前待处理请求：须由服务端确认有效并返回完整选项后才可应答；已处理或失效的请求只展示结果。该决策调整当前“仅历史请求不可应答”的交付边界，具体身份绑定与防重复处理规则待正式协议设计。
- 按一次用户发送及其引发的执行组织对话，组内保持真实发生顺序；不属于某一轮的事件独立按时间呈现。同一工具调用的状态更新合并在同一卡片，最终回复正常展示。
- 执行中的工具默认展开，完成后收起为摘要；思考默认收起，计划显示紧凑步骤，最终回复展开。用户手动折叠选择优先于后续自动更新；待处理审批、提问与失败原因保持醒目。
- 提问支持按 Agent 表单生成文本、数字、布尔、单选、多选控件及必填/范围校验，提供提交、拒绝、取消；不支持的类型明确说明，不提交空值冒充填写。多设备仅第一个有效答案被接受，其余更新为已处理；具体表单词汇需对照协议核实。
- 执行中允许编辑下一条草稿，但不允许发送、不建立消息队列；当前轮结束后才能发送。停止须等待服务端确认后才能提交下一轮，保持同一会话最多一个执行中的轮次。
- 无附件产品额度不代表无运行保护：分块、控制内存使用、并发与速率；Agent 实际限制提前说明，磁盘不足明确失败，不截断内容。
- 工作目录文件引用只传路径，不固定内容版本、不追踪后续文件变化；历史展示代表路径引用，不代表保存了当时文件内容。覆盖此前“固定发送版本”的建议。
- 未发送草稿及附件选择仅保留于当前页面内存；切换会话或打开文件查看时保留，刷新或关闭页面不保证恢复并提供离开提醒。未提交临时上传闲置 24 小时清理；本次不做刷新后的断点续传。
- 位于底部时跟随新内容；向上阅读后保持位置并显示新内容/回到底部入口。加载更早记录、展开详情和图片加载时保持阅读位置，切回会话恢复原位置。
- 正文支持常用 Markdown（标题、列表、表格、引用、链接、代码高亮与复制），文件路径可打开对应文件；Agent 实际提供的图片可预览、音频可播放、文件可下载。HTML、脚本与可执行内容不直接运行，外部图片链接不自动加载。
- 本次补齐真实 ACP 终端服务：Agent 可按能力请求启动、查看、等待和停止任务；页面展示命令、持续输出、退出结果及截断说明，相关操作遵守审批规则。不提供用户手动输入的交互终端；须用真实链路验收。
- Q22 Agent 明确发送的思考文本或摘要单独保存与展示，并支持历史恢复，遵循会话正文保留/清理规则；不生成或推测 Agent 未提供的思考。
- Q23 全部采用：回复、Agent 提供的思考、工具输出及终端日志按实际增量持续更新，同段内容原位追加，不新增重复卡片；工具未提供增量时仅展示真实运行状态，不模拟输出。未完成的 Markdown 格式不得导致正文丢失或页面闪动。断线后补回遗漏内容并去重，历史最终内容与实时结果一致；停止或失败保留已收到内容并标记实际结果；向上阅读不自动滚动，底部才跟随输出。

## 正式变更需同步的约定

### 文件栏移除“会话变更”（2026-10-19，补充访谈）

已确认：

- 仅移除对话页文件栏的“会话变更”来源入口及其专属查看，保留目录浏览与“Git 变更”。
- 对话时间线中的工具调用、文件差异展示与已有历史记录继续保留；不删除后端文件改动事件或改变 ACP 能力。
- “Git 变更”表示整个会话工作目录的未提交修改，可能包含人工操作和其他会话造成的修改，不表示当前会话独占的改动。
- 当时仅讨论并记录设计；该决定其后由 `remove-session-file-changes` 同步到前端权威文档并实施，讨论记录本身不代表验收已通过。

- 后续确认：首次进入默认“全部文件”，保留现有名称；旧的“会话变更”选择回退到“全部文件”。非 Git 目录仍可浏览文件，“Git 变更”明确说明不可用原因。
- 本补充访谈已结束；决定已同步至 `FRONTEND_DESIGN.md` §2 与 `INITIAL_DESIGN.md` 文件栏边界，并由变更 `remove-session-file-changes` 实施到客户端与桌面原型。讨论结论仅为文件栏来源收敛：只移除文件栏的「会话变更」来源，**不**移除对话时间线的工具调用与结构化差异、原有历史读取或后端 `file.changed`。验证状态与未执行项以 [`docs/evidence/remove-session-file-changes.md`](./evidence/remove-session-file-changes.md) 为准。

- 仅文本输入边界改为有能力校验的图片、文件与已有音频输入，补齐附件传输、保留与 Node Link 转发。
- 历史待处理交互由不可直接应答扩为可重新取得有效请求后应答，保留服务端有效性与防重复处理校验。
- 执行中草稿由只读改为可编辑，仍不允许发送或排队。
- 真实终端服务与对应能力宣告纳入本次交付；思考与非文本消息的历史恢复须补齐。
- 产品、前端、Sync、Node Link、安全、身份契约、核心端口与存储、模块职责、ACP 兼容矩阵及相关机器合同按实际影响同步，不提前声称已实现。
- 时间线结构、折叠方式、富文本覆盖与历史阅读体验。

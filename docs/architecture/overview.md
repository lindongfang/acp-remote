# Harness Control Plane 总体架构

本文维护 ACP Remote 的产品范围、单节点逻辑模块、数据权威以及会话恢复、控制与资源回收总体架构。已落地的对外产品行为以 [openspec/specs/](../../openspec/specs/) 长期规格为唯一权威，各能力排期与变更依赖见 [能力地图](capability-map.md)，领域术语见 [领域术语表](../../openspec/GLOSSARY.md)；尚未归档的远期规划（标记 `x-deferred: true`）不代表产品代码已实现。

## 1. 一页摘要

ACP Remote 的目标是基于 ACP（Agent Client Protocol）和 Tailscale 网络路径，统一管理 Harness 的实例、会话生命周期、执行调度、状态、权限审批和审计。Harness 是实际运行任务的程序，当前重点接入目标为 Codex 与 Pi（Pi 尚处于规划阶段，OMP、DeepSeek Harness 与 ZCode 暂不适配）。

已确认的核心原则：

1. **一个完整节点。** 没有中心服务器与执行节点的部署划分；管理、运行和存储都是本项目实例内部的能力。逻辑模块不等于服务或机器。
2. **不实现模型和工具系统。** Harness 负责推理、工具调用和内部任务组织；平台管理与记录其暴露的行为。
3. **原生上下文由 Harness 恢复。** 平台保存原生会话标识及必要参数，调用原生恢复接口；绝不通过把展示缓存文本拼回 Prompt 来伪造模型上下文。
4. **模型与原生事实以 Harness 为权威，展示快照受控淘汰。** 原生会话列表、消息、工具记录、父子关系和附件以 Harness 为权威，打开自动重放校准与手动重试同步以最新原生事实更新本地快照；平台核心管理库只持久保存配置、身份及必要管理和操作事实，另以物理隔离的受管展示快照库（默认 30 天滑动有效期、10 GiB 总磁盘上限）承接首屏秒开与跨回收展示，不建立无期限永久聊天档案，也不解析厂商私有文件。
5. **混合自适应恢复与展示。** 打开未加载会话命中有效本地展示快照时首屏立即秒开，若对端支持标准重放则后台自动按容量规则拉取一次最新原生历史并无感补齐外部 CLI 新增内容（满额或异常降级保留快照阅读并支持手动重试）；继续对话时支持 `session/resume` 轻量恢复并与展示快照衔接；无重放 Harness 亦可跨 30 分钟空闲回收与节点重启保留平台已观测历史，并如实标记外部变更或不可恢复边界。活跃连接内实时输出不另设内存截断预算。
6. **会话顺序以 Harness 为准。** 单个会话内的实时、刷新、分页与重启恢复顺序一致，不按平台接收时间或内容类型重排；工具晚完成时在其首次位置更新，后续文字不移动，具体关联和更新规则见 [structured-history](../../openspec/specs/structured-history/spec.md)。
7. **子 Agent 作为父会话的一步展开。** 按原生可靠身份与关系建立可重建视图，父步骤内展开子内容；不将父子正文混排为全局时间线。
8. **允许同目录并行，单会话单端执掌写控制。** 不同会话可以同时操作同一目录，不加目录锁、不自动隔离或合并修改；同一个主会话串行派发输入，并在活跃加载期最多允许 1 台受信客户端持有写控制权（支持顶号式显式接管，其余受信客户端只读共享查看队列、输出与待决审批，控制权随会话释放或重启自动归零），不限制 Harness 原生的子 Agent 或后台活动。
9. **页面断开不停止任务。** 前台执行中或等待审批时不因页面关闭、断网、控制权接管切换或资源回收策略关闭实例；仅加载但没有执行或待审批工作的资源可以按回收条件释放。
10. **不确定就明确标记。** 异常中断不自动重发输入，不假装外部副作用已经失败或成功，不复用失效审批。
11. **页面运行状态只有运行中、空闲。** 运行中表示会话资源已加载且未回收，包括等待输入；空闲表示资源已回收且会话可恢复。运行中存在有效授权请求时附加“待授权”，客户端会话控制角色（主控/只读/未接管）作为正交标识独立呈现，错误通过页面报错呈现。
12. **历史按轮次分页。** 一次用户输入及其对应执行内容为一轮，前端传入每页轮数、默认 10；父会话倒序分页，子会话在所属父步骤内正序分页。
13. **资源按活动与容量回收。** 可安全释放的主会话 30 分钟无活动后回收；默认最多加载 50 个主会话，子会话不单独计数。创建或恢复遇到容量上限时，先回收最久未活动的可回收会话；没有候选则明确报容量已满，不取消任务、不超限、不自动排队。
14. **优先最高共同可用协议。** 每个新连接优先发起平台已实现的最高 ACP 版本协商，按规范使用最高共同可用版本及其实际能力，不长期固定旧版或压成低版能力交集。规范回退与业务失败分开；详细规则见 [harness-management](../../openspec/specs/harness-management/spec.md)。

## 2. 产品范围与部署边界

### 2.1 完整节点

当前只设计一个完整节点内部的系统：

```text
Web / Mobile / CLI / IDE
            |
            v
+---------------------------------------------+
| ACP Remote                                  |
|                                             |
| Client Gateway                              |
| Identity / Policy / Approvals               |
| Harness / Session / Workspace Management    |
| Execution / Scheduler / Dispatcher          |
| History / Transcript Cache / Audit / Queries|
| Process Runtime / ACP Adapters / Storage    |
+---------------------------------------------+
            |
           ACP
            |
            v
       Codex / Pi
            |
            v
Magpie / Models / MCP / Tools
```

Tailscale 是网络接入与部署路径，不是另一个业务节点，也不替代应用认证。未来是否管理多台机器不在当前方案中展开，不预置中心服务器、远程执行节点或节点派发协议。

客户端设备形态（桌面 Web、手机 Web、CLI）本身不构成固定的节点级权限等级：首期面向个人使用，已认证且未撤销的客户端均可执行节点级管理（设备查看/撤销、容量观测、工作区与启动配置管理、新建主会话）并只读查看任意会话；但在单个主会话内部采用**单客户端显式控制权接管**（见 [会话控制权接管规格](../../openspec/specs/session-control-takeover/spec.md)），同一时刻仅当前接管设备可向该会话发起写操作与审批裁决，其他已配对设备对该会话保持只读。团队多租户账号与 RBAC 角色体系暂不展开。

### 2.2 管理范围

- 通用会话闭环按实际能力发现和读取已授权原生范围的会话，包含外部客户端创建的会话。
- 浏览不以导入或已有执行绑定为前提；命中本地有效展示快照时首屏立即展示，需要后台自动重放校准或无快照首次加载时沿原生恢复、互斥及资源所有权管理（满额时优雅降级保留快照阅读）。外部原生会话显式纳管不复制厂商私有历史文件，不承诺所有外部写入在未打开或无重放能力时实时推送。
- 平台负责 Harness 实例生命周期、会话与单会话控制权协调、执行调度、审批、混合自适应展示快照与历史分页、以及审计。
- 模型路由、MCP、工具实现和 Harness 内部推理不由平台重新实现；必要启动配置通过 Harness 配置引用传入。
- Harness 启动默认继承节点环境变量，显式启动配置可覆盖对应值；不新增环境白名单或指纹门禁。敏感值仍不得进入普通日志、审计或错误，具体行为见 [harness-management](../../openspec/specs/harness-management/spec.md)。
- 思考、工具、终端、文件差异和子 Agent 等结构化内容不静默降为普通文本。
- 只展示标准 ACP 实际重放、当前连接及由此形成的受管展示快照内容；无重放仍可接入并在展示快照保留范围内如实标记外部变更或不可恢复边界，不宣称恢复未暴露内容。

## 3. 逻辑模块划分

采用一个应用内的模块化结构。首期不按每个模块拆独立进程、服务或 Rust crate。

| 模块 | 职责 | 状态归属 |
|---|---|---|
| `identity` | 客户端身份、认证、信任与撤销 | 客户端身份与信任记录 |
| `policy` | 管理动作资格、单会话控制权接管校验与本机限制衔接 | 策略配置与运行期主会话控制权状态；首期不引入团队角色系统 |
| `harnesses` | Harness 定义、版本、配置与实例生命周期 | 定义、实例身份与生命周期 |
| `workspaces` | 登记工作目录、解析目录引用 | 工作空间资料；不维护独占锁 |
| `sessions` | 会话生命周期、原生绑定、运行期控制权接管、参与者和父子关系 | 会话、绑定、参与者与活跃控制代际 |
| `execution` | Run、命令协调、排队、派发、取消与结果 | 执行和命令状态 |
| `approvals` | 请求、裁决、失效与交付跟踪 | 审批事实 |
| `history` | 原生历史读取、受管展示快照库、来源顺序与实时衔接 | Harness 为上下文权威；平台展示快照按策略保留与重建 |
| `audit` | 操作者、动作、决策依据与结果 | 审计记录 |
| `queries` | 汇总列表、过滤、分页和展示视图 | 可重建的查询结果，不决定业务状态 |

Scheduler / Dispatcher 分别表示安排执行与下发操作，放在 `execution` 内部，不单独建设远程调度服务。已有会话继续执行使用自己的原生绑定，不随机重新分配到其他 Harness。

运行与接入边界：

| 边界 | 职责 |
|---|---|
| Client Gateway | 客户端命令入口、控制权接管校验、实时订阅与分页接口 |
| ACP Facade | 按需为 ACP 客户端提供入口，与 Harness 侧适配器分开 |
| Harness Adapter | ACP 能力协商、原生会话操作、结构化事件与管理视图转换 |
| Process Runtime | 进程启停、异常检测、取消、完整进程树清理及平台实现 |
| Storage | 核心控制面 SQLite（配置、身份、命令、审批与审计事务）与物理隔离的展示快照库及备份 |
| Keystore | 隔离平台密钥存储；密钥不进入普通历史字段 |

协议类型、业务对象、数据库记录和页面视图分别建模。核心业务不依赖具体数据库、网络框架、子进程 API 或 ACP DTO；适配器负责转换，应用入口负责装配。禁止巨型 Runtime 统揽所有业务。

ACP 兼容层保留管理所需的结构化视图和必要原始/扩展载荷，不能以精简内部表示替代完整协议语义。版本与可选能力必须实际协商，未来版本支持不视为已实现。

物理 crate 数量、目录名和具体存储后端可在详细设计中自主确定。早期讨论中的中心连接、执行节点和节点网关拆分不属于当前方案。

## 4. 数据对象与术语

术语定义见 [领域术语表](../../openspec/GLOSSARY.md)。原生身份跨启动入口稳定，审批归属原生操作上下文，当前连接指节点的 Harness 连接代际，能力准入与实测证据分开，通用机制按接入能力独立交付；单会话控制权接管（`SessionControlState`）与受管展示快照库（`TranscriptCache`）边界各自正交独立。

本节是概念清单，不是数据库 DDL。Session、ConversationItem、ToolCall、AgentParticipant、Delegation 和历史 Blob 表示原生对象引用或受管展示视图，不表示平台拥有模型上下文权威或永久聊天档案。平台操作 Run 与 Command 只描述平台实际发起的动作；外部对话不得补造成平台执行。

### 4.1 资源与执行对象

| 对象 | 含义 | 主要字段 |
|---|---|---|
| `HarnessDefinition` | 一份可启动的 Harness 定义 | ID、名称、类型、程序位置、启动参数、配置引用 |
| `HarnessInstance` | 实际启动的进程实例 | ID、定义 ID、版本、适配器版本、协商能力、进程状态、启动/退出时间 |
| `Workspace` | 登记的本地工作目录 | ID、名称、规范化路径、可用状态 |
| `ClientIdentity` | 可连接本节点的客户端身份 | ID、公钥、显示名称、信任与撤销状态 |
| `Session` | 可以反复返回继续交互的会话 | ID、Harness 定义、工作空间、标题来源、来源类型、创建/活动/归档时间、当前执行引用 |
| `SessionControlState` | 主会话活跃加载期内的客户端写控制状态（仅内存） | 根主会话标识、当前主控 `controllerClientId`（可空）、单调递增 `controlEpoch`、接管时间 |
| `NativeSessionBinding` | 平台管理目标与原生会话的对应关系 | 显式接入来源、原生会话标识、恢复引用；启动配置及连接为独立引用 |
| `Run` | 一次输入引发的执行过程 | ID、会话 ID、输入条目、执行实例、排队/开始/结束时间、状态、结束原因、原生执行标识（若有） |
| `AgentParticipant` | 主 Agent 或某个子 Agent 的稳定身份 | ID、会话 ID、直接父参与者 ID、根参与者 ID、创建 Run/工具调用引用、名称、角色、原生 Agent ID（若有） |
| `Delegation` | 一次向子 Agent 委派任务的关系 | ID、发起/目标参与者、发起 Run、输入/结果引用、原生消息或工具调用引用、状态 |

`Run` 不是一次模型请求：一次 Run 可以包含多次模型调用、工具调用和子 Agent 活动。平台不重建其内部推理步骤。

`AgentParticipant` 区分参与者稳定身份与单次 Run 执行。Agent 身份不因进程重启而自动改变；恢复同一个原生子 Agent 时沿用对应身份。

### 4.2 历史、审批与内容对象

| 对象 | 含义 | 主要字段 |
|---|---|---|
| `ConversationItem` | 一条可展示的结构化历史条目 | ID、会话内位置、Run/参与者引用、类型、正文或内容引用、完成状态、内容版本 |
| `SessionEvent` | 来源事件视图；管理事实另由平台持久记录 | ID、会话内位置、事件类型、Run/条目/工具/审批引用、必要协议载荷及来源 |
| `TranscriptSnapshot` | 物理隔离展示快照库中的受管会话展示快照 | 原生范围与会话标识、快照代际、最近实际写入时间、估算字节数、轮次边界与完整性标记 |
| `ToolCall` | 平台观察到的一次工具执行 | ID、原生调用 ID、会话/Run、名称、类别、输入、输出、状态、错误、审批/附件引用 |
| `ApprovalRequest` | Harness 请求批准的具体操作 | 原生操作上下文、原生目标、实例/连接代际/请求标识、可选 Run 与工具引用、操作内容、选项、有效状态 |
| `ApprovalDecision` | 用户作出的最终裁决 | 请求 ID、决定、决定者、时间 |
| `ApprovalDelivery` | 裁决是否成功交付到有效的 Harness 请求 | 请求/裁决引用、交付状态、失败原因 |
| `Command` | 可追踪的管理请求 | ID、稳定请求标识、调用客户端、动作、目标、受理与结果状态 |
| `Blob` | 按引用读取的大块内容 | ID 或内容摘要、字节大小、媒体类型、内容位置、引用关系 |
| `AuditRecord` | 谁要求做什么、依据与结果 | ID、操作者、动作、目标、时间、决策依据、相关命令/事件引用 |

Blob 视图引用原生图片及大型输出，平台只使用受容量与保留期约束的可淘汰展示缓存或有生命周期的临时上传，不建立永久历史附件库。工具调用是原生历史视图，不代表平台建设工具目录或执行系统。

### 4.3 关联约束

1. 一个 Harness 定义可以有多个运行实例、多个会话；实例退出不删除会话。
2. 一个会话可有多个 Run，但前台串行派发；忙碌时允许当前持有主会话控制权的客户端入节点队列（其他受信客户端可共享只读查看队列），排队不表示 Run 已开始，数量及操作由 [session-execution](../../openspec/specs/session-execution/spec.md) 与 [session-control-takeover](../../openspec/specs/session-control-takeover/spec.md) 协同定义。这不禁止 Harness 内部的子 Agent、后台任务或原生并行活动。
3. 同一目录可以关联多个会话，允许并行修改，不加独占约束。
4. 原生会话绑定用于恢复原会话；恢复失败不能静默创建一个新原生会话替代。
5. 父子关系按原生事实投影到 AgentParticipant 视图中：根参与者没有父参与者；父关系不能形成循环，子参与者必须能追溯到根。子会话继承所属根主会话的客户端控制权状态，不单独设立独立控制锁。
6. 子 Agent 有可靠独立原生身份时引用其原生会话并按需读取子历史，父步骤保留来源引用视图并可在受管展示快照库有效期内缓存已观测子内容，但不建立平台永久正文或关系档案。
7. 父子归属说明谁创建谁；Delegation 说明哪次任务委派给谁。同一子 Agent 可以被多次委派，不能把每次委派误认为创建新 Agent。
8. Harness 未提供可靠子身份或父子关系时，保留已知信息并明确缺失，不伪造执行树；只有工具调用时保留为工具调用。
9. 审批请求最多有一个最终裁决，且仅允许当前持有所属主会话控制权的客户端提交裁决；裁决保存与交付成功分别记录。平台 Run 关联不替代原生请求有效性，前台结束不自动失效后台审批。旧运行连接中的失效请求不能因恢复而重新变成有效审批。
10. 原生标识按显式接入来源解释，不能假设各款 Harness 的标识全局唯一或平台 ID 与原生 ID 天然相同。文档中原生范围指该配置来源命名空间，不表示平台已证明物理存储或账户等价。

子会话以所属父会话轮次中的一个委派步骤展示名称、角色和状态，点击后在原步骤内展开子历史，支持折叠及逐层展开；不跳转子页；展开区域支持自身正序分页，轮数由前端传入、默认 10，父会话则使用其前端分页参数倒序读取、默认 10。子会话仍保留可靠原生身份与原生存储，父步骤引用其内容而非混排正文；父步骤位置与子内容内部顺序各自保留，不在父平级时间线上混排父子正文。同一子会话多次委派保留各自父步骤和来源关联，不根据时间猜测子内容归属范围。

### 4.4 字段与记录职责的补充

对象字段按上述清单收敛，具体类型、可空性、数据库列和索引可自主细化。以下职责必须保持：

- 启动配置、显式接入来源和 Harness 连接身份分别建模。原生会话以接入来源及原生标识识别；同来源经不同安装路径、配置别名或连接访问时归属同一执行协调对象，不重复计数。不同来源中的相同 ID 不自动合并。多个入口访问同一来源时显式引用同一来源身份；平台不自动判定不同来源背后的物理存储是否相同，不承诺跨这些来源识别重复或提供互斥，也不为此增加厂商探测器或私有文件解析。缺少物理存储证明不构成已配置来源的接入阻断。
- ConversationItem 视图采用可验证的原生条目、轮次、位置、参与者及更新语义；连接内临时标识不得冒充跨重启稳定原生 ID。位置、版本和读取/快照代际不能混用，不假定每款都有单调内容版本。
- 工具卡片的位置属于 ConversationItem，工具结构化输入、输出与结果属于 ToolCall；卡片引用工具对象，不再独立维护一份可修改的工具正文。审批卡片同理。
- Command 保存请求标识、调用客户端、动作、目标、请求摘要和处理结果；请求有效期内相同身份重试返回原处理结果，内容不一致则明确报错。过期后仅拒绝执行或按权限只读查询原事实，不因记录已清理而重新派发。平台请求标识不等于 ACP JSON-RPC 请求 ID，具体有效期及去重容量由 [session-execution](../../openspec/specs/session-execution/spec.md) 定义。
- 原生操作上下文覆盖真实加载、恢复、输入引发的工作及会话内后台或 Agent 自发工作；审批首先绑定节点验证的目标、实例、连接代际和当前真实请求，仅有可靠依据时关联 Run，不要求协议额外提供精确前后台分类。Run、工具及审批已关联时目标必须一致，不能借用其他操作权限；Delegation 是显式跨父子关系。查看和自发工作无需伪造 Run。
- 工作目录暂时不可用不自动删除 Workspace；恢复同一个原生 Agent 不自动创建新的 AgentParticipant。
- 凭据和密钥保存为安全引用，不进入普通正文、配置快照或审计载荷。

### 4.5 平台约束与 ACP 原生流程

标准能力直接复用 ACP 当前协商、能力声明和标准方法；Harness 不支持时直接报告 ACP 所表达的不支持及实际错误，不建立额外平台能力准入、兼容验证阻塞、用户裁决流程或私有兜底。实测记录只用于开发维护和验收追溯，不决定用户是否可以发起标准调用。身份权限、单会话控制权、必要去重、原生请求有效性及资源安全仍按负责规格执行；这些真实安全条件不被当作另一套 ACP 能力证明。具体行为由 [harness-management](../../openspec/specs/harness-management/spec.md) 单一定义。

Harness 专项工作面向能力调研与真实验证，代码不固定 Harness 与 ACP 版本的对应关系。固定程序及适配器版本仅用于证据追溯；运行阶段每次连接初始化按协议规则协商版本和能力，再绑定该连接代际的处理策略。重连重新协商，不用旧报告、程序版本号或 Harness 名称代替。通用协议实现仍有明确的已实现版本集合，不承诺无需实现即可支持任意未来版本。

当前能力使用与错误边界见 [harness-management](../../openspec/specs/harness-management/spec.md)，历史展示与混合快照见 [structured-history](../../openspec/specs/structured-history/spec.md) 与 [session-transcript-cache](../../openspec/specs/session-transcript-cache/spec.md)。无重放不统一阻断其他能力；不按厂商增加私有读取器，也不以当前能力或旧报告宣称新版产品已验收。

协议协商优先使用平台已实现的最高共同可用协议，避免同一 Harness 支持多版却长期低版对接；不要求程序版本报告白名单，也不承诺尚未实现的未来版。遵守对端合法协商选择；分别报告发起版本、实际选择与已知回退依据，没有提供原因时不编造。仅高版无共同可用支持且规范允许时协商低版，不以网络、认证或业务失败自动降版重发。升级及重连后的新连接重新优先高版，既有连接内不热切版本。

标准能力按协议版本与实际协商能力处理，不按厂商名称分支。共用协议客户端，通过版本策略和适配器模式隔离 v1/v2 差异；具体实现设计、逐版本合同和验证范围见 [通用 ACP 设计](../../openspec/changes/archive/2026-11-16-deliver-codex-session-loop/design.md)。ACP v1/v2 均纳入兼容目标；每版规范、实际版本标识、稳定/草案状态与真实对端均需核实，不将 JSON-RPC 2.0、SDK 版本或兼容设计本身视为 ACP v2 已支持。每款仅验证实际提供的版本/能力组合，不假定都支持两版。

Agent 升级后的连接按 ACP 重新协商；不支持或协议错误直接报告，不要求先通过平台兼容复验或等待用户裁决。开发维护中的影响分析和独立验收仍有固定版本归属，旧证据不冒充新版本通过；不自动增加私有适配、替代原生会话或以业务失败降版重发。协议完成、取消及审批遵循对应版本语义。

平台可以强制自己的关联一致性、请求防重复、单会话控制权互斥、审批唯一裁决和命令协调，但不能为凑平台状态而重新解释 Harness 流程。

“取消中仍占用名额”仅指：在确认前台执行结束前，不向同一个原生会话派发下一次普通输入。它不是消息位置、目录锁，也不要求退出整个进程或结束所有原生后台任务。

执行结束、取消和权限请求首先遵循实际协商的 ACP 版本。以 ACP v1 为例：

- 前台轮次结束由原 `session/prompt` 响应及结束原因表达。
- `session/cancel` 是通知，没有独立成功响应；发送通知不等于取消完成。Agent 中止相关操作并发送剩余更新后，应对原 prompt 返回 `cancelled`。
- `session/request_permission` 是请求/响应；取消当前轮次时，客户端必须将相关待处理权限请求回复为 `cancelled`。
- 取消未确认或连接丢失时，不假装取消完成，也不盲目重发原输入；按已知事实记录中断或结果未知。

其他版本按对应规范映射，不把 v1 的完成信号套用到其他版本。计划内各款 Harness 的验证是接入验收：核对适配器是否正确处理规范消息及已协商能力，不重新决定协议已定义的语义，也不要求 Harness 遵循平台自造的流程。

取消逻辑必须区分活动前台、待确认输入与已可靠空闲。以 v2 为例，前台已确认 idle 且无待确认输入时，取消不要求额外完成通知；不能仅因发送取消而新增输入阻挡或假报后台停止。存在活动或待确认输入时仍跟踪对应事实；与自然完成交错时接受实际正常终态，不要求额外 cancelled 事件。具体行为见 [执行规格的“空闲取消与活动前台取消分开”](../../openspec/specs/session-execution/spec.md)，协议依据为 [ACP v2 取消](https://agentclientprotocol.com/protocol/v2/prompt-lifecycle#cancellation)。

规范来源：[ACP v1 执行与取消](https://agentclientprotocol.com/protocol/v1/prompt-turn)、[权限请求](https://agentclientprotocol.com/protocol/v1/tool-calls)。

## 5. 数据权威、缓存与管理记录

### 5.1 权威划分

| 事实 | 权威来源与平台职责 |
|---|---|
| 会话列表、消息、工具记录、父子关系、历史附件 | Harness 为原生权威；平台按实际接口读取并在独立展示快照库中保存受保留期与容量上限约束的结构化展示快照 |
| 原上下文如何继续 | Harness 原生存储及恢复接口（`session/resume` 或 `session/load`）；绝不回灌展示快照充当模型上下文 |
| 平台配置、身份、命令受理及交付结果 | 核心控制面 SQLite 持久记录，不混入聊天正文或展示快照 |
| 平台审批裁决与交付、管理审计 | 核心控制面 SQLite 持久记录必要元数据，不永久复制提示词和工具正文 |
| 主会话单客户端写控制权（`SessionControlState`） | 节点活跃运行期内存协调状态，随会话资源释放或节点重启自动归零 |
| 当前工具和进程是否仍执行 | 当前运行实例实际观测，未知明确说明 |

平台不建立永久聊天档案，也不改写 Harness 私有存储或通过解析厂商私有 `.jsonl` 文件补足未经授权的接入能力。受管展示快照库在打开自动同步重放或手动重试同步时以最新原生事实为准建立新快照代际，在原生会话确认删除时立即同步擦除，并受默认 **30 天滑动保留期**（仅随实际内容写入或发现实质变更的原生同步刷新，纯读取及无变更自动核对不续期）与 **10 GiB 总磁盘上限**（超限时按最久未写入优先淘汰非活跃会话快照）自动治理。

### 5.2 历史读取与更新

平台按能力列出原生会话和按标识读取历史，范围包含外部创建会话，浏览不以执行绑定或会话写控制权接管为前提。对于当前未加载且本地存在有效展示快照的会话，打开时首屏立即返回本地展示快照（零白屏等待）；若对端支持标准重放，节点无需用户手动点击即同时在后台按容量规则自动触发一次标准重放校准，收齐后更新本地快照并在前端保持阅读位置无感补齐外部 CLI 新增对话（50 名额被受保护会话占满或拉取失败时优雅降级保留已秒开的本地快照阅读并轻提示，支持手动重试；已处于活跃加载态的会话直接读取内存共享视图不重复拉取）。原生删除或压缩后不承诺平台另存完整永久版本。

有真实订阅能力时可主动推送外部更新，无该能力时不承诺未打开期间所有外部 CLI 操作实时推送，而是在打开会话时自动拉取同步。不进行私有桥接、私有目录扫描或改写原生文件。原生同步失败或满额降级时不得伪装展示快照已包含最新外部写入。

### 5.3 当前连接输出与缓存

实时输出由节点按原生会话及 Harness 连接代际向所有有权客户端（含当前主控端与只读观察端）共享广播，首次订阅无后续增量也能展示已有内容，并异步落入物理隔离的展示快照库；活跃连接内不另设输出内存截断预算。历史、展示快照和实时输出只按可靠来源与代际关联，慢读取或展示快照库 I/O 异常不阻塞 ACP 接收、核心命令去重、严格审批裁决及执行控制，展示故障不取消执行。具体行为见 [structured-history](../../openspec/specs/structured-history/spec.md) 与 [session-transcript-cache](../../openspec/specs/session-transcript-cache/spec.md)。

正常页面不出现平台保存进度条；展示快照降级、历史不支持、原生同步失败及内容衔接边界仍须明确说明。核心控制面管理存储失败不能降格为可忽略缓存错误。

### 5.4 混合自适应历史与展示快照

“当前连接”指节点到 Harness 连接，非浏览器。浏览器切换或控制权顶号接管不清空节点队列、活跃连接视图或展示快照。当主会话因 30 分钟无活动回收或节点重启释放连接后：
- 若本地展示快照仍在有效期内，任意受信客户端打开会话时首屏立即渲染本地结构化历史，并对支持标准重放的对端在后台自动拉取补齐外部 CLI 增量；
- 当持有控制权的客户端继续对话时，若会话已由后台重放加载则直接继续输入，若尚未加载且 Harness 支持轻量 `session/resume` 则可轻量恢复模型上下文并将新一轮输出无缝衔接在展示快照之后；
- 若 Harness 仅支持当前连接或仅支持无重放 `session/resume`，展示快照仍跨空闲回收与重启保留平台已观测对话，并如实标记潜在外部 CLI 缺口或不可继续恢复的只读快照状态，绝不开发厂商私有读取器或回灌文本上下文。

### 5.5 命令、审批与异常

输入、队列变更、取消与审批裁决提交到节点时，除校验客户端受信身份、目标及内容外，还必须校验该客户端当前持有所属主会话的控制权（且若携带期望 `controlEpoch` 则须一致）；只读未接管客户端或已被顶号降级的旧控制端发起写请求将立即被无副作用拒绝。请求一旦在控制权有效时被节点受理，即由节点接管后续派发责任：后续控制权被其他设备顶号接管、原操作者断线或被撤销，均不自动取消已受理输入或已开启的 `Run`，也不在派发时重验原提交者。队列正文仅内存，不跨节点重启保存；必要去重与发送元数据独立保存在核心控制面库中，具体行为见 [session-execution](../../openspec/specs/session-execution/spec.md) 与 [session-control-takeover](../../openspec/specs/session-control-takeover/spec.md)。

受理、原生接收和原生完成分别记录；异常不自动重发。执行终态按协议可靠事实记录，不以展示快照落盘成功为条件，也不代表原生历史必然完整可读。平台 Run、原生前台活动和后台工作分别判断；无 Run 不证明原生空闲，前台完成不证明后台结束。审批有效性按真实请求及协议生命周期判断，控制权顶号接管会将仍在有效期内的待决 `ApprovalRequest` 平滑移交新控制端裁决，而其他只读设备仅可查看待审批详情。无法验证目标、连接和真实请求时保持未授权，不复活旧决定，不用客户端自报正文替代可信来源。

- **管理存储故障边界**：核心控制面 SQLite 中必要去重、唯一派发、批准决定及资源归属无法可靠维护时停止相关新动作；独立展示快照库故障或附加审计失败仅触发对应告警与展示降级，绝不阻断核心安全控制或伪报已保存。批准必须在核心控制面严格保存后才交付，由节点完成，不因原审批者事后让渡控制权或被撤销而重验；真实请求失效仍不批准。
- **请求去重与时间基准**：节点登记稳定请求身份及处理状态防重复，不再额外每动作签名，不依赖统一 24 小时输入截止、回退锁定或持久时间水位。队列无期限，按节点处理顺序排列，管理事件用节点时间，客户端时间不决定受理或顺序；超时/耗时用单调计时。客户端认证凭据原有期限独立维护。

## 6. 原生顺序、分页与查看激活

### 6.1 来源身份与顺序

保留 Harness 实际暴露的结构、必要原始字段及轮内顺序；工具后续完成更新原位置，文字不得跨工具合并。历史、展示快照与实时必须有可靠关联依据；时间戳和正文摘要不能替代身份或排序键。只有连接内顺序时只承诺该连接或对应快照代际范围，不能伪造成跨原生重排稳定位置。

### 6.2 分页与重连

前端可指定每页轮数，默认 10 轮。父会话先显示最近一页，页内从早到晚排列；手动输入子会话标识后，从第 1 轮开始展示。父步骤内展开由 agent-session-tree 负责。轮内保持原顺序，一轮不跨逻辑页，页内大块按需读取。标准重放视图与本地有效展示快照共用同一套可证明轮次分页合同：当本地存在有效展示快照时，首屏与翻页可直接在有效代际上按轮次切片读取而无需重复重放；当打开未加载会话触发后台自动校准、快照不存在/已淘汰或用户手动重试同步时，按 [history-navigation](../../openspec/specs/history-navigation/spec.md) 遍历标准重放建立新快照代际并无感对齐分页视图。可靠轮次无法证明时明确限制，不按消息条数猜测轮次。

游标绑定来源范围、会话、方向、轮次边界及可证明版本或读取/快照代际。原生同步发现压缩/删改使稳定续读无法证明时，明确失效旧代际游标并支持新代际目标重新定位；旧响应不能覆盖新视图，不能假定所有 Harness 提供事务快照或递增版本。

缓存外缺页分为同一有效快照/连接代际内的边界续读，以及新原生同步代际中的目标重新定位。不能证明跨代际连续性时，旧游标失效，但客户端可独立请求新代际中的轮次范围，取得目标页并替换对应视图，明确说明重新定位及连续性限制，不一律返回首页。完整行为以 [分页规格的“缓存外目标重新定位”](../../openspec/specs/history-navigation/spec.md) 为准；来源删改时不承诺保留旧快照边界。

父子各自读取进度独立，嵌套按需展开，每次读取和订阅校验目标受信读取权限（不要求持有会话写控制权）。重新打开校准与原生重连重新读取原生状态并衔接仍在的实时缓存，关系和历史不可读时说明限制，不伪造完整树。

关系展示与子历史分页展开分别判断能力，具体条件见 [子树规格](../../openspec/changes/deliver-agent-session-tree/specs/agent-session-tree/spec.md) 和 [分页规格](../../openspec/specs/history-navigation/spec.md)。子目标可在有效展示快照或标准全量重放上形成平台分页；关系可读不自动证明子内容可重建或轮次可证明，原生分页不是必要条件。

### 6.3 首屏快照秒开、后台自动同步与查看激活

打开未加载会话协调以下两步：
1. **首屏快照秒开与降级兜底**：目标主会话未加载且本地展示快照库存在未过期快照时，任意受信客户端打开会话的首屏请求立即从展示快照库零等待返回；若对端不支持标准重放，或 50 个主会话名额均被受保护忙碌会话占满导致后台自动校准跳过，整个查阅与翻页过程保持**零子进程拉起、零 50 主会话名额占用、不改变“空闲”状态、不启动或刷新 30 分钟无活动计时、也不刷新快照自身的 30 天保留期**。
2. **后台自动拉取校准与查看激活**：当对端支持标准加载重放且节点存在可用名额（或可安全淘汰空闲候选）时，打开未加载会话会自动在后台启动或激活 Harness 执行一次标准重放校准（不要求客户端先接管写控制权，只读查看加载后主会话仍保持“未接管”状态；无本地快照首次查看或手动重试同步同理）。实际触发原生会话加载遵循主树资源所有权与 50 名额管理，实际标准重放接收会刷新 30 分钟空闲计时但不形成任务保护（后续新会话需要名额时可随时安全淘汰）；查看激活绝不自动发送新输入、批准工具或隐式授予写控制权。

正常接管并继续对话时，若会话已由后台重放加载则直接继续输入；若会话尚未加载且 Harness 支持轻量 `session/resume`，可采用无全量重放的原生上下文恢复并与本地快照衔接。恢复不意味着工具、终端或子 Agent 从原执行指令位置续跑。

### 6.4 内容与资源的信任边界

Harness 为历史来源权威，不使正文、标题、审批描述、工具输出、URI、路径或未知扩展成为可信管理指令。实时、标准重放与展示快照回放使用完全一致的安全展示边界，保留原结构不等于执行其中的脚本、主动内容或终端控制。内容不能直接调用管理动作或替用户审批，可信操作控件与原生显示内容分别处理。

链接、文件和附件的实际读取及打开独立校验权限、范围和访问方式，不由节点通用代理任意 URL，不把主动附件作为受信同源页面执行。已有 TLS、应用认证及 CSP 继续有效；具体可观察要求由 [结构化历史规格的内容安全和资源引用要求](../../openspec/specs/structured-history/spec.md) 统一定义，其他快照、分页和子树展示引用该边界，不另建一套规则。

协议依据：[ACP v2 原生前后台工作](https://agentclientprotocol.com/protocol/v2/prompt-lifecycle)、[请求权限](https://agentclientprotocol.com/protocol/v2/tool-calls)及[内容安全](https://agentclientprotocol.com/protocol/v2/security)。这些是规范依据，不构成未实测 Harness 已通过验收的声明。

## 7. 生命周期与多客户端行为

### 7.1 页面运行状态与内部操作分开

页面会话运行状态固定为：

| 展示 | 定义 |
|---|---|
| 运行中 | 会话资源已加载且尚未回收，包括正在执行和等待下一次输入 |
| 空闲 | 未加载或资源已回收；本地若有有效展示快照可直接离线回看，原生上下文恢复依原生实际能力 |
| 运行中 · 待授权 | 运行中的特殊展示，存在有效待处理授权请求，不是第三个独立生命周期 |

客户端相对于当前主会话的**控制角色标识**（`当前设备控制中` / `只读（由 <设备名> 控制中）` / `只读（未接管）`）与页面运行状态正交展示，不构成新的会话运行生命周期枚举。一轮回复完成，只要运行资源未回收，仍为“运行中”；空闲指进程/会话资源已回收（此时控制角色必为“只读（未接管）”）。恢复中可以给出操作加载反馈，连接异常、恢复失败或控制权被顶号降级通过明确反馈呈现，不能用空闲掩盖未知资源情况。

内部仅保留执行协调与历史解释所需的信息，不把每个瞬时步骤都升级成会话字段或页面状态：

| 对象 | 内部记录职责 |
|---|---|
| Session | 原生绑定、归档时间等；页面活动状态由实际资源事实推导，不维护庞大生命周期枚举 |
| SessionControlState | 活跃运行期内存中的当前控制客户端与单调递增 `controlEpoch`；释放或重启归零 |
| 加载/释放/删除操作 | 由 Command 跟踪进行过程与结果；不要求持久化“删除中、已删除”会话状态 |
| HarnessInstance | 进程存活、退出时间与原因，启动/停止过程由操作管理 |
| Run | 执行进行情况与完成、取消、失败、中断、结果未知等终态；取消中不等于已结束 |
| ConversationItem | 生成是否完整；异常时标记中断，不意味着任务本身成功或失败 |
| ToolCall | Harness 实际提供的运行及结果信息，未确认结果不补成成功 |
| Approval | 请求是否有效、唯一裁决、交付结果分别记录 |

正常资源转换是“空闲 → 恢复成功 → 运行中”和“运行中 → 确认释放 → 空闲”。恢复失败、释放失败或连接异常通过操作结果及报错表达，不假装状态已成功转换。

Run 与未发送队列分开，按 ACP 真实语义由派发/执行推进到终态；正常完成或取消路径须收到对应完成信号，取消请求本身不结束 Run。异常路径的重新准入条件见下段。新一轮建立新 Run，不让已结束 Run 重新变为运行中。会话资源状态不能替代某轮结果：同样处于运行中的会话，上一轮可能完成，也可能失败。

异常后能否接受新请求按 [执行规格的“异常后重新准入”](../../openspec/specs/session-execution/spec.md) 判断；旧执行已停止与副作用结果已知分别记录，恢复连接或显式接管控制权本身不解除异常安全约束，也不授权重发原请求。

确认原生删除后不必为展示“已删除”保留可见会话记录，同时同步擦除展示快照库中对应快照。重复请求处理和必要审计使用 Command/AuditRecord 保存删除事实，不把它作为可见会话继续返回。

### 7.2 断开、释放、恢复、删除

| 操作 | 已确认行为 |
|---|---|
| 页面关闭或客户端断网 | 后台执行与 ACP 保持，不因没有页面而中止任务；运行期控制权状态在会话未释放前保留，其他受信设备可随时显式顶号接管 |
| 显式释放控制权 | 仅清空当前主会话客户端控制权归属并使全员回到只读（未接管），不中止正在运行的 `Run`、队列或子进程资源 |
| 自动资源回收 | 只回收没有执行、待审批或需保留后台工作、满足 §7.4 条件的资源；回收成功后页面变为“空闲”，主会话控制权同步自动归零，展示快照库保留供秒开回看 |
| 显式释放会话资源 | 协调结束工作，按实际能力关闭并释放资源，同时清空控制权归属；失败明确反馈，不假装成功 |
| 恢复与接管继续 | 需要操作会话的受信设备显式接管并按原生绑定恢复（支持轻量 `session/resume` 衔接本地快照，或直接复用打开时后台同步连接），成功后才接受新输入；绝不自行灌文本历史 |
| 异常退出 | 保留平台已提交管理事实与已观测展示快照，按需重读可用原生历史；执行标为中断或未知，不自动重发；节点重启后控制权归零 |
| 删除会话 | 只提供显式原生删除，须校验删除范围与主会话控制权保护，确认删除后同步清理对应展示快照；不提供隐藏或仅删平台快照冒充原生删除 |

历史恢复不等于恢复文件系统快照，也不保证外部工具、终端或子 Agent 从原执行指令位置续跑。

### 7.3 多客户端单端控制权接管与原生 CLI

- **查看共享、写控制单端独占**：多个已认证且未撤销的网页、手机或平台 CLI 可以同时只读查看同一会话（包括实时流式输出、共享输入队列状态、停止原因、待处理审批详情及展示快照分页），但同一主会话（含所属全部子会话）在任意时刻**最多允许 1 台受信客户端持有写控制权**。
- **顶号式显式接管（Preemptive Explicit Takeover）**：新建主会话自动将初始控制权授予发起创建的客户端；对于未接管或已由其他客户端控制的主会话，任意受信客户端均可显式发起接管请求，节点原子切换 `controllerClientId`、递增 `controlEpoch` 并向全端广播，原主控客户端立即降级为只读，其滞后在途写请求被确定性拒绝。
- **平滑移交不中断现场**：顶号式显式接管不取消正在运行的 `Run`、不清空节点已受理输入队列、不废除仍在有效期内的待决 `ApprovalRequest`；新主控端立即接手该会话的队列编辑/取消/置顶、中断/继续及待决审批裁决权。
- **只读客户端范围**：未接管的只读受信客户端无法向该会话提交输入、修改队列、中断/恢复执行或裁决审批，但仍可执行全部节点级操作（设备管理、容量检查、配置登记、新建另一个会话），且打开冷会话时可首屏秒开展示快照并由节点在后台按能力自动同步外部更新。
- **活跃期内存生命周期**：单会话客户端控制权仅在主会话活跃加载期内驻留内存；显式释放控制权、控制端设备被撤销、主会话 30 分钟空闲自动回收、显式释放会话资源或节点重启后，控制状态一律自动归零为“未接管”，下次哪台设备需要操作再显式接管。
- **平台锁与外部原生 CLI 边界**：平台内部的会话控制权与平台执行归属（`native-session-import`）只能约束经过平台的操作，不能强制阻止本机外部原生 CLI 直接读写同一原生会话。提供会话资源释放入口方便切换回外部原生 CLI；重新在平台同步或纳管后的上下文恢复仍交给 Harness。
- Harness 有可靠占用检测时呈现占用状态；没有时明确能力限制，不承诺平台可以检测所有外部写入，也不支持承诺外部 CLI 与平台同时写同一原生会话的一致性。
- 外部客户端绕过平台追加的内容在用户于平台打开未加载会话时通过后台自动标准重放（或重连、重新纳管、手动重试）同步更新展示快照并无感补齐到界面；无重放接口则明确标记外部变更不可见边界，不将外部操作记为平台执行或审批。

### 7.4 自动资源回收与容量上限

本节规定平台何时发起自动回收。ACP 提供关闭与释放机制，不替平台决定 30 分钟超时或容量上限；`deliver-session-capacity` 已实现基础 50 名额与 30 分钟回收闭环，与控制权归零及展示快照秒开/降级的联动由后续规划变更承接。

#### 7.4.1 计数与可回收条件

- 默认最多同时加载 **50 个主会话**，不是最多保存 50 个历史会话或展示快照，也不是最多运行 50 个 Harness 进程。
- 子会话不单独占用这个名额；其资源和活动归属于对应主会话的执行树。子会话不计数不意味着不消耗内存或进程资源。
- 直接子目标加载的主树归属、名额和根不可用分支，以 [容量规格的“子目标加载归属主执行树”](../../openspec/specs/session-resource-policy/spec.md) 为准；根正文未打开不免除树资源的计数及所有权。
- 平台只对主会话执行资源池分配、超时回收和容量淘汰；子会话生命周期交由父会话及 Harness 管理，平台不单独为子会话设置超时或淘汰，只依据其运行事实保护所属主会话。
- 新建并加载主会话、恢复已回收的主会话、以及打开支持重放的冷会话触发后台自动重放校准（或无快照首次查看、手动重试同步）都需要名额；首屏读取本地展示快照、无重放会话快照兜底及满额降级只读浏览**不需要**名额，已经加载不重复计数。
- 前台执行、有效待授权请求、需要保留的后台工作，以及子 Agent 的上述活动，均阻止对应主会话被自动回收。单纯持有客户端写控制权（`controllerClientId` 非空）或刚完成打开时的后台自动重放但无任何执行/审批活动时，**不豁免** 30 分钟空闲回收或容量满额淘汰；一旦主会话被成功回收，其控制权自动归零。
- 节点按已知活动选择并请求关闭，Harness 负责内部执行；不要求平台证明隐藏活动不存在或保证检查到实际关闭窗口绝不中断。未提供后台/子覆盖不能伪报为空闲，也不单独禁用请求；已知活动及审批仍保护，发送前复核。关闭成功和必要管理协调后才返额，不修改上游。详见 [容量规格的能力边界](../../openspec/specs/session-resource-policy/spec.md)。
- 待授权会话同时豁免 30 分钟超时回收和容量满额淘汰。授权状态取消后只解除对应待授权保护，重新纳入资格判断，不直接回收；仍有其他有效授权或父/子执行、后台工作时继续保护。授权取消与执行结束、资源释放是不同事实。
- 释放某个会话不等于关闭整个 Harness 进程；共享实例不能因回收一个会话影响其他会话。

#### 7.4.2 30 分钟计时

“没有消息”按**没有会话活动**解释，包含主会话及所属子会话的用户输入、Harness 回复、可见思考、工具进展和子 Agent 活动，以及节点本次实际接收的标准历史重放。重放以当前接收时刻刷新活动时间，持续重放可以持续延后超时回收；不使用旧内容的历史时间作为本次活动时间。网络心跳、页面停留查看、单纯接管/释放控制权动作（未触发原生加载）及仅读取本地展示快照翻页均**不刷新**活动计时；打开后台自动重放或手动重试实际触发标准重放时按重放处理。

只有节点已知执行、审批及需保留后台/子工作全部结束，主会话满足请求资格后，才开始计算无活动时间。计时起点不得早于进入可回收状态的时刻；之后发生新的有效会话活动则重新计时。刚加载但尚未输入的会话从加载成功且满足可回收条件时开始计时。

可回收状态持续 **30 分钟**且没有新活动时发起回收。长工具调用或等待审批即使超过 30 分钟也不自动中止；工作结束后重新开始计时，不因上条文字消息很早就立即回收。

授权取消后若已满足安全可回收条件，沿用上述计时规则，不能将此前受待授权保护的时长抵作安全空闲；若随后仍有任务执行则继续保护，直到工作结束。取消授权仅恢复被规则评估的资格，不是独立的立即回收触发器。

页面持续停留查看或读取本地展示快照本身不保活。重放刷新计时不代表有新执行、有效审批或后台工作，不使安全可释放目标获得满额淘汰豁免；历史状态不复活为当前活动。回收后再次打开时本地未过期展示快照支持首屏秒开，并在名额允许且支持重放时后台自动校准；满额时优雅降级保留快照只读浏览。

#### 7.4.3 容量满时优先回收

创建或恢复主会话需要新增名额时：

1. 未达到 50 个时正常加载，分配过程需协调并发，不能因多个客户端同时请求而超限。
2. 达到上限时，排除待授权、自身或所属子会话仍有执行/后台工作的主会话，再在可安全释放的候选中选择**最久没有会话活动**者。容量触发不必等待满 30 分钟；刚解除授权保护且安全可释放的主会话也可参与，不因曾经待授权或仍挂有空闲控制客户端而永久排除。
3. 在关闭前重新确认候选没有新输入、授权或后台/子 Agent 活动，并确认必要管理事实已记录。
4. 按已协商能力调用关闭/释放路径，确认资源释放成功后同步清空候选会话的控制权状态并释放名额，再创建或恢复目标会话。
5. 释放失败不得假装已有名额；按实际结果处理并给出明确错误，不静默超限。
6. 没有可回收候选（例如全部忙碌）时，明确提示容量已满，不强制取消任务，也不自动排队。

计数范围、回收资格和名额预留是平台内部规则，不增加新的页面会话状态。仅发出关闭请求、连接异常或进程状态未知都不能直接视为成功回收。

缺少当前有效前台、资源归属或关闭能力的接入可继续提供其他已准入会话操作，仍计入 50 个上限，但明确自动回收受限，不能承诺等待 30 分钟最终就会释放。所有目标均受保护或未知时拒绝新加载，并保留有权用户的显式释放入口；显式释放仍需协调工作、审批及资源，不能保证成功。连接及能力变化后重新判断，不以厂商名单、旧报告或私有探测代替当前事实。Harness 未暴露的内部活动不再作为请求前置证明，具体以 [session-resource-policy](../../openspec/specs/session-resource-policy/spec.md) 为准。

故障安全控制确认资源已关闭但管理结果尚未可靠保存时，关闭事实与记录失败分别展示；容量保留至核验和持久化账本协调完成，不借故障先转移名额启动新工作。自动回收不以管理存储故障为理由绕过安全条件。

#### 7.4.4 待实施参数与验收

运行池 30 分钟空闲回收与 50 个已加载主会话上限已在 `deliver-session-capacity` 中交付；展示快照库默认 **30 天滑动保留期**与 **10 GiB 最大总磁盘配额**将在 `deliver-session-transcript-cache` 正式实施时纳入 `acp-remote.toml` 配置并补充独立验收。

验收覆盖：超时边界、新活动及实际重放重置、长任务与待授权保护、子会话/后台活动保护、首屏快照秒开与满额降级零名额不保活、后台自动重放不形成任务保护、容量触发提前回收与控制权同步归零、最久未活动选择、并发创建不超限、关闭失败不释放名额、满额无候选时明确反馈或快照降级，以及 Run 结束后后台审批及 Agent 自发前台活动、无稳定条目标识的缓存外分页重新定位、主动内容与资源引用安全、前台 idle 但后台未知、检查至关闭竞态和失去回收依据。远期变更的独立 `tests.md`、详细合同和工作包待取消 `x-deferred: true` 正式开工时生成。

## 8. 原生删除、缓存清理与备份

- 只提供原生会话删除，不提供隐藏、取消隐藏或以仅删平台快照冒充会话删除。无已验证原生删除能力则明确不可用，不直接删除厂商私有文件。
- 原生删除前明确目标及固有级联范围并取得授权；若目标所属主会话处于活跃加载且已被另一客户端接管，未接管只读客户端不得越权发起删除。协调平台执行、审批及释放后调用原生删除；结果未知不自动重发。平台不能额外删除未选中的子会话。
- 删除授权绑定固定目标集合，范围变化及查询后并发变化按 [删除规格的“删除授权绑定固定范围”](../../openspec/changes/deliver-session-data-lifecycle/specs/session-data-lifecycle/spec.md) 处理，接口不能保证影响范围时不执行。
- 原生删除经确认成功后，节点立即同步擦除展示快照库中该会话（及确认级联删除的子会话）的全部快照数据与分块引用。
- 原生正文和附件归 Harness 管理；平台独立展示快照库默认按 **30 天滑动有效期**（按最近一次实际内容写入或发现实质变更的原生同步时间起算，纯读取及无变更自动核对不续期）和 **10 GiB 总磁盘上限**（超限时按最久未更新顺序淘汰非活跃加载会话的快照，保护当前活跃占用 50 名额的会话及在途分块流）自动回收，同时清理无有效引用的临时上传，绝不通过缓存回收修改 Harness 原生数据。
- 审计保留最小不含正文的目标、范围及结果；不从审计恢复已删聊天，不让清展示快照成为原生删除成功证明。
- 管理审计保留和容量以 [management-audit](../../openspec/specs/management-audit/spec.md) 为准；请求去重保护、未收敛事实和过期拒绝依据分别管理，不能把展示快照淘汰或审计到期当作重新执行旧请求的许可。实际管理元数据清理由 [session-data-lifecycle](../../openspec/changes/deliver-session-data-lifecycle/specs/session-data-lifecycle/spec.md) 在满足保护条件后执行，不自动清理身份、撤销或用户原生数据。
- 平台备份仅覆盖配置、身份边界允许的核心管理记录及必要操作事实，**显式排除独立展示快照库与临时内容缓存**，也不声称通过展示快照备份或恢复原生会话上下文。原生组件需独立已验证的一致性备份路径，单纯导出文本快照不等于可恢复上下文。
- 恢复验证只在隔离新目标进行，不覆盖实际库、密钥或原生存储；旧审批、命令、运行期控制权和信任不自动复活。启用新目标另行授权。
- 恢复成功按清单声明包含的组件判断，未选择原生组件与已声明但缺失分别处理，见 [备份恢复规格](../../openspec/changes/deliver-backup-recovery/specs/backup-recovery/spec.md)。

## 10. 实施前的设计与验收工作

### 10.1 可自主补齐的详细设计

各未归档远期变更在实现前应按各自职责补齐：

- 对象完整字段、来源标识、关系约束和生命周期。
- 每个状态的合法转换、运行期控制权代际校验、错误与异常恢复。
- 原生会话发现与读取端口、消息身份、流式边界、顺序及最终值更新规则。
- 物理隔离展示快照库的表结构/分块布局、30 天与 10 GiB 清理水位、读取背压，以及核心管理库故障与快照库故障的隔离边界。
- 事务边界、命令重复处理及审批移交与交付规则。
- 原生历史、展示快照代际、当前连接缓存与分页的可靠衔接。
- 外部原生会话纳管、原生删除联动擦除快照、自有缓存清理及分组件备份恢复规则。
- 数据库表结构、索引、迁移与容量测试。

这些由后续各 change 设计自主确定；若发现必须改变已确认用户行为、安全边界或数据权威，再明确指出影响并确认。

### 10.2 必须实测的能力

对当前计划内各款 Harness 的受测组合按对应 change 验证：

1. 正常结束后释放进程，再显式接管恢复原会话并继续输入，上下文连续且控制权归零/重接管符合预期。
2. 页面断开或顶号接管不停止 Harness、在途 `Run`、已受理队列及待决审批；打开未加载会话首屏秒开本地快照并后台自动补齐外部新增内容（满额时优雅降级），无重放 Harness 跨回收与重启保留平台已观测快照并如实标记边界。
3. 工具执行中异常退出，平台不自动重发，保留可证明事实并标记未知部分。
4. 等待审批时异常退出或发生控制权顶号接管，旧失效请求不被复用，未接管只读设备无法越权裁决，多客户端不能产生多个最终裁决。
5. 子 Agent 身份、父子关系和各自历史可恢复并继承根主会话控制权；没有暴露的能力明确标记。
6. 实时、首屏快照秒开、后台自动重放补齐、分页、重启后的同一会话顺序一致；思考、工具和文字交替不被合并重排。
7. 上下文压缩后打开自动同步（或手动重试同步）按原生可读历史建立新快照代际，明确完整性边界，不承诺永久保留压缩前旧快照。
8. 高速输出及长会话下原生读取、展示快照异步落盘、分页及当前输出衔接可用，快照库 30 天滑动过期与 10 GiB 淘汰不影响活跃会话与核心管理库。
9. 验证历史不可用、原生同步失败/满额降级、展示快照淘汰/损坏降级与核心管理存储故障的区别，绝不把展示快照回灌充当模型上下文。
10. 释放失败、外部占用与不支持接口明确呈现，不以假成功掩盖。
11. 按 §7.4 验证 30 分钟回收与默认 50 个主会话上限，满额降级快照读取零名额不保活、后台自动重放不形成任务保护、活动保护、候选选择、释放确认同步归零控制权和并发名额协调均符合已确认策略。

## 12. 规格职责归属

# 对话保留 Agent 输出的先后关系

当前消息页以创建时间和消息标识排序，同批写入的思考与回复可能具有相同时间，消息标识的字典序不能代表实际输出顺序。用户已确认：思考、工具调用、回复可以交替出现，持久记录与页面呈现应保留其先后关系，不按类型预设顺序，也不将穿插其他内容后的输出合并回较早位置。是否显示时间不改变这些关系。

旧历史能依据保留的事实恢复顺序时予以恢复；无法证明原始顺序时保留正文及原有稳定顺序，明确说明顺序无法完整还原，不猜测、不删除历史。

顺序以 Agent 在同一 ACP 输出流中实际写出的可观察先后关系为权威，不推测 Agent 内部尚未发送的生成过程。Owner 接收、处理与持久化链路必须保持该顺序，并将其固定为可恢复的持久事实；时间戳仅作时间信息，不能用来重建或覆盖该顺序。用户已确认此定义。

连续呈现单位按输出片段划分：同一消息的相邻连续输出可追加到同一片段；用户输入、其他消息、思考与回复通道切换、工具调用或其他可见条目插入时，后续文字必须在新位置呈现，不跨条目合并。工具卡等已有条目的状态更新保留首次出现的位置；需要呈现的新增输出按其出现位置排列。

实时观看、刷新、历史分页、断线重连与经其他节点访问必须保持同一顺序。Owner 应独立于短期原始事件的保留期限，持久保存恢复输出片段与展示顺序所需的事实；Access 仍只作连接期内的有界转发，不新增远程资源持久化或本地顺序映射。以上行为要求均已由用户确认。

本次变更不考虑旧版本兼容，不为旧客户端或旧节点维护旧排序与分页行为。这不改变前述旧数据保留与尽力恢复的要求；协议、schema、fixture 和消费方仍须同步更新。

时间仅作辅助信息：用户消息和每组连续 Agent 输出显示一次时间，思考块、工具卡及连续文字不逐项重复时间；是否显示时间不影响排序。以上选择已由用户确认。

用户已确认本决策并授权实施；对应实现、数据库迁移、协议合同和前端展示已随 preserve-agent-output-order 变更落地。

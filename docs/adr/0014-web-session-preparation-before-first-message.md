# Web 新会话在首条消息提交前只进行临时准备

真实 Codex 对照实验表明：未发送消息的空会话可以在原 Agent 进程中使用，但更换进程后可能因尚无恢复文件而无法恢复。拿到 Agent 会话 ID 不足以承诺持久恢复；现有恢复探针先发送了消息，遗漏了这个边界。

拟将 Web/PWA 本机新建入口拆为会话准备与首次提交：准备阶段由后端分配最终 ID，允许建立临时 Agent 会话以取得真实模式和配置，但 ACP Remote 不持久化会话记录。首次提交先保存会话、首条消息和请求，再派发消息；成功或失败均留在同一页面与 URL。临时资源在后台或服务重启后可重建；已正式提交后的无法确认结果仍遵守不自动重发的规则。浏览器准备草稿按标签页隔离并支持刷新恢复，主动离开或更换 Agent/目录时清除，后两者同时分配新 ID。

用户已逐项确认产品选择，完整方案仍待最终核对；详细边界见[设计访谈记录](../SESSION_LIFECYCLE_DISCUSSION.md)。本 ADR 尚不是已实施能力，也不覆写现行创建协议。Zed、Node Link 创建合同与旧会话迁移不在本轮范围内。

`[合同已冻结，实现待 WP2–WP8]`（2026-10-22，`web-session-preparation` WP1）方案 A 的 wire 与端口形状已固定：准备控制帧、`session.start`（`initial`/`continue`）、闭合五态结果与准备凭据见 [SYNC_PROTOCOL.md](../SYNC_PROTOCOL.md) §11.9，纯端口与计划 DDL 见 [CORE_PORTS_AND_STORAGE.md](../CORE_PORTS_AND_STORAGE.md) §5.11/§12。两处关键取舍已定：①准备凭据只是归属证明，不是登录凭证；②正常重启与**存储整体重建**必须区分——前者可重建准备（已受理则返回 `committed`），后者旧材料统一失效并返回不可重试的 `preparation.store_rebuilt`。ADR 状态保持 `proposed`，直到对应工作包接线并通过验收。

## Considered Options

- 新建即持久化真实 Agent 空会话：不能保证 Agent 在首条消息之前已写入恢复数据，正是本次故障的来源。
- 准备阶段完全不建立 Agent 会话：现有通用 ACP 接口无法提供真实的会话模式和配置，不能满足发送前可调整的要求。
- 用隐藏消息促使 Agent 写盘：引入用户未要求的执行，不采用。
- 浏览器生成准备 ID，保存成功后替换为正式 ID：用户要求后端分配、地址始终不变，不采用。

## Consequences

需要独立表达尚未提交与已提交会话，明确提前分配 ID 的归属、重启后的准备核实、临时资源预算与清理、浏览器草稿和附件生命周期，以及首次提交跨保存/配置/上传/派发的失败处理。不得把已有恢复数据缺失的会话解释为可重新准备，也不得让任意陌生 URL 触发创建。后续需同步产品、前端、Sync、核心端口/存储和安全权威文档及相应合同资产，不能只靠页面分支实现。

# Web 直接创建会话并清理无内容的空会话

Web/PWA 新建会话 SHALL 直接调用 `session.create`，不再是提交首条消息前的准备阶段。创建成功后，正式会话立即进入目录与会话列表；客户端按匹配的完成结果导航到 `/session/<id>`，声明正在查看并激活该会话。创建结果直接投影为 `localActivity: active`，不发布中间的空闲状态。切换、刷新、页面重新可见和重连都以当前可见会话为目标执行相同的查看和激活顺序，迟到结果不得把页面切回旧会话。

空会话表示已经正式创建，但从未保存任何会话内容。标题、模式、配置、目录归属、普通元数据事件和未提交附件都不构成内容。最后一个查看者离开，并且没有未结束或排队任务、未解决交互、未确认停止或释放时，系统开始完整保留期；默认 30 分钟，可由现有配置改为其他时长或关闭按时间回收。保留期内空会话仍出现在目录和列表，可进入、激活并发送第一条消息。期满后先真实释放会话资源；只有明确确认原会话关闭或受管进程已退出，才静默删除，不向用户发送通知。非空会话只回收资源并保留身份与历史。

Daemon 重启后，仍存在的空会话从启动发现时重新获得完整保留期，不复用可能已经过期的内存截止时间。重启不得自动发送、重放或替换任何会话。

激活、查看、释放和删除按 Owner 上每个会话的单一生命周期顺序线性化。删除先提交时，迟到的激活和普通命令返回 `session.not_found`；激活先提交时，删除重新检查全部保护条件并等待新的完整保留期。

删除保留一个不可见的最小墓碑，以维持既有命令和事件的外键、重放序列及 `(actor, requestId)` 幂等结果。墓碑清除可显示资料与全部会话内容，所有产品读取面都必须把它当作不存在；删除事务先持久化 `session.deleted`，再写命令终态。客户端按稳定事件去重并静默移除投影。Access Node 只在已认证连接期传播 Owner 删除，不持久化远程删除索引、正文或游标。

本决策取代 [ADR-0014](0014-web-session-preparation-before-first-message.md) 中“Web 在首条消息提交前进行临时准备”的默认新建方案。ADR-0014 及其相关证据仍作为历史保留，但不再是现行目标。`session.delete` 是 ACP Remote 的 Sync mutation，不是 ACP `session/delete`，也不承诺清理 Agent 自身数据或宿主工作目录。

该决策已于 2026-10-26 获得用户确认；对应的 OpenSpec 规划已建立，代码与合同实现仍以该变更的任务和验收结果为准。

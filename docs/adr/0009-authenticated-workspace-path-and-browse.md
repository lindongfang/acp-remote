# ADR-0009：把「已登记目录路径」与「节点目录浏览」纳入已认证设备能力面

- 状态：Accepted
- 日期：2026-10-17
- 影响范围：信任边界与数据分类（`SECURITY_DESIGN.md` §3/§8/§10.2/§10.3/§12.3/§19）、产品边界与同步策略（`INITIAL_DESIGN.md` §2/§3.3/§8）、Sync wire（`SYNC_PROTOCOL.md` §5.2/§9/§11.5/§14）、feature 词表（`compatibility/features/v1/features.json`）、命令词表（`compatibility/commands/v1/commands.json`）、`schemas/sync/v1/`

## 背景

在本次变更之前，`SECURITY_DESIGN.md` §12.3 与 §10.3 把边界写成一句绝对的话：**规范化路径永不出网**（具体的措辞是「路径与规范化结果不得出现在 catalog、事件、错误 `details` 或对端可见的任何输出里」）——口径是「不得泄漏**客户端尚未知道的**宿主路径」，因此已登记目录的规范化路径也不算可下发内容。

原型的目录页与创建选择器做不到这一点：它需要「显示用的目录路径」来消歧同名目录、需要在详情页显示路径行、需要在对话页左栏显示目录上下文。路径不可见时，两个显示名相同的已登记目录在同一份快照里不可区分，创建弹层也无法让用户确认自己在选哪台机器上的哪一个目录。这就是本次要收口的第一处边界缺口。

第二处缺口是**目录浏览**：原型的创建弹层要让人从根逐层选到一个目录，而 `compatibility/commands/v1/commands.json` 的 13 条命令与本地管理通道的 25 个方法里都没有「列举目录」这一项。要让「在电脑上选一个目录」这件事成立，就必须给已认证设备一条只读的逐层查看能力。

关键约束是：`workspaceRef`（`schemas/sync/v1/common.schema.json`）是一个 `additionalProperties: false` 的封闭对象。给已经协商了 `core.local-catalog.v1` 的旧客户端多塞一个键，会让它按 `protocol.schema_invalid` 拒收整条消息。因此「多出来的键」只能走**新的 feature 协商**——口径与 `core.event-origin.v1` 相同：键只在协商后才出现。

## 决策

1. **已登记目录的路径收在目录资源一处，并受新 feature 门控。** 已登记目录的规范化路径**只**出现在快照的 `workspaces` 资源条目上，且只在客户端协商了 `core.workspace-path.v1` 时下发；未协商时该键**缺席**（不是 `null`、不是空串），因此协商了 `core.local-catalog.v1` 的旧客户端仍能通过自己的封闭形状校验。会话摘要的 `workspace` 引用**保持 `{ alias, displayName }` 两个键不变**，需要路径的客户端按引用里的别名在同一份快照内查表。下发形式是「规范化结果剥掉平台 verbatim 前缀」（Windows 上 `canonicalize` 必然带 `\\?\`），客户端回传该形式时服务端**重新**规范化并以其为权威值，因此显示形式与权威值不会分叉。
2. **浏览做成一条新的 Sync 查询命令 `workspace.browse`，请求一层、返回一层。** 请求只含一个父路径（`null` = 根列表），结果只含该层的直接子目录（名称 + 绝对路径 + 是否已登记）与一个截断标记。它归入既有的 `grant.observe` 分组，受新的 feature `core.workspace-browse.v1` 门控；未认证连接被拒、未协商该 feature 的连接返回 `protocol.feature_required`，两者都在**触碰文件系统之前**。
3. **路径可见面只有两处，两处之外的一切输出继续不含路径。** 路径只出现在快照的 `workspaces` 资源条目（决策 1）与 `workspace.browse` 的 `command.result`（决策 2；只含被请求那一层的名称与绝对路径、以及逐字回显的父路径）上；除这两处之外的事件载荷、`command.result`、错误 `details`、日志（§14.1）与审计记录 MUST NOT 含任何路径；**客户端自己提交的目录不得被回显**。审计动作词表**不因浏览扩张**：浏览是只读查询，纳入既有的命令级日志（命令名、主体标识、资源标识、请求标识、终态类别）即可，不新增审计动作。
4. **不新增建目录命令，建目录做成 `session.create` 的显式开关。** 开关与别名互斥；开关为真且目标不存在时先创建（连同缺失父层）再启动 Agent；已创建的目录在后续失败时**不删除、不回滚**（删除要区分「哪些层是这次建的」，误删用户目录的代价远高于留下一个空目录）。
5. **限额是固定 v1 常量，不是可下调配置键**（单层条目上限、差异行上限等，见 `SYNC_PROTOCOL.md` §14），与 `CONFIG_REFERENCE.md` §2「只有三项 Sync 键可下调」的口径一致。

### 被否决的备选

- **把路径加进 `workspaceRef`。** 否。同一目录会在每条会话摘要里重复携带；且别名被重指向后「这条摘要里的路径该是创建时的还是当前的」变成一个必须额外规定的语义坑。路径只在目录资源出现一次，语义单一。
- **只在 `sessionSummary` 顶层加路径。** 否。重复面比目录资源更大，且不解决目录页——目录页只需要目录资源。
- **把浏览并进 `session.create`。** 否。查询与 mutation 的终态语义完全不同，会让「查询命令同步完成」这条契约出现例外。
- **新开 `fs.*` 命令族。** 否。它的用途就是选 workspace，`workspace-resolution` 已经拥有「目录来源」这个概念；另立一族会让同一个语义有两个名字。归入既有 `grant.observe` 分组即可。
- **一次返回整棵子树。** 否。目录树可能极大，一次性下发等于把整台机器的结构塞进一条消息；逐层是唯一同时满足「有界」与「够用」的形状。
- **隐式建目录（「路径不存在就默默创建」）。** 否。它会把用户的一次笔误变成一棵被建出来的目录树；建目录必须是显式开关。
- **独立 `workspace.create` mutation。** 否。多一条 mutation 的幂等/终态/崩溃窗口面，而原型并不需要「先建目录」这个可观察步骤。

## 结果

### 限制（本次纳入能力面的东西被收得多窄）

- **只读**：`workspace.browse` 不写任何登记、缓存或会话状态，不改变本机 workspace 登记表，不让被查看的目录因此获得任何后续权限。经浏览选定但**未登记**的目录创建的会话呈现为「未分组」，系统不为它补出别名。
- **单层**：只返回被请求那一层的直接子目录，不回退到父层或根列表，也不借该命令泄漏其它层的路径。
- **无文件元数据**：结果不含文件条目，也不含任何文件内容、大小、时间戳或权限位。
- **不产生审计动作**：避免多出第二条「谁看了什么」的隐私面；浏览只进既有的命令级日志，且日志字段不含路径。
- **路径只含已登记目录**：客户端自己提交的目录不进入可见输出——唯一例外是 `workspace.browse` 按 `SYNC_PROTOCOL.md` §11.5 逐字回显它自己的请求父路径并返回该层条目。

### 残余风险（如实记录）

- **任一被配对设备都能拿到本机全部已登记目录的规范化路径。** 这是 feature 门控打开后的直接后果，不是意外发现。之所以接受：设备方向没有授权维度，任一已认证设备本就可见本节点全部会话与事件，路径对它的增量信息有限；而目录页与创建选择器确实需要路径。
- **浏览构成有限的目录结构探测面。** 一台已认证设备可以逐层枚举本机目录结构。

### 缓解（残余风险的对价）

- **feature 门控**：未协商 `core.workspace-path.v1` / `core.workspace-browse.v1` 一律不下发/拒绝，拒绝发生在触碰文件系统之前；旧客户端既不会多收到键，也不会被新命令影响。
- **只限已登记目录**：路径字段只覆盖本机主动登记的目录，不含客户端提交过的任意路径。
- **只返回一层 + 单层条目上限**：浏览单次只给一层，超出固定上限置截断标记而不失败、不静默丢弃。
- **复用既有命令族限流**：单设备 120 次/分钟、窗口 1 分钟（`SYNC_PROTOCOL.md` §14），不新造限流机制。
- **日志 / 审计 / 错误 `details` 不含路径**：`SECURITY_DESIGN.md` §14.1 的日志禁止项**保持原样不动**（新增命令不得让路径进日志）；错误响应只含别名或字段名。

### 需要同步更新的文档

- `SECURITY_DESIGN.md`：§3（数据分类把已登记目录路径纳入 `operational-metadata`）、§8、§10.2（新增 `workspace.browse` 行与目录校验口径）、§10.3（删去与 §10.2 自相矛盾的「规范化路径永不出网」）、§12.3（路径口径改为「只下发给协商该能力的设备、且只含已登记目录」）、§19（登记残余风险）。§14.1 **未变**。
- `INITIAL_DESIGN.md`：§2（非目标里「workspace 实际路径不离开 Owner Node」收窄为带前提）、§3.3、§8。
- `SYNC_PROTOCOL.md`：§5.2（三条新 feature）、§9（目录资源路径键）、§10.2/§10.3（`file.changed` 差异行）、§11.5（新命令与建目录开关）、§14（新固定限额）。

### 未决

- 浏览结果的排序规则取「Unicode 码点升序」还是「平台本地化排序」——前者可判定、跨平台一致，倾向前者；实现时若本地化排序对中文目录名体验明显更好再单独决定，不改变命令形状。
- 单层条目上限与差异行的行数/字节上限的具体取值在实现时按既有 `payload_json` 容量与单条消息 1 MiB 反推，写进 `SYNC_PROTOCOL.md` §14 即可，不影响本决策。

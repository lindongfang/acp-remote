# 会话容量实现

容量账本与显式释放的已验收基线见 [第一阶段合同](../../openspec/changes/archive/2026-11-19-deliver-session-capacity/phase1.md)。本次继续按 [RB-001 运行时合同](../../openspec/changes/archive/2026-11-19-deliver-session-capacity/automatic-release-runtime.md) 实现自动关闭请求及父子读取；完整独立验收和真实 Harness 长时间验收尚未完成，不能据内部测试归档整个 change。

## 实现

`session_storage/session_capacity_schema.rs` 建立必要容量管理表；版本以 `storage.rs::SCHEMA_VERSION` 为准。SQLite 事务复用原 registry 的连接所有者，预留检查、身份绑定和返额使用 `BEGIN IMMEDIATE`。预留、已加载以及关闭但管理结果未协调的责任共同占用名额；上限来自领域容量策略。

创建先为原 source operation 预留，再由原 writer 写标准 `session/new`。收到原 Created 响应且必要响应记录和确认完成后，绑定来源、原生 ID 和原 source instance。未取得 ID、提交未知及所有权冲突保留责任；不从超时或调用者取消推断无副作用。

执行加载和 SourceOnly 标准重放复用同一账本。只初始化辅助 source 或进行不加载的查询不占额。实际重放在产生 `session/load`（v1）或 `session/resume`（v2）之前预留。相同来源和原生 ID 优先路由回原 owner，即使调用入口使用另一启动配置；不能接管尚未协调的旧 owner。

只有原始无未解释扩展的标准 new 成功能够建立第一阶段独立主会话依据。请求配置包含未知扩展时在写入前拒绝；原始成功响应包含未知字段、非空元数据或未知变体时，保留原始响应、原生身份、确认和预留责任，但不建立主树证明，并返回 `session_tree_unverified`。检查按原连接的协议版本识别标准模式、配置及命令结构，也检查 MCP 配置的嵌套扩展；不从界面名称或描述猜测父子关系。允许字段的上游依据及下载快照摘要见 协议证据（`testing/runs/deliver-session-capacity/2026-11-16-schema-evidence.json`）。

外部会话没有可靠主树关系时，实际加载返回 `session_tree_unverified`，不加载的查询仍按自身能力提供。不会修改未知配置字段、猜测父子关系或为子目标单独增加名额。旧资源迁移只保留容量责任，不补造主树证明。

## 显式关闭与恢复

显式释放仍经过原认证、撤销、目标身份和持久化释放操作。普通执行资源沿原关闭路径；只有创建或重放、尚无普通执行资源的会话，在原 source 上保留独立关闭 reservation、frame、ticket 和响应，不先 resume，也不结束共享进程。

关闭封存原读取 authority 和已知子会话展示代际，并等待整棵已知树登记在原主资源下的读取任务及审批责任收敛；晚到的子关系同样封存。确认原生关闭后只记录 `physically_closed`，此时仍占额。释放开始的必要事务固定该操作负责的原预留集合；外层 `native_release.finish` 在同一必要事务保存成功结果并仅归还这个集合。必要保存失败时保留原关闭操作，重试协调而不重发原生 close；已是 Released 的操作重试也只检查原集合，不能返还同一身份后来新占用的名额。旧操作没有可靠关联时保守保额，由新的显式释放或完整 source 关闭协调。

原生关闭也由该释放操作固定的预留集合授权，不能只按当前原生 ID 查找。节点核对原预留、来源、实例和运行代次；普通执行资源只有与这份容量责任共享同一 authority 时才可作为关闭对象，旧实例或旧执行资源的关闭结果不能用于后来重新加载的资源。关闭开始时固定预留记录，等待读取和确认关闭均使用同一资源及原记录；必要存储只更新这一个预留 ID。

原集合非空、全部已归还且每个原来源实例均有必要关闭依据时，仍处于 Releasing 的操作只完成自身管理结果，不再发送原生 close。即使同一原生身份已由新实例恢复，也不会关闭或归还新实例的名额。空集合及没有可靠代次关联的旧操作不能据此宣告成功。异步准入返回后在原来源的门内重新核对资源是否仍有效及预留身份；新资源不能采纳旧资源的预留，迟到结果不能改写已经封存的资源。预留尝试在调用存储前登记给原来源，未能发布的结果仍由该来源的完整关闭流程负责协调。

必要查询取得原所有者后，若原来源在关闭任务登记或执行期间进入关闭状态，原来源工作的 Stopped 结果按释放未确认处理，原操作继续保持 Releasing。内存中的关闭标志不能直接完成释放；下一次重试仍须重新读取原集合及原来源的必要关闭依据，符合条件才完成管理结果。此分类只适用于本次捕获的原来源，不改变全局停止错误，也不转向后来加载的实例。

完整 source 关闭只在原进程树、读取任务、协议与必要管理责任全部确认后，按原 source 关闭依据收敛残留预留。不能把进程消失、后台未知、页面断开或空闲时间作为关闭依据。重启和迁移继续计入未协调责任，已有数量超过上限时保留已有数据并拒绝新增。

硬退出后，同一来源及配置的旧 source 尚未确认关闭时，沿既有运行所有权规则拒绝启动新 owner；保留名额不等于旧资源已经可接管。其他显式来源仍可在剩余全局名额内新建，不会因节点重启把旧占用重置为零。

显式恢复在必要预留成功后、与释放共用的 source gate 内检查原 authority。新的展示代际使用新 flag，并由原采集 FIFO 中携带本次不可伪造代际凭据的标记发布；旧 flag 永久封存。延迟的旧恢复标记不能取得后来代际的 flag，新读取等待有效代际发布。关闭先发生时迟到恢复被拒绝；标记发布或工作线程处理失败时封存对应展示并明确报错，容量责任保留。损坏的展示状态锁不能授予恢复权限。

## 策略与验证边界

实现遵循 [RB-001 运行时合同](../../openspec/changes/archive/2026-11-19-deliver-session-capacity/automatic-release-runtime.md)：节点依据已知活动选择候选并发起普通关闭，Harness 负责执行。未上报后台/子范围不单独禁止请求，也不代表完整空闲；已知执行、工具、审批及子工作仍保护。历史状态与当前快照分别处理，实际收到重放只刷新计时。前台未知、归属不明、必要管理未协调或没有关闭能力时保护。请求发送与确认释放分开，未确认不返额。

正常启动完成旧运行责任协调、进入 Running 后，节点登记自有周期扫描任务；启动失败使运行进入未确认状态并停止健康处理。扫描与容量压力请求共用原关闭操作，退出沿节点 stop 和任务 join 收敛。压力请求在首字节前重新核对原候选的活动和完整排序；若原目标已失去资格，本次撤回并保额，不改关另一棵树。SQL 等待期间唯一候选收到重放不构成永久豁免。

可信子会话读取复用原主资源所有者及名额，直接打开两个子会话时只恢复主会话。子正文沿原连接自动投递，保持当前连接模式，不因主会话完成历史重放而宣称子历史完整。原读取任务真实加入主资源的关闭责任，最后一个任务尚未 join 或 join 失败时不能返额。详细边界见 [父子读取合同](../../openspec/changes/archive/2026-11-19-deliver-session-capacity/tree-read-runtime.md)。

开发 SQLite、单调策略和原生模拟对端各有不同证据范围。真实节点阶段验收使用独立 tester 的 入口及说明（`testing/runs/deliver-session-capacity/tester/2026-11-16-phase1/driver-handoff.md`）。模拟 ACP 对端没有模型任务，不证明真实 Harness 的实际关闭效果或完整 L6；逐项结果以实际报告及 [执行计划](../../openspec/changes/archive/2026-11-19-deliver-session-capacity/plan.md) 为准。启动接线后的独立验收与真实 50 树、实际 30 分钟验收仍须另行完成。

真实Harness验收启动器与专属输入要求见 [L6运行说明](../../testing/tools/capacity-l6/README.md)。配置校验和测试枚举只证明入口准备；四项真实场景的必需分支、实际50树/1800秒及清理均须有对应运行证据，缺认证、能力或实现分支分别记为受阻，不能记成通过。

验收执行与独立审查分别留证：format2原执行完成后仍保持待审查，绑定测试程序、构建清单、配置、原节点/来源及实际清理。独立审查工具只允许从完整原执行和同节点页面材料新建汇总，拒绝旧格式直接通过、缺少节点分支、未确认清理或证据不一致。工具自检与独立静态检视只覆盖该判断逻辑，不证明真实L6已执行；当前结果与入口缺口见执行计划。

关闭写入故障设施仅在 `test` 与 `native-dispatch-dev-fixtures` 同时启用时存在。它绑定原来源实例、连接代际及原生会话，只对匹配的自动Close生效，并由入队后的原命令持有。零写入、真实接受一字节后失败、完整写入但flush前失败，均沿原传输路径产生票据结果；安装guard释放不能撤销已命中的部分写入故障。IO失败仍可能停止整个原连接，因此真实验收须使用独占故障来源及健康对照来源。重试接口只唤醒原来源的必要管理协调，不自行写关闭或返额事实。内存协议测试只证明这些钩子与票据的行为，真实Harness及Node名额闭环须另行验证。

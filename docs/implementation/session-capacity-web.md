# 会话容量 Web 管理入口实现

对外行为依据为 [会话资源策略规格](../../openspec/specs/session-resource-policy/spec.md) 与 RB-001 请求/执行职责边界，节点侧实现见 [节点容量实现说明](session-capacity.md)，完整交付与浏览器验收结果见 [归档计划](../../openspec/changes/archive/2026-11-19-deliver-session-capacity/plan.md)。

## 协议与页面状态协调

认证后的管理连接通过 `session.capacity.inspect` 查询必要容量事实，payload 必须为空；客户端不能指定或修改上限。该入口沿现有认证和撤销校验，不返回会话正文、密钥、配置内容或启动参数。

响应字段为 `limit`、`occupied`、`reserved`、`closedPending` 和 `automaticRecycling`。占用由节点账本提供，Web 不从进程数量、页面或队列推算。占用可因升级保留旧资源而超过上限；自动回收布尔值取本节点实际运行状态：正常启动登记扫描且仍为 `Running` 时为 `true`，未启用或停止后为 `false`。该值不表示某个 Harness 的关闭结果。解析器接受实际布尔值，拒绝不安全整数、未知字段和不一致计数。

管理页“原生会话名额”展示一次节点快照、创建预留、关闭待协调及自动回收状态。未取得快照时显示状态尚未读取；启用时解释节点根据已知活动请求 Harness 关闭主会话，发起请求不代表关闭成功或返额。用户可显式刷新；连接重建或释放动作后清除本地快照。名额不是页面会话生命周期状态。刷新失败使用原管理错误反馈，不显示推测的空名额。

`session_capacity_full` 表示本次没有取得名额，提示稍后重试或使用既有显式释放入口，并说明关闭未确认继续占额；不从这条错误猜测自动策略是否启用。`session_tree_unverified` 说明尚无可靠主树归属、不能加载，非加载查询仍可使用。页面及缓存读取不会保活。

“原生会话释放”继续先登记、再由用户明确执行。关闭成功及必要管理结果共同协调后才显示 `Released`。用户可重试同一释放协调操作；这些重试仍通过原节点幂等合同，不由页面重新创建原生副作用。

## 前端测试与验证职责边界

Web 协议、客户端和展示单测位于 `clients/web/tests/session-capacity.test.ts`。页面可观察事实与 [长期会话资源策略套件](../../testing/suites/session-resource-policy/tests.md) 的职责划分如下（内部策略由节点证据证明，页面不另建会话生命周期或资格诊断状态）：

| 用例范围 | 页面可观察事实 | 节点证据及边界 |
| --- | --- | --- |
| CP-005、010、018、020、029、030、031 | 原生会话名额、预留、关闭待协调、容量满或归属不可验证错误；刷新和重新加载后的真实计数 | 三种加载入口、候选选择、关闭结果及必要事务由节点测试核对。关闭后最后读取任务未结束的页面保额，只证明资源责任尚未收敛；不代替 CP-030 的 SQLite 提交故障。 |
| CP-008、019、021、022、024、026、031 | 直接打开子目标的实际正文、两个目标内容隔离、关闭后重开，以及 `CurrentOnly` 的历史不完整提示 | 子目标沿可信主树加载，根重放完成不证明子历史完整；实际重放刷新计时与缓存访问不保活由节点观察分别验证。页面断言不代替真实 Harness 的历史或子会话能力。 |
| CP-006、007、009、013–017、025、028 | 既定操作产生的计数与错误 | 活动保护、资格计时、排序及关闭首字节前复核属于节点判断，页面不额外显示或推算这些内部状态。 |
| CP-027、029 | 自动回收已启用时的请求职责说明、能力限制及错误 | `automaticRecycling` 只证明节点扫描的运行事实；未观测范围、已知保护及实时请求资格须结合有权节点观察，不能由该布尔值推断。 |

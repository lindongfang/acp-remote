## 1. 一页摘要

ACP Remote 的目标调整为：基于 ACP 和 Tailscale 网络路径，统一管理 Harness 的实例、会话生命周期、执行调度、状态、权限审批和审计。Harness 是实际运行任务的程序，首批重点支持 Codex、ZCode、DeepSeek Harness。

已确认的核心原则：

1. **一个完整节点。** 没有中心服务器与执行节点的部署划分；管理、运行和存储都是本项目实例内部的能力。逻辑模块不等于服务或机器。
2. **不实现模型和工具系统。** Harness 负责推理、工具调用和内部任务组织；平台管理与记录其暴露的行为。
3. **原生上下文由 Harness 恢复。** 平台保存原生会话标识及必要参数，调用原生恢复接口；不通过重新发送聊天历史构造上下文。
4. **会话与历史以 Harness 为权威。** 原生会话列表、消息、工具记录、父子关系和附件从 Harness 读取；平台只持久保存配置、身份及必要管理和操作事实，不保存独立聊天档案。
5. **重放兼容与可丢弃视图。** 标准历史重放为基础接入条件；平台共用协议处理，在有界、可丢弃视图上分页，不要求 Harness 原生按轮次分页；无重放能力暂不接入。
6. **会话顺序以 Harness 为准。** 单个会话内的实时、刷新、分页与重启恢复顺序一致，不按平台接收时间或内容类型重排。
7. **子 Agent 作为父会话的一步展开。** 按原生可靠身份与关系建立可重建视图，父步骤内展开子内容；不将父子正文混排为全局时间线。
8. **允许同目录并行。** 不同会话可以同时操作同一目录，不加目录锁、不自动隔离或合并修改；同一个会话最多有一次由平台发起、尚未结束的前台执行，不限制 Harness 原生的子 Agent 或后台活动。
9. **页面断开不停止任务。** 前台执行中或等待审批时不因页面关闭、断网或资源回收策略关闭实例；仅加载但没有执行或待审批工作的资源可以按回收条件释放。
10. **不确定就明确标记。** 异常中断不自动重发输入，不假装外部副作用已经失败或成功，不复用失效审批。
11. **页面运行状态只有运行中、空闲。** 运行中表示会话资源已加载且未回收，包括等待输入；空闲表示资源已回收且会话可恢复。运行中存在有效授权请求时附加“待授权”，错误通过页面报错呈现。
12. **历史按轮次分页。** 一次用户输入及其对应执行内容为一轮，前端传入每页轮数、默认10；父会话倒序分页，子会话在所属父步骤内正序分页。
13. **资源按活动与容量回收。** 可安全释放的主会话 30 分钟无活动后回收；默认最多加载 50 个主会话，子会话不单独计数。创建或恢复遇到容量上限时，先回收最久未活动的可回收会话；没有候选则明确报容量已满，不取消任务、不超限、不自动排队。
14. **优先最高共同可用协议。** 每个新连接优先发起平台已实现并验证的最高 ACP 版本协商，按规范使用最高共同可用版本及其实际能力，不长期固定旧版或压成低版能力交集。规范回退与业务失败分开；详细规则见 harness-management。

## 2. 产品范围与部署边界

### 2.1 完整节点

本轮只设计一个完整节点内部的系统：

```text
Web / Mobile / CLI / IDE
            |
            v
+---------------------------------------------+
| ACP Remote                                  |
|                                             |
| Client Gateway                              |
| Identity / Policy / Approvals                |
| Harness / Session / Workspace Management     |
| Execution / Scheduler / Dispatcher           |
| History / Audit / Queries                    |
| Process Runtime / ACP Adapters / Storage     |
+---------------------------------------------+
            |
           ACP
            |
            v
Codex / ZCode / DeepSeek Harness
            |
            v
Magpie / Models / MCP / Tools
```

Tailscale 是网络接入与部署路径，不是另一个业务节点，也不替代应用认证。未来是否管理多台机器不在本轮方案中展开，不预置中心服务器、远程执行节点或节点派发协议。

客户端形态不构成不同权限角色。首期面向个人使用，已认证且未撤销的客户端可以管理本节点；运行时权限审批单独处理。团队账号、角色和多人授权体系暂不展开。

### 2.2 管理范围

- 首个闭环按实际能力发现和读取已授权原生范围的会话，包含外部客户端创建的会话。
- 浏览不以导入或已有执行绑定为前提；需要加载时沿原生恢复、互斥及资源所有权管理。显式执行接管不复制历史，不承诺所有外部写入实时推送。
- 平台负责 Harness 实例生命周期、会话与执行管理、调度、审批、历史展示和审计。
- 模型路由、MCP、工具实现和 Harness 内部推理不由平台重新实现；必要启动配置通过 Harness 配置引用传入。
- Harness 启动默认继承节点环境变量，显式启动配置可覆盖对应值；不新增环境白名单或指纹门禁。敏感值仍不得进入普通日志、审计或错误，具体行为见 harness-management。
- 思考、工具、终端、文件差异和子 Agent 等结构化内容不静默降为普通文本。
- 只展示标准 ACP 实际重放及当前连接暴露的内容；缺少标准重放能力时暂不接入，不提供仅当前连接聊天，不宣称恢复未暴露的内部内容。

## 3. 逻辑模块划分

采用一个应用内的模块化结构。首期不按每个模块拆独立进程、服务或 Rust crate。

| 模块 | 职责 | 状态归属 |
|---|---|---|
| `identity` | 客户端身份、认证、信任与撤销 | 客户端身份与信任记录 |
| `policy` | 管理动作的资格判断、策略与本机限制衔接 | 策略配置；首期不引入团队角色系统 |
| `harnesses` | Harness 定义、版本、配置与实例生命周期 | 定义、实例身份与生命周期 |
| `workspaces` | 登记工作目录、解析目录引用 | 工作空间资料；不维护独占锁 |
| `sessions` | 会话生命周期、原生绑定、参与者和父子关系 | 会话、绑定、参与者与关联 |
| `execution` | Run、命令协调、排队、派发、取消与结果 | 执行和命令状态 |
| `approvals` | 请求、裁决、失效与交付跟踪 | 审批事实 |
| `history` | 原生历史读取、来源顺序、实时衔接及缓存 | Harness 为权威；平台视图可重建 |
| `audit` | 操作者、动作、决策依据与结果 | 审计记录 |
| `queries` | 汇总列表、过滤、分页和展示视图 | 可重建的查询结果，不决定业务状态 |

Scheduler / Dispatcher 分别表示安排执行与下发操作，放在 `execution` 内部，不单独建设远程调度服务。已有会话继续执行使用自己的原生绑定，不随机重新分配到其他 Harness。

运行与接入边界：

| 边界 | 职责 |
|---|---|
| Client Gateway | 客户端命令入口、实时订阅与分页接口 |
| ACP Facade | 按需为 ACP 客户端提供入口，与 Harness 侧适配器分开 |
| Harness Adapter | ACP 能力协商、原生会话操作、结构化事件与管理视图转换 |
| Process Runtime | 进程启停、异常检测、取消、完整进程树清理及平台实现 |
| Storage | 配置、身份、命令、审批和审计事务；自有临时内容及备份 |
| Keystore | 隔离平台密钥存储；密钥不进入普通历史字段 |

协议类型、业务对象、数据库记录和页面视图分别建模。核心业务不依赖具体数据库、网络框架、子进程 API 或 ACP DTO；适配器负责转换，应用入口负责装配。禁止巨型 Runtime 统揽所有业务。

ACP 兼容层保留管理所需的结构化视图和必要原始/扩展载荷，不能以精简内部表示替代完整协议语义。版本与可选能力必须实际协商，未来版本支持不视为已实现。

物理 crate 数量、目录名和具体存储后端可在详细设计中自主确定。之前讨论中的中心连接、执行节点和节点网关拆分不属于最终方案。

## 4. 数据对象与术语

术语定义见 [领域术语表](../openspec/GLOSSARY.md)。2026-10-30 用户确认本轮五项审查建议：原生身份跨启动入口稳定，审批归属原生操作上下文，当前连接指节点的 Harness 连接代际，能力准入与实测证据分开，通用机制按接入能力独立交付。

本节是概念清单，不是数据库 DDL。2026-10-30 起，Session、ConversationItem、ToolCall、AgentParticipant、Delegation 和历史 Blob 表示原生对象引用或可重建展示视图，不表示平台拥有对应正文、关系或附件。平台操作 Run 与 Command 只描述平台实际发起的动作；外部对话不得补造成平台执行。具体类型与索引留待详细合同重基准。

### 4.1 资源与执行对象

| 对象 | 含义 | 已讨论的主要字段 |
|---|---|---|
| `HarnessDefinition` | 一份可启动的 Harness 定义 | ID、名称、类型、程序位置、启动参数、配置引用 |
| `HarnessInstance` | 实际启动的进程实例 | ID、定义 ID、版本、适配器版本、协商能力、进程状态、启动/退出时间 |
| `Workspace` | 登记的本地工作目录 | ID、名称、规范化路径、可用状态 |
| `ClientIdentity` | 可连接本节点的客户端身份 | ID、公钥、显示名称、信任与撤销状态 |
| `Session` | 可以反复返回继续交互的会话 | ID、Harness 定义、工作空间、标题来源、来源类型、创建/活动/归档时间、当前执行引用 |
| `NativeSessionBinding` | 平台管理目标与原生会话的对应关系 | 显式接入来源、原生会话标识、恢复引用；启动配置及连接为独立引用 |
| `Run` | 一次输入引发的执行过程 | ID、会话 ID、输入条目、执行实例、排队/开始/结束时间、状态、结束原因、原生执行标识（若有） |
| `AgentParticipant` | 主 Agent 或某个子 Agent 的稳定身份 | ID、会话 ID、直接父参与者 ID、根参与者 ID、创建 Run/工具调用引用、名称、角色、原生 Agent ID（若有） |
| `Delegation` | 一次向子 Agent 委派任务的关系 | ID、发起/目标参与者、发起 Run、输入/结果引用、原生消息或工具调用引用、状态 |

`Run` 不是一次模型请求：一次 Run 可以包含多次模型调用、工具调用和子 Agent 活动。平台不重建其内部推理步骤。

`AgentParticipant` 取代讨论中暂用的 `AgentExecution`，避免与 Run 混淆。Agent 身份不因进程重启而自动改变；恢复同一个原生子 Agent 时沿用对应身份。

### 4.2 历史、审批与内容对象

| 对象 | 含义 | 已讨论的主要字段 |
|---|---|---|
| `ConversationItem` | 一条可展示的结构化历史条目 | ID、会话内位置、Run/参与者引用、类型、正文或内容引用、完成状态、内容版本 |
| `SessionEvent` | 来源事件视图；管理事实另由平台持久记录 | ID、会话内位置、事件类型、Run/条目/工具/审批引用、必要协议载荷及来源 |
| `ToolCall` | 平台观察到的一次工具执行 | ID、原生调用 ID、会话/Run、名称、类别、输入、输出、状态、错误、审批/附件引用 |
| `ApprovalRequest` | Harness 请求批准的具体操作 | 原生操作上下文、原生目标、实例/连接代际/请求标识、可选 Run 与工具引用、操作内容、选项、有效状态 |
| `ApprovalDecision` | 用户作出的最终裁决 | 请求 ID、决定、决定者、时间 |
| `ApprovalDelivery` | 裁决是否成功交付到有效的 Harness 请求 | 请求/裁决引用、交付状态、失败原因 |
| `Command` | 可追踪的管理请求 | ID、稳定请求标识、调用客户端、动作、目标、受理与结果状态 |
| `Blob` | 按引用读取的大块内容 | ID或内容摘要、字节大小、媒体类型、内容位置、引用关系 |
| `AuditRecord` | 谁要求做什么、依据与结果 | ID、操作者、动作、目标、时间、决策依据、相关命令/事件引用 |

Blob 视图引用原生图片及大型输出，平台只使用可丢弃缓存或有生命周期的临时上传，不建立历史附件库。工具调用是原生历史视图，不代表平台建设工具目录或执行系统。

### 4.3 关联约束

1. 一个 Harness 定义可以有多个运行实例、多个会话；实例退出不删除会话。
2. 一个会话可以有多个 Run，但同时最多一个由平台发起、尚未结束的前台执行；此时再次提交普通输入明确返回忙碌，不默认排队。这不禁止 Harness 内部的子 Agent、后台任务或原生并行活动。
3. 同一目录可以关联多个会话，允许并行修改，不加独占约束。
4. 原生会话绑定用于恢复原会话；恢复失败不能静默创建一个新原生会话替代。
5. 父子关系按原生事实投影到 AgentParticipant 视图中：根参与者没有父参与者；父关系不能形成循环，子参与者必须能追溯到根。
6. 子 Agent 有可靠独立原生身份时引用其原生会话并按需读取子历史，父步骤只保留来源引用视图，不建立平台永久正文或关系档案。
7. 父子归属说明谁创建谁；Delegation 说明哪次任务委派给谁。同一子 Agent 可以被多次委派，不能把每次委派误认为创建新 Agent。
8. Harness 未提供可靠子身份或父子关系时，保留已知信息并明确缺失，不伪造执行树；只有工具调用时保留为工具调用。
9. 审批请求最多有一个最终裁决；裁决保存与交付成功分别记录。平台 Run 关联不替代原生请求有效性，前台结束不自动失效后台审批。旧运行连接中的失效请求不能因恢复而重新变成有效审批。
10. 原生标识按显式接入来源解释，不能假设三款 Harness 的标识全局唯一或平台 ID 与原生 ID 天然相同。文档中原生范围指该配置来源命名空间，不表示平台已证明物理存储或账户等价。

子会话以所属父会话轮次中的一个委派步骤展示名称、角色和状态，点击后在原步骤内展开子历史，支持折叠及逐层展开；不跳转子页；展开区域支持自身正序分页，轮数由前端传入、默认10，父会话则使用其前端分页参数倒序读取、默认10。子会话仍保留可靠原生身份与原生存储，父步骤引用其内容而非复制正文；父步骤位置与子内容内部顺序各自保留，不在父平级时间线上混排父子正文。同一子会话多次委派保留各自父步骤和来源关联，不根据时间猜测子内容归属范围。

### 4.4 字段与记录职责的补充

对象字段按上述清单收敛，具体类型、可空性、数据库列和索引可自主细化。以下职责必须保持：

- 启动配置、显式接入来源和 Harness 连接身份分别建模。原生会话以接入来源及原生标识识别；同来源经不同安装路径、配置别名或连接访问时归属同一执行协调对象，不重复计数。不同来源中的相同 ID 不自动合并。多个入口访问同一来源时显式引用同一来源身份；平台不自动判定不同来源背后的物理存储是否相同，不承诺跨这些来源识别重复或提供互斥，也不为此增加厂商探测器或私有文件解析。缺少物理存储证明不构成已配置来源的接入阻断。
- ConversationItem 视图采用可验证的原生条目、轮次、位置、参与者及更新语义；连接内临时标识不得冒充跨重启稳定原生 ID。位置、版本和读取代际不能混用，不假定每款都有单调内容版本。
- 工具卡片的位置属于 ConversationItem，工具结构化输入、输出与结果属于 ToolCall；卡片引用工具对象，不再独立维护一份可修改的工具正文。审批卡片同理。
- Command 保存请求标识、调用客户端、动作、目标、请求摘要和处理结果；请求有效期内相同身份重试返回原处理结果，内容不一致则明确报错。过期后仅拒绝执行或按权限只读查询原事实，不因记录已清理而重新派发。平台请求标识不等于 ACP JSON-RPC 请求 ID，具体有效期及去重容量由 session-execution 定义。
- 原生操作上下文覆盖真实加载、恢复、输入引发的工作及会话内后台或 Agent 自发工作；审批首先绑定节点验证的目标、实例、连接代际和当前真实请求，仅有可靠依据时关联 Run，不要求协议额外提供精确前后台分类。Run、工具及审批已关联时目标必须一致，不能借用其他操作权限；Delegation 是显式跨父子关系。查看和自发工作无需伪造 Run。
- 工作目录暂时不可用不自动删除 Workspace；恢复同一个原生 Agent 不自动创建新的 AgentParticipant。
- 凭据和密钥保存为安全引用，不进入普通正文、配置快照或审计载荷。

### 4.5 平台约束与 ACP 原生流程

能力准入区分四类事实：平台是否已有经验证的协议处理；当前对端协议规定或明确声明的能力；当前操作权限、资源、来源及审批条件；该程序版本的实测证据状态。前三项满足即可准入标准操作，缺少程序版本报告不自动禁止连接或操作，也不使该版本被宣称实测通过。平台未实现、对端无协议依据或安全条件不满足时拒绝相应操作。扩展仅按已实现且获授权的路径使用，不自动私有桥接；运行时不发送输入、批准工具或删除会话作为探针。实际行为不符时停用受影响连接能力并报告，不自动重发副作用。

2026-10-30 用户确认：Harness 专项工作面向能力调研与真实验证，代码不固定 Harness 与 ACP 版本的对应关系。固定程序及适配器版本仅用于证据追溯；运行阶段每次连接初始化按协议规则协商版本和能力，再绑定该连接代际的处理策略。重连重新协商，不用旧报告、程序版本号或 Harness 名称代替。通用协议实现仍有明确的已实现版本集合，不承诺无需实现即可支持任意未来版本。

RP-001 补充：标准重放的准入以 [harness-management](../openspec/changes/deliver-codex-session-loop/specs/harness-management/spec.md) 为权威；重放处理以 [structured-history](../openspec/changes/deliver-codex-session-loop/specs/structured-history/spec.md) 为权威。外部通用扩展保留显式注册和协商边界，但不自动提供厂商专用读取、私有文件解析或“仅当前连接”降级来绕过基础准入。能力发现的启动及初始化不等于产品接入成功，也不构成新程序版本实测通过。

PV-001（2026-10-30）：用户明确“能用最新协议的优先使用新协议”，避免同一 Harness 支持多版却长期低版对接。优先级以通用规格的“优先最高共同可用协议”为准，不要求程序版本报告白名单，也不承诺尚未实现的未来版。遵守对端合法协商选择；分别报告发起版本、实际选择与已知回退依据，没有提供原因时不编造。仅高版无共同可用支持且规范允许时协商低版，不以网络、认证或业务失败自动降版重发。升级及重连后的新连接重新优先高版，既有连接内不热切版本；本轮只修订原则，实现继续暂停。

2026-10-29 补充确认：通用 ACP 会话闭环以 Codex 首验，DeepSeek/ZCode 仅做接入配置与兼容性验收；标准能力按协议版本与实际协商能力处理，不按厂商名称分支。共用协议客户端，通过版本策略和适配器模式隔离 v1/v2 差异；具体实现设计、逐版本合同和证据门禁见 [通用 ACP 设计](../openspec/changes/deliver-codex-session-loop/design.md)。ACP v1/v2 均纳入兼容目标；每版规范、实际版本标识、稳定/草案状态与真实对端均需核实，不将 JSON-RPC 2.0、SDK 版本或兼容设计本身视为 ACP v2 已支持。每款仅验证实际提供的版本/能力组合，不假定都支持两版。

Agent 升级触发影响分析、重新协商及受影响兼容性复验，不自动意味着修改代码；旧版本证据保留其版本归属，不能作为新版本通过依据。必要能力缺失、协议不兼容、版本规范无法核实或必须依赖私有桥接时，向用户明确报告版本、缺口、影响、脱敏证据和可选方案，暂停受影响操作，由用户决定后续处理；不自行增加私有适配、降级产品要求或虚报支持。协议完成、取消及审批仍以各版本规范为准，不能用统一业务接口抹平语义差异。

平台可以强制自己的关联一致性、请求防重复、审批唯一裁决和命令协调，但不能为凑平台状态而重新解释 Harness 流程。

“取消中仍占用名额”仅指：在确认前台执行结束前，不向同一个原生会话派发下一次普通输入。它不是消息位置、目录锁，也不要求退出整个进程或结束所有原生后台任务。

执行结束、取消和权限请求首先遵循实际协商的 ACP 版本。以 ACP v1 为例：

- 前台轮次结束由原 `session/prompt` 响应及结束原因表达。
- `session/cancel` 是通知，没有独立成功响应；发送通知不等于取消完成。Agent 中止相关操作并发送剩余更新后，应对原 prompt 返回 `cancelled`。
- `session/request_permission` 是请求/响应；取消当前轮次时，客户端必须将相关待处理权限请求回复为 `cancelled`。
- 取消未确认或连接丢失时，不假装取消完成，也不盲目重发原输入；按已知事实记录中断或结果未知。

其他版本按对应规范映射，不把 v1 的完成信号套用到其他版本。三款 Harness 的验证是接入验收：核对适配器是否正确处理规范消息及已协商能力，不重新决定协议已定义的语义，也不要求 Harness 遵循平台自造的流程。

R2-001：取消必须区分活动前台、待确认输入与已可靠空闲。以 v2 为例，前台已确认 idle 且无待确认输入时，取消不要求额外完成通知；不能仅因发送取消而新增输入阻挡或假报后台停止。存在活动或待确认输入时仍跟踪对应事实；与自然完成交错时接受实际正常终态，不要求额外 cancelled 事件。具体行为见 [执行规格的“空闲取消与活动前台取消分开”](../openspec/changes/deliver-codex-session-loop/specs/session-execution/spec.md)，协议依据为 [ACP v2 取消](https://agentclientprotocol.com/protocol/v2/prompt-lifecycle#cancellation)。

规范来源：[ACP v1 执行与取消](https://agentclientprotocol.com/protocol/v1/prompt-turn)、[权限请求](https://agentclientprotocol.com/protocol/v1/tool-calls)。

## 5. 数据权威、缓存与管理记录

### 5.1 权威划分

| 事实 | 权威来源与平台职责 |
|---|---|
| 会话列表、消息、工具记录、父子关系、历史附件 | Harness；平台按实际接口读取并建立可丢弃视图 |
| 原上下文如何继续 | Harness 原生存储及恢复接口 |
| 平台配置、身份、命令受理及交付结果 | 平台持久记录，不作为聊天历史 |
| 平台审批裁决与交付、管理审计 | 平台持久记录必要元数据，不永久复制提示词和工具正文 |
| 当前工具和进程是否仍执行 | 当前运行实例实际观测，未知明确说明 |

平台不保存独立聊天正文、工具输出、子历史及历史附件档案。列表索引和关系视图如有缓存也须可失效、可清除，不可覆盖原生事实。不得改写 Harness 私有存储或通过解析私有文件补足未经授权的接入能力。

### 5.2 历史读取与更新

首个闭环提供按能力列出原生会话和按标识读取历史，范围包含外部创建会话，浏览不以执行绑定为前提。显式刷新、重新打开、重连和重新接管均重新校验原生来源并读取可用历史；失效旧缓存，原生删除或压缩后不承诺平台另存完整版本。

有真实订阅能力时可主动推送外部更新，无该能力时不承诺所有客户端操作实时同步。此次确认不授权私有桥接、私有目录扫描或改写原生文件。读取失败不能由缓存或审计伪装为最新完整历史。

### 5.3 当前连接输出与缓存

实时输出经节点按原生会话和 Harness 连接代际管理的有界共享视图推送页面；首次订阅即交付仍保留的在途内容和可见范围，不等下一增量。历史与实时按可证明来源身份、顺序及更新语义衔接，不能按文字或时间猜测去重。缓存预算、慢订阅和过期读取由展示通道背压处理；单纯缓存失败不取消 Harness 执行，不宣称原生保存失败。

原先500ms/64KiB保存、条目入库、历史强刷、平台提交版本及保存失败停止规则取消。正常页面不出现平台保存状态；历史不支持、读取失败及内容衔接不完整仍须明确说明。管理存储失败不能降格为可忽略缓存错误。

### 5.4 标准重放准入与连接视图

“当前连接”统一指节点到 Harness 的有效连接代际，不指浏览器。浏览器刷新、断网、关闭或有权设备切换不直接清除节点缓存；各客户端仍独立校验权限，撤销不能借共享视图绕过。预算可淘汰早期内容并明确缺失范围。实际会话释放、Harness 换代或节点重启后旧视图失效，重新查看按标准重放重建；本次重放失败、无法安全重新加载或原生内容不再保留时明确限制。单纯查看不保活，实际接收重放则按 §7.4 刷新计时；不为保留视图增加永久存储。

用户最新确认：不提供标准历史重放的 Harness 暂不接入。仅有上下文恢复、列表或握手成功不足以开放会话创建、输入、恢复和接管；配置及能力调研可保留，平台身份、管理事实及离线平台备份不因原生接入不可用而被删除或失效。已受理动作仍保留真实结果及资源管理责任，不通过取消任务或删除数据掩盖能力变化。

### 5.5 命令、审批与异常

输入受理前校验身份、原生目标、资源状态、互斥及请求身份；平台事务只保留防重复、执行所有权、请求摘要及结果所需元数据，提交后派发。输入正文和临时上传只为在途交付使用，有明确所有者和清理路径，不作为永久档案；具体释放点、摘要与内容引用合同必须在恢复实现前补齐。

受理、原生接收和原生完成分别记录；异常不自动重发。执行终态按协议可靠事实记录，不以平台保存聊天为条件，也不代表原生历史必然完整可读。平台 Run、原生前台活动和后台工作分别判断；无 Run 不证明原生空闲，前台完成不证明后台结束。审批有效性按真实请求及协议生命周期判断，Run 完成、前台空闲和加载返回不一概使后台请求失效；明确取消、专属工作及请求失效、关闭或连接换代时按协议处理。具体归属、取消范围和新连接重新建立请求的规则见 [审批规格](../openspec/changes/deliver-codex-session-loop/specs/permission-approvals/spec.md)。无法验证目标、连接和真实请求时保持未授权，不复活旧决定，不用客户端自报正文替代可信来源。

R2-002：必要受理、唯一执行归属、派发或审计事实无法可靠提交时，不派发新的危险动作；批准决定未可靠保存时不交付允许。原生动作或决定可能已发送但结果记录失败时，分别报告已观测事实、管理记录故障和未知范围，不重发。仍能验证身份、目标和资源归属时，取消、协议安全拒绝、显式关闭及节点退出保持收敛路径；这些控制不扩大为输入、批准或原生删除，绑定当前运行及资源代际，换代后不能执行旧控制。故障恢复先核验并持久化协调，再恢复危险受理；具体边界见 [执行规格](../openspec/changes/deliver-codex-session-loop/specs/session-execution/spec.md)、[审批规格](../openspec/changes/deliver-codex-session-loop/specs/permission-approvals/spec.md)及[管理审计规格](../openspec/changes/deliver-codex-session-loop/specs/management-audit/spec.md)。

R2-003：新的产品副作用请求采用节点签发、绑定操作者及节点请求代际、具有不可延长截止时间的稳定身份；正常重启保留去重事实，原请求身份可独立验证，去重结果删除后也不能恢复过期请求的执行资格。请求到期不取消既有工作或原生审批，不自动换新身份重试。结果及必要摘要至少保留至请求截止，未收敛责任继续保护；时钟回退或期限不能可靠验证时拒绝新危险派发。请求期限、容量及只读查询以 [执行规格](../openspec/changes/deliver-codex-session-loop/specs/session-execution/spec.md) 为唯一行为来源。节点请求代际与 Harness 连接代际分别存在，隔离恢复的新目标不能复用旧请求资格，不改写已归档撤销接口的过期合同。

## 6. 原生顺序、分页与查看激活

### 6.1 来源身份与顺序

保留 Harness 实际暴露的结构、必要原始字段及轮内顺序；工具后续完成更新原位置，文字不得跨工具合并。历史与实时必须有可靠关联依据；时间戳和正文摘要不能替代身份或排序键。只有连接内顺序时只承诺该连接范围，不能伪造成跨重启稳定位置。

### 6.2 分页与重连

保留前端传轮数、默认10轮、父倒序及父步骤内展开子正序；轮内不反转，一轮不跨逻辑页，页内大块按需读取。标准重放兼容允许遍历全部历史，在流式、有界视图上形成平台分页；页面10轮不意味着原生只传10轮。缓存缺页、重放代际变化及无法安全重读按 [history-navigation](../openspec/changes/deliver-history-navigation/specs/history-navigation/spec.md) 处理，不建立永久聊天档案。可靠轮次无法证明时明确限制，不按消息条数猜测轮次。

游标绑定来源范围、会话、方向、轮次边界及可证明版本或读取代际。原生变化使稳定续读无法证明时，明确失效并重取；旧响应不能覆盖新视图，不能假定所有 Harness 提供事务快照或递增版本。

缓存外缺页分为可靠边界续读与新重放中的目标重新定位。不能证明跨代际连续性时，旧游标失效，但客户端可独立请求本次重放中的轮次范围，取得新代际目标页并替换对应视图，明确说明重新定位及连续性限制，不一律返回首页。不变历史在可靠轮次、可安全重放及公开预算条件下应能逐页访问到全部保留轮次；没有跨加载稳定 ID 不成为只能浏览缓存窗口的理由。定位坐标不冒充原生身份，完整行为以 [分页规格的“缓存外目标重新定位”](../openspec/changes/deliver-history-navigation/specs/history-navigation/spec.md) 为准；来源删改时不承诺保留旧快照边界。

父子各自读取进度独立，嵌套按需展开，每次读取和订阅校验目标权限。重新展开、刷新与重连重新读取原生状态并衔接仍在的实时缓存，关系和历史不可读时说明限制，不伪造完整树。

关系展示与子历史分页展开分别判断能力，具体条件见 [子树规格](../openspec/changes/deliver-agent-session-tree/specs/agent-session-tree/spec.md) 和 [分页规格](../openspec/changes/deliver-history-navigation/specs/history-navigation/spec.md)。子目标可用标准全量重放形成平台分页；关系可读不自动证明子内容可重建或轮次可证明，原生分页不是必要条件。

### 6.3 查看允许激活

用户已确认查看可启动或激活 Harness，不要求进程只读，也允许真实接口需要的会话加载。查看不等于发送新输入、批准工具或复用旧审批；激活若触发真实权限请求，仍按审批安全规则处理。

辅助进程启动不直接计作加载一个主会话；实际加载会话资源则遵循原生作用范围、平台唯一执行归属、共享实例和容量管理，并如实显示运行状态。查看请求本身不刷新执行活动时钟。

正常继续优先无重放原生恢复；需要重放时隔离旧内容与新输出。恢复不意味着工具、终端或子 Agent 从原执行指令位置续跑。

### 6.4 内容与资源的信任边界

Harness 为历史来源权威，不使正文、标题、审批描述、工具输出、URI、路径或未知扩展成为可信管理指令。实时与重放使用同一安全展示边界，保留原结构不等于执行其中的脚本、主动内容或终端控制。内容不能直接调用管理动作或替用户审批，可信操作控件与原生显示内容分别处理。

链接、文件和附件的实际读取及打开独立校验权限、范围和访问方式，不由节点通用代理任意 URL，不把主动附件作为受信同源页面执行。已有 TLS、应用认证及 CSP 继续有效；具体可观察要求由 [结构化历史规格的内容安全和资源引用要求](../openspec/changes/deliver-codex-session-loop/specs/structured-history/spec.md) 统一定义，其他分页和子树展示引用该边界，不另建一套规则。

协议依据：[ACP v2 原生前后台工作](https://agentclientprotocol.com/protocol/v2/prompt-lifecycle)、[请求权限](https://agentclientprotocol.com/protocol/v2/tool-calls)及[内容安全](https://agentclientprotocol.com/protocol/v2/security)。这些是当前规范依据，不构成任何真实 Harness 已通过本轮验收的声明。

## 7. 生命周期与多客户端行为

### 7.1 页面运行状态与内部操作分开

页面会话运行状态固定为：

| 展示 | 定义 |
|---|---|
| 运行中 | 会话资源已加载且尚未回收，包括正在执行和等待下一次输入 |
| 空闲 | 未加载或资源已回收；原生引用保留，历史可读性及上下文恢复依原生实际能力 |
| 运行中 · 待授权 | 运行中的特殊展示，存在有效待处理授权请求，不是第三个独立生命周期 |

一轮回复完成，只要运行资源未回收，仍为“运行中”，不能显示为空闲。空闲指资源已回收，不等于 ACP 原生的“当前前台没有工作”。恢复中可以给出操作加载反馈，连接异常、恢复失败等以页面报错呈现，不新增会话运行状态，也不能用空闲掩盖未知资源情况。

内部仅保留执行协调与历史解释所需的信息，不把每个瞬时步骤都升级成会话字段或页面状态：

| 对象 | 内部记录职责 |
|---|---|
| Session | 原生绑定、归档时间等；页面活动状态由实际资源事实推导，不维护庞大生命周期枚举 |
| 加载/释放/删除操作 | 由 Command 跟踪进行过程与结果；不要求持久化“删除中、已删除”会话状态 |
| HarnessInstance | 进程存活、退出时间与原因，启动/停止过程由操作管理 |
| Run | 执行进行情况与完成、取消、失败、中断、结果未知等终态；取消中不等于已结束 |
| ConversationItem | 生成是否完整；异常时标记中断，不意味着任务本身成功或失败 |
| ToolCall | Harness 实际提供的运行及结果信息，未确认结果不补成成功 |
| Approval | 请求是否有效、唯一裁决、交付结果分别记录 |

正常资源转换是“空闲 → 恢复成功 → 运行中”和“运行中 → 确认释放 → 空闲”。恢复失败、释放失败或连接异常通过操作结果及报错表达，不假装状态已成功转换。

Run 按 ACP 前台执行语义由已接受、派发/执行推进到终态；正常完成或取消路径须收到对应完成信号，取消请求本身不结束 Run。异常路径的重新准入条件见下段。新一轮建立新 Run，不让已结束 Run 重新变为运行中。会话资源状态不能替代某轮结果：同样处于运行中的会话，上一轮可能完成，也可能失败。

异常后能否接受新请求按 [执行规格的“异常后重新准入”](../openspec/changes/deliver-codex-session-loop/specs/session-execution/spec.md) 判断；旧执行已停止与副作用结果已知分别记录，恢复连接本身不解除安全约束，也不授权重发原请求。

确认原生删除后不必为展示“已删除”保留可见会话记录。重复请求处理和必要审计使用 Command/AuditRecord 保存删除事实，不把它作为可见会话继续返回。完整内部状态枚举和合法转换可自主补齐，但不得额外扩大页面状态。

### 7.2 断开、释放、恢复、删除

| 操作 | 已确认行为 |
|---|---|
| 页面关闭或客户端断网 | 后台执行与 ACP 保持，不因没有页面而中止任务 |
| 自动资源回收 | 只回收没有执行、待审批或需保留后台工作、满足 §7.4 条件的资源；回收成功后页面才变为“空闲” |
| 显式释放 | 阻止新的相关操作，协调结束工作，按实际能力关闭并释放；失败明确反馈，不假装成功 |
| 恢复 | 使用原生标识与参数，成功后才接受新输入；不自行灌历史 |
| 异常退出 | 保留平台已提交管理事实，重读可用原生历史；执行标为中断或未知，不自动重发 |
| 删除会话 | 只提供显式原生删除，必须验证支持及影响范围；不提供隐藏或删除平台聊天副本替代 |

正常释放应记录必要管理结果并确认资源关闭，不要求保存聊天缓存。历史恢复不等于恢复文件系统快照，也不保证外部工具、终端或子 Agent 从原执行指令位置续跑。

### 7.3 多客户端与原生 CLI

- 多个网页、手机或平台 CLI 可以同时查看和操作同一会话。
- 经过平台的命令统一协调；同一会话存在未结束的前台执行时，新普通输入返回忙碌，取消和有效审批仍可处理。这与页面“运行中”（资源已加载）不是同一个判断。
- 多客户端同时裁决审批，最多接受一个最终决定；交付失败独立记录。
- 平台内部的锁只能约束平台操作，不能强制阻止外部原生 CLI 打开同一原生会话。
- 提供释放入口方便切换原生客户端；重新接管后的上下文恢复仍交给 Harness。
- Harness 有可靠占用检测时呈现占用状态；没有时明确能力限制，不承诺平台可以检测所有外部写入。
- 不支持承诺外部 CLI 与平台同时写同一原生会话的一致性；这与多个会话共享目录并行是不同问题。
- 外部客户端新增内容在刷新、重开、重连或接管时从原生重新读取；无接口则明确不可用，不承诺所有外部写入实时推送，也不将外部操作记为平台执行或审批。

### 7.4 自动资源回收与容量上限

本节规定平台何时发起自动回收。ACP 提供关闭与释放机制，不替平台决定 30 分钟超时或容量上限；这些是本轮已确认的产品策略，不是现有配置已实现的声明。

#### 7.4.1 计数与可回收条件

- 默认最多同时加载 **50 个主会话**，不是最多保存 50 个历史会话，也不是最多运行 50 个 Harness 进程。
- 子会话不单独占用这个名额；其资源和活动归属于对应主会话的执行树。子会话不计数不意味着不消耗内存或进程资源。
- 直接子目标加载的主树归属、名额和根不可用分支，以 [容量规格的“子目标加载归属主执行树”](../openspec/changes/deliver-session-capacity/specs/session-resource-policy/spec.md) 为准；根正文未打开不免除树资源的计数及所有权。
- 平台只对主会话执行资源池分配、超时回收和容量淘汰；子会话生命周期交由父会话及Harness管理，平台不单独为子会话设置超时或淘汰，只依据其运行事实保护所属主会话。
- 新建并加载主会话、恢复已回收的主会话都需要名额；单纯查询不需要；查看导致实际加载时同样需要，已经加载不重复计数。
- 前台执行、有效待授权请求、需要保留的后台工作，以及子 Agent 的上述活动，均阻止对应主会话被自动回收。没有可靠证据证明可安全释放时，不能当作候选强制关闭。
- 容量计数、前台观测、后台及子工作覆盖、关闭接口与自动安全回收分别判断。标准重放、Run 全部结束或 ACP 前台 idle 不证明后台静止；自动回收还须证明完整活动范围及检查至关闭窗口的安全性。平台锁不能排除原生自发或外部活动，不能先无条件关闭再以成功证明原本无工作。详见 [容量规格的能力边界](../openspec/changes/deliver-session-capacity/specs/session-resource-policy/spec.md)。
- 2026-10-29 用户补充澄清：待授权会话同时豁免30分钟超时回收和容量满额淘汰。授权状态取消后只解除对应待授权保护，重新纳入资格判断，不直接回收；仍有其他有效授权或父/子执行、后台工作时继续保护。授权取消与执行结束、资源释放是不同事实。
- 释放某个会话不等于关闭整个 Harness 进程；共享实例不能因回收一个会话影响其他会话。

#### 7.4.2 30 分钟计时

“没有消息”按**没有会话活动**解释，包含主会话及所属子会话的用户输入、Harness 回复、可见思考、工具进展和子 Agent 活动，以及节点本次实际接收的标准历史重放。重放以当前接收时刻刷新活动时间，持续重放可以持续延后超时回收；不使用旧内容的历史时间作为本次活动时间。网络心跳、页面打开及只读缓存的翻页不刷新，查看或翻页实际触发重放时按重放处理。

只有执行、审批及需要保留的后台工作全部结束，主会话可以安全释放后，才开始计算无活动时间。计时起点不得早于进入可回收状态的时刻；之后发生新的有效会话活动则重新计时。刚加载但尚未输入的会话从加载成功且满足可回收条件时开始计时。

可回收状态持续 **30 分钟**且没有新活动时发起回收。长工具调用或等待审批即使超过 30 分钟也不自动中止；工作结束后重新开始计时，不因上条文字消息很早就立即回收。

授权取消后若已满足安全可回收条件，沿用上述计时规则，不能将此前受待授权保护的时长抵作安全空闲；若随后仍有任务执行则继续保护，直到工作结束。取消授权仅恢复被规则评估的资格，不是独立的立即回收触发器。

用户查看页面本身不保活。重放刷新计时不代表有新执行、有效审批或后台工作，不使安全可释放目标获得满额淘汰豁免；历史状态不复活为当前活动。回收后历史能否读取依原生能力；读取需要再次加载时重新申请名额，下一次输入同样先按原生绑定恢复。

#### 7.4.3 容量满时优先回收

创建或恢复主会话需要新增名额时：

1. 未达到 50 个时正常加载，分配过程需协调并发，不能因多个客户端同时请求而超限。
2. 达到上限时，排除待授权、自身或所属子会话仍有执行/后台工作的主会话，再在可安全释放的候选中选择**最久没有会话活动**者。容量触发不必等待满 30 分钟；刚解除授权保护且安全可释放的主会话也可参与，不因曾经待授权而永久排除。
3. 在关闭前重新确认候选没有新输入、授权或后台/子 Agent 活动，并确认必要管理事实已记录。
4. 按已协商能力调用关闭/释放路径，确认资源释放成功后才释放名额，再创建或恢复目标会话。
5. 释放失败不得假装已有名额；按实际结果处理并给出明确错误，不静默超限。
6. 没有可回收候选（例如全部忙碌）时，明确提示容量已满，不强制取消任务，也不自动排队。

计数范围、回收资格和名额预留是平台内部规则，不增加新的页面会话状态。仅发出关闭请求、连接异常或进程状态未知都不能直接视为成功回收。

缺少完整活动或安全关闭依据的接入可继续提供其他已准入会话操作，仍计入50个上限，但明确自动回收受限，不能承诺等待30分钟最终就会释放。所有目标均受保护或未知时拒绝新加载，并保留有权用户的显式释放入口；显式释放仍需协调工作、审批及资源，不能保证成功。能力及运行约束变化后重新判断，不以厂商名单、旧报告或新增私有探测补足安全证明。

故障安全控制确认资源已关闭但管理结果尚未可靠保存时，关闭事实与记录失败分别展示；容量保留至核验和持久化账本协调完成，不借故障先转移名额启动新工作。自动回收不以管理存储故障为理由绕过安全条件。

#### 7.4.4 待实施参数与验收

30 分钟与 50 个是已确认的默认值。具体配置键和调度扫描方式可自主确定，正式实施时同步配置权威文档，不在本次整理中新增配置接口。

验收应覆盖：超时边界、新活动及实际重放重置、长任务与待授权保护、子会话/后台活动保护、页面及缓存访问不保活、重放不形成任务保护、容量触发提前回收、最久未活动选择、并发创建不超限、关闭失败不释放名额，以及满额无候选时明确拒绝。

ARCH-001 追加规格场景覆盖：Run 结束后后台审批及 Agent 自发前台活动、无稳定条目标识的缓存外分页重新定位、主动内容与资源引用安全，以及前台 idle 但后台未知、检查至关闭竞态和失去回收依据。独立 tests、详细合同和工作包尚待按本轮规则重基准，不将这些规格场景当成已定义的独立用例或产品验收结果。

## 8. 原生删除、缓存清理与备份

- 用户已确认只提供原生会话删除，不提供隐藏、取消隐藏或平台历史删除。无已验证原生删除能力则明确不可用，不直接删除私有文件。
- 原生删除前明确目标及固有级联范围并取得授权，协调平台执行、审批及释放；结果未知不自动重发。平台不能额外删除未选中的子会话。
- 删除授权绑定固定目标集合，范围变化及查询后并发变化按 [删除规格的“删除授权绑定固定范围”](../openspec/changes/deliver-session-data-lifecycle/specs/session-data-lifecycle/spec.md) 处理，接口不能保证影响范围时不执行。
- 原生正文和附件归 Harness 管理；平台只回收自身无有效引用的缓存、临时上传，不通过缓存回收修改原生数据。
- 审计保留最小不含正文的目标、范围及结果；不从审计恢复已删聊天，不让清缓存成为删除成功证明。
- 管理审计保留和容量以 [management-audit](../openspec/changes/deliver-codex-session-loop/specs/management-audit/spec.md) 为准；请求去重保护、未收敛事实和过期拒绝依据分别管理，不能把聊天缓存清理或审计到期当作重新执行旧请求的许可。实际管理元数据清理由 [session-data-lifecycle](../openspec/changes/deliver-session-data-lifecycle/specs/session-data-lifecycle/spec.md) 在满足保护条件后执行，不自动清理身份、撤销或用户原生数据。本轮仅定义未来行为，不执行清理或迁移。
- 平台备份仅覆盖配置、身份边界允许的管理记录及必要操作事实，不含聊天缓存，也不声称恢复原生会话、历史或上下文。原生组件需独立已验证的一致性备份路径，单纯导出不等于可恢复上下文。
- 恢复验证只在隔离新目标进行，不覆盖实际库、密钥或原生存储；旧审批、命令和信任不自动复活。启用新目标另行授权。
- 恢复成功按清单声明包含的组件判断，未选择原生组件与已声明但缺失分别处理，见 [备份恢复规格](../openspec/changes/deliver-backup-recovery/specs/backup-recovery/spec.md)。

## 10. 实施前的设计与验收工作

### 10.1 可自主补齐的详细设计

本轮产品方向足够进入设计整理，无需逐字段向用户确认。实现前应补齐：

- 对象完整字段、来源标识、关系约束和生命周期。
- 每个状态的合法转换、错误与异常恢复。
- 原生会话发现与读取端口、消息身份、流式边界、顺序及最终值更新规则。
- 可丢弃缓存范围、内存上限、读取背压，以及必要管理数据写入失败的处理。
- 事务边界、命令重复处理及审批交付规则。
- 原生历史、当前连接缓存、读取代际与分页的可靠衔接。
- 原生接管、原生删除、自有缓存清理及分组件备份恢复规则。
- 数据库表结构、索引、迁移与容量测试。

这些由后续设计自主确定；若发现必须改变已确认用户行为、安全边界或数据权威，再明确指出影响并确认。

### 10.2 必须实测的能力

至少对三款 Harness 的固定版本验证：

1. 正常结束后释放进程，再恢复原会话并继续输入，上下文连续。
2. 页面断开不停止 Harness，重连时标准重放并衔接当前输出；不提供重放的接入在能力发现后拒绝，不开放当前连接聊天降级。
3. 工具执行中异常退出，平台不自动重发，保留可证明事实并标记未知部分。
4. 等待审批时异常退出，旧请求不被复用，多客户端不能产生多个最终裁决。
5. 子 Agent 身份、父子关系和各自历史可恢复；没有暴露的能力明确标记。
6. 实时、刷新、分页、重启后的同一会话顺序一致；思考、工具和文字交替不被合并重排。
7. 上下文压缩后按原生可读历史展示，明确完整性边界，不承诺平台另存压缩前全文。
8. 高速输出及长会话下原生读取、分页及当前输出衔接可用，缓存有界；不支持的能力明确报告。
9. 验证历史不可用、原生读取失败、缓存失效及管理存储故障的区别，不以当前连接输出承诺跨重启可恢复。
10. 释放失败、外部占用与不支持接口明确呈现，不以假成功掩盖。
11. 按 §7.4 验证 30 分钟回收与默认 50 个主会话上限，活动保护、候选选择、释放确认和并发名额协调均符合已确认策略。

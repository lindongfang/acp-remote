# 会话激活与资源回收：设计访谈草稿

状态：访谈已收敛；核心/服务端/前端实现与跨层套件已落地，真实浏览器验收与 50 档容量结论仍待主检出/产品确认；本文保留访谈记录，正式行为以 OpenSpec 变更与权威文档为准。

验收入口：[`docs/evidence/session-lifecycle-acceptance.md`](evidence/session-lifecycle-acceptance.md)（WP6 的跨层套件、真实浏览器脚本与 10/25/50 基准；第 8 节已记录 app 套件 8/8 与三档实测数据，真实浏览器 live 未执行，未执行项不勾选）。真实 Codex 上下文连续性的上一轮探针证据见 [`docs/evidence/session-lifecycle-probe.md`](evidence/session-lifecycle-probe.md)。

## 已确认的目标行为

- 进入会话页面，以及页面重新可见时，立即激活当前会话；已有可用资源时复用，已回收时恢复原会话。
- 仅当页面可见且选中该会话时，视为正在查看。查看历史也保持活跃；后台标签页、锁屏及已关闭页面不保活。
- 多设备共享会话所属节点管理的运行资源与计时；同时进入不应重复恢复。
- 异常断网、浏览器崩溃等无法主动报告离开的情况，由服务端在连接断开或查看保活超时后移除查看者；最后一个查看者失效后，在无任务及待处理请求时开始保留期。重新连接后激活当前可见会话。
- 本次只覆盖本机直接管理的会话；Node Link 导入会话暂不纳入本次设计与实现范围。
- 自动回收默认 30 分钟，允许配置时长及显式关闭；计时条件不因自定义时长而改变。
- 最后一个查看者离开后开始完整的 30 分钟保留期。仍有未结束任务、排队输入或有效待处理请求时不回收，待这些条件全部解除后重新开始完整计时。
- 回收只释放该会话的运行资源，保留身份与历史，不结束同一 Agent 的其他会话；全部会话都满足回收条件后才退出共享 Agent 进程。
- 目标状态使用“活跃”替代“运行中”的产品称呼：覆盖任务执行、排队及资源保留期；资源回收后才为空闲。有效待处理请求优先显示待处理（授权请求显示待批准）。此处尚未决定 wire 枚举迁移方式。
- 活跃且没有未结束任务时允许发送；不能仅凭“活跃”禁用发送。
- 恢复期间历史始终可读，显示“正在恢复”且暂不可发送；恢复失败保留草稿，展示明确原因及重试入口，不自动新建会话代替。
- 仅恢复成功后才因运行资源可用而显示活跃。恢复失败且没有真实任务或待处理请求时显示空闲，并单独呈现恢复错误和重试入口；不能覆盖仍存在的任务或待处理请求状态。
- 恢复开始后切换会话，不取消已开始的恢复；恢复成功时若无人查看且无任务或待处理请求，从成功时开始完整保留期。迟到响应不得将当前页面切回原会话。

## 首条消息前的会话准备（2026-10-22 访谈，尚未实现）

本节记录排查 Codex 空会话跨进程无法恢复后，用户确认的新方向；尚未写入正式协议或实现，不改变上文已有会话的恢复规则。

- 本轮只调整 Web/PWA 的新建入口；Zed 与 Node Link 的现行创建合同不在本轮默许改写。
- 首条消息提交前不在 ACP Remote 服务端持久化会话。准备阶段由后端提前分配会话 ID，首次保存沿用同一 ID，地址不变；保存成功或失败都留在同一会话页，不采用浏览器准备 ID 替换为 Owner 正式 ID 的方案。提前分配 ID 的协议、内存归属与服务重启后的处理仍待设计。
- 准备草稿包含文字、模式、配置和附件，只在当前浏览器用于恢复刷新；离开新会话页即清除，再次新建为空白页。不跨设备保存准备草稿。附件过大或浏览器无法保存时明确提示，不得静默声称能够恢复。
- 多标签页的会话准备相互独立；一个标签页的离开或提交不清除另一标签页的准备草稿。
- 准备页面的 ID 在正式保存前只由发起准备的标签页识别；陌生标签页/设备访问该地址按不存在处理，任意输入 ID 不得自动新建准备记录。
- 首次保存失败时在当前会话页保留输入并显示失败；保存成功也留在同一会话页，不采用“保存成功后才从新会话页跳到正式会话页”的方案。
- 首条消息保存成功后即作为正式会话保留并在目录中可见，即使后续 Agent 建立或发送失败；保留已提交内容与明确状态。可证明未发送时允许重试，结果不明时先核实，不自动重发。
- 准备阶段变更工作目录或 Agent 等同重新开始：释放旧临时资源、清除旧准备草稿，由后端重新分配 ID，页面输入不保留；新 Agent 的模式和配置从默认值开始，允许用户重新调整。
- 用户要求首条消息前允许切换模式和配置，未修改时采用默认值；允许准备阶段建立临时 Agent 会话以取得并切换真实选项，ACP Remote 此时不持久保存会话记录。Agent 自身是否写盘不在此保证范围内。离开释放临时资源；刷新后资源已丢失时重新准备并重新验证设置。
- 服务重启后，原标签页保留准备草稿和原 ID；后端须核实该次准备，再重建临时 Agent 会话、重新验证设置，不得自动发送消息。具体身份核实与 ID 预分配协议仍待设计。
- 页面进入后台后允许回收临时 Agent 资源，但不清除该标签页的准备草稿；回到前台沿用原 ID 并重新准备。旧模式或配置已不可用时明确提示并阻止发送，不得静默替换设置。
- 首次发送先持久保存首条消息与发送请求，再向 Agent 派发首条消息；不禁止此前为模式/配置准备而建立临时 Agent 会话。保存成功只是受理，不得显示为已发送。保存响应丢失时核实原请求，不新建第二条会话。
- 已有会话不迁移、不自动重置为待开始、不替换已有 Agent 身份。
- 服务端明确确认会话不存在时跳转目录页 `/`；断网、未认证或服务异常不能当成不存在处理。
- 产品选择已逐项确认，完整方案待用户最终核对。后端预分配 ID 的认证/重启核实协议、浏览器刷新与离开判定、附件保存与上传时序、首次提交的原子保存及崩溃窗口属于后续技术设计，尚未实现。

上述选择的原因与备选方案记于 [ADR-0014（提案）](adr/0014-web-session-preparation-before-first-message.md)。正式合同更新和实现须在完整方案最终确认后进行。

## 已确认的容量策略

补充硬要求：激活必须恢复原 Agent 会话上下文；只展示旧历史不代表恢复成功。资源回收后及 Daemon 重启后均须验证连续性，不新建替代、不重发旧消息、不重新执行旧任务。恢复不支持、原身份丢失或恢复失败时明确失败并保留草稿。

- 设置节点共享、可配置的会话运行资源上限，本机所有 Agent 合计计算；不限制历史会话总数，待处理会话同样占用名额。
- 达到上限后，优先回收无人查看、没有未结束或排队任务、没有有效待处理请求的会话，选择最久未被使用者；容量压力允许提前结束尚未满 30 分钟的保留期。
- 没有可安全回收的会话时，不中断其他任务、不回收正在查看或待处理的会话；拒绝本次激活并明确提示资源已满，历史保持可读。
- 默认上限候选值为 50，可配置；用户同意先验证再决定是否采用，不表示已验证的安全容量。不新增同时执行任务数限制。
- 正在创建或恢复的会话预占名额，避免并发激活突破上限；恢复失败释放名额。
- 实施验证需覆盖 10、25、50 个已恢复会话的内存占用、切换速度及回收效果，区分保留资源与执行任务的负载；若结果不支持 50，带测量结果重新确认默认值，不擅自视为已通过。
- 当前关闭单会话端点只清理本地会话及终端，不能据此保证外部 Codex 内部上下文已经卸载。需要验证逐会话回收是否真正释放资源；不能仅改变状态便声称完成资源回收，也不能结束仍服务其他会话的共享进程。

## 已核实的现状与差距

- 同 Agent 多会话共享进程；`agent-host` 已提供逐会话真实 `session/close` 与三态释放结果，进程级扫描只在全部会话可回收时才停共享进程。
- `sessions.idle_timeout_ms` 默认值已按本变更改为 `1800000`（30 分钟），显式 `0` 只关闭按时间回收；容量策略不受影响。现行定义以 [CONFIG_REFERENCE.md](CONFIG_REFERENCE.md) 为准。
- Sync v1 已接受经 `core.local-session-lifecycle.v1` 协商的 `session.resume`；恢复依赖 Agent 实际宣告能力，不得虚报或替换为新建。现行合同见 [SYNC_PROTOCOL.md](SYNC_PROTOCOL.md) §11.5 与 [ACP_COMPATIBILITY_MATRIX.md](ACP_COMPATIBILITY_MATRIX.md)。
- 现行会话主状态仍只根据任务与交互归约（`idle`/`running`/`pending`）；资源生命周期作为独立的 `localActivity` 投影，不改写任务三态。见 [CORE_PORTS_AND_STORAGE.md](CORE_PORTS_AND_STORAGE.md) 与 [GLOSSARY.md](../GLOSSARY.md)。

## 收敛状态与实施边界

- 核心/服务端/前端实现与跨层套件已落地；真实浏览器 live 验收与 50 档容量结论仍未完成/待产品确认。
- 50 是待验证默认候选值；10/25/50 已测但 50 档内存较高，容量验证与默认值仍需产品重新确认。
- 后续变更需统一制定状态及协议兼容策略：页面“活跃”不能静默改写现行 `running` 语义，Sync 激活/查看保活与旧 peer 的行为需显式协商；具体 wire 设计、资源上限配置键和查看保活时限由正式设计确定并同步机器合同。
- 本次不扩展 Node Link 导入会话行为，不新增同时执行任务数限制；保留现有身份认证、单会话单任务和命令不可自动重派的不变量。

# 文件列表刷新需求访谈

状态：已完成访谈与实现；最终规则已同步 FRONTEND_DESIGN，验证记录见 docs/evidence/file-list-refresh.md。本记录不取代权威行为定义。

## 已确认

- 首次打开文件栏、切换“全部文件 / Git 变更”时读取。
- 重新进入会话、恢复连接、切回浏览器标签页时也自动刷新当前文件来源（Q4 用户选择一并自动刷新）。
- 手动刷新只刷新当前来源；全部文件包含已展开的子目录。
- 取消当前会话 file.changed 事件触发的文件列表自动刷新。
- 文件列表刷新不替换已经打开的文件正文或 Git 差异；重新打开文件时读取最新内容。
- 保留 file.changed 对已打开文件的过期标记及提示，但不因事件自动刷新文件列表或替换正文（Q5 已确认需要提示）。
- “全部文件”与“Git 变更”保留现有分页和“加载更多”。刷新时根目录、已展开子目录和 Git 列表均回到第一页，保留目录展开状态（Q6 最终确认；取代之前取消分页的暂定选择）。
- 刷新期间图标旋转、按钮高亮并禁止重复点击；成功后短暂显示勾号；不新增加载文案，失败保留错误。
- 一次刷新涉及多个目录请求时，等待全部结束；只有全部成功才显示勾号。部分失败保留对应旧列表并显示错误（Q7 已确认）。

用户已明确要求开始实现；无待确认行为。

- file.changed 同时负责列表自动刷新与正文过期标记，需分别明确规则。

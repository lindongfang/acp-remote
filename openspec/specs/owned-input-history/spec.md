# owned-input-history Specification

## Purpose
规定 Owner 对已受理用户输入的持久保存与可读取保证，使对话正文不依赖 Agent 是否回传输入，并确保重试、回显、失败和进程恢复不会造成输入消失或误合并。

## Requirements

### Requirement: 每次受理输入均有持久正文

Owner SHALL 在接受首条或后续输入时原子保存完整用户内容、稳定消息身份及请求关联，成功后才允许派发与广播。该输入 SHALL 可由会话读取恢复，MUST NOT 依赖 Agent 回显；附件与结构化内容 MUST 保持原有语义。Access MUST NOT 为此保存远程正文或命令关联。

#### Scenario: Agent 不回显第二条输入
- **WHEN** 用户提交第二条输入且 Agent 只返回回复
- **THEN** 刷新及另一已认证客户端读取都能看到该条完整输入

#### Scenario: 保存失败
- **WHEN** 保存输入的事务失败
- **THEN** 请求明确失败，不派发 Agent，不广播已保存消息，客户端保留可修正输入

#### Scenario: 执行失败仍保留输入
- **WHEN** 输入已保存而 Agent 启动、执行或恢复失败
- **THEN** 输入仍可读取，失败与输入分开呈现

#### Scenario: 长输入与事件清理后仍完整可读
- **WHEN** 受理输入超过单个事件文本上限，或对应的 `user.message.delta` 已过期、被压缩
- **THEN** 会话读取仍从保存的完整消息返回该输入，不按事件文本截断，也不要求 Agent 补回显

#### Scenario: 保存的输入与事件投影不重复
- **WHEN** 同一次受理同时存在持久用户消息与 `user.message.delta` 事件
- **THEN** 读取结果对该请求恰好返回一条用户输入，事件只用于实时可见性，不参与二次拼接

### Requirement: 请求消息及回显以稳定身份关联

同一受理请求 SHALL 只产生一条提交输入，重试 MUST NOT 重复保存或派发。不同请求即使文字相同 SHALL 保持独立。Agent 回显只有在可靠派发关联且完整内容一致时才可作为同一提交输入处理，MUST NOT 凭文本相同或时间接近关联；不同内容及无法关联的事件 SHALL 保留。

#### Scenario: 连续两次继续
- **WHEN** 两个不同请求各提交一次“继续”
- **THEN** 时间线和刷新后的历史均显示两条用户输入

#### Scenario: 重试及回显重投
- **WHEN** 同一请求被重试，且相同回显事件重复投递
- **THEN** 正式历史只有一条该请求的提交输入，副作用不重复

#### Scenario: 异内容或迟到回显
- **WHEN** Agent 提供不同内容，或无法可靠关联到该次派发
- **THEN** 保留其独立内容，不覆盖或删除已保存输入

### Requirement: 输入恢复不等于重新执行

Owner SHALL 在进程恢复后提供已保存输入；可能已派发的请求 MUST 维持结果不确定的既有语义，MUST NOT 因正文存在或页面重新打开而重发副作用。历史旧数据没有保存的输入 MUST NOT 被编造或按附近回复推断补齐。

#### Scenario: 保存后进程退出
- **WHEN** 保存成功后进程在派发边界退出
- **THEN** 重启后输入可读，命令按既有派发证据收敛，不自动执行结果不确定的工作

#### Scenario: 旧历史缺少输入
- **WHEN** 读取升级前没有持久输入的历史轮次
- **THEN** 保留已有历史，不生成猜测的用户输入

# web-session-preparation Specification

## Purpose
定义 Web/PWA 本机新会话在首条消息提交前的临时准备，以及提交后的持久化和派发边界，使用户能够提前选择真实 Agent 设置、刷新恢复输入，并在进程重启或请求重试时保持同一地址且不重复执行任务。

## Requirements

### Requirement: 后端提前分配固定会话身份

系统 SHALL 在认证后的会话准备中由所属节点分配最终会话 ID；从进入准备页到首条保存成功或失败，页面 SHALL 始终使用同一 `/session/<id>` 地址。提前分配 ID MUST NOT 等同持久创建会话，客户端 MUST NOT 自行指定任意正式 ID。

#### Scenario: 首条保存成功不换地址
- **WHEN** 用户在后端分配的准备页提交首条消息且保存成功
- **THEN** 正式会话沿用原 ID，页面不跳转、地址不替换为另一个 ID

#### Scenario: 保存失败保留同页输入
- **WHEN** 首条保存因存储故障失败
- **THEN** 页面保持原地址和完整输入，明确说明未保存，目录中没有半成品会话

### Requirement: 未提交准备不进入持久目录

首条消息被持久接受之前，ACP Remote SHALL 只在运行期管理准备，MUST NOT 保存对应的会话行、命令收据、消息、附件关联、目录记录或准备进度。准备 SHALL 不进入快照、目录汇总或其他设备的会话列表。明确请求建目录所产生的主机目录不等同会话记录，后续失败 MUST NOT 删除它。

#### Scenario: 只准备不提交
- **WHEN** 用户打开准备页、输入文字并调整配置，但未发送
- **THEN** 其他设备和重启后的正式目录中均没有该会话，ACP Remote 没有对应持久记录

#### Scenario: 显式建目录后放弃
- **WHEN** 用户明确要求创建工作目录，准备后又离开页面
- **THEN** 临时会话被释放且无会话或目录记录，已创建的主机目录不被自动删除

### Requirement: 已正式提交的身份返回明确结果

一个准备 ID 首次被持久接受后，准备恢复 SHALL 返回 `committed` 及正式会话和首次/当前请求关联，而不是 `failed` 或 `ready`。客户端 SHALL 在同页核实原请求和读取正式会话，不再创建准备、不再次上传或派发。正常重启保留该判断；存储整体重建使旧存储代材料失效。本轮不处理正式会话删除及首条关联记录清理，也不新增 `consumed` 或删除墓碑。

#### Scenario: 保存响应丢失后恢复
- **WHEN** 会话首条已被接受但响应丢失，原标签页请求恢复准备
- **THEN** 返回 `committed` 和原请求关联，客户端保持同一 URL 读取正式会话，不重复提交

#### Scenario: 服务重启与存储重建有区别
- **WHEN** 同一节点正常重启，或其存储被整体重建
- **THEN** 前者对未提交准备返回可准备结果、对已提交 ID 返回 `committed`；后者返回不可重试的 `preparation.store_rebuilt`，客户端不使用旧材料、认证后回目录重新开始

### Requirement: 真实模式与配置在提交前可调整

准备阶段 SHALL 允许建立临时真实 Agent 会话以取得和切换 Agent 实际提供的模式与配置；未修改时采用默认值。不支持的选项 MUST 明确说明，MUST NOT 使用虚构或过期选项冒充可用能力，MUST NOT 发送隐藏消息来获得选项或促使写盘。

#### Scenario: 首条前切换模式和配置
- **WHEN** Agent 提供多个模式与可修改配置，用户在发送首条前选择非默认值
- **THEN** 页面可操作这些选项，以 Agent 确认结果显示当前值，首条按确认的设置派发

#### Scenario: 默认值与未提供能力
- **WHEN** 用户未修改设置或 Agent 没有宣告某类设置
- **THEN** 前者使用默认值，后者明确显示未提供，不伪造选择列表或静默转换能力

### Requirement: 准备操作不得绕过设备认证

分配、重建、配置、读取、上传和提交准备 SHALL 均要求当前已认证且未撤销的设备。准备恢复材料 SHALL 绑定所属节点、设备、会话 ID 与准备上下文，MUST NOT 是登录令牌，MUST NOT 仅凭 URL、材料存在或网络可达授予权限。

#### Scenario: 跨设备或篡改的准备恢复被拒
- **WHEN** 另一设备使用准备恢复材料，或调用方修改其中 ID、Agent 或目录
- **THEN** 请求被拒，不启动替代会话、不读工作目录、不暴露草稿内容

#### Scenario: 设备撤销立即阻止提交
- **WHEN** 设备在准备后被撤销，再尝试重建、配置或首次提交
- **THEN** 认证前提失败，不因曾取得准备 ID 而继续执行

### Requirement: 刷新恢复完整准备草稿

当前标签页 SHALL 能在同一来源、节点和设备身份下刷新恢复准备 ID、文字、模式、配置、工作目录路径引用及附件。附件内容 SHALL 实际可恢复，MUST NOT 把已失效的文件句柄或临时地址当成内容。浏览器无法保存时 SHALL 明确指出不能恢复的内容，不得报告完整保存成功。

#### Scenario: 带附件刷新
- **WHEN** 用户输入文字、选择非默认配置及附件，草稿保存成功后刷新
- **THEN** 同页同 ID 恢复文字、选择及可读取的附件，不重复上传或自动发送

#### Scenario: 浏览器空间不足
- **WHEN** 附件或草稿因浏览器资源不足不能保存
- **THEN** 页面明确提示恢复能力受限，保留仍可用的当前输入，不静默丢附件或上传到服务端替代保存

### Requirement: 标签页隔离与主动离开清除

不同标签页的准备草稿、资源归属和清理 SHALL 相互独立；刷新与后台隐藏 MUST NOT 当成主动离开。用户主动离开准备页 SHALL 清除该准备草稿并请求释放临时资源，下一次新建为空白。重复标签页 MUST NOT 克隆可操作同一准备的归属。异常终止的残留 SHALL 不被陌生页面恢复，并以有界清理策略回收。

#### Scenario: 两个标签页独立刷新
- **WHEN** A、B 各自准备，A 离开，B 随后刷新
- **THEN** A 的准备被清除，B 恢复自己的完整草稿且不受影响

#### Scenario: 后台隐藏不清草稿
- **WHEN** 标签页进入后台后返回
- **THEN** 草稿仍在，不因隐藏事件而清空输入

#### Scenario: 复制未保存地址
- **WHEN** 用户将准备 URL 复制到没有该准备上下文的标签页
- **THEN** 新标签页不取得原草稿或临时资源归属，确认不存在后跳到目录页

### Requirement: 更换 Agent 或目录重新开始

准备阶段更换 Agent 或工作目录 SHALL 释放旧临时资源、清除文字和附件及旧设置，并由后端分配新 ID。新准备采用新 Agent 的默认设置并允许调整；迟到的旧准备结果 MUST NOT 覆盖新页面，也不得恢复被清除的输入。

#### Scenario: 更换目录清空输入
- **WHEN** 用户在有文字和附件的准备页改选另一目录
- **THEN** 后端分配新 ID，旧输入不带入，新页面从空白开始

#### Scenario: 更换 Agent 与旧响应迟到
- **WHEN** 改选 Agent 后旧 Agent 的配置结果迟到
- **THEN** 新页面保持新 ID、新 Agent 与其默认设置，旧结果被丢弃

### Requirement: 临时资源可回收且能沿原 ID 重建

准备资源 SHALL 有容量上限、过期与关闭路径，可在后台、断线或服务重启后回收。原标签页重新认证并核实准备后 SHALL 使用同一 ID 重新准备，而不依赖旧 Agent 空会话可恢复；所选模式与配置 SHALL 重新验证。不兼容时 MUST 明确提示并阻止发送，MUST NOT 静默换默认值。

#### Scenario: Codex 空准备经历进程重启
- **WHEN** 尚未提交的 Codex 准备没有恢复文件，测试 Agent 或 Daemon 进程被重启
- **THEN** 原标签页可在同一 ID 下重新取得真实选项并首次发送，不把旧临时身份的恢复失败当成正式会话损坏

#### Scenario: 重建后的选项改变
- **WHEN** 原来选择的模式或配置在新临时会话中已不可用
- **THEN** 输入和附件保留，页面要求用户处理设置，不自动发送、不静默回退

#### Scenario: 满额不影响其他会话
- **WHEN** 准备申请超过节点运行资源上限且没有可安全回收的候选
- **THEN** 明确返回容量原因，不中断其他受保护会话，当前准备草稿仍保留

### Requirement: 陌生地址仅在权威不存在后跳转

会话 URL 读取 SHALL 先识别当前标签页合法准备，再按正式会话读取。无准备上下文且所属节点明确确认会话不存在时 SHALL 替换到目录页 `/`；认证未完成、快照未就绪、离线和服务异常 MUST NOT 被解释成不存在。单凭任意 ID MUST NOT 启动 Agent 或新建准备。

#### Scenario: 随机输入不存在的会话地址
- **WHEN** 已认证用户输入未保存且无本标签准备上下文的 ID，服务端确认不存在
- **THEN** 地址被替换为 `/`，不触发创建，后退不反复进入该失效页面

#### Scenario: 断线不误跳目录
- **WHEN** 打开正式或准备会话时服务暂不可达
- **THEN** 页面呈现连接状态并保留可用内容，不以不存在为由跳转

### Requirement: 首条消息完整持久受理先于派发

首条提交 SHALL 在派发用户消息前原子保存会话、完整用户输入、模式与配置选择、附件归属、稳定请求记录和可判定的派发阶段；原子保存失败 MUST NOT 派发。保存成功只表示受理，不得显示已发送或完成；其他设备 SHALL 能读到已提交会话及首条内容，后续 Agent 建立或派发失败不删除它。

#### Scenario: 保存后立即崩溃
- **WHEN** 首条内容保存成功，且尚未持久声明进入可能派发阶段时进程崩溃
- **THEN** 重启读取仍得到同一会话和完整首条内容，能确认尚未派发，不依赖 Agent 回显补回正文

#### Scenario: 提交事务失败
- **WHEN** 保存首条内容、附件归属或请求记录中的任一步失败
- **THEN** 不留下部分会话或部分消息，也不向 Agent 发出 prompt，页面同 ID 保留输入

### Requirement: 首条输入只展示一次且保持保真

系统 SHALL 为持久首条用户消息保留稳定身份，并与随后 Agent 的用户输入回显关联去重；输入顺序、结构化块及扩展内容 MUST 保持语义和协议要求的原文保真，不得重复展示或因回显缺席而丢失。未知字段与大整数 MUST NOT 因新增路径被截断或改写。

#### Scenario: 保存正文后收到 Agent 回显
- **WHEN** 首条消息已在历史可读，Agent 又回显同一输入且事件重复投递
- **THEN** 时间线仍只有一条对应用户消息，稳定身份不因回显或重放而改变

#### Scenario: Agent 不回显或扩展输入
- **WHEN** Agent 没有回显，或输入含协议允许的未知字段与精确数值
- **THEN** 已保存用户内容仍完整可读，新增保存路径没有把扩展结构变成普通文本

#### Scenario: 相同文字的第二条输入
- **WHEN** 第一轮结束后用户有意再次发送相同文字，或出现无法可靠关联的 Agent 用户输入事件
- **THEN** 第二次提交保留独立消息身份；无法关联的事件仍可见且保留来源，不按内容相同吞掉或覆盖已保存首条

### Requirement: 首次提交的幂等与并发互斥

同一提交 SHALL 使用稳定请求标识与输入指纹；重复请求返回原受理或终态，MUST NOT 第二次保存首条消息、建立正式会话或派发。不同请求竞争同一准备 ID 时 SHALL 最多接受一个首次提交。响应丢失 MUST 先核实原请求，不能另换 ID 新建。

#### Scenario: 保存响应丢失后刷新
- **WHEN** 服务已保存首条请求但响应丢失，原标签页刷新并查询
- **THEN** 找到原请求及同一正式会话，不再创建准备，不重复执行首条消息

#### Scenario: 并发双击与不同请求竞争
- **WHEN** 同一首条请求重复到达，或两个不同请求同时提交同一准备 ID
- **THEN** 正式会话和首条输入最多各有一份，后端派发最多一次；语义冲突明确拒绝

### Requirement: 持久派发边界决定故障后的重试

首条流程 SHALL 持久区分可证明尚未派发和可能已派发；跨越可能派发边界后结果无法确认时 MUST 进入明确的不确定状态，不自动重发或新建替代。保存后可证明未派发的失败 SHALL 保留内容并允许用户显式继续；继续不得新增一份首条消息或第二次受理原请求。

#### Scenario: 明确未派发时显式继续
- **WHEN** 首条已保存，但 Agent 建立或配置验证明确失败且从未派发 prompt，用户选择重试
- **THEN** 同一会话页保留首条消息，重新验证设置后只尝试第一次实际派发

#### Scenario: 可能已发出后崩溃
- **WHEN** 请求已进入可能向 Agent 发出的阶段，进程在保存结果前崩溃
- **THEN** 重启后原请求明确为不确定，不自动新建 Agent 身份来重发，用户内容仍保留

### Requirement: 附件完整可用才接受首条消息

首条带附件 SHALL 在点击发送后才向所属节点上传，全部附件完成且归属核验通过后才能持久接受整条消息；传输阶段不得要求提前创建正式会话。已持久首条引用的附件 SHALL 随消息保留，不能被未提交上传的闲置清理删掉。上传中断不得派发部分文本。

#### Scenario: 首条第二个附件上传失败
- **WHEN** 首条包含两个附件而第二个上传失败
- **THEN** 正式会话尚未保存，Agent 未收到任何 prompt，页面保留全部草稿与同一 ID

#### Scenario: 已保存首条长期等待重试
- **WHEN** 带附件首条已保存但尚未派发，停留超过未提交上传的清理期限
- **THEN** 首条附件仍可读且可用于明确的重试，不因暂时未执行而被清理

### Requirement: 兼容边界与旧会话不变

新流程 SHALL 只用于协商了会话准备能力的 Web/PWA 本机新建入口。旧会话 MUST NOT 因无恢复文件被自动改为准备或替换 Agent 身份；Zed、Node Link 及原 `session.create` 语义不变。未协商时 SHALL 明确禁用新入口，不偷偷退回旧创建路径。

#### Scenario: 旧空会话仍走旧恢复边界
- **WHEN** 打开历史上已创建但无法恢复的会话
- **THEN** 仍保留原身份并报告原恢复失败，不自动新建替代或把它当作合法准备

#### Scenario: 旧服务端与其他协议
- **WHEN** 新 Web 连接旧服务端，或 Zed/Node Link 使用原创建命令
- **THEN** 前者明确说明准备能力不可用，后者保持原创建与恢复合同

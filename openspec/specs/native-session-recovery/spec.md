# native-session-recovery Specification

## Purpose

定义原生会话引用、查看激活、执行接管、释放及异常恢复的区别。会话内容归 Harness 所有，平台仅记录管理和操作事实，不重灌本地历史，也不以查看激活冒充新输入或审批授权。

## Requirements

### Requirement: 原生身份不依赖启动入口
系统 SHALL 以显式配置的接入来源及原生会话标识协调同一会话，分开识别启动配置、接入来源及 Harness 连接代际；MUST 不仅因同一来源的程序安装路径、配置别名、启动入口或连接代际不同就创建可并行写入的第二个会话归属。启动配置须引用明确的接入来源，同一来源的多个入口共享执行协调、加载归属与容量计数。原生范围在当前合同中指该配置来源命名空间，不要求 ACP 提供物理存储或账户等价性证明，不自动判断不同来源是否访问相同物理存储，不增加厂商探测器或私有文件解析。

#### Scenario: 多个入口访问同一会话
- **WHEN** 两个安装入口或启动配置显式引用同一接入来源中的同一原生会话
- **THEN** 复用同一执行协调对象、加载归属和容量计数，不因入口不同绕过前台互斥

#### Scenario: 不同来源中的相同短标识
- **WHEN** 两个不同接入来源提供相同原生会话标识
- **THEN** 按各自来源区分会话、权限与缓存，不因标识相同自动合并；不承诺发现或协调这些来源背后相同的物理存储

#### Scenario: 接入来源未配置
- **WHEN** 新入口没有明确的接入来源引用
- **THEN** 要求补齐来源配置后再进行产品会话操作，不按显示名、正文或安装路径猜测归属；来源已配置时，不因缺少物理存储等价性证明而拒绝接入

### Requirement: 原生绑定与按需恢复
系统 SHALL 按 Harness 原生范围及会话标识通过原生接口（`session/resume` 或 `session/load`）恢复原会话上下文，成功后才接受依赖该恢复的新输入；MUST 不静默创建替代会话，也 MUST NOT 将平台展示快照文本重灌给 Harness 伪造上下文。原生会话无法恢复时，未过期的本地展示快照仍可按只读历史展示，但不得宣称会话可执行。

异常执行的恢复还须满足 `session-execution` 的“异常后重新准入”，原生恢复成功本身不证明旧执行已停止，也不改变其未知结果。

#### Scenario: 原生状态缺失
- **WHEN** 已知原生会话在 Harness 侧无法恢复（无论独立展示快照库中是否仍有未过期只读快照）
- **THEN** 新输入或恢复操作明确失败且不可继续派发，管理审计与未过期本地只读快照可按各自边界查阅并明确标注原生会话不可恢复

### Requirement: 查看允许激活进程
系统 SHALL 允许为查看启动或激活 Harness，并按实际接口需要加载会话，不要求进程只能只读运行；查看本身 MUST 不发送新输入、复用旧审批或授权工具副作用。实际加载遵循互斥、容量及生命周期管理。

#### Scenario: 查看需要加载
- **WHEN** 历史读取需要激活进程或加载原生会话
- **THEN** 节点管理激活与加载，实际加载如实显示并计入适用容量，不为读取伪造新执行轮次

#### Scenario: 查看触发权限请求
- **WHEN** 为查看激活的 Harness 发出权限请求
- **THEN** 关联真实的加载或恢复操作上下文并按有效审批流程处理，不把查看当作默认批准，也不为满足关联而伪造 Run

### Requirement: 释放确认与管理事实
系统 SHALL 在释放时阻止新相关执行，协调工作与审批，记录必要管理结果并释放资源；只有确认成功才显示空闲，MUST 不要求保存平台聊天历史，也不通过清缓存冒充释放完成。

#### Scenario: 关闭或管理记录失败
- **WHEN** 关闭未确认或必要管理事实无法可靠记录
- **THEN** 报告失败或未知并保留管理责任，不报告完全成功

#### Scenario: 存储失败但仍需安全关闭
- **WHEN** 节点仍能可靠验证操作者和当前资源归属，但管理存储故障使关闭审计或结果暂时无法保存
- **THEN** 按 session-execution 的故障安全控制规则尝试协调和关闭，不因无法写审计无限阻塞；实际关闭与记录失败分别表达，未完成持久化协调前不复用容量或恢复危险派发，不影响共享实例其他会话

### Requirement: 恢复与历史读取分离
系统 SHALL 分别管理与报告模型上下文恢复、当前连接实时内容、原生历史重放及本地展示快照状态；缺少标准重放不禁止实际可用的 `session/resume` 上下文恢复。支持 `session/resume` 的未加载会话在恢复时 SHALL 可直接衔接本地有效展示快照与后续新输出，同时如实区分“仅展示本地平台快照”与“已完成原生历史同步”；已通过打开时后台重放加载的会话可直接继续新输入，不保证工具、审批及子 Agent 从旧指令位置自动继续，也不重发输入。

#### Scenario: 无重放恢复
- **WHEN** 对端可 `session/resume` 恢复同一原生会话但不能重放历史
- **THEN** 允许恢复模型上下文并结合未过期的本地展示快照呈现平台既有历史与新输出，页面明确提示历史来自平台快照（不含外部直接变更）；若本地快照已过期清除则提示历史缺失

#### Scenario: 已准入连接选择无重放恢复
- **WHEN** 对端同时支持标准重放与 `session/resume`，此前打开时因容量满额等原因尚未完成重放同步，随后名额释放且主控端采用轻量 `session/resume` 配合本地展示快照恢复
- **THEN** 快速恢复可执行状态并衔接本地快照，不谎称已同步外部最新原生变更；用户也可随时手动重试原生重放校准

#### Scenario: 恢复重放旧消息
- **WHEN** 原生重放或恢复再次发出旧条目
- **THEN** 按可靠来源与读取代际更新视图及本地快照（前缀一致时前端无闪烁补齐新增轮次），不能证明连续性则整代替换并说明限制，不按文字去重或当作新回复

### Requirement: 恢复和重放保留有效接入参数
系统 SHALL 对重复恢复及重放使用有可信来源的、已授权有效 Client 配置及工作根，不将空值或省略误作保持不变。外部目标参数未知时说明影响，不能在查看历史时悄悄清空配置；无法取得足够授权参数时限制该路径，不因此禁用无关能力。

#### Scenario: 已有非空或未知 Client 配置
- **WHEN** 查看或翻页需再次 resume，已有 Client MCP 或额外工作根非空或未知
- **THEN** 复用已授权有效参数；未知时明确限制或取得该操作所需授权，不默发空集合覆盖

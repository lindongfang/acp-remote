## Purpose

定义个人节点与客户端之间的持久信任及撤销行为，使多个客户端可以安全管理同一节点。区分网络连接、平台身份和运行时权限审批，防止已撤销连接继续操作，并确保信任状态持久化失败时不虚报授权成功。

## Requirements

### Requirement: 本机命令启动 Web 配对

节点 SHALL 由本机用户通过 `device pair` 命令启动限时配对，由 Web 客户端输入配对码认领；本 change 的运行与验收范围为 Windows 节点和 Web，移动端扫码后续实现。

#### Scenario: Web 输入配对码
- **WHEN** 本机用户启动配对且 Web 客户端输入有效配对码
- **THEN** Web 客户端可以认领该配对，不能仅因持有码而直接取得管理权限

### Requirement: 本机确认后才建立信任

节点 MUST 在客户端认领后向发起配对的本机用户展示客户端名称与公钥指纹，只有明确批准才建立信任；拒绝、默认回车或取消不得建立信任。未经认证的网络请求不能代替本机批准。

#### Scenario: 本机批准
- **WHEN** 本机用户核对认领客户端并明确批准
- **THEN** 节点为该公钥可靠保存信任后通知客户端完成配对，客户端仍需完成后续身份认证

#### Scenario: 本机拒绝或取消
- **WHEN** 用户拒绝、在确认提示直接回车或取消 `device pair`
- **THEN** 本次配对失效，未批准客户端不能访问管理接口

### Requirement: 配对限时且不可转授

节点 MUST 拒绝过期、取消、已拒绝及重启前的配对材料；同一次配对只能绑定一个客户端公钥，重复认领不能更换已绑定身份。错误尝试和配对状态查询 MUST 受有界资源与速率限制。

#### Scenario: 多个 Web 客户端并发认领
- **WHEN** 不同 Web 客户端使用同一次配对码并发认领
- **THEN** 最多绑定一个客户端公钥，其他认领被拒绝，本机确认只针对已绑定的身份

#### Scenario: 重放失效配对
- **WHEN** 客户端使用过期、取消或重启前材料尝试认领或取回配对资料
- **THEN** 节点拒绝，不恢复旧配对或建立额外客户端信任

#### Scenario: 配对码猜测
- **WHEN** 未认证来源持续提交错误配对码或查询请求
- **THEN** 节点限制其尝试与资源使用，不暴露配对秘密、客户端资料或管理数据

### Requirement: 配对过程核实目标节点

客户端 MUST 将配对绑定到实际访问来源及节点身份，验证节点持有对应身份私钥；节点身份或来源不一致时不能保存信任或自动改绑。配对码中的秘密不得进入 URL 查询参数、访问日志或第三方请求。

#### Scenario: 节点身份被替换
- **WHEN** 客户端取得的配对响应与配对材料绑定的节点身份不一致或身份证明无效
- **THEN** 客户端停止配对，提示失败，不保存替代节点信任

### Requirement: 身份必须经过验证

节点 MUST 验证客户端对其身份凭据的持有，不能仅凭客户端自报名称、公钥或客户端标识授予管理访问；未完成信任建立的身份不能使用管理接口。

已保存有效身份的 Web 客户端 SHALL 在临时断线或节点恢复后自动复用该身份重新连接，无需用户手动重试认证或重新配对。新连接 MUST 重新验证身份证明；身份被拒绝或撤销时 MUST 停止旧身份重试并直接进入配对页，以新密钥重新配对且仍需本机批准。节点身份不匹配或本地密钥损坏时 MUST 保留错误，不自动替换身份。结果未知的管理操作 MUST NOT 因重连而自动重发。

#### Scenario: 冒用已知客户端标识
- **WHEN** 连接声称使用可信客户端标识但不能提供有效身份证明
- **THEN** 节点拒绝访问，不将该连接视为可信客户端

#### Scenario: 验证有效身份
- **WHEN** 客户端提交与有效信任记录对应的有效身份证明
- **THEN** 节点将本次操作归属于对应客户端身份，允许其访问授权范围内的管理入口

### Requirement: 信任建立必须可靠保存

节点 SHALL 为通过信任建立流程的客户端保存稳定标识、公钥、显示名称与信任状态；只有信任记录可靠保存后才能报告建立成功。配对授权与后续认证的凭据 MUST 区分用途，不能将一次配对授权作为永久共享身份。

#### Scenario: 保存成功
- **WHEN** 客户端通过信任建立流程且记录保存成功
- **THEN** 节点返回稳定客户端标识，该信任在重启后仍可用于身份验证

#### Scenario: 保存失败
- **WHEN** 信任记录无法可靠保存
- **THEN** 节点报告建立失败，不向客户端宣称已获得持久管理权限

### Requirement: 可信客户端可查看和撤销信任

节点 SHALL 允许有效可信客户端列出客户端标识、显示名称及信任状态，并撤销指定客户端；撤销事实可靠提交后才能确认成功。重复撤销 MUST 保持撤销结果，不重新授予信任。

#### Scenario: 撤销其他客户端
- **WHEN** 有效可信客户端撤销另一个已登记客户端且提交成功
- **THEN** 目标被标为撤销，后续认证与管理操作被拒绝

#### Scenario: 撤销保存失败
- **WHEN** 撤销无法可靠提交
- **THEN** 节点明确报告失败，不声称撤销已经完成

#### Scenario: 重复撤销
- **WHEN** 有效可信客户端再次撤销已撤销身份
- **THEN** 节点保持已撤销状态，不产生重新启用的副作用

### Requirement: 撤销覆盖已有连接

节点 MUST 将已提交撤销应用于目标客户端已有连接及订阅，拒绝撤销之后受理的新操作并停止继续交付受保护数据。已经受理的动作不因撤销被声称已回滚；撤销也不等于取消运行时 Harness 任务。

#### Scenario: 长连接被撤销
- **WHEN** 客户端维持管理订阅期间其身份被成功撤销
- **THEN** 节点使该订阅失效，不继续交付受保护数据，并拒绝该客户端的新管理操作

#### Scenario: 撤销与操作并发
- **WHEN** 撤销与该客户端的管理操作并发
- **THEN** 节点依据明确的受理顺序判断该操作是否已受理，不允许撤销提交后新受理该身份的操作
- **AND** 不对先前已受理操作的副作用作未经证实的回滚承诺

### Requirement: 信任不代替运行时审批

节点 MUST 将客户端管理身份与 Harness 操作审批分开；建立客户端信任不能自动批准未来工具调用，也不能让失效审批恢复有效。

#### Scenario: 后续模块请求权限
- **WHEN** 已认证客户端访问需要运行时审批的后续能力
- **THEN** 客户端身份只用于判定操作者资格，不作为该操作已经获得审批的证据

### Requirement: 认证材料不得作为管理数据返回

节点 MUST 对客户端列表、认证失败、信任管理及相关审计保护秘密凭据；管理查询只能返回必要身份资料，不返回私钥、认证秘密或配对秘密。

#### Scenario: 查询客户端列表
- **WHEN** 可信客户端读取客户端管理资料
- **THEN** 返回结果包含必要身份与信任状态，不包含任何私钥或秘密凭据

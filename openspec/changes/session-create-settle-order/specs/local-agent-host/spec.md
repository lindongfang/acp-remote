# Spec Delta

## MODIFIED Requirements

### Requirement: 失败路径的明确结果与 turn 不设超时

系统 SHALL 对启动失败、短请求超时、Agent 异常退出、非法 JSON 以及乱序或未知请求标识的响应给出明确失败结果与可区分原因；`session/prompt` 所代表的 turn MUST NOT 因超时被终止，只有显式取消或进程退出才结束它。

这些失败原因是「Agent 侧有没有可能已经产生会话」这一判定的输入：进程未能启动（spawn 失败）、Agent 对会话建立请求明确返回错误，以及请求未发出即失败，都属于**可证明未产生会话**；短请求超时与请求发出后连接断开属于**无法证明**。该区分 MUST 可被调用方观察到。

#### Scenario: 启动超时失败并回收

- **WHEN** `initialize` 在 10 s 内没有完成
- **THEN** 返回启动超时错误并回收该进程树，不留下可继续写入的会话

#### Scenario: 进程无法启动时返回明确不可用

- **WHEN** 会话创建或打开指向一个程序不存在或不可执行的 Agent profile，spawn 本身失败
- **THEN** 请求以明确的不可用类错误（区别于请求非法与凭据不可用）失败，不启动任何进程，也不留下可复用的运行时或会话映射；同一 Agent 的后续重试不受本次失败影响

#### Scenario: 可证明与无法证明可区分

- **WHEN** 一次会话建立分别以「spawn 失败」与「短请求超时」结束
- **THEN** 调用方能区分这两类失败：前者属于可证明未产生会话，后者属于无法证明

#### Scenario: turn 不因超时被杀

- **WHEN** 一个 prompt 长时间未完成但 Agent 仍在正常产出更新
- **THEN** 系统不终止该 turn 也不杀掉进程，只有显式取消或进程退出才结束它

#### Scenario: 异常退出成为明确事件

- **WHEN** Agent 进程在 turn 进行中退出
- **THEN** 该会话收到明确的失败或退出事件，后续写入被拒绝，其进程与子进程被回收

#### Scenario: 未知响应标识不被误配

- **WHEN** 子进程返回一个与任何未完成请求都不匹配的请求标识，或返回无法解析的 JSON
- **THEN** 该响应被记为明确的协议错误，不解析为任何会话的结果，也不使既有未完成请求被错误完成

### Requirement: 会话创建时暴露 ACP 会话标识

会话创建成功后，后端 SHALL 向 core 暴露本次建立的 ACP 会话标识，使 core 能把它持久化到该会话；后端 MUST NOT 自行读写存储，也 MUST NOT 在未取得标识时编造占位值。会话的创建时工作目录 MUST 取 core 已解析并传给后端的 workspace 解析结果。该标识、创建时工作目录与目录归属 SHALL 由 core 在后端**成功返回之后**、与本次命令的终态在**同一次提交**里写入会话行；受理阶段 MUST NOT 写入会话行。

#### Scenario: 创建成功暴露 ACP 会话标识

- **WHEN** core 以一个已解析的 workspace 调用后端创建 owned 会话，且 `session/new` 成功返回
- **THEN** 后端暴露本次 ACP 会话标识，core 在同一次提交里把它与已解析的规范化目录、目录归属一起写入该会话行并写下终态

#### Scenario: 未取得标识时不编造取值

- **WHEN** 会话创建未成功完成 `session/new`（启动失败、超时或 Agent 返回错误）
- **THEN** 后端不产生任何 ACP 会话标识取值，core 不写入占位标识；该会话不被当作可恢复会话，且在可证明未产生会话时连会话行都不落盘

#### Scenario: 可证明未建立时以 failed 终结

- **WHEN** 会话创建未能完成 `session/new`，且失败属于可证明未产生会话（进程未能启动、Agent 明确返回错误、请求未发出）
- **THEN** core 不写入会话行，该命令以 `failed` 终结且零会话行

#### Scenario: 无法证明时以 uncertain 终结

- **WHEN** 会话创建以无法证明的失败结束（例如短请求超时）
- **THEN** core 不写占位标识、不落会话行，该命令以 `uncertain` 终结并标记可能已到达 Agent

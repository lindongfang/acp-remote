- 成功、失败、取消均关闭本次拥有的连接、读取句柄、快照、订阅、任务和完整进程树，释放临时锁、端口及本操作持有的租约，只清理自有专用副本并保留脱敏证据；不删除用户实际数据库、原生会话、密钥或配置。
- 正式结果另存 testing/runs/deliver-native-session-import/，按 plan 的报告分工记录版本、OS/工具/依赖、逐 ID 状态、命令、实际断言与执行数量、证据及问题闭环。同版本、同范围且环境符合要求的有效证据可复用，不要求用户重复操作；必需项失败、未执行或待确认均不能视为验收通过。归档前按能力同步长期 suite 并保留 ID。

## Cases

### NI-001 真实构建及类型检查

- 用例级别：L1
- 操作步骤：在仓库根目录按 README 和 package.json 执行 npm run check、npm run build:rust；另执行 openspec.cmd validate deliver-native-session-import --strict 与 git diff --check，分开记录规划检查和产品构建结果。核对构建目标是否实际包含本 change 的节点与 Web 实现。
- 预期结果：真实编译、Web 构建和类型检查成功，检查覆盖本 change 的实际目标；现有上游开发实现通过构建不证明本 change 通过。缺对应目标或入口记受阻/未执行，规划校验不能代替编译或功能验收。

### NI-002 静态合同和供应链检查

- 用例级别：L2
- 操作步骤：在仓库根目录执行 npm run check、openspec.cmd validate deliver-native-session-import --strict、git diff --check、npm audit --audit-level=high；对实际 BASE/HEAD 执行 npm run lint:commits -- --from BASE --to HEAD --verbose，按 .github/workflows/ci.yml 的 secrets 作业执行密钥扫描。核对本 change 的协议合同、依赖审查和锁文件是否纳入实际入口，缺专用合同入口记未执行。
- 预期结果：真实适用检查按工程配置执行；开发工具审计不等于产品供应链通过，无专用结构门禁，reviewer人工核对精确引用和覆盖。

### NI-003 领域边界及异常状态

- 用例级别：L3
- 操作步骤：构造同原生范围同ID/不同范围同短ID、同请求重试/异内容、无列表但可按ID恢复/两者皆无、无历史但可证明新输出边界、无可靠边界混流；验证不按内容/哈希/时间去重，附件字节复用不合并消息身份。
- 预期结果：逐一断言spec中正常、异常、取消、重复与边界结果；状态/引用不串会话，不把未知写成成功，不弱化协议语义；局部模拟不替代真实验收。

### NI-004 事务资源与并发协作

- 用例级别：L4
- 操作步骤：并发接管争唯一绑定和容量预留；在恢复成功后数据库提交失败、导入暂存批次失败、取消和资源关闭失败处注入故障；断言未发布预留不变可见会话、所有权保留且安全清理，授权视图不泄漏其他身份。
- 预期结果：跨组件失败无假成功或半提交，幂等请求不重复副作用；取消和关闭有所有者，失败仍保留管理责任；模拟边界和实际断言另存报告。

### NI-010 独立安全及交互检视

- 用例级别：L5
- 操作步骤：由不继承 coder 对话的独立 reviewer 使用源码、配置、依赖审查、脱敏日志、浏览器和协议探针，核对设计权威与引用、页面状态及失败提示、敏感信息/权限边界、依赖维护许可与 Windows 支持、证据脱敏和限制展示；以实际 DOM、响应及执行证据核对行为。缺工具、环境、权限或入口记受阻/未执行，不自动转为用户手测。

- 用例级别：L6

# 交付外部原生会话显式接管

状态：2026-10-30 RP-001 重放兼容修订；实现暂停。当前 specs 已同步最新重放准入，详细合同及完整验收计划仍待重基准。此前审查只适用于原快照，不授权恢复实现。

## Why

节点接入已交付，本能力尚未完成产品验收。为按重设计建立可独立验收的交付闭环，需要交付外部原生会话显式接管，避免仅交付孤立模块而没有可观察结果。

## Success Criteria

DC-001 最新确认：接管按显式接入来源及原生会话ID协调，同来源多个入口共享加载、执行及名额；不同来源分别管理，不要求或承诺自动判断物理存储是否相同，不新增厂商身份探测。下方早期跨入口身份要求仅在同一显式来源内适用。

### 本 change 的成功判据

- SC1：复用基础发现与读取，处理原生会话显式执行接管、唯一归属、重新校验、占用与加载失败；不导入历史。
- SC2：验证原生来源和实际能力、外部更新后重新读取、缓存失效及历史不可用边界；外部操作不伪造为平台命令或审批。
- SC3：按新规格完成独立用例修订、方案检视、真实实现和交付验收；本次仅规格修订，尚未执行这些检查。

## What Changes

- 复用基础发现与读取，处理原生会话显式执行接管、唯一归属、重新校验、占用与加载失败；不导入历史。
- 取消平台独立聊天历史持久化，原生及当前连接能力分别呈现；平台管理数据的可靠记录和审批安全约束继续有效。
- 同步 design 和对应 specs；原 tests/plan/tasks 标为待重基准，旧记录只适用于旧快照。未恢复实现、提交、推送或发布。

## Impact

- 依赖：基础原生身份、加载/恢复端口及 [deliver-session-capacity](../deliver-session-capacity/proposal.md)；子树专属场景按已接入能力另验，不作为基础接管硬前置。显式接管加载也必须遵守主会话容量上限；跨 change 依赖由[能力地图](../../../docs/REBUILD_CAPABILITY_MAP.md)维护，CLI不会自动强制执行。

- 尚未新增运行依赖、实现文件、数据库迁移或长期规格；本提案不预选具体库和后端。

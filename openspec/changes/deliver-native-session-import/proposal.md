# 交付外部原生会话显式接管

## Why

节点接入与基础原生会话浏览已交付，外部原生会话的显式执行接管、唯一归属与冲突协调尚未实现。为按重设计建立可独立验收的交付闭环，需要支持安全的显式执行接管而不复制或导入历史正文。

## Success Criteria

### 用户原始要求

> acp-remote还是不保存会话数据，以harness 数据为准
> 只提供原生删除，不保留隐藏功能。
> 查看时允许激活进程，不限制只读；查看本身不发送新输入或批准工具。

- **DC-001 确认**：接管按显式接入来源及原生会话 ID 协调，同来源多个入口共享加载、执行及名额；不同来源分别管理，不自动判断物理存储是否相同，不新增厂商身份探测。

### 硬约束与非目标

- 以[重设计 §2.2、§4.3–§4.4、§6.3、§7.3](../../../docs/HARNESS_CONTROL_PLANE_REDESIGN.md)与 `openspec/specs/` 长期规格为依据；采用新架构、不兼容旧系统。
- 外部 CLI 与平台同时写同一原生会话的一致性不在承诺范围；不导入聊天历史落盘。
- 首期限定 Windows 节点 + Web，App 后续；当前处于需求与设计定义阶段，`tests/plan/tasks` 在正式启动本变更时基于真实代码树生成。

### 本 change 的成功判据

- SC1：复用基础发现与读取，处理原生会话显式执行接管、唯一归属、重新校验、占用与加载失败；不导入历史正文。
- SC2：验证原生来源和实际能力、外部更新后重新读取、缓存失效及历史不可用边界；外部操作不伪造为平台命令或审批。
- SC3：正式开工时基于当前规格生成 `tests/plan/tasks` 并通过编码前门禁、真实实现与集成交付验收。

## What Changes

- 实现外部原生会话显式执行接管、同来源跨入口唯一执行绑定、重放准入核验及占用/加载失败收敛。
- 子目标接管纳入主树容量与资源所有权协调，不建立导入批次或永久正文档案。

## Capabilities

### New Capabilities

- `native-session-import`：原生会话显式执行接管及重新校验边界。对应文件为 `specs/native-session-import/spec.md`。

### Modified Capabilities

（无；开工前若需调整已归档长期能力，按实际精确路径补充增量规格。）

## Impact

- 依赖：基础原生身份/加载端口及 [deliver-session-capacity](../deliver-session-capacity/proposal.md)，跨 change 依赖见[能力地图](../../../docs/REBUILD_CAPABILITY_MAP.md)。
- 影响范围：执行所有权登记、原生恢复协调、容量预留接线与 Web 接管交互；具体写范围在开工阶段 `plan.md` 定义。

## Exploration

- **显式接入来源身份（DC-001）**：按显式接入来源 + 原生 `sessionId` 判定同来源身份，同来源多入口共享加载与执行归属；不同来源分别管理，不新增厂商探测或私有目录解析。
- **重放准入与不导入正文（Q-001 / RP-001）**：目录 ID 保留 `native-session-import`，职责已收敛为显式执行接管而非复制历史；接管前核对重放与恢复能力，无重放时按规格拒绝接管或明确限制。
- **主树容量协调（SR-003）**：子目标接管遵循 `session-resource-policy` 主树归属规则，无法可靠建立主树管理时拒绝实际加载。
- **术语与 ADR 复核**：复用 [领域术语表](../../GLOSSARY.md) 中原生范围、接入来源与主执行树定义，无新增独立 ADR。

# 交付外部原生会话显式纳管

## Why

节点接入与基础原生会话浏览已交付，外部 CLI 已创建原生会话的显式平台执行纳管、同来源唯一归属与冲突协调尚未实现。为按重设计建立可独立验收的交付闭环，需要支持安全的外部原生会话显式平台纳管而不导入厂商私有历史文件，并与客户端级单主会话控制权接管（`session-control-takeover`）及受管展示快照库（`session-transcript-cache`）协同对齐。

## Success Criteria

### 用户原始要求

> acp-remote还是不保存会话数据，以harness 数据为准
> 只提供原生删除，不保留隐藏功能。
> 查看时允许激活进程，不限制只读；查看本身不发送新输入或批准工具。

- **DC-001 确认**：平台纳管按显式接入来源及原生会话 ID 协调，同来源多个入口共享加载、执行及名额；不同来源分别管理，不自动判断物理存储是否相同，不新增厂商身份探测。
- **CT-001 / TC-001 对齐（2026-11-19）**：明确区分“平台对外部原生会话的执行纳管（`native-session-import`）”与“单个受信客户端对主会话的写控制权接管（`session-control-takeover`）”；纳管后若客户端需发起输入或修改操作，须同时持有该主会话的客户端控制权；标准重放同步可更新独立展示快照库，但绝不解析厂商私有文件或拼回文本冒充模型上下文。

### 硬约束与非目标

- 以[重设计 §2.2、§4.3–§4.4、§6.3、§7.3](../../../docs/architecture/overview.md)与 `openspec/specs/` 长期规格为依据；采用新架构、不兼容旧系统。
- 外部 CLI 与平台同时写同一原生会话的一致性不在承诺范围；不拷贝厂商私有会话文件，不回灌展示快照充当模型上下文。
- 首期限定 Windows 节点 + Web，App 后续；当前处于需求与设计定义阶段，`tests/plan/tasks` 在正式启动本变更时基于真实代码树生成。

### 本 change 的成功判据

- SC1：复用基础发现与读取，处理外部原生会话显式平台纳管、同来源唯一归属、重新校验、外部占用检测与加载失败；不解析或导入厂商私有历史文件。
- SC2：验证原生来源和实际能力、外部更新后通过标准路径重新同步展示快照与缓存失效边界，并与单会话客户端控制权接管衔接；外部操作不伪造为平台命令或审批。
- SC3：正式开工时基于当前规格生成 `tests/plan/tasks` 并通过编码前门禁、真实实现与集成交付验收。

## What Changes

- 实现外部原生会话显式平台执行纳管、同来源跨入口唯一执行绑定、重放/恢复核验及外部占用/加载失败收敛。
- 对齐单会话客户端控制权接管（纳管同时或后续需执行写操作时按主会话授予/校验客户端控制权）与展示快照库代际刷新。
- 子目标纳管纳入主树容量、主树控制权继承与资源所有权协调，不建立私有文件导入批次或永久正文档案。

### Modified Capabilities

（无；开工前若需调整已归档长期能力，按实际精确路径补充增量规格。）

## Impact

- 依赖：基础原生身份/加载端口、[deliver-session-capacity](../archive/2026-11-19-deliver-session-capacity/proposal.md)、[deliver-session-control-takeover](../archive/2026-11-20-deliver-session-control-takeover/proposal.md) 及 [deliver-session-transcript-cache](../deliver-session-transcript-cache/proposal.md)，跨 change 依赖见[能力地图](../../../docs/architecture/capability-map.md)。
- 影响范围：平台执行所有权登记、原生恢复与展示快照代际协调、容量预留与客户端控制权接线及 Web 纳管交互；具体写范围在开工阶段 `plan.md` 定义。

## Exploration

- **显式接入来源身份（DC-001）**：按显式接入来源 + 原生 `sessionId` 判定同来源身份，同来源多入口共享加载与执行归属；不同来源分别管理，不新增厂商探测或私有目录解析。
- **平台纳管与客户端控制权正交分离（CT-001）**：目录 ID 保留 `native-session-import`，用于表达“节点平台将外部 CLI 创建的原生会话纳入平台执行归属管理”，与多设备之间的“单会话客户端写控制权接管（`session-control-takeover`）”明确区分。发起纳管并准备继续执行的受信客户端可一并获得主会话初始控制权；只读浏览不要求平台纳管或客户端控制权接管。
- **混合恢复与不导入私有文件（Q-001 / TC-001）**：支持标准重放时以最新原生历史刷新独立展示快照库新代际；仅有 `session/resume` 无重放时允许纳管恢复并如实标记此前外部历史缺口，绝不读取厂商私有 `.jsonl` 文件或将缓存拼回 Prompt。
- **主树容量协调（SR-003）**：子目标纳管遵循 `session-resource-policy` 主树归属规则，无法可靠建立主树管理时拒绝实际加载。
- **术语与 ADR 复核**：复用 [领域术语表](../../GLOSSARY.md) 中接入来源、原生会话身份、展示快照库与会话控制权接管定义，无新增独立 ADR。

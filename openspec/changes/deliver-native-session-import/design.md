# Design

## Context

动机与用户确认要求见 [proposal.md](proposal.md)，行为规则见 `specs/native-session-import/spec.md` 与 `openspec/specs/` 长期规格。本变更当前处于需求与设计定义态，具体施工工作包与验收用例在正式开工时基于真实代码树建立。

## Goals / Non-Goals

**Goals:**
- 将外部已存在的原生会话安全纳入平台唯一执行所有权与主树容量管理，支持重新校验与异常收敛。

**Non-Goals:**
- 复制或持久化导入原生聊天历史；承诺外部 CLI 与平台双写同一会话时的一致性；跨不同显式接入来源自动合并物理存储身份。

## Decisions

### 1. 职责与权威

基础会话发现与浏览已由通用闭环提供；本变更保留目录标识，负责显式执行接管与所有权绑定，不复制历史正文。

### 2. 来源能力与接口

按显式接入来源 + 原生会话标识判定同来源跨入口身份，协调唯一平台执行绑定与加载名额；普通无加载浏览不要求执行绑定。子目标接管复用 `session-resource-policy` 主树归属规则：先确认可靠主树所有者并申请或复用树名额，再调用加载；根已删除或归属不可验证时拒绝实际加载。

### 3. 状态与失败

重新接管先核对重放与恢复准入，再校验来源并协调重放，隔离历史内容与接管后的新输出；无重放时拒绝接管，不提供当前连接降级冒充完整上下文。

### 4. 资源与安全

具备可靠外部占用检测时拒绝不安全加载；无检测时明确提示并发写风险。加载后中途失败仍由原所有者负责清理并确认无残留资源后才释放名额，未知副作用不自动重发。

## Risks / Trade-offs

- [外部进程并发修改同一原生会话] → 明确检测能力边界与风险提示，重读时刷新代际，不伪造平台操作记录。
- [接管加载半途失败占额] → 复用统一资源关闭与容量账本协调，确认释放前保留名额。

## Migration Plan

开工前核对当时管理存储的执行所有权表与容量 schema，增量扩展接管状态字段时不破坏已有身份、信任、管理记录与原生数据。

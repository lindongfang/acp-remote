## Context

见 proposal.md。依赖三款真实能力记录、可靠身份、独立子浏览及deliver-session-capacity的加载名额端口；目前均待实施，须按上游最终原生范围和容量定义重基准。显式接管与正常平台恢复不同，不开放后台目录扫描。

## Goals / Non-Goals

只接管用户选择的原生会话。不解析私有文件替代公开能力，不承诺外部CLI与平台同时写入的一致性，不按文字去重。

## Decisions

### 1. 能力分支与用户确认对象

适配器分别声明列表、按ID恢复、历史读取、占用检测和重放标识的真实能力。Web展示原生范围、会话标识、可证明的目录与历史可用性；无列表但可验证按ID恢复时允许显式输入ID，二者皆无则拒绝。对象选择不是自动接管；客户端发有请求ID的接管命令后才占资源。ZCode路径继续以真实探测证据为门禁，不套用其他Harness列表方法。

### 2. 绑定唯一约束与操作事务

沿上游原生范围ID+原生会话ID建立唯一约束，接管Command先创建带操作所有权的绑定预留，禁止第二个命令创建并发实例。按容量端口申请加载名额并执行原生验证，成功后原子发布会话与绑定；失败记录结果，协调资源关闭后撤销未发布预留。原生恢复成功而数据库失败时保留操作日志和实例所有权以完成关闭/人工处理，不向客户端谎称接管成功。重复同请求返回原结果，不再次导入。

### 3. 历史导入暂存

公开历史在导入批次暂存，保留源会话、源条目身份、轮次边界与顺序；加载代际将重放和实时消息隔离，全部边界可证明才事务发布。可靠源ID映射避免同消息重复，字节哈希只用于附件复用。缺少可靠分界时不启用混流导入路径；允许原生恢复但明确“旧历史不可用”的前提是仍可证明新输出边界。不能证明则阻断接管。导入失败不发布半套“完整历史”，保留失败诊断及缺失范围。

### 4. 占用与授权

读取列表、接管、导入附件与原始结构均复核可信身份。占用可靠时关闭接管入口并返回可识别错误；没有占用探测时Web明确并发写入不受保证，不能通过本地锁宣称阻止外部CLI。平台释放便于用户切换原生客户端，后续不自动同步外部新增历史。

## Risks / Trade-offs

- [原生范围误识别] → 复用上游包含安装/配置根与身份上下文的范围，不能只用会话短ID。
- [导入量很大] → 暂存分批处理且缓存有界，发布前核对完整性；失败不泄漏临时附件。
- [外部并发写入无法检测] → 明示能力限制，不能建立强一致承诺。

## Migration Plan

新增绑定唯一约束与导入批次。先在隔离原生根逐款验证，不能对用户实际会话执行验收。回滚停用接管入口并关闭未发布实例，保留已经成功接管的平台历史和绑定；不删除或修改原生存储。

## Implementation Gate

各款真实列表/按ID/历史/占用路径、混流边界及失败清理须验证；没有支持证据的分支保持禁用，当前未实测。

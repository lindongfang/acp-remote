# Design

## Context

动机与用户确认要求见 [proposal.md](proposal.md)，行为规则见 `specs/native-session-import/spec.md` 与 `openspec/specs/` 长期规格。本变更当前处于需求与设计定义态，具体施工工作包与验收用例在正式开工时基于真实代码树建立。

## Goals / Non-Goals

**Goals:**
- 将外部已存在的原生会话安全纳入平台唯一执行所有权与主树容量管理，并与单会话客户端控制权（`session-control-takeover`）及受管展示快照库（`session-transcript-cache`）无缝衔接。

**Non-Goals:**
- 解析或复制厂商私有会话文件；把展示快照拼回文本冒充模型上下文；承诺外部 CLI 与平台双写同一会话时的一致性；跨不同显式接入来源自动合并物理存储身份。

## Decisions

### 1. 职责、术语与正交边界

基础会话发现与浏览已由通用闭环提供；本变更保留目录标识 `native-session-import`，负责**平台对外部原生会话的显式执行纳管与所有权绑定**。这与客户端级 `session-control-takeover` 正交：前者解决“平台是否纳管该外部原生会话的执行归属”，后者解决“多台已配对设备中哪一台当前执掌该主会话的写控制权”。客户端显式发起纳管并准备继续交互时，可在主会话加载成功后同步取得初始客户端控制权；纯只读查看不建立执行纳管，也不隐式授予写控制权。

### 2. 来源能力与接口

按显式接入来源 + 原生会话标识判定同来源跨入口身份，协调唯一平台执行绑定与 50 主会话名额；命中有效展示快照库的冷查看不激活子进程、不建立执行绑定。子目标纳管复用 `session-resource-policy` 主树归属与 `session-control-takeover` 根树控制继承规则：先确认可靠主树所有者并申请或复用树名额，再调用加载；根已删除或归属不可验证时拒绝实际加载。

### 3. 混合恢复、快照同步与失败收敛

重新纳管先核对原生身份与当前恢复能力：若支持标准历史重放（`session/load`），协调重放并在独立展示快照库中建立新快照代际，隔离外部历史与纳管后的新输出；若仅支持无重放恢复（如仅 `session/resume`），允许建立平台执行归属与节点队列，并在展示视图/快照中明确标记外部未观测历史缺口，绝不伪造完整前文或读取私有文件。

### 4. 资源与安全

具备可靠外部占用检测时拒绝不安全纳管；无检测时明确提示并发写风险。加载后中途失败仍由原所有者负责清理并确认无残留资源后才释放名额与活跃期控制权，未知副作用不自动重发。

## Risks / Trade-offs

- [外部进程并发修改同一原生会话] → 明确检测能力边界与风险提示，显式重读时刷新展示快照代际，不伪造平台操作记录。
- [纳管加载半途失败占额] → 复用统一资源关闭、控制权归零与容量账本协调，确认释放前保留名额。

## Migration Plan

开工前核对当时核心控制面存储的执行所有权表、运行期控制权端口与独立展示快照库接口，增量扩展平台纳管状态字段时不破坏已有身份、信任、管理记录与原生数据。

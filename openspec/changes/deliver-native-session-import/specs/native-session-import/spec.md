## Purpose

定义显式接管原生会话继续执行的边界。基础发现与读取由首个闭环提供，本能力复用原生身份及内容，不再导入聊天历史；保留目录 ID 作为规划标识，浏览和执行加载分别管理。

## ADDED Requirements

### Requirement: 浏览与执行接管分离
系统 SHALL 复用基础闭环原生列表与读取；查看不等于新输入或审批授权，需要执行或查看所需实际加载时建立受节点管理资源，MUST 不以复制历史作为接管条件。

#### Scenario: 选择已有原生会话
- **WHEN** 用户选择原生会话查看或继续输入
- **THEN** 查看按读取和激活能力进行，继续输入前完成所需恢复，不创建聊天副本

#### Scenario: 无原生列表能力
- **WHEN** 无列表但有已验证按标识接管
- **THEN** 明确限制，仅开放按标识路径，不扫描私有目录伪造能力

### Requirement: 范围内唯一执行绑定
系统 SHALL 在显式接入来源和原生会话标识内协调唯一平台执行绑定；并发接管 MUST 不建立同来源同目标的第二个并行平台写入者，多个查看视图可引用同一原生身份。

原生范围在此指显式接入来源，多入口身份判定遵循 native-session-recovery 的原生身份规则；启动配置引用来源，不将启动配置或程序安装路径自动作为独立来源。不承诺判断不同来源背后的物理存储是否相同，不要求物理存储证明或厂商探测作为基础接管门槛。

直接接管子目标须遵循 session-resource-policy 的“子目标加载归属主执行树”，不因根尚未打开而独立加载或绕过容量；无法建立可靠主树归属时仅保留无需加载且有权的查询能力。

#### Scenario: 并发接管同一原生会话
- **WHEN** 两客户端同时加载或接管同一原生会话
- **THEN** 至多建立一次原生加载归属，另一返回已有资源授权视图或明确冲突

#### Scenario: 不同启动配置并发接管
- **WHEN** 两个不同配置入口引用同一接入来源及原生会话标识，并同时请求接管
- **THEN** 按同一原生身份协调唯一归属，不重复占用加载名额或建立第二个平台写入者

### Requirement: 接管重新读取原生状态
系统 SHALL 接管前核验原生身份、上下文恢复及当前实际能力；有重放时读取可用历史，无重放时允许当前连接模式并明显提示历史不完整及缓存丢失后无法补回。MUST 不以缺重放拒绝实际可用接管，不永久保存输出或增加厂商专用读取器。

#### Scenario: 无标准重放仍可接管
- **WHEN** 原生上下文可恢复但没有标准历史重放
- **THEN** 核验接管自身条件后允许接管及节点队列，不补造前文、不建立第二个写入者

#### Scenario: 外部操作后重新接管
- **WHEN** 释放后外部继续同一原生会话再返回平台
- **THEN** 按同一原生身份恢复，有历史则读取，无历史则提示限制，不将外部操作记为平台输入

### Requirement: 外部占用与接管失败
系统 SHALL 可靠检测到占用时阻止不安全接管，无检测时明确限制；失败 MUST 不显示成功，不承诺平台与外部并发写入一致性。

#### Scenario: 检测到外部写入占用
- **WHEN** 可靠检测会话外部占用
- **THEN** 拒绝接管并说明，不强制改写原生状态

#### Scenario: 加载后后续步骤失败
- **WHEN** 加载已发生但接管后续失败
- **THEN** 保留所有权并关闭或报告失败，不遗留无人管理资源，不删除原生历史

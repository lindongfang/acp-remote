## Purpose

定义平台显式纳管外部原生会话以继续执行的边界（与多设备间的单会话客户端写控制权接管 `session-control-takeover` 区分）。基础发现与读取由首个闭环提供，本能力复用原生身份及协议恢复能力，不导入厂商私有会话文件；浏览和平台执行纳管分别管理。

## ADDED Requirements

### Requirement: 浏览与平台执行纳管分离
系统 SHALL 复用基础闭环原生列表、离线展示快照与标准读取；查看不等于新输入、审批授权或隐式获取单会话写控制权，需要平台执行或无快照查看所需实际加载时建立受节点管理资源，MUST 不以复制厂商私有历史文件作为纳管条件。客户端在平台纳管后向该会话提交输入或修改操作，仍 MUST 遵循 `session-control-takeover` 持有所属主会话的客户端控制权。

#### Scenario: 选择已有外部原生会话查看或纳管继续
- **WHEN** 用户选择外部原生会话仅查看，或显式发起纳管并接管控制权以继续输入
- **THEN** 纯查看优先命中有效本地展示快照或按标准只读重放加载且保持未接管只读状态；显式纳管继续输入时完成所需原生恢复并授予/校验主会话客户端控制权，不创建私有文件副本

#### Scenario: 无原生列表能力
- **WHEN** 无列表但有已验证按标识纳管能力
- **THEN** 明确限制，仅开放按标识路径，不扫描私有目录伪造能力

### Requirement: 范围内唯一执行绑定
系统 SHALL 在显式接入来源和原生会话标识内协调唯一平台执行绑定；并发纳管 MUST 不建立同来源同目标的第二个并行平台写入进程，多个客户端查看视图可共享引用同一原生身份，而会话内写操作互斥由所属主会话的客户端控制权协调。

原生范围在此指显式接入来源，多入口身份判定遵循 native-session-recovery 的原生身份规则；启动配置引用来源，不将启动配置或程序安装路径自动作为独立来源。不承诺判断不同来源背后的物理存储是否相同，不要求物理存储证明或厂商探测作为基础纳管门槛。

直接纳管子目标须遵循 session-resource-policy 的“子目标加载归属主执行树”及 session-control-takeover 的根树控制继承规则，不因根尚未打开而独立加载或绕过容量；无法建立可靠主树归属时仅保留无需加载且有权的查询能力。

#### Scenario: 并发纳管加载同一外部原生会话
- **WHEN** 两台受信客户端同时请求加载或纳管同一外部原生会话
- **THEN** 节点至多建立一次原生加载归属，并按单会话客户端控制权规则保持至多一个写控制端，另一客户端获得只读观察视图或明确冲突提示

#### Scenario: 不同启动配置并发纳管
- **WHEN** 两个不同配置入口引用同一接入来源及原生会话标识，并同时请求平台纳管
- **THEN** 按同一原生身份协调唯一平台归属，不重复占用 50 主会话加载名额或建立第二个平台写入进程

### Requirement: 纳管重新校验原生状态与快照同步
系统 SHALL 在平台纳管前核验原生身份、上下文恢复及当前实际能力；有标准重放时读取可用历史并刷新独立展示快照库的新代际，无标准重放但支持原生上下文恢复（如 `session/resume`）时允许纳管并保留已有受管展示快照（同时明确标记潜在外部未观测内容缺口）。系统 MUST 不以缺标准重放拒绝实际可用的原生恢复纳管，不建立无期限永久正文档案，不拼回快照文本冒充模型上下文，也不增加厂商专用读取器。

#### Scenario: 无标准重放但支持原生上下文恢复时纳管
- **WHEN** 原生上下文可通过 `session/resume` 恢复但没有标准历史重放接口
- **THEN** 核验纳管条件后允许建立平台执行归属并在持有客户端控制权时接收新输入，展示视图保留已知快照并明确标记外部未同步边界，不补造前文、不建立第二个平台写入进程

#### Scenario: 释放回外部 CLI 操作后重新纳管
- **WHEN** 会话资源释放后用户在外部原生 CLI 继续同一原生会话，随后再次返回平台显式纳管
- **THEN** 按同一原生身份恢复，支持标准重放时建立新快照代际覆盖旧快照以反映外部增量，不支持重放时如实标记外部变更缺口，不将外部 CLI 操作伪造为平台 Run 或审批记录

### Requirement: 外部占用与纳管失败
系统 SHALL 在可靠检测到外部写入占用时阻止不安全纳管，无检测能力时明确限制；失败 MUST 不显示成功，不承诺平台与外部 CLI 并发双写一致性。

#### Scenario: 检测到外部写入占用
- **WHEN** 可靠检测到目标原生会话正被外部进程写入占用
- **THEN** 拒绝平台纳管并说明原因，不强制改写原生状态

#### Scenario: 加载后后续步骤失败
- **WHEN** 原生加载已发生但纳管后续初始化或核验失败
- **THEN** 保留协调所有权直至确认关闭释放资源并归零运行期控制权，不遗留无人管理资源，不删除原生历史

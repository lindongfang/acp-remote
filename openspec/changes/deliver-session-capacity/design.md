## Decisions

### 1. 单一容量协调器

容量按显式接入来源及原生会话ID计数，同来源同目标经多个启动配置访问不重复占名额。不同来源不自动推断物理存储等价性；来源配置沿用 native-session-recovery，不新增厂商身份探测。通用策略先对已满足活动与资源安全条件的接入独立交付；活动可由可靠执行树接口提供，不要求先可浏览子历史。当前必要事实失效继续保护，未提供隐藏范围不单独阻止发起请求，但不阻止其他已满足条件目标运行策略。

容量计数适用于所有实际加载的受管理主树，不以自动回收能力已就绪为前提。harness-management 分别呈现前台、后台及子工作覆盖、权限请求、关闭与自动回收可用范围，本 change 判定当前目标能否安全回收。前台 idle 与已知工作结束只支持节点请求决策，不代表完整内部活动证明。未提供的后台/子范围如实说明，已知活动继续保护；关闭能力不足或必要事实失效时保留计数并说明限制。

节点应用服务拥有容量账本，记录主会话的reserved/loaded/releasing内部事实及操作ID。已加载+预留名额不超过默认50；预留在实际加载前原子获得，加载失败确认资源不存在后归还。选择节点单协调器而非客户端计数或每适配器限额，避免多客户端、多个实例重复分配。子会话通过可靠关系归属主树，不额外占50名额但仍受实际资源监控。此内部账本不新增页面状态。

平台只对主会话分配名额和发起自动回收。子会话的创建、执行、结束和清理由所属父会话及 Harness 管理；平台只观察上游暴露的执行树活动事实以保护父资源，不为子会话建立单独的超时扫描、淘汰队列或关闭策略。释放主会话仍由上游资源所有者协调其所属资源，共享实例中的其他主会话不得受影响。

直接子目标加载按规格“子目标加载归属主执行树”处理：先证明主树身份、资源管理及释放路径，原子预留或复用该树唯一名额，再沿父会话及 Harness 管理路径加载。无需为此读取根正文，但树只要存在所属加载或在途预留资源，就不能返还名额；页面仍按实际资源事实呈现，不伪报根进程或根正文已经加载。同树多个子目标与父目标共享所有者和名额。根已删除、关系不可验证或不能建立主树管理时，拒绝实际加载，仅允许无需加载且有权的原生查询；失败后的预留只在确认无所属资源时撤销，不猜测提升子目标为新根。

### 2. 回收资格与时钟

每主树跟踪最近有效活动、进入安全可释放时刻及活动代际；回收起点为两者较晚者。资格要求当前前台空闲、无非终态Run或待派发输入、无有效审批、无已知后台及子活动，并有当前原生关闭能力、可靠主树归属和必要管理状态。未提供隐藏覆盖不单独阻止请求；已知活动必须收到可靠结束事实才解除。使用单调时钟计算当前进程30分钟，墙钟仅审计。重启后先协调实际资源，无法延续单调时间则从重新证明安全时开始计时，宁可晚回收不提前中断。

没有平台 Run 的实时原生前台、后台及子活动只要已被节点接收，同样参与保护；协议缺字段不清除此前已知活动。快照与历史重放不复活旧审批或旧执行。重连使当前前台与时间依据失效，重新建立后计时。平台不下载或修改上游，不用私有存储探测补足隐藏范围。

DC-001：将节点本次实际接收的标准重放计入最近有效活动，并增加活动代际；按当前单调时间刷新，不按旧消息时间回填。持续重放允许持续延后超时回收；纯页面查看、心跳或只读缓存翻页不刷新。重放中的旧工具或审批状态只属于历史视图，不改变真实执行、审批及后台工作保护。满额候选沿用更新后的活动排序，最近重放不使安全目标免于容量淘汰，也不要求候选已等满30分钟。

待授权保护是资格门槛，不是授权请求的30分钟到期策略：任何有效待授权请求存在时同时禁止超时回收和容量淘汰。Agent取消授权后只撤销该请求的保护并增加活动/资格代际，重新检查是否仍有其他有效授权、非终态Run、父/子前台或后台工作；取消授权不等于prompt结束，更不等于资源释放。仍有保护事实则继续保留；全部保护解除且安全释放可证明时恢复两类候选资格。沿用既有安全空闲计时规则，从进入安全可回收状态后计满30分钟才触发超时回收，不把之前等待授权的时间抵扣；容量满额选择则不必等待30分钟。此处区分候选资格与实际关闭，不能在授权取消事件处理器中直接关闭会话。

### 3. 调度与竞态

每30秒扫描可回收树，仅在达到30分钟时启动释放；边界验收通过可控时钟不依赖长时间睡眠。满额请求不等扫描、不等30分钟，按最近有效活动升序、主会话ID作为同值稳定次序选择候选。锁定候选命令通道后复核变化的类别：新增真实工作、有效审批或安全释放条件失效时撤销候选；重放仅刷新活动时间及代际，不直接撤销安全资格。超时回收遇重放后重新计满30分钟，容量回收则重新校验候选排序，目标仍是应选安全候选时可以继续释放，不能仅因收到重放而反复撤销唯一安全候选。沿上游管理记录/释放流程协调在途读取，不为绕过已知活动保护额外发送取消命令；释放过程仍允许取消及必需审批协调，不接受新的普通输入。

平台命令准入与最后复核防止节点已知输入、审批及活动被遗漏；该同步不宣称排除 Harness 自发或外部活动。使用已协商的普通关闭能力，允许 Harness 按自身语义执行；不要求条件关闭接口，不保证尚未报告或发送后才产生的工作不会被中断。关闭请求发出后跟踪实际响应，错误及未知保额，不以成功响应倒推此前全树空闲。

### 4. 释放确认再转移名额

释放完成证据来自会话级适配器关闭和所有者资源确认，连接丢失不能替代。成功后原子返还原名额，新加载再竞争原子预留；并发者可能先取得该名额，原请求此时明确返回容量已满，不连续关闭更多会话；失败维持占用并返回明确错误。共享实例仅释放会话资源，不能为争取名额杀掉其他会话。无候选直接返回容量已满，不排队；同一请求重复沿Command返回原结果，避免重复回收。

自动回收受限时显式释放仍沿 native-session-recovery 协调实际工作及审批，并允许返回失败或未知；其授权及取消工作语义与“自动回收不选择已知忙碌目标”分别处理。全部名额受保护或证据不足时拒绝新增加载，向有权用户说明限制和可选的显式释放入口，不承诺自动排空资源。此处能力说明不是新增页面会话生命周期状态。

管理存储故障时，显式安全关闭按 session-execution 保持收敛路径；即使 Harness 已返回关闭确认，只要必要结果或账本协调未可靠提交，就保留名额并分别呈现实际关闭和记录故障。存储恢复后重新核验实际资源，完成持久化协调才返还或转移名额，不以临时内存记账恢复新危险加载；正常回收仍先满足 RB-001 的请求资格和发送前复核。

## Risks / Trade-offs

- [活动暴露不足导致长期占用] → 保守保护并明确限制，可由用户显式释放；不能用超时推断工作结束。
- [名额约束不等于内存上限] → 不宣称50会话代表硬件负载能力，真实并发验收记录实例数与资源消耗。
- [释放失败占住容量] → 保留所有权和错误供处理，不以假成功修正计数。

## Migration Plan

启用策略前从真实资源重建账本并验证主树归属；未知资源保持保护。默认50与30分钟不得被测试参数覆盖产品默认。回滚禁用自动扫描和容量触发回收，保留已运行资源由显式释放管理；不改变历史和原生存储。

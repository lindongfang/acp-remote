# 交付安全资源回收与容量协调

状态：待实现文档齐备；旧快照独立方案结论见 review.md，本轮资源保护修订需另行检视，产品未实施；上游真实交付和能力探测门禁仍需满足。

## Why

当前分支没有产品实现。为按重设计建立可独立验收的交付闭环，需要交付安全资源回收与容量协调，避免仅交付孤立模块而没有可观察结果。

## Success Criteria

### 用户原始要求

> 当前项目需要基于HARNESS_CONTROL_PLANE_REDESIGN重新实现，在进入spec流程分解需求之前，还有什么需要确认的吗

> 同意，那就先建立整体能力地图及依赖关系，再按可独立验收的闭环拆成多个 change。

> 其他九项也补齐文档到待实现状态吧

> 待授权的会话不受30分钟超时影响，也不参与满额淘汰。如果授权状态取消了，则需要纳入了。

### 硬约束与非目标

- 以[重设计 §7.4、§10.2.11](../../../docs/HARNESS_CONTROL_PLANE_REDESIGN.md)为本闭环依据；采用新架构、不兼容旧系统，其他适用的全局约束仍然有效。
- 前序 change 负责正常显式释放及进程树清理，本 change 增加自动策略；前序版本不作为具备完整资源策略的正式交付。
- 本轮补齐待实现文档，不开始产品实现，不将规划或模拟结果写成已提供能力。首期限定 Windows 节点 + Web，App 后续。

### 本 change 的成功判据（待详细规格转成场景）

- SC1：落实30分钟无活动回收、默认50个已加载主会话名额和容量满时最久未活动优先回收。
- SC2：验证长任务、有效审批、子 Agent 与需保留后台活动保护；查看不保活；并发分配不超限，释放成功才返还名额，无候选明确拒绝且不排队。
- SC4：待授权同时排除于超时及满额淘汰；授权取消仅解除对应保护并重评资格，仍有工作则不回收；平台只管理主会话名额及自动回收，不单独干预子会话生命周期。
- SC3：建立真实构建及适用检查，完成独立用例/方案检视和交付验收；记录未验证项及实质限制。

## What Changes

- 明确待授权保护及解除后的资格重评；取消授权不直接触发回收，超时与满额继续按各自规则处理。父/子任务仍执行即保护主会话，静默时长不能证明后台已结束。
- 50个名额只计主会话，子会话不设置独立超时或淘汰；容量满从排除待授权与执行中工作的安全候选中选择静默最久者。
- 落实30分钟无活动回收、默认50个已加载主会话名额和容量满时最久未活动优先回收。
- 同步负责上述行为的设计、规范、测试、配置与操作文档；不复活旧系统合同。

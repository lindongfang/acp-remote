## Purpose

定义已加载主会话的容量协调、无活动回收及执行树保护规则，使节点在有限资源下仍保持长任务、有效审批和后台工作的所有权，并将关闭请求、释放完成及名额返还明确区分，避免并发超限或虚假空闲。

## ADDED Requirements

### Requirement: 按已接入能力独立启用通用策略
系统 SHALL 对满足通用资源所有权及安全判断条件的接入独立提供容量和回收策略，不以所有计划中的 Harness 均已接入或完整子树浏览交付为条件；执行树活动可来自已验证的活动接口，不要求先能浏览完整子历史。MUST 不因未接入其他厂商而禁用已满足条件的通用策略，无法可靠判断安全释放的目标仍保守保护。

#### Scenario: 仅一款 Harness 已可用
- **WHEN** Codex 的资源归属及活动判断已满足条件，而 ZCode 或 DeepSeek 尚未接入
- **THEN** 可独立验证并启用 Codex 的容量协调及安全回收，不等待其他厂商验收通过

#### Scenario: 子活动无法确认
- **WHEN** 某目标缺少可靠子活动或后台工作状态
- **THEN** 保留容量计数并排除自动回收，不通过猜测空闲绕过保护；其他可判断目标继续按策略管理

### Requirement: 容量计数与自动回收能力分开
系统 SHALL 对每个当前接入分别说明容量计数、前台观测、主子会话及后台活动覆盖、有效审批、原生安全关闭的可用范围，并在操作时判断目标是否具备自动回收条件。具备历史读取或前台完成信号不等于具备自动回收能力。自动回收须有当前有效依据证明所属执行树没有需保留的工作或有效审批，并有可安全隔离该树的释放路径；该保证须覆盖检查至实际关闭期间的新工作竞态，不能只依赖平台锁排除 Agent 自发或外部活动。MUST 不以 Run 全部结束、前台 idle、静默30分钟、已观察工具均结束或一次历史重放完成代替完整证据，也不先调用会取消工作的关闭接口再以成功证明此前可安全回收。

活动接口或当前已验证的协议及运行约束能够证明相关活动不存在时均可作为依据，不要求厂商提供额外私有探测接口。无法证明全部相关范围或无法防止关闭窗口内新增工作时，明确自动回收受限并保护该目标，容量计数及其他已满足条件的会话操作继续有效；MUST 不因此改变其他能力准入、增加厂商探测器或关闭其他会话。

#### Scenario: 有重放和前台空闲但后台未知
- **WHEN** 接入满足当前操作条件，全部平台 Run 已结束且原生前台 idle，但无法确认后台及子工作是否仍存在
- **THEN** 仍计入50个主会话上限，并说明后台范围未知、自动回收受限；不因30分钟或满额关闭该目标，不将此限制误报为整个接入不支持

#### Scenario: 活动覆盖与安全关闭均有依据
- **WHEN** 当前能力及运行约束可证明整棵主树无受保护工作，且可防止检查至释放期间新工作进入并隔离关闭该树
- **THEN** 可按30分钟及满额策略评估和释放，记录所用依据及实际结果；不要求其他厂商具备相同能力，不因缺少某程序版本报告新增白名单门槛

#### Scenario: 检查与关闭之间可能自发开始工作
- **WHEN** 平台已冻结自身新输入，但无法排除 Agent 或外部客户端在安全检查之后、关闭生效之前开始新的相关工作
- **THEN** 不将平台冻结当作原生排他保证，拒绝本次自动回收并说明竞态边界，不用无条件关闭取消新工作来完成淘汰

### Requirement: 自动回收受限时保持可管理
系统 SHALL 在自动回收证据缺失、失效或当前范围不完整时保留资源所有者及名额，向有权客户端说明限制和显式释放入口；显式释放按 native-session-recovery 协调工作与审批并确认资源收敛，不承诺必然成功。MUST 不把自动回收受限解释为允许超限、自动排队或强制停止工作，也不保证未知目标最终会自行进入回收候选。重连、能力及运行约束变化后重新判断，旧证据不能证明新代际安全。

#### Scenario: 满额目标均无法自动回收
- **WHEN** 50个名额均被受保护或缺少完整安全证据的主树占用
- **THEN** 拒绝新的加载，说明容量已满及无安全候选，有权用户可显式选择释放；不强杀、不超限、不以重新计时掩盖限制

#### Scenario: 重连后失去活动或安全关闭依据
- **WHEN** 旧连接曾可自动回收，但重连后活动覆盖或安全关闭依据不再成立
- **THEN** 重新保护相关目标并保留名额，说明失去的依据；其他能力仍按当前准入判断，不用旧报告或过去的 idle 状态自动关闭

### Requirement: 默认五十个主会话名额
系统 SHALL 默认最多同时加载50个主会话，创建加载与恢复都原子分配名额；仅查询而未加载会话资源时不占名额；查看导致实际加载时同样分配名额，已加载不重复计数，子会话归属主执行树而不单独计数。

系统 MUST 仅以主会话为容量分配与自动回收对象，子会话生命周期交由所属父会话及 Harness 管理，不单独对其设置名额、超时或淘汰动作。

#### Scenario: 最后一个名额并发分配
- **WHEN** 已加载49个主会话且两个客户端同时请求加载
- **THEN** 至多一个直接取得剩余名额，不超过50个

#### Scenario: 子会话不单独管理
- **WHEN** 已加载的主会话创建或结束多个子会话
- **THEN** 主会话名额不随子会话数量变化，平台不单独对这些子会话执行容量淘汰或超时回收

### Requirement: 子目标加载归属主执行树
系统 SHALL 在直接查看或接管子目标需要实际加载资源时，先验证其主执行树身份和可管理的资源归属，并在加载前为该主执行树原子取得或复用唯一名额；根会话正文未打开不等于该树不占名额。最后一项所属资源确认释放前 MUST 保留树的名额及所有者，不单独淘汰子会话。根目标已删除、关联不可靠或无法建立受管理的主树资源归属时，拒绝需要加载的操作，不将子目标猜测为新根；不加载会话资源的有权原生查询仍可按自身能力提供。

#### Scenario: 直接查看尚未加载的子目标
- **WHEN** 用户直接打开子目标且原生读取需要加载，所属主执行树尚无加载资源或预留名额
- **THEN** 先验证主树归属并申请一个主树名额，再加载所需资源；同树多个子目标共享该名额，满额按既有回收或拒绝规则处理

#### Scenario: 根删除或归属不可验证
- **WHEN** 子目标仍可按标识发现，但根已删除、关系不可读或主树资源无法受节点管理
- **THEN** 不加载子目标、不猜测新根、不零名额接管；若原生支持无需加载的读取，则可在有权范围内展示并说明加载限制

#### Scenario: 子目标加载失败或仍未释放
- **WHEN** 已为主树预留名额，但子目标加载失败或释放后仍无法确认其资源已收敛
- **THEN** 节点继续拥有相关资源及名额，只有确认该树没有任何所属加载或在途预留资源时才返还名额，不影响共享实例的其他主树

### Requirement: 执行树活动保护
系统 SHALL 在主会话或子会话有前台执行、有效审批、需保留后台工作，或无法可靠证明安全释放时排除自动回收；共享实例其他会话 MUST 不受单会话回收影响。

#### Scenario: 长任务无输出
- **WHEN** 工具运行超过30分钟但无新文字
- **THEN** 不自动取消或回收该主会话

#### Scenario: 仅子会话仍在运行
- **WHEN** 主会话没有新消息且已超过30分钟，但所属子会话仍在前台或后台执行
- **THEN** 保护该主会话，超时回收及满额淘汰均不得选中它，也不为腾名额取消子任务

### Requirement: 待授权保护随状态解除
系统 SHALL 将仍有有效待授权请求的主会话同时排除于30分钟超时回收和容量满额淘汰；授权状态取消后仅解除对应授权保护并重新评估资格，MUST 不将授权取消直接等同于资源释放。仍有其他有效授权、未结束执行、后台工作或运行中的子会话时继续保护；全部保护条件解除后按既有超时及容量规则处理。

#### Scenario: 待授权超过三十分钟且池满
- **WHEN** 主会话等待有效授权已超过30分钟且新建请求遇到50个名额已满
- **THEN** 该会话既不因超时回收，也不作为满额淘汰候选；没有其他安全候选时明确返回容量已满

#### Scenario: 授权取消后仍有工作
- **WHEN** Agent 已取消待授权状态，但该主会话仍有未结束执行、后台任务、运行中的子会话或另一有效授权请求
- **THEN** 仅移除已取消请求的保护，主会话仍不进入可回收候选，不提前结束执行或回收资源

#### Scenario: 授权取消后重新纳入判断
- **WHEN** 最后一个有效待授权状态取消，且主会话的其他保护条件均已解除并可安全释放
- **THEN** 主会话恢复超时回收及容量淘汰资格；超时沿用进入安全可回收状态后30分钟规则，满额时可按静默时长选择，不因取消事件本身立即释放

### Requirement: 安全空闲三十分钟回收
系统 SHALL 在执行树全部工作结束且可安全释放后开始无活动计时，连续30分钟无有效会话活动时发起回收；输入、输出、可见思考、工具进展、子活动及节点当前实际接收的标准历史重放刷新计时。重放按本次接收时刻计时，不使用旧消息的历史时间；持续重放允许不断延后超时回收。单纯打开页面、心跳或只读取已有缓存的翻页 MUST 不保活，查看或翻页实际触发重放时按重放活动处理。

重放刷新计时 MUST 不被视为新的平台执行、有效审批或原生后台工作，不仅因最近发生重放就排除满额安全淘汰；历史中的旧执行或审批状态不恢复为当前活动保护。

#### Scenario: 工作结束后重新计时
- **WHEN** 长任务在最后文字出现很久后结束
- **THEN** 从进入可回收状态起重新计时，不立即回收

#### Scenario: 页面持续查看
- **WHEN** 页面持续查看已安全空闲30分钟的会话，期间只有心跳或缓存翻页，没有实际重放或其他有效活动
- **THEN** 仍发起回收，确认成功后显示空闲，历史能否重读依 Harness 实际读取能力说明

#### Scenario: 历史重放刷新计时
- **WHEN** 可安全释放的会话因刷新或翻页实际接收历史重放
- **THEN** 按最近一次实际重放活动重新计算30分钟；继续收到重放可继续延后，但不产生新执行或复活旧审批

#### Scenario: 最近重放仍可容量淘汰
- **WHEN** 需要新增主会话名额且容量已满，候选最近发生过重放但无执行、有效审批或需保留后台工作且可安全释放
- **THEN** 该目标仍属于可回收候选，按更新后的最近有效活动参与排序，不因重放获得任务保护或要求等满30分钟

### Requirement: 满额回收与拒绝
系统 SHALL 在满额时优先选择可安全释放且最久无活动的主会话，关闭前复核活动并记录必要管理事实，确认释放成功才返还名额；无候选或释放失败 MUST 明确拒绝，不强制取消、不自动排队、不静默超限。

#### Scenario: 候选获得新活动
- **WHEN** 候选选定后、关闭前出现新输入或有效审批
- **THEN** 重新判断候选，不关闭已不安全的会话

#### Scenario: 释放失败
- **WHEN** 候选关闭请求失败或资源状态未知
- **THEN** 不返还其名额，不加载超限目标，反馈失败

#### Scenario: 安全关闭成功但管理结果未提交
- **WHEN** 故障安全控制已确认目标资源关闭，但管理存储仍无法提交其关闭结果或完成账本协调
- **THEN** 分开报告已观察关闭和管理记录故障，保留名额及核验责任；持久化协调成功前不转移名额加载其他目标，不为满足容量要求伪造记录成功

#### Scenario: 最静默会话受到保护
- **WHEN** 容量已满，静默最久的会话仍待授权或有自身/子会话后台工作，而其他安全候选静默时间较短
- **THEN** 跳过受保护会话，从其余安全主会话中选择静默最久者，候选无需已静默30分钟

### Requirement: 查看激活不绕过资源策略
系统 SHALL 管理查看所需进程激活与会话加载；查看请求本身不作为执行工作，实际接收的重放按“安全空闲三十分钟回收”刷新计时，实际工作及审批仍受保护。MUST 不把辅助进程启动直接等同加载一个主会话，也不将实际加载伪装成零名额查询。

#### Scenario: 查看引起实际加载
- **WHEN** 查看需要加载尚未加载的主会话
- **THEN** 申请名额，满额沿原安全回收或拒绝规则，不发送新输入，不绕过待授权保护

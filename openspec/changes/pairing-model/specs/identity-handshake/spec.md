# Spec Delta

## MODIFIED Requirements

### Requirement: 认证输出只包含事实与凭据状态

系统 SHALL 只输出两类结果：已验证事实（即调用主体，不足以授权）与明确的失败分类。系统 MUST NOT 向业务层传递「已授权」标志，也 MUST NOT 代替业务层判定命令级权限。凭据状态 SHALL 可区分「有效」「范围缩减」「已撤销」「未知」，其中「已撤销」「未知」MUST NOT 降级为权限不足；「范围缩减」在存在授权集合的方向上（节点）仍然成立，设备方向不再有授权集合，因此也不会出现该状态。

#### Scenario: 已撤销设备与权限不足可区分

- **WHEN** 一台已撤销的设备完成证明校验
- **THEN** 结果为已撤销状态，而不是权限不足，以便上层映射到不同的错误与连接行为

#### Scenario: 范围缩减提示需要重新认证

- **WHEN** 一次认证后该对端（节点方向）的 grant 集合被缩减
- **THEN** 结果为范围缩减状态，上层据此主动关闭连接并要求重新认证

#### Scenario: 事实本身不携带授权结论

- **WHEN** 业务层收到一次成功的认证结果
- **THEN** 该结果只包含主体标识，以及在存在授权集合的方向上的 grant 集合；设备方向不携带任何授权集合，且任何方向都不含「允许此命令」的判定

### Requirement: transcript 与仓库固定向量保持一致

系统 SHALL 按登记表（domain 与字段 tag 的唯一机器来源）装配签名与 HMAC 输入，使每个已登记 domain 的固定向量都能被逐字节重算；系统 MUST 拒绝畸形输入（非法长度、非曲线点、非规范 base64url、tag 乱序或重复、零值签名分量），且拒绝 MUST NOT 引发任何信任变更。登记表 MUST NOT 再包含配对短验证码相关的 domain。

#### Scenario: 固定向量被逐字节重算

- **WHEN** 用登记表的字段集合与固定向量的输入重算全部已登记 domain 的 transcript
- **THEN** transcript 字节、其摘要与 HMAC 值都与向量期望逐字节相等

#### Scenario: 畸形输入被拒绝且无副作用

- **WHEN** 提交 33 字节压缩点公钥、非曲线点、带填充 base64url 或 `r`/`s` 为零的签名
- **THEN** 每次都以结构或校验失败拒绝，且不创建、修改或撤销任何信任记录

# Spec Delta

## ADDED Requirements

### Requirement: 导出授权的展开与拒绝

系统 SHALL 把跨节点导出授权展开为它直接列出的命令名集合（其展开结果同时用于导出侧的 scope 表达）；展开 MUST 在进入 wire 与写入记录之前完成。系统 SHALL 拒绝任何未知或拼错的导出授权名称，MUST NOT 忽略未知项，也 MUST NOT 部分展开后继续。设备方向不再有任何授权词汇（无授权包、无配对预设）。

#### Scenario: 导出授权展开为命令名

- **WHEN** 一个 Export 或 Import 以导出授权名称请求授权
- **THEN** 结果是这些名称所列命令名的集合，每一项都等于一个命令名，且不出现重复项

#### Scenario: 拼错的导出授权被拒

- **WHEN** 请求中包含一个未登记的导出授权名称
- **THEN** 展开失败，且没有任何授权被写入

## REMOVED Requirements

### Requirement: 授权词汇展开为命令级 scope

**Reason**：设备配对不再授予授权（`pairing-model` 删除设备权限层），因此「设备授权包」与「配对预设」这两类输入词汇连同它们的展开规则一起消失；剩下的只有跨节点导出授权。

**Migration**：见本 delta 的新增要求「导出授权的展开与拒绝」；设备方向不再接受任何授权词汇，提交即被拒绝。

### Requirement: 未知名称显式拒绝

**Reason**：该要求的三类输入里有两类（授权包、配对预设）随设备权限层一并消失，原文与剩余词汇不再对应。

**Migration**：未知导出授权名称的拒绝并入新增要求「导出授权的展开与拒绝」。

## Context

事件日志已按 Agent stdout 顺序写入，问题在消息聚合和消息页丢失该顺序。当前同通道跨整轮分组，且消息页以创建时间和随机消息标识排序。用户已批准完整链路修改及不兼容旧版本。

## Goals / Non-Goals

目标：真实交替、同毫秒确定顺序、工具卡原位更新、实时与持久读取一致、远程来源保序、旧历史不编造。
非目标：推测 Agent 内部生成时间；改变认证、安全或 Access 持久化规则；支持旧版本排序行为。

## Decisions

1. 同一 ACP 流的连续输出片段拥有独立 Remote 消息标识；相邻同消息与同通道 delta 追加，其他可见条目中断片段。ACP 原文始终保真保留，外部消息标识不改写。
2. `MessageRecord` 增加 `first_sequence` 与 `first_origin_sequence`，均为可缺席的纯类型序号。首次消息片段与事件同事务固化两域序号，后续 delta、completed 不移动起点。用户持久输入使用相同机制。
3. wire 消息增加 `sequence`（十进制字符串）：owned 使用会话域，Node Link 与 imported 使用来源域。缺席只表示旧历史证据不足。`before` 可携带 `sequence`，保留时间和消息标识定位旧历史。严格顺序主键为已知标记、序号、旧时间及标识；未知旧历史独立前置稳定分区，页面明确提示。
4. 消息页与结构化历史继续独立读取，但客户端以各自最早位置协调续页，在任一资源尚未追平时不宣称当前时间线完整。页面合并必须使用同一权威序号域，不按时钟重排已知条目。
5. Node Link 投影显式选择来源域，Access 不建立本地替代位置。两域数值可不同但各自单调。
6. 每组连续 Agent 输出显示一次时间。已有卡片生命周期更新使用首次事件位置。

## Migration Plan

版本化 SQLite migration 新增两域起始位置；从现存首条有效事件尽力恢复。缺少首条 delta 或原始片段边界无法证明的旧记录不伪造完整顺序。正文始终保留。新增消息的起点不依赖将来会清理的事件行。升级在事务中执行且重复启动无副作用；旧二进制对新文件格式拒绝启动。部署不自动修改当前运行数据库，先在测试副本验证。

## Risks / Trade-offs

片段增加消息条数，分页保持按用户输入轮组的既有外观而不截断已知顺序。实现时必须覆盖纯媒体、权限交互和工具穿插；不可仅按 thought/reply 切换。旧记录可能正文可读但顺序未知，必须显式提示。不能只保存 firstSequence 然后仍跨工具聚合正文。

## Open Questions

无待用户决策事项。内部实现按上述不变量细化，并以回归测试验证。

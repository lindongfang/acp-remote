# Proposal

## Why

用户在已有 Codex 会话发送纯文字时遇到 `protocol.schema_invalid`；代码已证实旧会话缺少活动端点会被泛化为此错误，但本次失败尚无完整复现证据。需要让进入会话主动恢复原 Agent 上下文，并为多设备查看、资源保留与回收建立明确生命周期，避免历史可读却无法继续交流。

## What Changes

- 进入或返回可见的本机会话页面立即激活；只查阅历史也保活。激活复用原会话，回收后及 Daemon 重启后均保持上下文连续，绝不以新建或重发历史冒充恢复。
- 多设备共享节点统一管理的资源与查看状态；最后一个查看者离开且无任务、排队输入、待处理请求后，开始完整保留期，默认 30 分钟，可配置或显式关闭。断网以连接关闭或查看租约超时识别离开。
- **BREAKING（显式协商的本机生命周期合同）**：页面主状态采用“空闲 / 活跃 / 待处理”；活跃包含任务执行及资源保留，不等同于正在生成。保持任务状态独立；无任务的活跃会话可以发送。恢复中和恢复失败独立呈现。
- 节点共享会话运行资源上限，创建/恢复预占名额；候选默认值 50，必须经 10/25/50 档实测再决定采用，不新增同时执行任务数限制。达到容量优先提前回收无人查看、无任务、无待处理请求且最久未使用的会话；否则明确拒绝激活、历史仍可读。
- 逐会话回收不影响其他会话，全部会话可回收后才停止共享 Agent 进程。必须验证真实资源释放，不能以端点标记关闭充数。
- 恢复中历史可读、发送暂禁用；失败保留草稿、明确原因、允许重试，不误报为 schema 错误。切页不取消已开始的恢复，迟到结果不能切回旧页面。

非目标：Node Link 导入会话生命周期、历史会话数量限制、任务并发上限、自动重试旧任务、云服务、认证放宽。保持单会话至多一个执行中的任务及既有排队规则。

## Capabilities

### New Capabilities

- `local-session-lifecycle`：本机会话激活、上下文连续性、查看保活、保留期、容量与安全回收。

### Modified Capabilities

- `session-activity`：本机协商后的活跃展示与原有任务三态分离，防止静默重新解释已有 wire 状态。
- `local-agent-host`：恢复与资源释放的真实能力门控，逐会话隔离及共享进程清理。
- `sync-command-handling`：增加经协商的本机激活与查看控制入口，遵守命令终态、认证及错误分类。
- `pwa-web-client`：可见会话激活/保活、恢复状态与输入门控、切页和多设备行为。

## Impact

涉及 core 的生命周期模型与端口、agent-host、server::sync、storage-sqlite 的 owned 命令/事件复用及必要迁移、app 配置/装配、前端协议/同步/平台可见性/feature/UI。保持 crate 依赖方向，不让 core 依赖 runtime 或协议。

实施时同步 Sync schema/fixture、命令/feature/错误登记、ACP 兼容矩阵和相关测试；同步 INITIAL_DESIGN、MODULE_ARCHITECTURE、FRONTEND_DESIGN、SYNC_PROTOCOL、CORE_PORTS_AND_STORAGE、CONFIG_REFERENCE、SECURITY_DESIGN 与 GLOSSARY。本次仅创建规划资产，不提前修改现行合同或实现。

成功判据：真实 Codex 在回收及重启两种路径后承接先前上下文；无历史重发或重复工具副作用；可见/后台/多设备/断网计时一致；容量并发不超限；共享进程内其他会话不受影响；实测回收释放资源；合同检查、相关 Rust/前端测试及真实浏览器 E2E 有可读证据。无法证明恢复或卸载能力时明确阻断交付，不把缺失能力写成已实现。

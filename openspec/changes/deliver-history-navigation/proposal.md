# 交付历史分页与实时重连

状态：2026-10-30 ARCH-001 架构缺口补齐；实现暂停。当前 specs 已同步缓存外续读与目标重新定位，详细合同及完整验收计划仍待重基准。此前审查只适用于原快照，不授权恢复实现。

## Why

节点接入已交付，本能力尚未完成产品验收。为按重设计建立可独立验收的交付闭环，需要交付历史分页与实时重连，避免仅交付孤立模块而没有可观察结果。

## Success Criteria

ARCH-001 用户本轮要求：“同意，先修订整体设计和相关 change 的 spec，把这三个缺口补齐，自动回收的能力边界也明确一下，暂不改代码。”本 change 补齐缓存外分页成功路径，区分可靠连续续读和新代际目标重新定位，并复用通用内容安全边界；不改变 Harness 数据权威、有界缓存或父子分页方向。

### 硬约束与非目标

- 以[重设计 §5.1–§6.3](../../../docs/HARNESS_CONTROL_PLANE_REDESIGN.md)为本闭环依据；采用新架构、不兼容旧系统，其他适用的全局约束仍然有效。
- 首个闭环建立基础原生发现及读取，本 change 扩展按能力分页、衔接及查询规模。
- 本轮补齐待实现文档，不开始产品实现，不将规划或模拟结果写成已提供能力。首期限定 Windows 节点 + Web，App 后续。

### 本 change 的成功判据

- SC1：从原生历史按能力实现轮次分页及实时衔接，父倒序、子正序、默认10轮；刷新重读外部更新，不再依赖平台历史库。
- SC2：验证原生来源和实际能力、外部更新后重新读取、缓存失效及历史不可用边界；外部操作不伪造为平台命令或审批。
- SC3：按新规格完成独立用例修订、方案检视、真实实现和交付验收；本次仅规格修订，尚未执行这些检查。
- SC4：不变历史远大于缓存、无原生分页及跨加载稳定条目标识时，在可靠轮次、可安全重放及预算条件下可逐页访问全部保留轮次；无法证明跨代际边界时明确重新定位并替换视图，不循环回首页或假报无损续读。

## What Changes

- 从原生历史按能力实现轮次分页及实时衔接，父倒序、子正序、默认10轮；刷新重读外部更新，不再依赖平台历史库。
- 取消平台独立聊天历史持久化，原生及当前连接能力分别呈现；平台管理数据的可靠记录和审批安全约束继续有效。
- 同步 design 和对应 specs；原 tests/plan/tasks 标为待重基准，旧记录只适用于旧快照。未恢复实现、提交、推送或发布。

## Exploration

- 2026-10-30 ARCH-001：用户确认补齐分页持续读取缺口。当前规格分别定义可靠续读和新重放中的轮次范围重新定位，展示坐标不是原生身份；重新定位返回实际范围、新代际及游标并替换对应视图，源变化时不拼接旧快照。可重复全量重放但正文、元数据、响应和临时内容有界，缓存外每次读取成本均可能随全部历史增长。页面与子步骤复用 structured-history 内容安全规则。沿用轮次、读取代际及游标，不新增持久化对象或重复 ADR；独立用例、完整计划与检视仍待重基准，实现不恢复。

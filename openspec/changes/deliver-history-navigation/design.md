## Decisions

### 1. 职责与权威

基础原生列表及通用标准重放属于首个闭环。本 change 负责重放视图的轮次分页、历史与实时缓存衔接和外部更新后的重新读取；原生分页只是通用能力优化，不建立永久平台历史索引作为权威。

### 2. 来源能力与接口

按原生范围、会话、可靠轮次边界、方向和读取代际建立游标。原生版本或快照只有被证明支持时使用；不能比较或原生变动破坏边界时失效重取，不能套用平台 SQLite 快照。

接口分开表达“继续原边界”和“在新重放中重新定位目标范围”。前者必须有可靠来源依据；后者采用从本次最早保留轮次起的正序展示坐标，独立校验目标、方向、父步骤和权限，不把旧游标当作新授权。返回定位结果同时提供实际范围、新代际和下一步位置，替换相应分页视图并说明连续性未获证明；不能把坐标称为跨加载原生标识。来源变化后旧位置可能指向不同内容，因此重新定位不声称延续旧快照，也不能与旧页默默拼接。

### 3. 状态与失败

保留父倒序、子父步骤内正序、前端传参默认10轮及逻辑页内按需分块。标准全量重放可以形成平台分页；协议处理及候选视图、正文、元数据和响应均有预算，不将全部历史一次性驻留内存。页大小不限制原生重放总量，首次加载成本随全部历史增长。展开仅引用原生重放事实，不做厂商专用适配。

父步骤和关系展示由 agent-session-tree 负责；本 change 提供可靠轮次及有界重放视图的分页合同。主接入先满足重放准入，父及各子目标再分别判断内容和轮次能否重建；缺少原生分页不阻断标准重放兼容。实际加载引用 session-resource-policy 的主树归属。缓存只保留有限窗口及所需页，缺页重新协调标准重放；重放代际改变失效旧游标，无可靠来源边界时明确重建，不把新历史拼接进旧页。重新加载可能扰动原生工作时拒绝本次读取，不为翻页取消任务。

缺页不能形成“重放、失效、回首页”的循环。有可靠来源边界时重新验证并交接新代际游标；否则提供独立定位请求，让用户继续访问本次目标轮次范围。流式处理只保留有界选择窗口、请求范围及必要更新，遍历可重复，计数等展示坐标不要求保存全历史索引；大轮仍按已定义预算分块，无法完整取得的范围不发布完整页。父倒序从首轮起的坐标选择对应较早范围，子正序选择后续范围；历史不变且请求页可交付时可反复定位直到访问全部保留轮次。缓存外每次读取可能重新遍历全量，不能只宣称首次昂贵。来源删改、权限变化和安全重放受限分别处理，不自动把不可达目标改成首页；旧定位响应不得覆盖较新视图。

### 4. 资源与安全

当前连接缓存由节点按原生身份及 Harness 连接代际共享，不按浏览器建立一份权威副本；刷新和设备切换重新授权后读取保留窗口。预算淘汰须给出缺失范围，释放及换代后重新协调标准重放，不回放旧视图为当前内容；失败或无法安全重放时说明限制，不降低基础接入要求。

首次订阅捕获已有实时缓存，并协调原生读取的交接；对迟到读取和旧位置更新按可证明身份处理。无原生可比较版本时采用失效重取，不能按到达顺序覆盖。查看允许激活，实际加载由资源所有者和容量管理。

父页、子步骤及重新定位结果共用 structured-history 的不可信内容展示和资源访问边界；原始载荷只作惰性数据，不能通过分页或子展开额外执行主动内容、读取本机路径或代理任意 URL。旧页因重定位被替换时同步失效其读取引用，不能使权限撤销后的内容继续交付。

## Risks / Trade-offs

- [来源能力不齐] → 原生分页/身份/外部更新、慢读取、取消及重连均待固定版本验证；原测试 HN 系列需独立重基准。
- [旧证据失效] → 原固定版本证据仅按未改变范围复用，方案及用例重新独立检视，不把文本校验当产品通过。

## Context

见 proposal.md 与重设计§5–§6。依赖 Codex 闭环提供稳定条目、轮次、位置及双版本；当前上游未实施，须在其真实交付后按最终合同重基准。首次交付仍是 Windows 节点与 Web，不引入移动端。

## Goals / Non-Goals

限定读取规模和读订阅竞态；不改变平台数据库历史权威，不重定义原生恢复或建立 Harness 历史读取依赖。

## Decisions

### 1. 轮次键集分页

共用一套轮次键集分页查询：请求传pageSize与可选cursor，前端首次及后续翻页传入期望轮数，默认10；服务端在参数省略时也使用10作为默认，不将有效自定义值改成10。父会话按轮次位置DESC，从最新向较早返回；展开子会话按ASC，从最早向较晚返回。轮内条目始终按首次位置ASC，不能因父轮次倒序而颠倒文字/思考/工具的实际交替顺序。以25轮默认请求为例，父返回25→16、15→6、5→1，子返回1→10、11→20、21→25。相比OFFSET，使用排他轮次边界不受新增行数影响。

分页参数、权限、错误和预算规则共用，方向由父/子入口上下文确定且写入游标，不能靠伪造方向把父游标用于子请求。游标绑定协议版本、身份/授权范围、目标会话、父步骤展开引用（子请求）、方向及排他轮次边界，不含正文或认证凭据。不同父步骤的子游标互不串用，即使指向同一子会话也要核实步骤来源。前端可在下一逻辑页改变pageSize，边界仍排他续取；当前逻辑页的块续取只沿用句柄已冻结的轮次集合，不在同页中途改大小或方向。pageSize必须为正整数；服务端公布有界查询上限并拒绝超限，不静默截成默认值。具体上限是实施时依据预算固定的接口参数，不作为用户已经确认的产品常量；固定后需纳入接口文档及边界测试。未知游标版本、跨目标/跨方向游标或无效参数明确报错。

### 2. 大轮次保持完整结构

一次逻辑页按有效pageSize选择至多相应轮数（默认10），但允许在该页内分块取回条目元数据和正文，轮次不会被拆到相邻逻辑页。每块序列化总量最多16KiB且最多64个条目描述；单条描述只含固定身份、类型、版本、位置、大小和展开引用，过大原始元数据也以授权引用展开，单帧保持低于上游32KiB限制。正文按最多16KiB块展开，逻辑页默认最多主动读取1MiB正文，其余明确按需展开，不能静默裁剪。服务端以流式游标查询每块，不在内存预组装整轮全部元数据；客户端一次只保留一个未消费块，并沿用上游1MiB发送队列上限和背压。

页句柄绑定会话、所选轮次集合、数据库快照修订、缓存代际及流交接修订，块游标额外包含轮次内首次位置边界和已消费块编号。分页轮次边界在创建句柄时冻结，元数据续取按固定快照枚举身份，期间收到的更新以条目ID/内容版本合并；新出现的所选轮次内条目由订阅补入。快照句柄空闲60秒或总存活5分钟到期，断线、主动取消和队列溢出立即释放读快照及订阅资源，返回明确重新同步指示；失效游标不能静默跳过剩余块。单次展开请求固定条目版本，版本已不可用则明确重取最新版本。全部块读取前页面标记该轮“尚未加载完整”，不能把局部元数据宣称为完整轮次。续取不延长会话资源保活。

### 3. 快照与订阅交接

在会话协调器内先注册有界订阅并取得缓存代际/流修订，再读取数据库事务快照，然后在同一协调器取所选轮次的最新缓存覆盖及交接修订。向客户端同步模块返回基线、覆盖、内部已提交版本、缓存代际与续传修订；交接期间排队更新在交接之后继续发送。页面按条目ID与内容版本比较，只接受更高内容版本，提交确认仅推进同步模块内部的提交事实，不进入正常页面状态。订阅过滤会话与已加载轮次而非只过滤最新位置，未加载旧轮次记录失效标志，读取该页时取最新值。相比先读再订阅，该方案消除无后续增量时漏掉当前回复的窗口。

### 4. 重连与流边界

流缓冲有界，不承诺永久事件日志；代际变化、修订已淘汰、队列溢出均返回重新同步指示。页面撤销旧订阅并按当前已加载轮次重新取提交基线及缓存，异常导致先前尾部可能丢失或无法确认完整性时显示错误，其余正常重同步透明处理。每会话顺序与版本沿用上游。父页按父轮次倒序分页，子历史通过父步骤展开引用正序分页；各自有逻辑分页进度，均使用前端参数、默认10轮，不跳转子页或建立跨会话排序。逻辑分页与页内字节分块游标分别建模，不能以分块续取替代子轮次分页。

### 5. 父步骤内的子历史展开

子会话在父条目/委派步骤的首次位置显示名称、状态、实际摘要及展开入口；点击在同一步骤内展开，折叠恢复步骤摘要。主列表按前端指定轮数倒序分页（默认10）；子内容在该步骤内按前端指定轮数正序分页（默认10），两个分页实例各自维护目标、方向、边界及页大小。子分页不消耗额外父轮次、不推动父游标，也不跳转子页。子正文仍以原Session/条目身份保存，展开只引用源历史，不复制成父会话条目。

展开请求绑定可信身份、父会话/轮次/步骤、可靠子关联、子来源范围和读取代际；服务器验证父步骤到目标的真实关系及目标读取权限，不能仅凭任意子ID读取。首次只取有界块，不预读全部子正文或整棵树；沿用本设计16KiB/64描述、正文16KiB、默认主动读取1MiB、页句柄寿命和背压预算，父页与已展开分支共享主动读取及发送队列预算，不随展开数成倍放大。展开区域提供子轮次的继续加载/翻页，页大小由前端传入；所选子逻辑页内部再按条目位置分块，加载中的块与尚有后续页分别表达，不把只读首10轮误报为子历史已完整加载。折叠、翻离父页、断线、到期和队列溢出释放所属展开读取快照及订阅；不取消子执行、不删除历史、不触发原生恢复或刷新保活时间。分支重新展开须重新校验权限与关系，读取最新已提交基线及仍在的实时缓存，按原条目ID/内容版本合并，仅在异常丢失或无法确认完整性时展示错误，不展示正常保存状态；错误只标在该步骤，不泄漏子正文或冒充完整。

父步骤位置和子内容内部顺序分开维护；实时更新路由至对应子身份及展开代际，旧请求在折叠/重开后返回不得覆盖新视图。折叠状态继续保存输出，父步骤可显示真实状态；子输出不插入父平级时间线。嵌套子步骤仍在该分支内按需展开。可靠身份、委派映射和多次委派范围由后续agent-session-tree负责；本change提供通用展开查询/投影合同及组件验证，不承担提前伪造子关系。完整真实父子身份和Harness展开体验由后续子会话树验收，不形成03依赖06的反向实施门禁。

### 6. 保存透明与异常反馈

当前内容版本、已提交版本与缓存代际属于后端及客户端同步模块的内部事实，不向页面视图暴露保存中/未保存/已保存状态或提交版本；提交确认只更新内部恢复依据，不触发徽标、进度或保存成功toast。正常重连可透明重新取基线并合并缓存，重同步本身不是保存异常。分页加载中、还有后续页等导航状态仍可显示，不能与保存状态混为一谈。

保存失败、缓存异常丢失导致尾部可能缺失、正文缺失或无法确认完整性时展示错误及必要受影响范围，不能为隐藏正常保存状态而隐瞒异常。后台500ms/64KiB保存、强制刷新、缓存有界和失败停止均沿用上游；不把“页面不感知”解释成停止持久化或丢弃提交事实。

## Risks / Trade-offs

- [单轮含大量条目] → 保留全部身份关联但按需展开正文；真实长轮次检查元数据成本，不能声称任意大小无限返回。
- [读订阅锁占用] → 锁内只做订阅注册/缓存快照，数据库读取不持锁；通过修订队列补齐，队列超限显式重同步。
- [上游双版本字段变化] → 编码前核对并修订查询、游标与合并合同，不复制上游权威定义。

## Migration Plan

在上游模式上新增轮次和位置查询索引；通过临时库检查查询计划和旧数据完整性，迁移不改变已有条目ID。回滚禁用新分页入口并保留索引与历史，不能删除已保存正文。没有旧系统数据迁移。

# Design

## Context

动机与用户确认要求见 [proposal.md](proposal.md)，行为规则见 `specs/history-navigation/spec.md` 与 `openspec/specs/` 长期规格。本变更当前处于需求与设计定义态，具体施工工作包与验收用例在正式开工时基于真实代码树建立。

## Goals / Non-Goals

**Goals:**
- 在标准重放与有界共享视图上实现按轮次分页（父倒序、子正序、前端传参默认 10 轮）及实时输出衔接。
- 分离“可靠边界连续续读”与“新重放代际中的轮次范围重新定位”，消除缓存淘汰后翻页回首页的循环。

**Non-Goals:**
- 建立永久平台历史数据库或全量驻留索引；引入未经授权的厂商私有文件读取器。

## Decisions

### 1. 职责与权威

基础原生列表及通用标准重放属于已归档通用闭环。本变更负责重放视图的轮次分页、历史与实时缓存衔接和外部更新后的重新读取；原生分页只是可选优化，不建立永久平台历史索引作为权威。

### 2. 来源能力与接口

按原生范围、会话、可靠轮次边界、方向和读取代际建立游标。接口分开表达“继续原边界”和“在新重放中重新定位目标范围”：前者必须有可靠来源依据；后者采用从本次最早保留轮次起的正序展示坐标，独立校验目标、方向、父步骤和权限，返回实际范围、新代际和下一步位置并替换对应分页视图，不与旧快照默默拼接。

### 3. 状态与失败

保留父倒序、子父步骤内正序、前端传参默认 10 轮及逻辑页内按需分块。流式处理只保留有界选择窗口与请求范围，可重复遍历；缓存外每次读取成本可能随全部历史增长。重新加载若会扰动正在执行的原生工作则拒绝本次翻页重放，不为翻页取消任务。

### 4. 资源与安全

当前连接缓存由节点按原生身份及 Harness 连接代际共享；实际加载由资源所有者和 `session-resource-policy` 容量策略管理。父页、子步骤及重新定位结果共用 `structured-history` 的不可信内容展示和资源访问边界；旧页被替换时同步失效其分块读取引用。

## Risks / Trade-offs

- [单轮超大载荷或超长历史] → 逻辑页内保持有界分块传输，流式跳过非目标窗口以控制单节点内存峰值。
- [并发外部写入导致轮次偏移] → 重新定位明确返回新读取代际并替换旧视图，不伪报跨代际无损拼接。

## Migration Plan

本能力操作节点内存共享视图与协议帧，不新建永久聊天历史表；开工前核对当时管理协议版本与已有视图组件接口，保留全部现有身份、管理与原生数据。

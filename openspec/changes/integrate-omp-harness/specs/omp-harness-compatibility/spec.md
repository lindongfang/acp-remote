# OMP 接入兼容性

## Purpose

定义 Oh My Pi（OMP）通过自身 ACP 入口接入本平台时的配置、真实能力和兼容性证据边界。即使 OMP 与 Pi 具有项目渊源，也分别验证原生会话身份、权限请求、结构输出和资源清理，不相互借用支持结论。

## ADDED Requirements

### Requirement: OMP 原生 ACP 入口可追溯
系统 SHALL 为 OMP 登记明确的启动配置及接入来源，兼容性报告绑定实际程序版本、入口与环境；MUST 不把交互模式、RPC 或 Pi 的 ACP 适配器视为 OMP 原生 ACP。原生身份与来源复用 native-session-recovery。

#### Scenario: 使用 OMP ACP 入口
- **WHEN** 用户登记提供 ACP 的 OMP 启动配置
- **THEN** 使用标准 ACP 协商并记录实际程序信息和显式来源，不沿用 Pi 的版本或能力结果

#### Scenario: 实际版本没有 ACP 入口
- **WHEN** 配置入口不可启动或仅输出 RPC、终端内容
- **THEN** 明确报告启动或协议错误，不自动升级、切换私有协议或宣称已接入

### Requirement: OMP 能力按当前 ACP 连接处理
系统 SHALL 复用 harness-management 的版本协商、能力及错误语义，分别记录 OMP 的声明、实际协商与真实验证结果。受测版本不作为运行时白名单；升级后重新协商，标准业务失败不自动降版重发。

#### Scenario: 标准能力不支持
- **WHEN** OMP 未提供所请求的标准操作或平台未实现其声明能力
- **THEN** 区分 Harness 不支持和平台未实现并报告，其他标准操作独立使用，不提供私有替代

#### Scenario: 升级后重新连接
- **WHEN** OMP 版本或配置改变后重连
- **THEN** 使用新连接实际协商结果，旧兼容报告保留原版本归属，受影响但未复验能力标记未验证

### Requirement: OMP 结构内容与 Client 请求保真
系统 SHALL 按 structured-history、management-input-upload 和 permission-approvals 保留 OMP 实际提供的结构内容及标准 Client 请求语义。未知内容或平台未实现请求 MUST 明确处理，不将终端、文件、工具差异和权限请求统一降为聊天文本，也不虚报已执行。

#### Scenario: 工具内容及标准 Client 请求
- **WHEN** OMP 提供结构化工具更新并请求标准文件或终端能力
- **THEN** 已实现请求受既有工作区授权与安全边界控制，未实现请求明确报错；输出保留工具关联和原始结构

#### Scenario: 权限请求在等待中失效
- **WHEN** OMP 的真实权限请求在用户作答前已取消或连接失效
- **THEN** 不向新请求或新连接重发旧批准，不因交互选项外观相似就当作仍有效的权限请求

### Requirement: OMP 恢复与历史独立验证
系统 SHALL 对 OMP 的上下文恢复、列表、重放和子会话暴露分别验证，不从 Pi 的实现或项目渊源推断。MUST 不读取 OMP 私有会话文件补造历史，不创建替代会话或重灌聊天副本。

#### Scenario: 恢复可用但历史不完整
- **WHEN** OMP 可以恢复同一原生会话而未提供完整历史重放
- **THEN** 允许实际可用操作并提示当前连接历史限制，缓存丢失无法补回，不冒称同步完成

#### Scenario: 来源不同或原生会话失效
- **WHEN** OMP 与 Pi 的不同显式来源提供相同短标识，或 OMP 已登记原生会话无法恢复
- **THEN** 不跨来源合并；恢复失败明确报错，不替换原生身份或猜测底层存储等价

### Requirement: OMP 活动与关闭按真实范围呈现
系统 SHALL 由节点管理 OMP 实例和所属进程树；页面断线不停止执行，取消和释放沿通用生命周期规则。MUST 不从前台完成、子 Agent 名称或关闭入口存在推断后台全部停止；完整自动回收能力仍由 session-resource-policy 负责。

#### Scenario: 页面断线或前台完成
- **WHEN** 页面断线或 OMP 前台执行结束，而后台或子工作状态未知
- **THEN** 节点继续管理资源，明确观测范围与未知状态，不宣布全部活动停止或安全自动回收

#### Scenario: 取消与释放未确认
- **WHEN** OMP 取消未取得可靠原生工作终态，或实例关闭后所属资源仍未收敛
- **THEN** 分别报告执行取消与实例释放结果；取消已有可靠终态时允许常驻进程继续存在，实例关闭未收敛时保留清理责任，不将发送成功当执行停止，不影响无关进程或共享实例其他会话

### Requirement: OMP 兼容证据与用户数据隔离
OMP 兼容性验收 SHALL 在明确隔离的配置、会话、工作区和进程中执行，逐项标记真实、模拟及未执行结果。MUST 不读取或改写与验证无关的本机凭据、会话和隐私正文，不将 Pi 验收或上游文档当作 OMP 实测。

#### Scenario: 尚未取得真实 OMP
- **WHEN** 本地安装、固定版本或隔离环境不可用
- **THEN** 将真实 OMP 用例记未执行，文档及协议替身只证明各自范围，不声明真实兼容

#### Scenario: 失败或取消后清理
- **WHEN** 隔离测试失败或被取消
- **THEN** 清理本次拥有的完整进程树及临时资源，保留脱敏证据，不删除用户原生数据

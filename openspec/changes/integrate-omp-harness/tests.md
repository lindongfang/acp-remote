# Tests

## 执行边界与需求映射

本文件由独立 tester 基于 proposal、增量规格和 design 编写，仅定义后续验收，不记录执行结果。本轮不安装、调用或升级真实 OMP，不修改产品代码。plan 生成后须再核对执行者、隔离资源、固定版本及证据位置；编码前还须通过独立 reviewer 的方案与用例检视。

- 需求路径 `specs/omp-harness-compatibility/spec.md` 仅指本变更增量。下表列出精确 Requirement/Scenario；长期约束使用显式 `openspec/specs/...` 路径。
- 正式执行固定平台提交及文件清单摘要、Windows 环境、OMP 实际发行版/版本/摘要和来源、ACP 入口、配置版本及显式来源。结果存入 `testing/runs/integrate-omp-harness/`，按 ID 分别记录 passed、failed、not-run、命令、断言及脱敏证据；不得沿用 Pi 的版本或验收结论。
- L4 使用真实配置解析/存储及自有进程或故障夹具；L5 使用真实节点认证入口、存储和传输，协议对端允许使用明确标记的合同替身；L6 的 Windows 节点、Web、OMP 原生 ACP、原生会话及所属进程树必须真实。各 L5 的真实分支集中在 OMP-013 逐项追踪，协议替身不能证明真实 OMP 能力。
- 当前实际检查入口为根 `package.json` 的 `npm run check`、`npm run build:rust` 以及 README 的专项入口。OMP 专项验收脚本尚未存在，由实施任务交付并由 tester 核对实际断言数量；缺入口、环境、权限或真实依赖记受阻/未执行，不转为 LX。本次无必须人工判断且工具无法验证的场景，不设置 LX。
- 故障注入、受控文件/终端请求和清理仅作用于本次拥有的测试根及进程；不扫描、改写或删除用户实际会话、密钥和配置。不运行按程序名批量终止的清理。

| 用例 | Requirement | Scenario |
|---|---|---|
| OMP-004 | OMP 原生 ACP 入口可追溯 | 使用 OMP ACP 入口；实际版本没有 ACP 入口 |
| OMP-005 | OMP 能力按当前 ACP 连接处理 | 标准能力不支持 |
| OMP-006 | OMP 能力按当前 ACP 连接处理 | 升级后重新连接 |
| OMP-007 | OMP 结构内容与 Client 请求保真 | 工具内容及标准 Client 请求 |
| OMP-010 | OMP 结构内容与 Client 请求保真 | 权限请求在等待中失效 |
| OMP-008 | OMP 恢复与历史独立验证 | 恢复可用但历史不完整 |
| OMP-009 | OMP 恢复与历史独立验证 | 来源不同或原生会话失效 |
| OMP-010 | OMP 活动与关闭按真实范围呈现 | 页面断线或前台完成 |
| OMP-011 | OMP 活动与关闭按真实范围呈现 | 取消与释放未确认 |
| OMP-012 | OMP 兼容证据与用户数据隔离 | 尚未取得真实 OMP；失败或取消后清理 |
| OMP-001–003、OMP-013 | proposal.md `Success Criteria` | SC1–SC4；OMP-013 复核以上场景的真实可达分支及逐能力限制 |

共用长期依据：`openspec/specs/harness-management/spec.md` 的“优先最高共同可用协议”“默认继承节点环境”“能力准入与证据状态分开”“会话工作观测与回收能力分别呈现”；`openspec/specs/native-session-recovery/spec.md` 的“原生身份不依赖启动入口”“恢复与历史读取分离”“释放确认与管理事实”；输入、结构及审批分别遵循 `openspec/specs/management-input-upload/spec.md`、`openspec/specs/structured-history/spec.md`、`openspec/specs/permission-approvals/spec.md`，执行与取消遵循 `openspec/specs/session-execution/spec.md`。完整自动回收由其他活跃变更 `openspec/changes/deliver-session-capacity/specs/session-resource-policy/spec.md` 规划，其长期规格尚未建立；本专项不预设其实现或将前台结束当作全部活动停止。

## Cases

### OMP-001 规划一致性与依赖证据可追溯

- 用例级别：L1
- 操作步骤：执行 `openspec validate integrate-omp-harness --strict` 和 `git diff --check`；人工逐项核对上述场景名、六类规划、tasks 到 plan 工作包映射及独立角色安排。实施前核对 OMP 身份、固定来源、许可证、维护与安全审查、Windows 支持及依赖锁定证据；对照用户授权和 design 的 Implementation Gate。
- 预期结果：规划校验无错误，映射真实存在且无遗漏；结构校验不冒充场景覆盖。安装、路径、版本、隔离条件和清理办法未确认时明确阻断后续实施，不能由 Oh My Pi 名称或 Pi 项目渊源推断实际兼容；依赖证据不成为运行时白名单。

### OMP-002 现有构建与回归入口覆盖集成结果

- 用例级别：L2
- 操作步骤：后续实施完成后，在固定最终版本运行 `npm run check`、`npm run build:rust`；记录 Web/Rust 实际测试数量与失败信息，核对配置解析、目录登记及通用 Web 受影响测试是否执行。对新增行为断言按 `docs/code-standards.md` 保存旧实现失败和新实现通过的 Red Check 证据。
- 预期结果：适用检查和构建成功，非零有效断言约束改动；通用 ACP 行为无回归。缺依赖或未运行如实记录，不以上游检查、静态通过、Pi 或旧归档结果替代 OMP 验收。

### OMP-003 Windows 启动配置与敏感数据边界

- 用例级别：L4
- 操作步骤：通过现有 format-one 配置入口发布隔离示例，经真实解析/存储核对 `omp acp` 对应独立 argv、原始字段与来源；用自有参数回显进程验证空格、引号、非 ASCII 路径及实际选用的 `.cmd`/`.ps1` 或可执行入口。用合成环境标记检查默认继承和显式覆盖，用合成凭据标记检查日志/错误/报告；对缺来源、畸形配置及越权目录执行拒绝检查。
- 预期结果：参数与来源完整保留，无未转义 shell 拼接或私有 RPC 配置替代；无效配置明确拒绝。继承及覆盖按长期规则生效，秘密标记不泄漏；夹具只证明平台启动路径，OMP 的真实配置生效留给 OMP-013。

### OMP-004 原生 ACP 入口与错误启动

- 用例级别：L5
- 操作步骤：经真实节点认证入口登记 OMP 定义、启动配置及来源，读取连接协商信息；在隔离来源中分别使用不存在路径、无 `acp` 子命令、仅 RPC 输出和交互终端输出的合同对端，观察错误与进程状态。核对同来源多个配置访问同一原生标识时的协调归属。
- 预期结果：有效入口实际按 ACP 工作，报告绑定 OMP 程序及来源；同来源别名不绕过互斥。错误入口明确报启动/协议错误，不自动升级或安装、不切换 `--mode rpc`、终端解析或 Pi 适配器，不假报已连接。

### OMP-005 标准能力缺口独立呈现

- 用例级别：L5
- 操作步骤：合同对端分别不提供所请求标准操作、声明平台未实现能力，以及对已声明操作返回实际业务错误；通过 Web 请求相应操作后继续请求可用输入/读取，检查出站及状态。对未知扩展请求返回当前通用错误并检查保留的原始结构。
- 预期结果：Harness 不支持、平台未实现和业务失败明确区分；其他能力独立使用。无私有替代、替代会话或业务降版重发，不把未知扩展当作已执行，不以历史报告缺失整体拒绝标准能力。

### OMP-006 升级和配置变更后重新协商

- 用例级别：L5
- 操作步骤：用两个隔离固定版本或明确标记的版本合同替身，分别升级程序及改变启动配置后重连；覆盖最高已实现共同版本、规范允许回退、对端合法选择低版但无原因、无共同版本和协商后业务失败。观察旧请求/批准、实际版本及报告归属。
- 预期结果：新连接重新绑定版本和能力，不热切旧连接或固守旧低版；回退须符合规范，原因未知明示。旧请求及批准不迁移，业务失败不自动降版重发；旧报告保留版本归属，受影响未复验能力记未验证，模拟升级不冒充真实升级证据。

### OMP-007 结构内容、上传与标准 Client 请求

- 用例级别：L5
- 操作步骤：经实际上传/输入入口提交文本与当前支持结构，对不支持输入验证明确拒绝；合同对端交错发出工具多次更新、后续文字、晚完成、差异与未知结构，同时请求标准文件/终端能力。在已授权测试根内执行受控读写/终端命令，再请求越界根与平台未实现方法；注入主动 HTML、终端控制字符和伪装成审批的私有 UI/elicitation 请求。
- 预期结果：上传、受理与执行完成不混淆；工具身份、顺序、原结构保留，未知内容说明限制，显示内容不获得执行权限。已实现 Client 方法遵守工作区授权，越权拒绝，未实现明确报错；私有交互不冒充 `session/request_permission`，不把文件/终端/差异统一转聊天文本或虚报执行。

### OMP-008 恢复成功与历史不完整分别验收

- 用例级别：L5
- 操作步骤：在同一来源建立、释放并按原生标识恢复隔离会话，分别覆盖无重放、完整标准重放和重放中断；清除本次节点缓存后重开，观察历史提示和可用输入。分别请求列表、按标识加载及子会话信息，对未提供能力记录实际响应。
- 预期结果：恢复不冒称历史同步，无重放时可用执行继续，页面提示历史不完整及缓存丢失无法补回。重放完整须有完成事实；列表、重放、加载和子会话各自报告范围，不读取 OMP 私有文件补齐，也不继承 Pi 的会话发现结论。

### OMP-009 来源隔离与原生状态失效

- 用例级别：L5
- 操作步骤：用两个明确标记为 OMP/Pi 的隔离来源合同返回相同短原生标识，检查会话、权限及缓存独立；对 OMP 已登记会话注入原生恢复失败，再重试并核对出站请求和管理事实。测试数据只在自有来源中创建。
- 预期结果：相同短标识不触发跨来源合并，不根据路径或项目渊源猜物理存储等价。恢复失效明确报错，不创建替代会话、变换原生身份或重灌正文；保留管理事实，真实 OMP 行为单独在 OMP-013 取证。

### OMP-010 审批有效性与后台观测边界

- 用例级别：L5
- 操作步骤：合同对端发出真实协议权限请求，分别经 Web 允许、拒绝；页面断线后由另一有权页面继续观察和作答。覆盖批准保存失败、保存后请求取消、连接换代及旧批准重试；另让前台完成而后台状态未知或仍存在有效后台权限请求，并观察资源和审批状态。
- 预期结果：决定可靠提交后才向仍有效原请求交付，失效请求/旧连接不收到旧批准，不默认允许。页面断线不停止节点管理；前台结束不使仍有效后台请求自动失效，不伪造 Run；无法观测全部后台活动时明确未知，不宣布全部停止或安全自动回收。

### OMP-011 取消、释放与多进程归属

- 用例级别：L5
- 操作步骤：在隔离长任务中分别取消未发送输入和活动工作，等待可靠终态；覆盖自然完成与取消竞态、取消无响应、主进程退出但后台/孙进程存活及节点关闭超时。记录所属完整进程树，保留另一自有无关同名进程和共享实例第二会话作为保护对照。
- 预期结果：未发送项取消后不派发，执行取消按可靠原生工作终态确认，OMP 常驻进程可以继续存活；已发取消不等于执行停止，自然终态已证时不等待重复终态。实例关闭与执行取消分别判定，未知活动保留保护和清理/join 责任，不能只看前台/父进程结束就报完整实例释放成功；不误杀无关进程，不干扰共享会话，无法隔离时拒绝单会话释放。

### OMP-012 缺环境、失败与取消后的隔离清理

- 用例级别：L5
- 操作步骤：核验尚未取得安装/固定版本/隔离根时的报告状态；在自有测试根建立合成会话、认证配置和外部保护文件并记录摘要，分别使验收失败和主动取消。检查完整所属进程树、临时资源及脱敏报告，复核保护数据摘要；不读取用户真实凭据作为测试数据。
- 预期结果：真实环境不可用记 not-run，不能将上游说明、Pi 或替身通过冒充 OMP 兼容。失败/取消后只清理本次拥有资源，保护数据不变；未完成清理明确保留责任，错误及证据不泄漏秘密或敏感正文。

### OMP-013 固定真实 OMP 的 Windows 与 Web 完整闭环

- 用例级别：L6
- 操作步骤：获得后续实施授权并满足 Implementation Gate 后，在独立测试根启动固定真实 OMP 原生 ACP、真实 Windows 节点及 Web。从来源/配置登记、标准协商、创建或恢复隔离原生会话开始，完成文本及实际支持结构输入、工具输出、标准文件/终端请求（若提供）、有效审批（若提供）、页面断线继续观察、取消、释放、重连恢复及历史检查。逐项回填 OMP-004–012 的真实观察，在安全隔离范围复现升级、入口缺失、失效会话和完整进程树清理，并记录后台/子工作可观测范围。
- 预期结果：完整链路有真实运行结果及版本绑定证据，节点/浏览器/存储/OMP/原生来源均非替身。恢复、历史、列表、子会话、Client 方法、审批和后台范围分别判定；未提供可选能力有不支持依据，未触达记未验证，不由前台完成推断全部工作结束。必要安全或清理证据缺失阻断交付；独立 tester/reviewer 对同一最终版本核对结论，用户原生数据和凭据不受影响。

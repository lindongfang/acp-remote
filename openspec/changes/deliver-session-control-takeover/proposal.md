# 交付单会话客户端控制权接管与只读隔离

## Why

现有设计允许所有可信客户端无差别并发操控同一会话（同时编辑队列、抢占权限审批裁决与触发中断），在个人多设备场景下易因旧标签页误触或双端操作交错引发冲突。需要将会话级操控权与节点级设备信任分离，为每个主会话引入单设备显式控制权接管，其余可信设备默认保持实时只读。

## Success Criteria

### 用户原始要求

> 第一点 操作层面，原来希望远端多设备都可以同时操控这个会话，由owner侧来控制，现在想增加一个授权，只允许授权设备操控这个会话。其他设备只读。
> 授权，更加合理的说法是接管，只接管当前会话，只允许当前接管的设备操作这个会话，一个会话只允许一个接管设备。与设备授权区分开
> 1. 顶号式显式接管
> 2. 同意方案A
> 3. 同意，接管状态随会话释放（或重启）自动归零，下次哪台设备需要操作再显式接管
> 4. 同意

### 硬约束与非目标

- 以 [总体设计](../../../docs/HARNESS_CONTROL_PLANE_REDESIGN.md) 与 `openspec/specs/` 长期规格为依据；保持设备信任层（`client-trust`）、单会话客户端控制权接管（`session-control-takeover`）与外部原生会话纳管（`native-session-import`）三者职责独立。
- 会话控制权接管仅作用于主会话（根执行树）内的会话写操作，不阻塞设备列表查询、设备撤销、全局容量面板查看或创建新会话等节点级管理动作。
- 控制权接管状态属于会话活跃运行期内存事实，不跨会话资源释放或节点重启持久保留；不因控制权顶号切换而中止在途执行或清空节点已受理队列。
- 首期限定 Windows 节点与同源 Web，当前处于需求与设计定义阶段（`.openspec.yaml` 标记 `x-deferred: true`），正式启动本变更时基于真实代码树生成 `tests.md`、`plan.md` 与 `tasks.md`。

### 本 change 的成功判据

- SC1：同一主会话（根执行树）同一时刻最多允许一台可信客户端持有控制权；新建会话自动赋予创建客户端初始控制权，其他可信客户端默认处于只读态。
- SC2：支持顶号式显式接管与主动释放接管；设备 B 显式接管成功后原子递增控制代际，原主控设备 A 立即退回只读态且迟到旧控制请求被确定性拒绝，在途执行、已受理队列及待决审批无缝移交新主控设备操控。
- SC3：未接管的可信客户端可实时旁观会话输出、共享队列与待审批状态，并在查看空闲会话时按既有策略读取展示快照或按需触发历史重放，但所有会话写操作（提交输入、队列编辑/取消/优先发送、中断/继续、裁决审批）均被节点拒绝。
- SC4：主控客户端被撤销信任、主会话资源释放（含 30 分钟空闲自动回收或显式释放）或节点重启后，控制权状态自动归零为无主只读态；正式开工后通过编码前门禁、真实实现与独立集成交付验收。

## What Changes

- **BREAKING** 收敛单会话多客户端并发写权限：由“任意已认证可信客户端均可直接向任意会话提交输入、修改队列与裁决审批”调整为“仅当前持有该主会话控制权的唯一可信客户端允许执行会话写操作，其余可信客户端只读”。
- 新增会话控制权管理协议与 Web 交互：支持新建自动接管、无主会话显式接管、已接管会话顶号式抢占接管、主动释放接管及实时主控身份广播。
- 建立控制代际（`controlEpoch`）校验与自动归零机制：在输入受理、队列变更、中断/继续及审批裁决入口统一核验当前主控客户端身份与控制代际；会话资源释放、节点重启或主控客户端信任撤销时自动清空接管状态。

## Capabilities

### New Capabilities

- `session-control-takeover`: 单会话（主执行树）运行期客户端控制权接管、顶号式显式抢占、未接管设备只读隔离与释放/重启自动归零。对应文件为 `specs/session-control-takeover/spec.md`。

### Modified Capabilities

- `session-execution`: 会话输入受理、共享队列编辑/取消/优先发送、中断与显式继续操作增加主会话当前控制权核验，未接管客户端仅保留共享只读查看。对应增量文件为 `specs/session-execution/spec.md`。
- `permission-approvals`: 会话权限请求的人工裁决增加主会话当前控制权核验，未接管客户端只读展示待审批详情，顶号切换后待决请求移交新主控客户端裁决。对应增量文件为 `specs/permission-approvals/spec.md`。

## Exploration

- **顶号式显式接管（用户确认 1）**：鉴于所有可信客户端均属于同一节点 owner，若要求原设备先释放会导致用户离开原设备后无法远程操作；因此采用显式抢占（顶号）模式，新设备确认接管后原子切换主控身份并使旧设备降为只读。
- **业务只读与历史查看边界（用户确认 2 / 方案 A）**：“只读”仅禁止改变会话执行与队列/审批状态的写操作；只读客户端打开空闲会话时仍可读取本地展示快照或在必要时触发标准只读历史重放（受 50 主会话名额约束）。
- **活跃期内存驻留与自动归零（用户确认 3）**：控制权按主会话（根执行树）绑定，仅驻留当前活跃运行期内存，随主动释放、客户端撤销、会话资源释放或节点重启自动归零，不建立跨重启持久会话锁表。
- **术语防撞车（用户确认 4）**：在 [领域术语表](../../GLOSSARY.md) 中明确区分“会话控制权接管（客户端级单会话写权限）”与 `native-session-import` 中的“外部原生会话纳管（平台级原生执行绑定）”，无新增独立 ADR。

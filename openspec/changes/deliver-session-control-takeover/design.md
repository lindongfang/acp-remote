# Design

## Context

动机与用户确认要求见 [proposal.md](proposal.md)，行为规则见 `specs/session-control-takeover/spec.md`、`specs/session-execution/spec.md`、`specs/permission-approvals/spec.md` 与 `openspec/specs/` 长期规格。本变更当前处于需求与设计定义态，具体施工工作包与验收用例在正式开工时基于真实代码树建立。

## Goals / Non-Goals

**Goals:**
- 在不改变节点级客户端信任（`client-trust`）的前提下，按主会话（根执行树）建立单客户端互斥控制权与单调递增控制代际（`controlEpoch`）。
- 支持新建自动接管、无主显式接管、顶号式抢占接管与主动释放，确保其他可信客户端处于一致的实时只读态。
- 保证控制权移交、主动释放、客户端撤销、会话资源释放及节点重启时，在途执行、已受理队列与待决审批状态不丢失、不误中断。

**Non-Goals:**
- 引入多用户团队 RBAC 角色体系；将客户端控制权持久化到 SQLite 跨重启保留；限制未接管可信客户端的节点级管理操作（如设备管理、全局容量查看、新建会话）或冷会话历史查阅。

## Decisions

### 1. 职责分层与绑定粒度

客户端接入分两层校验：先由 `ApplicationPolicy` 校验可信客户端身份与当前未撤销状态（节点级准入），再由主会话控制权协调器校验目标主执行树的当前主控 `clientId` 与可选期望 `controlEpoch`（会话级写准入）。控制权严格绑定在主会话（根执行树）粒度，子会话继承所属主执行树的控制权状态，不单独设立子会话接管锁。

### 2. 状态流转与顶号抢占协议

每个活跃主执行树维护内存态控制记录 `{ controllerClientId: Option<ClientId>, controllerDisplayName: Option<String>, controlEpoch: u64 }`：
- **新建会话**：创建并加载主会话成功的客户端自动成为初始主控客户端（`controlEpoch = 1`）。
- **显式接管（含顶号抢占）**：可信客户端调用 `session.control.takeover`（携带稳定请求身份去重及目标主会话标识）。无论当前处于无主态还是由另一台客户端持有，节点在主树门内原子将 `controllerClientId` 更新为请求方并递增 `controlEpoch`，同时向订阅该会话的所有连接广播最新控制权快照；原主控客户端收到广播后立即切换为只读界面，其未发出的本地草稿保留在本地但不自动提交，任何在切换后到达节点的旧主控写请求因身份或代际不匹配返回 `session_not_controlled`。
- **主动释放接管**：当前主控客户端调用 `session.control.release` 后，`controllerClientId` 置空、`controlEpoch` 递增，会话进入无主全员只读态。

### 3. 队列、审批与资源生命周期联动

- **已受理动作由节点继续负责**：沿用“节点受理授权”原则，控制权切换、主动释放或原主控设备被撤销信任时，正在运行的 `Run` 继续执行，已在节点共享队列中的待发项保留原顺序与内容；新主控客户端接管后可直接编辑、取消、优先发送或显式恢复这些队列项，并裁决当前有效的 `ApprovalRequest`。
- **只读查看与容量释放边界**：未接管客户端允许订阅实时视图、读取本地展示快照，并在目标冷会话需要原生重放时按既有规则触发只读历史加载；当节点 50 主会话名额满且需手动释放空闲/无主会话时，全局容量管理入口按会话是否有主控及既有安全协调规则处理，不因无人接管而死锁容量释放。
- **自动归零**：当原主控客户端被 `device.revoke` 撤销时立即清空其持有的控制权；当主会话完成显式释放、30 分钟无活动自动回收或节点进程重启时，内存控制权状态自然销毁归零，后续重新加载查看默认进入无主只读态，待需要操控的设备显式接管。

## Risks / Trade-offs

- [双端网络延迟下旧主控点击写操作碰上顶号瞬间] → 所有会话写入口在主树同一互斥门内校验最新 `controllerClientId` 与 `controlEpoch`，迟到写请求确定性返回 `session_not_controlled` 且零副作用，前端据此刷新为只读提示。
- [主控设备离线挂起但任务卡在待审批] → 其他在线可信设备可在只读页面看到待审批提示，一键顶号显式接管后即可立即完成审批裁决，无死锁风险。

## Migration Plan

控制权接管状态为纯运行期内存协调对象，无需新增持久化会话锁表；开工前核对管理 WebSocket 协议错误码闭集与既有命令审计字段（将显式接管/释放纳入管理审计元数据），确保现有 SQLite 身份、信任、审批与容量数据完全兼容。

## Purpose

定义可信客户端通过 Web 操作会话时的输入受理、执行结果与取消语义，使多个客户端共用一致的执行协调边界，避免重复副作用、把取消请求误报为完成，或在节点异常后自动重发结果未知的输入。

## ADDED Requirements

### Requirement: 输入受理与防重复
系统 SHALL 为改变状态的请求关联操作者与请求身份；新产品会话操作先满足 harness-management 的基础重放准入，在“请求有效期与去重保留”的有效范围内，同身份同内容返回原受理或结果，同身份不同内容 MUST 拒绝。请求过期只返回过期或只读可查的原事实，不恢复派发资格。受理记录成功不等于执行成功，历史能力变化不使已受理请求被重新派发。

#### Scenario: 断线后重复提交
- **WHEN** 客户端在请求有效期内以原请求身份重试已受理输入
- **THEN** 系统返回原执行关联，不再次派发

#### Scenario: 请求身份冲突
- **WHEN** 同请求身份携带不同输入
- **THEN** 系统拒绝冲突且不执行新内容

### Requirement: 请求有效期与去重保留
系统 SHALL 对新的产品副作用命令使用节点签发、绑定当前节点请求代际及操作者且具有不可延长截止时间的稳定请求身份，默认有效24小时；该身份不代替客户端认证、目标权限或审批。有效期内的已受理记录及请求摘要须保留至截止时间，节点正常重启不重置期限或丢失去重事实。MUST 不允许客户端通过更换时间字段延长同一身份，不因重连、结果未知或记录清理自动签发新身份重试原动作。截止时间只限制请求的新受理及重试，不取消已受理工作或缩短真实原生审批有效期；未派发请求过期后不得开始派发，可能已派发的动作仍不重发。

系统 SHALL 在查找不到去重记录时仍能验证身份的原始截止时间和节点请求代际，过期、代际失效或无法可靠验证时拒绝执行，不能将其作为新请求。默认最多保留10000个仍需去重保护的新产品命令；容量不足且不能安全清理时拒绝新的危险受理，不提前驱逐有效或未收敛事实。未终态、结果未知且尚待核验、审批交付及资源责任未收敛的记录不因截止时间到达被自动清除。只读结果查询可在权限允许且记录仍保留时返回原事实，记录已清理则说明不可查询，不重新派发。该规则不改写已归档节点撤销接口的原有合同。

#### Scenario: 截止时间前后重试
- **WHEN** 已受理输入在请求截止时间前以同身份重试，随后在截止时间到达或之后再次重试
- **THEN** 截止前返回原关联而不派发，截止时起拒绝再次执行；有权查询可返回仍保留的原事实，不因到期终止原执行

#### Scenario: 记录清理后重放旧请求
- **WHEN** 一个已收敛且过期命令的去重记录已安全清理，客户端再次提交原请求身份
- **THEN** 仍依据不可延长的截止时间及节点请求代际拒绝执行，不因记录不存在而当作新请求，也不自动换新身份重试

#### Scenario: 有效期结束但工作未收敛
- **WHEN** 请求已过期，但动作仍执行、结果未知待核验或仍有相关资源及审批交付责任
- **THEN** 保留必要管理事实和资源所有权，不自动清理或重派；去重容量满时拒绝新危险命令，安全控制沿存储故障规则保持可用

#### Scenario: 时钟回退或请求代际失效
- **WHEN** 节点时间回退使有效期无法可靠判断，或恢复到新目标后旧节点请求代际已失效
- **THEN** 不使已过期或失效身份重新有效；无法可靠验证时拒绝新危险派发，保留只读核验和安全收敛路径，不重放旧动作

### Requirement: 同会话前台执行互斥
系统 SHALL 在同会话有未结束前台执行时拒绝新的普通输入，并继续接受对应有效审批与取消。不同会话可并行。

#### Scenario: 并发输入
- **WHEN** 两客户端同时向同会话提交普通输入
- **THEN** 至多一个被受理执行，另一个返回忙碌

### Requirement: 原生工作活动独立于平台输入记录
系统 SHALL 分别处理平台输入对应的 Run、原生会话前台活动及后台工作事实；原生前台活动即使没有平台 Run，也受同会话普通输入互斥约束。MUST 不因没有活动 Run 就推断原生空闲，不为 Agent 自发工作、外部输入或后台更新补造平台 Run，也不将前台结束解释为后台已全部停止。审批有效性遵循 permission-approvals，自动回收资格遵循 session-resource-policy。

#### Scenario: Agent 自行开始前台工作
- **WHEN** 有效连接报告 Agent 自行开始前台工作，没有对应的平台输入 Run
- **THEN** 按真实前台活动拒绝新的普通输入，仍处理有效审批与取消，不建立虚假输入或平台 Run；按协议确认前台结束后才解除该阻挡

#### Scenario: 前台结束仍有后台活动
- **WHEN** 当前协议确认前台结束，但后台工作继续或其状态无法确认
- **THEN** 按已确认事实结束对应前台执行，不将后台工作补成未结束 Run；后台、审批及自动回收保护分别判断，不以 Run 已结束证明资源可回收

### Requirement: 取消与异常结果
系统 SHALL 区分取消已请求、前台执行已结束和副作用结果已知；正常执行仅收到可靠完成事实后解除前台互斥，异常执行按“异常后重新准入”要求处理。连接丢失或进程异常 MUST 保留已知事实，标记中断或结果未知，不自动重发。

#### Scenario: 取消未完成
- **WHEN** 被取消的前台工作或既有待确认输入尚未结束，取消已发送但尚未取得对应协议完成或拒绝事实
- **THEN** 新普通输入仍被拒绝，界面不显示已取消完成

#### Scenario: 派发后异常退出
- **WHEN** 执行可能已产生副作用但未收到终态
- **THEN** 系统记录结果未知并提示人工判断，不自动重试输入

### Requirement: 空闲取消与活动前台取消分开
系统 SHALL 按实际协议和当前已知工作区分取消对象。当前前台已可靠确认为空闲且无既有待确认输入时，若该版协议不要求额外完成通知，MUST 不因发送取消而建立等待该通知的新输入阻挡，不伪造新的 Run 或完成事件，也不以此证明后台工作停止。已有前台工作、待插入输入或活动状态未知时仍按对应协议及异常重新准入规则协调；取消与自然完成竞态按实际终态记录，不能要求已自然结束的工作再产生取消终态。

待处理权限请求按 permission-approvals 的协议取消范围回应，与前台工作是否结束分别记录；之后出现的真实前台活动或未知事实仍按自身依据阻挡输入。新输入与取消沿同一原生目标协调，不能将新一轮错误纳入针对旧工作的取消结果。

#### Scenario: v2 前台空闲时取消后台审批
- **WHEN** v2 会话前台已确认 idle、没有待确认输入，但仍有有效后台权限请求，用户请求取消
- **THEN** 按协议回应适用待处理权限请求，记录取消已发送或请求处理事实；不等待协议未要求的额外 idle 通知，不新增前台阻挡，不宣称全部后台工作已停止

#### Scenario: 前台空闲但输入尚未确认插入
- **WHEN** 当前前台状态为 idle，但一个已受理输入尚未得到可靠插入或拒绝结果，随后发起取消
- **THEN** 按该版协议跟踪待输入结果，不仅凭 idle 清除其执行归属；没有可靠拒绝或完成事实时仍保持对应阻挡及未知结果，不重发输入

#### Scenario: 取消与自然完成交错
- **WHEN** 取消请求与原生前台自然结束交错，节点已取得该工作的可靠正常终态而未取得 cancelled 终态
- **THEN** 记录工作实际正常结束及取消未被证实，不再等待第二个取消完成通知，也不把正常结果改写为已取消；新活动独立判断

### Requirement: 管理存储故障时限制危险派发并保持安全控制
系统 SHALL 在命令受理、唯一执行归属、所需审计或必要派发事实无法可靠提交时，拒绝新的输入、创建、恢复加载、删除及其他可能扩大副作用或资源责任的派发，不返回已可靠受理。已接受动作完成后结果写入失败时，MUST 不改写为未发生、自动重发或报告已持久化完成；保留已观测原生事实、未知持久状态和资源责任，明确报告管理存储故障。

系统 SHALL 在仍可可靠验证当前操作者及目标时保留取消、拒绝或取消权限请求、显式安全关闭及节点退出的收敛路径；这些控制不得仅因审计或结果写入失败被无限阻断，也不得借此批准权限、派发输入或删除原生数据。安全控制自身的身份及目标无法验证时不执行远程控制，保留经操作系统身份验证的本机关闭路径。故障控制绑定当前节点运行代际及实际资源代际，同代际重复返回已观察事实，换代后旧控制拒绝执行，不自动转换为针对新工作的控制。未能持久保存的控制只报告已观察到的事实及记录失败，不承诺跨重启恢复原结果；不自动重放旧控制或改用过期请求。存储恢复后先重新核验在途工作、审批、资源及未提交结果，完成持久化协调后才恢复危险受理；节点重启也不根据残留旧记录自动派发。

#### Scenario: 受理或派发前写入失败
- **WHEN** 命令受理事务或必要派发事实提交失败，或提交结果无法确定
- **THEN** 不发起新的原生副作用，返回失败或受理未知；同身份重试须先核验已有事实，不因为响应失败重新派发

#### Scenario: 原生完成后结果写入失败
- **WHEN** 已受理动作有可靠原生完成事实，但其结果无法提交管理存储
- **THEN** 分别呈现原生结果和管理记录故障，不把旧记录当作动作未执行，不自动重发；重新启动后先核验再恢复受理

#### Scenario: 故障期间安全取消和关闭
- **WHEN** 管理存储故障期间，有权用户对节点仍能验证及管理的当前目标请求取消或显式安全关闭
- **THEN** 尝试安全收敛而不等待审计恢复，继续遵守共享实例隔离及审批规则；关闭或记录不能确认时分别报告，不为腾容量派发其他工作或删除原生数据

### Requirement: 异常后重新准入
系统 SHALL 将异常执行是否仍可能运行与其副作用结果是否已知分别判断。只有可靠确认旧前台执行已结束、其所拥有的执行资源已收敛，或原生接口可靠确认旧执行不再活动且不会在恢复后继续派发，并重新校验原生身份、唯一执行归属及所需恢复成功后，才允许用户以新请求身份显式提交下一次输入。MUST 不以连接断开、超时、标记结果未知或仅完成新连接握手作为解除互斥依据；不能证明安全时继续拒绝输入并说明原因。旧执行保留中断或未知事实，旧请求在有效期内重试只返回原事实，过期按只读核验及拒绝执行规则处理；旧审批失效，不将恢复本身视为重试授权。

#### Scenario: 旧执行退出后显式继续
- **WHEN** 旧执行未返回终态，但节点已确认所属执行资源收敛，并按原生身份重新取得唯一归属及完成所需恢复
- **THEN** 用户可用新请求提交下一轮，旧执行的副作用结果仍为未知；重试旧请求不再次派发，旧审批不复活

#### Scenario: 断线后旧执行仍可能运行
- **WHEN** 连接丢失但旧进程或原生执行仍可能活动，且新连接已握手成功
- **THEN** 继续拒绝新输入，不因新连接或未知标记解除互斥；共享实例中的其他会话不被为此强杀

### Requirement: 命令记录不成为聊天历史
系统 SHALL 保存防重复及异常判断所需的命令、执行关联与结果元数据；MUST 不将这些记录或待发送输入作为永久聊天档案，受理、原生接收与原生完成分别表达，外部对话不得被伪造成平台执行。

#### Scenario: 原生派发结果未知
- **WHEN** 平台已受理输入但无法确定 Harness 是否接收
- **THEN** 保留命令及未知事实，不自动重发，不把受理记录补成原生聊天消息

### Requirement: Windows 与 Web 操作闭环
系统 SHALL 在 Windows 节点提供 Web 会话创建、输入、结构化结果、审批、取消和显式释放入口；运行资源未释放时完成一轮仍显示运行中，释放确认后显示空闲。

#### Scenario: 一轮完成
- **WHEN** 回复完成但会话资源仍加载
- **THEN** 页面仍显示运行中，并分别显示本轮完成结果

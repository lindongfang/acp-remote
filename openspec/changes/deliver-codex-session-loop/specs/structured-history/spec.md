## Purpose

定义平台保存已观察会话内容的权威边界，包括结构化条目、稳定身份、源顺序、流式版本及合并保存结果，使实时页面与持久历史不会互相冒充，也不以压缩摘要或文本去重丢失真实工具和子 Agent 载荷。

## ADDED Requirements

### Requirement: 保留结构与会话源顺序
系统 SHALL 保留实际暴露的文字、可见思考、工具、审批、子 Agent 及必要原始字段，以稳定条目身份和轮内首次位置展示；更新原条目不移动位置，不跨其他条目合并文字，不按类型或时间戳重排。

#### Scenario: 工具晚完成
- **WHEN** 工具之后已出现文字而工具稍后完成
- **THEN** 更新原工具条目，文字位置保持不变

#### Scenario: 未知结构载荷
- **WHEN** 接入层提供平台尚不能完整展示的结构化内容
- **THEN** 保留必要原始字段并明确支持限制，不静默降为文本

### Requirement: 实时与提交版本分离
系统 SHALL 允许先展示实时内容再合并保存，内部区分当前版本和已提交版本；正常页面不展示保存进度、保存状态或提交版本，保存失败 MUST 以错误可见，不将已显示当作已保存，不用上下文压缩摘要覆盖平台已有历史。

#### Scenario: 保存失败
- **WHEN** 用户已看到输出但数据库提交失败
- **THEN** 页面显示保存失败错误及受影响内容说明，历史读取仅承诺已提交部分，不以常驻未保存徽标替代异常反馈

#### Scenario: 正常输出不展示保存状态
- **WHEN** 实时内容先展示，后台稍后成功提交
- **THEN** 内容持续展示且页面无保存中、未保存、已保存或提交版本提示，内部仍保留准确版本及提交事实

### Requirement: 有界缓存和失败停止
系统 SHALL 在输出高速或保存持续失败时保持缓存有界，达到停止阈值时停止接收新的执行并协调停止当前输出；截断、缺失或故障导致尾部无法保证完整等异常 MUST 以错误明确告知，不宣称零丢失。正常等待后台提交的实时尾部不作为保存状态展示。

#### Scenario: 持续保存故障
- **WHEN** 保存持续失败并达到缓存安全阈值
- **THEN** 系统拒绝新输入并协调停止，报告仍未提交的范围

### Requirement: 异常重启保留提交事实
系统 SHALL 在异常重启后保留已提交条目，避免复用已分配位置，并将未完整生成内容标记中断；无法证明的未保存尾部 MUST 不补成成功历史。

#### Scenario: 实时尾部丢失
- **WHEN** 节点在输出已显示但尚未保存时崩溃
- **THEN** 重启后保留提交历史并显示可能缺失的尾部，不伪造回复

## Context

动机与范围见 proposal.md。当前没有产品运行代码或长期规格；本设计是待实现方案，不是兼容性报告。首期选择 Windows 完整节点与 Web。依赖 establish-node-access 的认证、撤销、节点所有权合同；实现前须读取其最终规格重基准，不能把当前规划路径当成已发布接口。

## Goals / Non-Goals

领域、协议适配器、存储与页面视图分层，建立通用 ACP 会话闭环，以 Codex 首验。平台不实现模型推理、工具系统或原生上下文，不兼容旧数据库。ZCode/DeepSeek 复用通用实现，不通过 Codex 私有字段定义领域，不默认新增厂商协议实现。

## Decisions

### 0. 通用 ACP 与多版本兼容边界

采用端口与适配器模式隔离协议和业务，使用策略模式封装 ACP v1/v2 的编码、解码、能力解释、完成/取消、审批及恢复语义；由连接初始化入口按经核实的版本协商结果选择版本策略。公共传输、请求关联、连接生命周期和错误基础设施只实现一份；只有语义确有差异的部分进入版本模块，不复制整个客户端。版本协商引导必须遵循各版本正式规范，不先假设 v1/v2 握手相同，也不按程序名或 SDK 包版本推断 wire 协议版本。无共同已实现版本则明确拒绝，只有规范允许且不会重复产生副作用时才可协商回退；不能运行中混用或失败后重发输入。

规划目录统一为 app/src/adapters/acp/（公共客户端、版本策略及转换）、app/src/platform/（进程所有权）和 app/src/harnesses/（启动及本机认证引用配置）。具体内部文件名在实施时确定，不为每款 Harness 建立完整协议目录。应用依赖稳定业务端口，通过依赖注入接入所选版本策略；业务端口保留结构化内容、来源身份、协议版本和必要原始/扩展载荷，不能压成最低公分母文本，也不强迫不同版本拥有相同生命周期。

ACP v1/v2 是用户确认的兼容目标，不是两版已经发布或实测通过的声明。实施前分别记录官方规范地址、修订、实际协议标识及稳定/草案状态，并建立逐版本语义对照；不得把 JSON-RPC 2.0、SDK 版本或其他同名协议当成 ACP v2。未取得可核验规范或真实对端时，该版本保留未验证/阻断状态并向用户说明影响，由用户决定等待、调整范围或授权其他路径，不能伪造 v2 消息或静默只交 v1。

标准操作只按协议版本和协商能力选择策略；相同版本/能力的不同厂商应复用相同路径。Harness 名称只标识接入配置、展示及证据，不决定标准语义。非标准扩展与标准实现隔离，按显式扩展标识和能力门控；发现必须依赖厂商私有协议、缺少必需能力或语义不兼容时，停止受影响接入，报告版本、缺口、影响、证据及可选处理方式，等待用户决策后才调整范围或增加桥接。此设计不预先授权私有适配。

升级先分析程序、协议、扩展、配置及原生存储变化，再重新协商并运行受影响合同及真实验收。旧版本结果保留为旧版本历史，不冒充新版本通过，也不因版本号变化自动改代码。标准合同兼容时仅更新接入信息和证据；发现实际不兼容时报告用户决策。验证矩阵以 Harness × 协议版本 × 可选能力建立，只运行实际可用组合，不能假定每款同时支持 v1/v2。

### 1. 单节点所有权与模块边界

节点应用服务拥有 Command、Run、实例及订阅；Web 仅发命令和读取投影。领域对象不持有子进程句柄，适配器将协议事件映射为保留原始字段的输入，存储记录与 Web 响应独立转换。选 Rust 节点、TypeScript Web 与本地 SQLite 事务存储的实施方向；正式引入库时逐项审查许可证、维护、安全与 Windows 支持并锁定版本。相比内存状态或逐事件永久日志，SQLite 提供命令去重、事务与按会话查询，且无需独立数据库服务；不把实时流等同已提交事务。

### 2. 命令与执行事务

所有变更命令带客户端请求ID、动作摘要、操作者、目标与结果引用；唯一键为操作者身份及请求ID。同ID异内容返回冲突。输入受理事务检查会话未被释放锁定且无非终态前台 Run，保存 Command 和 Run 后才派发。派发前崩溃的未决命令不自动重发；重启统一标记需协调的中断/未知，避免数据库与外部进程之间无分布式事务造成重复副作用。取消仅产生取消命令，不提前结束 Run。页面运行状态由已确认资源事实推导。

### 3. 原生绑定与适配器门禁

Session 保存平台ID、Harness定义ID、原生范围ID、原生会话ID、目录ID及不含凭据的恢复参数；原生范围包含 Harness 类型、安装/配置根与身份上下文的稳定标识。选择 Codex 的固定发布版本及匹配 ACP 适配器作为实现前兼容性门禁，逐项记录协议版本、可执行文件摘要和真实能力。当前只有重设计中的调研，无固定版本实测；未通过创建、结构输出、审批、取消、释放恢复必需链路时不得将接入标为完成。无重放恢复优先；若只能重放，必须证明来源条目映射和恢复边界，否则阻止该恢复路径，不使用正文哈希去重。

### 4. 条目、位置与保存

ConversationItem 保存会话ID、轮次ID、条目ID、来源ID、首次位置、类型、结构载荷、内容版本与已提交版本。每次原始可见条目在进入异步处理前分配位置；按会话以事务预留位置区间，崩溃放弃余量，允许间隙但不复用。工具后续输出更新同一条目；不能证明同源时新增而不猜测合并。轮次从被受理用户输入建立，子载荷从首次接入即原样保留。数据库合并保存最新值，不存逐 token 永久日志。

保存触发沿用已确认的500毫秒或累计64KiB脏数据；结束、审批前和正常释放强制刷新。每会话脏缓存16MiB、节点128MiB，高水位80%时停止受理新输入并立即刷新；提交持续失败或达到硬上限时请求取消并协调终止所属输出，溢出内容只标记缺失，不无限增长。缓存容量和高水位是实施设计默认值，需真实高速输出验证，不能声称已达到吞吐指标；不得据此覆盖已确认的保存周期和大小阈值。大块正文写入临时附件，校验后原子入库引用；原始字节可复用但消息身份不复用。

保存进度与当前/已提交版本仅供后端及客户端同步内部使用；正常页面不显示保存中、未保存、已保存或提交版本。只有实际保存失败、异常丢失或完整性无法确认时显示错误；该展示调整不改变持久化权威、版本合并、缓存阈值及停止策略。

### 5. 审批与退出

审批ID关联 Run、实例连接代际与原生请求ID。事务比较未裁决且仍有效后接受唯一决定，交付结果独立保存；未知交付不自动重试。实例退出立即失效相关审批，不能在新连接重用。实例管理器拥有读写任务、取消令牌与 Windows Job Object；关闭先禁止新命令、协调 Run 与审批、刷新历史、关闭会话、关闭无引用实例、等待任务结束，超时再终止所拥有的完整进程树。共享实例不能为单会话强杀；无法安全隔离时返回失败并保留管理责任。

### 6. 管理边界

目录在节点解析绝对路径并执行访问检查，不以目录锁限制不同会话。命令、订阅、附件及审计每次复核可信身份和目标权限，撤销沿用节点入口合同。审计存动作元数据和状态引用，不复制提示词、凭据或恢复密钥。外部 CLI 的占用仅在适配器有可靠证据时报告，不承诺并发写入安全。

## Risks / Trade-offs

- [先显示后保存存在尾部损失] → 提交事实内部管理，正常页面不显示保存状态；仅异常时显示错误及可能缺失范围，失败阈值停止，验收真实崩溃窗口，不承诺零丢失。
- [三款能力差异尚未实测] → 共用端口按能力分支，固定版本探测为编码适配器之前的门禁；缺必需能力记录阻断，不修改产品语义绕过。
- [SQLite单写者与高速输出冲突] → 合并提交、独立有界写入队列，真实长会话验证后调整实现参数。

## Migration Plan

新库从空目录建立版本化模式，不迁移旧系统。所有初始化在专用测试根验证，不触碰实际原生数据。先验证节点认证再启用 Codex；兼容性门禁未通过时不开放对应操作。回滚停止节点并保留新库/附件和原生绑定，不降级写入未知模式；恢复旧可执行文件前核对模式兼容，必要时仅在隔离目录使用备份。

## Implementation Gate

固定真实 Codex/适配器版本与 Windows 程序路径、依赖安全审查、独立 tests/plan/tasks 和 reviewer 方案检视均为后续实施前工作。真实执行、进程树清理、保存故障、审批竞态与恢复尚未执行；当前文档通过不代表这些能力可用。

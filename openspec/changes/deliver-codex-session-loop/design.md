## Decisions

### 0. 通用 ACP 与多版本兼容边界

PV-001：每个新连接优先以平台已实现并验证的最高 ACP 版本按对应规范发起协商，优先使用最高共同可用版本；不以厂商、旧报告、上次低版缓存或缺少某程序新版实测报告固定低版。协商引导按各版规范处理，不假定握手结构相同或客户端能枚举对端所有版本；对端合法返回低版时遵守实际选择，分别呈现发起版、选择版及有依据的原因，未提供原因则如实显示。仅在高版无共同可用支持且规范允许时回退；网络、认证或已选版业务失败不构成版本不支持证据，不自动降版重发副作用。新版本的已实现、实际协商能力按该版语义提供，不压为低版交集；未实现未来版不宣称支持。重连及升级后的新连接重新优先最高可用版，存量有效连接不热切版本，旧请求/审批不跨代际重发。行为权威见 harness-management 的“优先最高共同可用协议”。

运行时准入遵循 harness-management 的四类状态：已实现并验证的公共协议处理、当前协议必备或声明的对端能力、当前操作安全条件、独立实测证据状态。前三项均满足才执行标准操作；程序报告缺失只影响证据标识，不构成版本白名单。未实现方法、未知扩展及安全条件缺失明确拒绝；不自动执行副作用做探测，实际协议故障只停用受影响连接操作并按未知结果处理。

2026-10-30 用户确认：Harness 专项工作负责能力调研、真实验证与接入配置，不在代码中绑定某款 Harness 的 ACP 版本。固定程序版本仅为受测证据可复现；通用协议实现仍需支持明确的协议版本，但运行时每个连接独立协商并选择版本策略。当前连接代际内不自动变更已选协议，重新连接重新协商；不把程序版本号或历史报告当作协议映射。连接使用的实际能力来自当前协商及有效验证，不能仅凭厂商名称开放功能。

采用端口与适配器模式隔离协议和业务，使用策略模式封装 ACP v1/v2 的编码、解码、能力解释、完成/取消、审批及恢复语义；由连接初始化入口按经核实的版本协商结果选择版本策略。公共传输、请求关联、连接生命周期和错误基础设施只实现一份；只有语义确有差异的部分进入版本模块，不复制整个客户端。版本协商引导必须遵循各版本正式规范，不先假设 v1/v2 握手相同，也不按程序名或 SDK 包版本推断 wire 协议版本。无共同已实现版本则明确拒绝，只有规范允许且不会重复产生副作用时才可协商回退；不能运行中混用或失败后重发输入。

规划目录统一为 app/src/adapters/acp/（公共客户端、版本策略及转换）、app/src/platform/（进程所有权）和 app/src/harnesses/（启动及本机认证引用配置）。具体内部文件名在实施时确定，不为每款 Harness 建立完整协议目录。应用依赖稳定业务端口，通过依赖注入接入所选版本策略；业务端口保留结构化内容、来源身份、协议版本和必要原始/扩展载荷，不能压成最低公分母文本，也不强迫不同版本拥有相同生命周期。

ACP v1/v2 是用户确认的兼容目标，不是两版已经发布或实测通过的声明。实施前分别记录官方规范地址、修订、实际协议标识及稳定/草案状态，并建立逐版本语义对照；不得把 JSON-RPC 2.0、SDK 版本或其他同名协议当成 ACP v2。未取得可核验规范或真实对端时，该版本保留未验证/阻断状态并向用户说明影响，由用户决定等待、调整范围或授权其他路径，不能伪造 v2 消息或静默只交 v1。

标准操作只按协议版本和协商能力选择策略；相同版本/能力的不同厂商应复用相同路径。Harness 名称只标识接入配置、展示及证据，不决定标准语义。非标准扩展与标准实现隔离，按显式扩展标识和能力门控；发现必须依赖厂商私有协议、缺少必需能力或语义不兼容时，停止受影响接入，报告版本、缺口、影响、证据及可选处理方式，等待用户决策后才调整范围或增加桥接。此设计不预先授权私有适配。

升级先分析程序、协议、扩展、配置及原生存储变化，再重新协商并运行受影响合同及真实验收。旧版本结果保留为旧版本历史，不冒充新版本通过，也不因版本号变化自动改代码。标准合同兼容时仅更新接入信息和证据；发现实际不兼容时报告用户决策。验证矩阵以 Harness × 协议版本 × 可选能力建立，只运行实际可用组合，不能假定每款同时支持 v1/v2。

### 1. 单节点所有权与模块边界

节点应用服务拥有 Command、Run、实例及订阅；Web 仅发命令和读取投影。领域对象不持有子进程句柄，适配器将协议事件映射为保留原始字段的输入，存储记录与 Web 响应独立转换。选 Rust 节点、TypeScript Web 与本地 SQLite 事务存储的实施方向；正式引入库时逐项审查许可证、维护、安全与 Windows 支持并锁定版本。相比内存状态或逐事件永久日志，SQLite 提供管理命令去重、事务与管理事实查询，且无需独立数据库服务；不把实时流等同已提交事务。

### 2. 管理事务与输入交付

命令身份、摘要、平台执行归属、审批裁决与交付结果仍需可靠记录。受理不等于原生接收或完成，未知不重派。平台不再事务创建永久聊天输入、Turn 与历史正文；外部输入只在原生视图呈现，不补造平台 Run。临时输入及上传只为在途交付服务，摘要、消费及清理边界需在新合同中补齐。

平台 Run 只追溯平台输入，原生前台活动及后台工作以当前协议事实独立判断。Agent 自发开始前台工作时不创建 Run，但普通输入互斥仍生效；前台完成也不证明后台停止。不要求每次活动都有协议未提供的执行 ID，不能把所有工具及审批强行挂到最近一个 Run。正式容量策略前的资源所有者也必须保守保护未知活动，不能依赖非终态 Run 集合代表全部原生工作。

异常后的新输入准入以 session-execution 的“异常后重新准入”为准。分别记录旧执行是否停止及副作用是否已知；资源所有者确认旧执行及其所拥有的执行资源收敛，或已验证原生查询确认旧执行不再活动且恢复不重新派发后，才能解除旧前台执行阻挡。新请求还须重新校验原生身份、唯一归属并完成所需恢复；旧 Command/Run 保持中断或未知事实，重试原请求不再派发。单纯重连、握手或超时不解锁，不为收敛单目标强杀其他共享会话；原生后台活动不明时保留相应资源保护。

### 2.1 请求有效期与管理记录保留

请求有效期和去重保护以 session-execution 为权威，新会话管理审计的保留及容量以 management-audit 为权威。请求默认24小时有效及10000个受保护命令名额、审计默认至少90天及100000条上限，是本轮为有界管理数据选择的设计默认值，不将归档节点撤销接口的24小时过期后可重新执行语义带入新产品命令。接受前确认所需记录及结果空间，不能为新动作驱逐有效去重、未知结果或未收敛资源事实；容量不足时拒绝新危险受理，安全控制走独立收敛分支。

节点为新的产品命令签发用途独立、不可篡改的请求身份，绑定节点请求代际、操作者、动作、目标及业务载荷摘要、签发时刻和固定截止时间。签发只建立请求身份，不授予权限、不消费原生动作；每次受理仍重新认证及验证目标、摘要和审批。使用已审查的标准签名封装及独立用途验证，不自行设计密码协议，也不要求永久保留全部签发清单。客户端保留完整身份重试，不能自动刷新期限或申请新身份重派未知动作；需要用户以新请求显式发起的后续动作与旧请求分别表达。

受理时先验证请求身份、截止及当前节点请求代际，再查去重记录和事务受理；同一身份内容冲突拒绝。记录即使已删除，原签发信息也能证明其过期或代际失效，不能由“查不到记录”取得派发资格。有效请求到期不终止已派发工作或原生权限请求；已受理但尚未开始派发的命令到期停止新派发，可能已派发则保留未知且不重派。过期动作请求明确拒绝；仍在的原事实通过独立只读查询获取，已清理结果返回不可查询，不据历史缺失执行。

清理前先证明不存在工作、审批交付、未知结果核验及资源责任，且原请求已不可再执行。过期拒绝水位与清理事务协调，水位及已确认过期事实不能回退；同进程使用单调经过时间辅助判断期限，正常重启保留签发验证、请求代际和去重事实。墙钟回退或期限无法可靠验证时，拒绝新危险派发并保留安全控制，不能让已过期身份复活。隔离备份恢复使用不同的新节点请求代际；旧代际及水位仅作历史记录，不通过恢复旧库、回滚时钟或复制密钥延续执行资格。

### 2.2 管理存储故障的安全边界

| 故障窗口 | 处理 |
|---|---|
| 新危险动作受理或必要派发事实未可靠提交 | 不向 Harness 派发，报告失败或受理未知，先核验原记录再处理同身份重试 |
| 批准决定未可靠提交 | 不发送允许，不接受冲突决定；必要时按协议安全拒绝或取消等待，单独报告未保存事实 |
| 原生动作或审批响应可能已发送，结果记录失败 | 保留可证明发送、完成或未知范围，不重发、不把原生事实改成未发生 |
| 有权安全取消、拒绝、显式关闭或节点退出无法写审计 | 仍尝试收敛，身份及当前资源归属不可验证时只保留经操作系统身份验证的本机关闭；不扩大为批准、输入或原生删除 |
| 存储恢复或节点重启 | 先核验旧工作、请求、资源和未提交结果，再持久化协调，不凭旧记录自动派发 |

故障收敛控制以当前节点运行代际及资源代际为范围，进程内串行防重复并保留观察事实；换代后旧控制身份直接失效，不能再次作用于新的工作。它不是绕过去重窗口的新危险命令接口，也不承诺未提交结果可跨重启恢复。既有认证或资源目标不能可靠校验时不执行网络控制，不以存储异常赋予新权限。单纯展示缓存失败不会进入这套管理存储故障规则。

管理结果未可靠保存时，即使已观察到关闭也保留账本协调责任，不用空出的进程事实直接加载新目标。故障恢复的补记包含实际核验时刻、来源及原记录缺失范围，不伪造原时间点已经提交。详细 wire 编码、签名用途、原子事务和故障注入入口须在新版合同中固定并独立检视，本轮不恢复旧 session-contract 或执行迁移。

### 3. 原生绑定与适配器门禁

2026-10-30 RP-001 门禁：标准历史重放为基础接入条件，列表、平台分页与可选原生分页、稳定身份、附件、外部更新及查看激活分别取证；缺重放暂不接入。下段旧探测只证明原版本对应执行范围，不证明新增重放准入。

Session 保存平台ID、Harness定义ID、显式接入来源ID、原生会话ID、目录ID及不含凭据的恢复参数。原生范围ID沿用为接入来源引用，不再表示平台已验证实际存储或账户等价。每份启动配置显式引用来源；同来源同原生ID经多个入口访问时共享协调及名额，不同来源相同原生ID分别管理，不承诺自动识别它们是否指向同一物理存储。没有来源引用时补齐配置；已有来源不因缺少物理等价证明被拒绝，不新增厂商探测器或私有文件解析。选择 Codex 的固定发布版本及匹配 ACP 适配器作为实现前兼容性门禁，逐项记录协议版本、可执行文件摘要和真实能力。WP1已有固定程序的有限协商实测，无登录新建最初因认证受阻；用户授权复用登录后创建成功但首轮模型流超时，范围见本文末及WP1探测报告；未通过创建、结构输出、审批、取消、释放恢复必需链路时不得将接入标为完成。产品准入先确认标准重放支持；已准入后，仅恢复上下文可按协议选择不重放，但查看历史需协调通用标准重放。缺少跨加载稳定关联时重建视图并失效旧代际，不要求厂商提供额外标识或按正文哈希去重。

Harness 默认继承节点环境变量，由启动配置显式覆盖对应值；保留现有进程边界的 Windows 同名变量处理，不引入白名单或环境指纹准入。不将默认继承列为不兼容或必改缺陷，配置引用及诊断仍不得泄漏凭据值；不在本轮增加环境隔离系统或修改进程实现。

### 4. 原生读取端口与当前连接视图

当前连接指节点拥有的 Harness 连接代际。视图由节点共享，浏览器刷新或切换设备只改变订阅，不直接丢弃缓存；预算淘汰明确范围并逐客户端授权。实际资源释放或连接换代后视图失效，重新查看协调标准重放；失败或不能安全加载时明确限制，既定自动回收不为保留正文而改变。历史重放代际与当前连接分别建模，不用旧代际视图覆盖新来源。

首个闭环共用 ACP 重放处理，提供基础原生发现、按标识加载、外部会话浏览及刷新重放。v1 按规范使用已声明的 load 能力；v2 按其已实现的标准重放请求及完成边界处理，不按厂商名分支。列表、附件、父子关系及更新通知分别取证；无重放的对端可初始化用于报告能力，但不开放产品会话操作。外部扩展保持显式协商，不提供厂商专用读取器、私有文件解析或其他当前连接降级。

按原生目标协调在途重放，分离重放读取代际、连接代际及实时消息来源，流式更新有界候选视图；只有协议重放完成及必要校验后才发布完整范围。缺跨加载稳定 ID 时重建候选视图并失效旧代际，不按文本去重。标准重放可遍历全部历史，正文、元数据、单帧解析及在途页都有预算，不把全部历史同时驻留内存；不落为可跨重启恢复的聊天档案。页缓存和缺页重新读取由 history-navigation 管理，首次成本随总历史增长，不承诺每页只传相应轮数。

重放端口向分页层报告本次读取代际、可验证轮次及完成范围，不把新代际等同必须返回首页。缺页后的可靠续读或独立重新定位由 history-navigation 统一定义；定位坐标仅在本次重放解释，不能用摘要比对或全历史常驻索引弥补身份缺失。重新加载无法证明安全时仍拒绝本次读取，不为定位取消工作。

历史身份、来源顺序和更新语义由原生提供；重放内临时位置不得伪装成跨重启身份。实时缓存与历史仅在可靠关联时衔接；重放能力缺失执行准入拒绝，本次重放失败与原生内容不再保留分别报告。删除平台入库、位置预留、提交版本、500ms/64KiB 保存及强刷要求。

查看允许激活进程及需要的会话加载，不限制只读；查看不等于新输入或工具批准。节点管理实际加载、共享实例、容量和关闭顺序，辅助服务进程不自动算一个主会话。实际重放刷新资源策略的无活动计时，但不产生新 Run、复活旧审批或建立后台任务保护；纯页面及缓存访问不保活。展示缓存满或慢订阅只处理读取通道，不作为取消执行的条件。必要管理数据失败仍按安全边界处理。

### 5. 审批与退出

取消的活动对象独立于取消命令状态。v2 在前台已可靠 idle 且无待确认输入时不需要额外完成通知，节点记录取消发送或适用权限请求的安全处理，不新建 Run 或输入阻挡，不声明后台已全部停止。前台活动或输入结果尚未确认时按真实协议终态协调，不能只看 idle 清除待插入输入；取消与自然完成交错时接受正常终态，不等第二个 cancelled 更新。发送顺序与原生目标由同一协调通道处理，后续真实新工作不被旧取消结果错误结算。具体行为以 session-execution 为准。

审批以节点验证的原生目标、实例连接代际及当前真实请求为归属基础，可靠关联平台输入时才记录 Run。原生操作上下文也覆盖加载、恢复、后台和 Agent 自发工作；协议未给出精确工作分类时，可靠会话及有效请求归属已经足够，不借用最近 Run 或伪造输入。Run 关联只用于追溯，失效由对应版协议和实际请求生命周期决定：前台 idle、Run 终态及加载返回不一概失效后台审批；已答复、取消、连接失效或可靠证明专属工作和请求已结束时才拒绝旧请求。会话取消须处理该版协议要求的全部待处理请求，不能因无法区分前后台遗漏。新连接重新建立的真实请求重新验证和裁决，不重用旧决定。具体行为以 permission-approvals 为准。

操作上下文只记录必要管理元数据，不成为聊天档案。事务比较未裁决且仍有效后接受唯一决定，交付结果独立保存；未知交付不自动重试。实例退出立即失效相关审批。实例管理器拥有读写任务、取消令牌与 Windows Job Object；关闭先禁止新命令、协调全部已知原生工作及审批、记录必要管理结果、关闭会话、关闭无引用实例、等待任务结束，超时再终止所拥有的完整进程树。共享实例不能为单会话强杀；无法安全隔离时返回失败并保留管理责任。自动回收在调用关闭之前还需满足 session-resource-policy 的完整活动及关闭窗口证据，不能把显式关闭会取消工作的语义当作自动回收安全证明。

上述正常写入顺序不构成故障安全取消或关闭的前置阻塞。决定提交未知时不交付允许；已有允许决定但原生请求随后失效或协议要求 cancelled 时，安全协议响应与人工最终裁决分别记录，不覆盖用户决定或制造第二个裁决。响应可能已发送但记录失败时不再次发送。故障例外只沿 §2.2 收敛，不能借此绕过正常新危险命令的持久化门禁。

### 6. 管理边界

目录在节点解析绝对路径并执行访问检查，不以目录锁限制不同会话。现有management_ws仅允许node.info/device.list/device.revoke，其余action返回invalid_request；会话在新版合同完成后显式扩展同一认证入口，复用trust client_gate及writer撤销协调，不新增旁路。命令、订阅、附件及审计每次复核可信身份和目标权限，撤销沿用节点入口合同。审计存动作元数据和状态引用，不复制提示词、凭据或恢复密钥。外部 CLI 的占用仅在适配器有可靠证据时报告，不承诺并发写入安全。

原生内容作为不可信数据进入展示层，实时与重放共用同一安全渲染边界。保留结构及必要原始字段与渲染分别建模；原始 HTML、主动 SVG、终端控制、未知扩展均不能取得脚本或管理执行权限，审批控件的真实目标不从描述文本推导。内容、命令和路径中的误导字符在安全展示中显露或去除其效果，必要来源载荷仍惰性保留。

资源引用先解析为待访问目标，实际读取重新校验权限、根范围、访问方式、重定向及预算；不提供凭原生 URI 就可调用的任意本机文件或 URL 代理。远程资源默认占位，用户触发也不能绕过受限网络、凭据和目标校验；主动附件通过安全下载或不具管理权限的隔离预览交付，不以受信同源 HTML 执行。TLS、同源 CSP 与身份边界继续复用，具体产品要求以 structured-history 的内容安全及资源引用条款为唯一规格来源。分页及子树只复用该显示与资源端口，不另建宽松入口。

## Risks / Trade-offs

- [标准重放缺失] → 按通用准入暂不支持，不用当前连接降级、永久聊天副本或厂商读取器兜底。
- [原生修改与分页竞态] → 按可验证来源身份、边界和读取代际处理；不能续读则失效重取，不假装原生提供事务快照。
- [移除聊天库误伤安全事务] → 保留命令去重、执行所有权、可信审批与交付记录；正文与管理元数据分开建模。
- [原有开发工作与规格不一致] → 暂停实现，逐模块评估复用，不在本次删改任何代码或数据库。

## Migration Plan

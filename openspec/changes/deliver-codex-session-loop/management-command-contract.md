# 管理请求、共享队列与单次派发合同：Q-001

状态：2026-10-31修订候选，替代旧§4B。行为权威为session-execution、management-audit及acp-platform-constraints。原阶段代码/报告仍属旧快照，本轮不是实现或独立检视结论。

## 1. 请求登记与受理授权

节点登记不透明请求ID，绑定动作、目标、操作者及内容版本；不再签每动作凭证或以24小时/clock floor判输入资格。身份未知不作为新动作，已处理重试返回原事实，异内容冲突。入队、编辑、取消、优先发送、失败继续是不同管理意图，各自在入口验当前操作者；有会话操作权限的B可操作A队列。

受理成功即由节点负责。输入及审批派发不再检查原actor当前trusted/auth_generation；原actor仅记录授权时事实。读取和新命令继续检查当前身份。不能复用旧require_actor-at-claim或持client_gate到首次写的实现，否则不符合新规则。

## 2. 共享队列与资源事实

每目标三个等待项，节点统一入队和检查容量；队列正文不持久化、无TTL，重启清空不专门提示。Run活动占用与队列分开，不可每入队立即reserve_input占同一work槽，也不能用accepted Run唯一索引拒绝第二第三条。

队列项有稳定身份、顺序和内容版本；编辑保留身份/位置并记录新授权，不覆盖原提交身份的内容绑定。发送与取消/编辑由节点顺序决定，查无项零发送；已经发送返回操作失败。已取出的发送意图仍可在进入传输前被可靠失效，但不能报告撤回已交字节。

普通派发前只核对队列版本/取消、唯一目标归属、当前资源及串行条件，不重验原actor，不以重放或旧输入期限阻挡。临时active保留等待；unknown核验，资源失效暂停，不自动换目标/新建会话。正常成功下一条；失败挂起旧项，新输入优先，用户点击继续才恢复旧项；可能旧工作活动时不能强行继续。

## 3. 中断和优先发送

只可从现有队列项选优先，满额新草稿不接受。优先请求与当前工作绑定，节点先发中断并观察旧工作实际结束，再只发送指定项，其他相对顺序不变。中断发送不是结束事实，旧回报不能结算新输入。空闲且无待插入不新增额外idle等待，自然完成不等第二个cancelled。

## 4. 并发与所有者

短状态协调决定队列顺序，不持会话或原actor锁等待SQL、writer、load/replay/prompt、Run或人工选择。接收循环不能等被命令持有的锁；事件与写意图有明确顺序、取消及owner关闭，审批/中断独立于普通队列。写取消失效潜伏资格，已可能交字节未知不重发。等待截止按用途用单调时间冻结，不用客户端时间，也不沿旧10/5/2秒产品化。

## 5. 必要状态、附加审计和重启

必要登记、去重、发送及资源事实可靠维护后才能相关派发；附加审计失败或满额只告警。编辑版本、开始发送及可能发送的元数据不得与正文混存。既有schema3/4仅为基线，不在本文臆造已验证的新DDL；迁移字段与CAS由下一实施子阶段冻结，旧数据不删。

重启不恢复队列正文。可证从未发出的项不应伪标副作用未知；已发送或可能发送项核验，不因无正文或actor离线重发。请求清理不复活旧身份；附加审计与必要状态寿命分开，输入不因节点校时失效。

执行失败时挂起原队列并保留项及顺序；后续新输入在前台/资源允许时直接优先执行，新输入成功不自动恢复旧项。点击继续后原项才重新加入可执行队列，不复制、重新授权或抢占当前新输入；新输入本身若需等待，仍遵守包含挂起项的三个未发送总名额，不建立第四等待项。正常队列满额新草稿规则保持，仅失败挂起后可直接执行的新输入走优先路径。

# 实际权限请求与节点交付合同：Q-001

状态：2026-10-31规划修订，permission-approvals为行为权威。已有schema4和旧报告仅保留原布局及原范围，不代表本合同已独立审查或实现。本轮不改旧数据和源码。

## 1. 原生来源与展示

请求必须来自当前协议owner实际读到的待响应RPC，绑定来源、原生会话、实例及连接代际，保留RPC标量类型、原始结构和广告选项。无需Run或工具关联；加载、后台及自发请求正常处理。未知subject或option kind可通用安全展示，人工只能选择原optionId，不能猜范围或自动允许；真实来源失效、错误形状和伪造选项仍拒绝。

历史重放及正文缓存不是审批前提，不为展示审批永久保存完整工具或提示正文。不使用旧单审批1MiB、连接8MiB、节点32MiB作为正文上限；真实来源/协议限制报告实际依据。非正文未决请求关联和关闭责任仍须有owner，不靠无所有者任务。

## 2. 受理与严格保存

提交决定时校验操作者权限、真实请求和原广告，节点接受至多一个最终选择，竞争客户端返回已有结果。必要审批决定必须可靠保存后才可发送允许；失败/未知零允许，附加审计失败不能被混作必要决定已保存，也不能据缺日志重新允许。

受理保存后节点接管交付，原审批者离线或撤销不重新验权；当前读取及新操作仍查当前权限。交付时仅验证当前原生请求/连接/广告有效，不复用旧client_gate到writer的actor围栏。原请求失效抑制允许，原用户决定与实际安全响应/未交付分开保存。

## 3. 单次响应与并发

人工selected与协议安全cancelled共用一次响应消费边界，已可能发送不得回退成可再次响应。保存决定不证明交付，write/flush不证明对端执行；结果记录失败保留可证事实，不补发另一种响应。节点中断时按当前协商版实际取消范围处理，不以Run结束、idle或load响应批量失效请求；恢复不复活旧请求。

接收循环独立于命令锁，不能等决定完成才继续pump；长SQL、人工选择、writer和Run等待不持会话互斥。审批和中断不进入普通输入队列。关闭/取消由owner负责，未发送意图可失效，可能发送未知不重发；共享实例不因单会话关闭伤及其他会话。

## 4. 实施与验证边界

下一子阶段固定真实RPC关联、必要决定事务及单次交付布局，不复制旧每动作JWS、time_floor、actor-at-claim或正文账本作为新前置。旧schema列保留，迁移和故障hook须独立定义、审查；不自动清库。

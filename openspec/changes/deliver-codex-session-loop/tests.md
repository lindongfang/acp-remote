- 本独立tester只维护验收定义，全部产品用例未执行。主执行获Q-002窄授权删除ACP累计请求阈值并另行回归；本候选不代签该代码验证，也不扩展为完整队列实现授权。候选结构检查只核对定义，不代表需求已经实现。正式实施前，由独立 reviewer 核对场景覆盖和新增迁移、队列交接、原始帧关联及有效配置合同；已核对本轮 plan 的 WP1→WP5候选→WP6 顺序及后续 WP2→WP3→WP4 依赖；正式执行仍须冻结具体执行者、独占数据/端口/target和可用入口，不把工作包角色安排当实际资源已备齐。

- 现有 `cargo test --manifest-path app/Cargo.toml --test session_loop_acceptance --locked` 及 `acp_message_id_acceptance`、`acp_view_observations_acceptance`、`acp_tool_projection_acceptance`、`domain_borrow_acceptance` 等仅作为可用入口定位；其内部现有期限/预算等旧断言须先按本文件重基准。L3 先行不完成 L5 义务，CL-086/100/101 的节点合同验证不替代 CL-030/046/054/057/060/085/105–107/114 的真实分支。

## 长期规格复用及回归范围

- `openspec/specs/node-access/spec.md` 及 `testing/suites/node-access/tests.md` 仍负责节点身份、网络认证、本机 OS 身份、进程所有权及重启信任；本 change 不把删除每动作签名/输入期限扩展为取消既有控制通道认证。
- `openspec/specs/client-trust/spec.md` 及 `testing/suites/client-trust/tests.md` 仍负责认证、当前读取/新操作撤销、信任与实时审批分离。其长期归档设备撤销期限不被本轮输入无 TTL 覆盖；已受理工作由节点接管的交界由 CL-092/093 验证。

## Cases

### CL-001 真实构建及类型检查

- 用例级别：L1
- 操作步骤：按 README、根 package.json 与 clients/web/package.json 执行 npm run check、npm run build:rust；Windows 测试按 testing/ci/windows-owner.ps1 准备实际 owner 环境。另执行 openspec.cmd validate deliver-codex-session-loop --strict、git diff --check。记录各入口实际测试数量、退出码和快照。
- 预期结果：编译、Web 类型/测试/构建、Rust 格式/clippy/测试及文档检查分别有结果；零测试、仅静态通过或旧合同测试通过不视为 Q-001 功能通过。

### CL-002 静态合同和供应链检查

- 用例级别：L2
- 操作步骤：按 .github/workflows/ci.yml 执行依赖审计与密钥扫描，检查产品依赖审查/锁文件，真实 BASE/HEAD 用 npm run lint:commits -- --from BASE --to HEAD --verbose；逐项核对本文件场景引用与实施合同。
- 预期结果：供应链、提交和静态合同检查分别可追溯；上游或开发工具审计不代替产品依赖审查，无专用脚本时人工核对而非虚报机器验证。

### CL-003 领域边界及异常状态

- 用例级别：L3
- 操作步骤：确定性模型覆盖节点登记去重、共享三个等待项、入队/编辑/取消/发送先后、正常优先中断、失败挂起旧项与新输入优先、点击继续恢复、受理后撤销、独立原生活动及早到终态；另执行CL-043–045/056/066/067/072–074/100和110–113的模型分支。
- 预期结果：数量、队列身份、可执行/失败挂起状态、前台与插入事实独立；并发结果对应节点顺序，新输入成功不恢复挂起旧项，继续不重复受理或抢占当前工作；模型只证明其输入前提下规则。

### CL-004 事务资源与并发协作

- 用例级别：L4
- 操作步骤：用自有全新库及 schema1/2/3/4 一致性副本，对编码前独立检视通过的新迁移合同逐事务注入失败并核对原身份、信任、撤销、管理及旧正文摘要；在必要登记、审批保存和派发交接前后崩溃。并发相反裁决与连接失效交错，检查正文/编辑旧版本未落盘。
- 预期结果：迁移原子且失败回滚，未知/残缺库拒绝不重建；旧数据保留，新入口不读写旧正文；必要事实可靠后方可派发，队列正文不恢复，可能发送不补发，裁决唯一。当前尚未冻结的新 DDL 不预设 schema5 或宣布可执行，缺合同/入口记录受阻。

### CL-005 能力未证实

- 用例级别：L5
- 操作步骤：登记 Harness 与目录后分别提供缺协议恢复依据、平台未实现能力、仅缺程序历史报告但标准与安全条件满足的组合；查看定义、当前协商、证据状态及原生调用。
- 预期结果：真正缺能力/安全条件时相应操作拒绝且不创建替代会话；仅缺该程序实测报告不拒绝已实现标准路径，证据仍未实测。登记不自动运行有副作用探针，不泄露配置凭据。

### CL-006 页面断开

- 用例级别：L5
- 操作步骤：真实节点执行中关闭/断网/退订页面，再用另一可信客户端查看已保留输出和有效审批；观察节点所有者及调用。
- 预期结果：客户端断开不取消工作或 Harness 连接，节点继续管理；退订只影响该订阅，不清空共享视图，不承诺已交网络栈数据收回。

### CL-007 共享实例释放

- 用例级别：L5
- 操作步骤：同实例两个自有会话并行，对一个显式释放；在可隔离及不可隔离两分支核对另一会话与资源树。
- 预期结果：可隔离则只释放目标，不能隔离则明确拒绝并保留责任；不强杀其他会话，不凭缓存清空判释放。

### CL-008 释放失败审计

- 用例级别：L5
- 操作步骤：令释放已受理而关闭失败/超时，查命令、审计与另一客户端状态；对照真实关闭确认但管理结果未保存。
- 预期结果：受理/关闭/结果持久化分别表达，失败或未知不记完全成功，不显示空闲或复用未协调容量。

### CL-009 已撤销客户端访问

- 用例级别：L5
- 操作步骤：两个可信客户端订阅/读取会话、队列、引用块、附件及审计，屏障撤销其一；撤销COMMIT后尝试新输入/取消/编辑/继续、订阅及逐块读取，另观察其撤销前已受理输入。
- 预期结果：撤销后新受理及尚未交网络栈的受保护读取停止，缓存/引用不绕过身份；撤销前已受理输入继续由节点规则处理，不因撤销自动取消，不声称收回已写字节；错误无敏感正文或凭据。

### CL-010 原生状态缺失

- 用例级别：L5
- 操作步骤：先有缓存及管理绑定，再让原生会话无法读取/恢复；清缓存后查看与继续输入，检查原生调用及绑定。
- 预期结果：明确原生缺失或读取失败，管理审计仍可查；不拼接命令/审计为聊天、不承诺旧全文、不静默新建或灌入平台副本。

### CL-011 释放时保存失败

- 用例级别：L5
- 操作步骤：在隔离真实节点对显式释放注入管理记录写失败及底层关闭失败，确保操作者与资源仍可验证；共享实例保留另一会话。解除故障后核验并补记，再观察容量。
- 预期结果：不再有聊天强刷前提；仍尝试安全收敛，实际关闭与记录失败分别报告，未持久协调不报完全成功/空闲或复用容量；共享会话不受强杀。

### CL-012 恢复重放旧消息

- 用例级别：L5
- 操作步骤：恢复时重放旧条目及重复正文的不同条目，分别有可靠来源关联和无跨加载 ID；混入实时输出及旧代际迟到响应。
- 预期结果：旧历史不成新回复；可靠关联才衔接，无依据重建/分开并说明限制，不按文字/摘要去重，不让旧代际覆盖新视图。

### CL-013 不支持的请求

- 用例级别：L5
- 操作步骤：协议对端给未知主题、未知选项提示种类但真实请求及 optionId 可验证的请求；人工选择原广告选项。对照结构错误、伪造选项、已取消请求，以及无 Run/精确前后台类别但归属真实的请求。
- 预期结果：未知展示扩展安全通用展示并说明限制，用户可选择真实原选项；未知内容不自动允许。错误结构/伪造选项/失效请求拒绝，缺 Run/工作细分类本身不构成来源无效。

### CL-014 两客户端同时审批

- 用例级别：L5
- 操作步骤：两个可信客户端屏障同时提交相反决定，再以原身份重试；统计决定记录与实际 writer 响应。
- 预期结果：最多一个最终用户决定，另一方得到原裁决事实；同身份不二次交付，不把传输写入当原生执行成功。

### CL-015 决定交付失败

- 用例级别：L5
- 操作步骤：唯一裁决保存后在交付前、可能写入后分别断连接或写失败；重试原决定并查询交付事实。
- 预期结果：保留唯一决定，未交付/未知/可证发送分开；未知不自动重发，不向新连接复用旧授权。

### CL-016 恢复后批准旧请求

- 用例级别：L5
- 操作步骤：异常后恢复同原生目标，操作旧连接待审批记录；再令新连接产生同标量 ID 的新真实请求。
- 预期结果：旧请求失效且零旧决定交付；新请求重新校验并独立裁决，不复用旧允许。

### CL-017 断线后重复提交

- 用例级别：L5
- 操作步骤：节点已登记输入，在响应丢失、浏览器重连及等待超过一天后用同 ID 同内容重试；分别让其仍排队、已发送、已完成及节点重启失去未发正文。查询节点事实及实际派发次数。
- 预期结果：重复返回原事实，不重复入队/派发；无统一期限。重启旧项不靠重试恢复正文，元数据仍防重；主动追加同文字须新登记身份，未发送与可能发送分别处理。

### CL-018 请求身份冲突

- 用例级别：L5
- 操作步骤：使用已登记 ID 改目标、动作或内容提交；同内容合法表达对照。另以有权 B 的新操作编辑原等待项并重试编辑操作，再用原提交 ID 携带编辑内容。
- 预期结果：登记 ID 内容冲突拒绝，原队列不被偷换；合法重复只返回原事实。编辑是新验权操作，保留项身份/位置并记录内容版本和实际操作者；不要求独立每动作签名、截止或时间水位。

### CL-019 并发输入

- 用例级别：L5
- 操作步骤：同来源同原生 ID 当前前台活动时，A/B 跨入口同时提交四条普通输入，再释放当前工作；对照不同会话共享目录并行，期间处理审批和中断。
- 预期结果：最多三个等待项全客户端共享，满额明确拒绝且不覆盖；前台至多一个，可靠成功后 FIFO 逐条派发。忙碌可入队但不派发，目录不建立锁，控制不排在普通输入后。

### CL-020 取消未完成

- 用例级别：L5
- 操作步骤：活动前台或已发送待插入输入存在时中断，只给取消发送/适用权限响应而无可靠终态；再提交普通输入，并对照空闲无 pending 分支。
- 预期结果：不把中断发送当已结束，不解除旧工作派发阻挡；剩余名额可排队，不向 Harness 发下一条。满额拒绝；空闲无 pending 按 CL-072 不新增额外等待。

### CL-021 派发后异常退出

- 用例级别：L5
- 操作步骤：输入可能已接收并产生副作用后断线/节点退出，无可靠终态，重启并重试旧登记ID；重新登记新输入并在需要时取得原生恢复，观察入队/派发及资源责任。
- 预期结果：已知发送与未知结果分开，不补发可能发送项，旧登记不因重启复活；所需恢复按当前能力校验，名额内可受理项与旧活动阻派发分别呈现，未知不改未发生，不从管理事实拼原生消息。

### CL-022 一轮完成

- 用例级别：L5
- 操作步骤：真实完成一轮但保留资源，再确认显式释放；另让关闭未确认，比较 Web 的前台结果与资源状态。
- 预期结果：一轮完成单独显示，资源仍加载时页面运行中；仅释放及管理协调确认才空闲，断线/idle 不替代释放。

### CL-023 工具晚完成

- 用例级别：L5
- 操作步骤：依原生顺序提供工具开始、后续文字、工具晚完成及重放重读；观察视图条目、位置及来源。
- 预期结果：更新原工具位置而非按类型重排；来源可关联才更新，无依据说明限制，不复制为新回复。

### CL-024 未知结构载荷

- 用例级别：L5
- 操作步骤：实时及重放提供未知结构/扩展、必要原始字段和支持结构；内容超过旧单对象/实体预算，读取安全视图与惰性原始数据。
- 预期结果：保留实际结构、来源和字段，未知明确显示限制，不静默降文本或执行主动内容，不因旧内容预算截断；真实分配/协议失败如实报告。

### CL-025 保存失败

- 用例级别：L5
- 操作步骤：使展示缓存更新/分配失败，同时管理存储及 Harness 连接健康、真实审批有效；观察工作、审批和错误。
- 预期结果：缓存故障报告读取限制且不当原生保存失败，不仅因此取消工作；有效审批不依赖聊天强刷仍按唯一裁决处理。

### CL-026 持续保存故障

- 用例级别：L5
- 操作步骤：持续流式输出跨越旧视图、实体、节点缓存与快照阈值；慢订阅暂停消费，随后恢复并核对已接收输出。并行审批、中断和队列操作，另注入真实展示故障及必要管理存储故障。
- 预期结果：不以旧输出容量驱逐、截断或间接正文限额，慢客户端不堵协议接收及控制；实际展示故障准确报告且不取消原生执行。必要管理故障按 CL-075–078，附加审计故障按 CL-094。

### CL-027 实时尾部丢失

- 用例级别：L5
- 操作步骤：已有原生历史与实时尾部时重启节点，确认内存视图丢失；让原生分别返回完整、压缩后历史及读取失败。
- 预期结果：从 Harness 重建实际可读内容，原生不再保留的尾部不补造；错误明确，不从平台管理记录恢复聊天，不宣称显示即已保存。

### CL-028 目录失效

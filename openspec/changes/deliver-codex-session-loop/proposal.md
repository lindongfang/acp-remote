# 通用 ACP 会话闭环，以 Codex 首验

## Why

已有节点与部分会话实现需要对齐“远端提交、节点共享排队、本地 Harness 串行执行”的最新确认。旧重放强制准入、派发时再次验证原操作者、固定期限及正文预算与该方向冲突，需要同步规格和规划，避免继续按旧合同接线。

### 硬约束与非目标

- Q-001只修订规格及规划；Q-002额外授权仅删除累计请求次数阈值的窄代码与回归。其余队列仍仅规划，不改数据库、历史runs/review或原生数据，不提交、推送、发布或归档。
- Harness 保有原生会话及历史权威；未发送队列正文和输出缓存不成为永久聊天档案。队列无期限但不跨节点重启保存，不要求专门丢失提示。
- 保留版本协商、显式来源、真实审批、资源隔离、原生删除范围及内容安全。能力逐项准入；不以产品缺口虚报支持或增加厂商私有读取器。
- 不将 ACP 未规定的大小称作标准上限；既有身份、认证控制通道与非正文资源策略不因本轮自动取消。

- **BREAKING** 将输入受理与 Harness 派发分开，加入节点共享队列；去重及已发生事实仍可持久记录，队列正文不持久化。

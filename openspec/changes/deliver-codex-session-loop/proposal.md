# 通用 ACP 会话闭环，以 Codex 首验

状态：2026-10-31 R2-001–003 复审修订；实现暂停。当前 specs 已补齐空闲取消、管理故障及期限去重，详细合同及完整验收计划仍待重基准。此前审查只适用于原快照，不授权恢复实现。

## Why

当前已有Windows节点、同源Web配对/管理、SQLite身份与撤销，会话与Harness闭环尚未实现。为按重设计建立可独立验收的交付闭环，需要打通 Codex 原生会话执行闭环，避免仅交付孤立模块而没有可观察结果。

## Success Criteria

ARCH-001 用户本轮要求：“同意，先修订整体设计和相关 change 的 spec，把这三个缺口补齐，自动回收的能力边界也明确一下，暂不改代码。”本 change 负责原生工作与平台 Run 分离、有效审批生命周期、通用内容安全及独立能力呈现；分页目标重新定位和自动回收资格分别由其所属 change 定义。本轮只交付规划修订，不扩展为代码、迁移或产品验收。

PV-001 最新确认：新连接优先平台已实现并验证的最高 ACP 版本，按规范使用最高共同可用版本及其实际能力，不因某 Harness 同时支持低版或旧实测记录而固定低版。规范回退、对端合法选择及业务失败分别处理，实际结果和原因证据如实呈现；不得因高版业务失败自动降版重发副作用。具体行为统一引用 harness-management 的“优先最高共同可用协议”。

DC-001 最新确认：默认继承节点环境并允许显式覆盖；原生会话身份采用显式接入来源及原生ID，同来源多入口共享协调，不要求证明物理存储等价或新增厂商探测。实际重放可刷新资源计时，但不创建执行或审批保护，行为由资源策略定义。本段取代下方早期说明中冲突的物理身份与查看保活假设。

### 本 change 的成功判据

- SC1：建立通用执行、审批和原生会话基础发现/读取；内容以 Harness 为准，仅有界缓存；平台保留命令去重、执行所有权和必要审批审计。
- SC2：验证原生来源和实际能力、外部更新后重新读取、缓存失效及历史不可用边界；外部操作不伪造为平台命令或审批。
- SC3：按新规格完成独立用例修订、方案检视、真实实现和交付验收；本次仅规格修订，尚未执行这些检查。
- SC4：规格覆盖无 Run 的原生前台、Run 结束后的有效后台审批、不可信实时及重放内容与资源访问，并明确标准重放不证明自动回收能力；相应独立用例及真实验证另行重基准。

## What Changes

- 建立通用执行、审批和原生会话基础发现/读取；内容以 Harness 为准，仅有界缓存；平台保留命令去重、执行所有权和必要审批审计。

## Capabilities

### New Capabilities

- `harness-management`：Harness 定义、版本、能力协商与实例所有权。后续文件为 `specs/harness-management/spec.md`。
- `workspace-registration`：工作目录登记、解析与可用性。后续文件为 `specs/workspace-registration/spec.md`。
- `session-execution`：受理、请求防重复、前台执行互斥、派发和取消。后续文件为 `specs/session-execution/spec.md`。
- `permission-approvals`：请求有效性、唯一裁决、交付与失效。后续文件为 `specs/permission-approvals/spec.md`。
- `structured-history`：原生会话发现、结构化读取、源顺序、有界缓存与能力限制。后续文件为 `specs/structured-history/spec.md`。
- `native-session-recovery`：原生绑定、正常释放、原生恢复与异常事实。后续文件为 `specs/native-session-recovery/spec.md`。
- `management-audit`：管理动作、操作者、依据与结果的审计。后续文件为 `specs/management-audit/spec.md`。

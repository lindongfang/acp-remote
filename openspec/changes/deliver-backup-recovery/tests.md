# Tests

来源变更：deliver-backup-recovery。本文件只定义验收，不记录执行结果。按当前 config 和测试模板整理，共 10 条用例，保留 BR-001–BR-010 的稳定编号、标题及行为断言；每例只列用例级别、操作步骤和预期结果。需求关联与共用信息集中说明，裸 specs 路径只指本 change 增量，不跨目录补位。

## 共用执行安排

- 首期 Windows 节点与受支持 Chromium 桌面 Web，不增加移动端门禁。仓库已有上游节点与 Web 开发实现及工程检查入口，本 change 仍待实现，不能把上游构建成功或规划齐备当成本 change 通过；开工前按上游实际交付、最终合同和固定版本重基准。
- 独立 tester 维护验收预期，coder 可补开发单元测试；独立 reviewer 检视用例/方案及交付证据，二者不继承 coder 对话。本次文本调整不是独立检视通过结论，旧 review 不覆盖新文本，修订后须重新检视。
- 在 D:/Project/acp-remote 按 README 和实际工程配置执行，固定提交或完整文件摘要及产品、Harness、适配器、协议版本；使用独立 owner、可信 Web 身份、专用配置/数据库/附件/原生根副本、端口、进程及浏览器 profile。真实 Web 验收使用受信 HTTPS。
- BR-001–004 从现有工程命令和实现后登记到 README 的领域/合同/故障入口执行；L3/L4 允许明确标注边界的可控时钟、存储故障及协议 fixture（模拟输入），不替代真实数据库、平台或 Harness 验收。缺对应目标、入口、工具、环境、权限或真实对端记受阻/未执行，不以零测试、只启动或模型推断判通过。
- 其余行为用例从实际节点终端给出的 HTTPS 地址进入本 change 的 Web 管理入口，交互优先 ego-browser，必要时使用协议探针、数据库查询和资源观测程序；按各例步骤核对操作结果、持久化及资源断言，不仅检查截图。BR-010 使用独立源码/证据检视和实际工具验证。
- BR-005–009 正常链路使用真实 SQLite、文件系统 ACL、附件租约及 Web；只在测试库/备份包和新建隔离空目录恢复，目标不得与实际库、附件、配置、原生或密钥根重叠。原生组件逐款固定版本取得一致导出或可证明静止的证据，平台与原生继续上下文证据分列；恢复默认只读离线，旧身份、信任、审批和命令不可执行，不自动切换生产。清理释放本次租约、快照与临时根，不删除完整备份或用户实际数据。
- 成功、失败、取消均关闭本次拥有的连接、读取句柄、快照、订阅、任务和完整进程树，释放临时锁、端口及本操作持有的租约，只清理自有专用副本并保留脱敏证据；不删除用户实际数据库、原生会话、密钥或配置。
- 正式结果另存 testing/runs/deliver-backup-recovery/，按 plan 的报告分工记录版本、OS/工具/依赖、逐 ID 状态、命令、实际断言与执行数量、证据及问题闭环。同版本、同范围且环境符合要求的有效证据可复用，不要求用户重复操作；必需项失败、未执行或待确认均不能视为验收通过。归档前按能力同步长期 suite 并保留 ID。
- 当前没有已识别的工具无法验证且必须人工介入的场景，原 BR-010 独立安全检视从 LX 调整为 L5，独立角色和安全范围保留。以后若确有必须由人判断的部分，只将该最小部分划入 LX，在步骤中说明具体原因；用户只需回答通过/不通过，Agent 记录 ID、受测版本和原始结论，未回复记待确认，不要求用户填写技术报告或代签。

## Cases

### BR-001 真实构建与类型检查

- 用例级别：L1
- 操作步骤：在仓库根目录按 README 和 package.json 执行 npm run check、npm run build:rust；另执行 openspec.cmd validate deliver-backup-recovery --strict 与 git diff --check，分开记录规划检查和产品构建结果。核对构建目标是否实际包含本 change 的节点与 Web 实现。
- 预期结果：真实编译、Web 构建和类型检查成功，检查覆盖本 change 的实际目标；现有上游开发实现通过构建不证明本 change 通过。缺对应目标或入口记受阻/未执行，规划校验不能代替编译或功能验收。

### BR-002 静态合同及安全检查

- 用例级别：L2
- 操作步骤：在仓库根目录执行 npm run check、openspec.cmd validate deliver-backup-recovery --strict、git diff --check、npm audit --audit-level=high；对实际 BASE/HEAD 执行 npm run lint:commits -- --from BASE --to HEAD --verbose，按 .github/workflows/ci.yml 的 secrets 作业执行密钥扫描。核对本 change 的协议合同、依赖审查和锁文件是否纳入实际入口，缺专用合同入口记未执行。
- 预期结果：无专项结构门禁；reviewer核对真实引用与覆盖，工具审计不代替产品安全。

### BR-003 包与目标校验

- 用例级别：L3
- 操作步骤：变异manifest版本/大小/摘要/完成标志、缺组件、路径父子别名与重解析点、非空或实际库/密钥根重叠。
- 预期结果：非法包和目标拒绝；不执行包内程序、不覆盖实际数据。

### BR-004 快照租约与故障协调

- 用例级别：L4
- 操作步骤：在停止变更、刷新缓存、SQLite快照/附件租约、复制和原子发布各点注入失败/取消，与回收并发及磁盘满。
- 预期结果：未完成包不可用；快照附件一致，租约与自有临时资源清理，源数据不变，不复制活跃DB/WAL冒充一致。

### BR-005 仅平台备份

- 用例级别：L5
- 操作步骤：Web从专用测试节点备份平台库和附件，不选择原生组件，读取清单与完成结果。
- 预期结果：明确可恢复平台历史、原生上下文未备份；不含认证密钥。

### BR-006 备份中断

- 用例级别：L5
- 操作步骤：快照生成后在附件复制完成前令本例存储失败或取消，重开备份列表。
- 预期结果：失败/未完成包不出现在完整可用备份列表，释放租约。

### BR-007 附件损坏

- 用例级别：L5
- 操作步骤：仅篡改本例备份包附件字节，再恢复到新隔离空目录并比较清单。
- 预期结果：摘要失败列出损坏对象，不报告完整恢复；实际库/密钥/原生根不变。

### BR-008 旧审批与身份不可执行

- 用例级别：L5
- 操作步骤：离线恢复含待审批、未终态Run、旧clients信任及幂等结果的包；尝试把恢复目录当daemon数据目录启动、用旧客户端接入。
- 预期结果：默认只读离线检验不进daemon；meta无key拒绝，不自动生成替代key或覆盖旧nodeId；旧nodeId仅来源，旧clients/幂等为历史不可执行，不能继承旧认证；旧审批不可裁决不交付、Run中断未知不派发；未来新空根身份+重新配对不属于自动启用。

### BR-010 独立安全及范围检视

- 用例级别：L5
- 操作步骤：由不继承 coder 对话的独立 reviewer 使用源码、配置、实际 ACL/路径查询、包清单、浏览器及脱敏执行证据，检查敏感历史访问限制、目标保护、包完成标志、组件范围、旧身份只读隔离与证据脱敏；构造重叠路径、损坏包及旧信任接入的负向检查，核对可观察拒绝结果。缺工具、环境、权限或入口记受阻/未执行，不自动转为用户手测。
- 预期结果：敏感历史受 ACL 与授权限制，越界或重叠目标被拒绝，未完成包不可用，范围与原生恢复限制明确，旧身份/信任/审批不可执行且无敏感信息泄漏。独立 reviewer 记录问题 ID、风险及结论；自查不能代签独立结论，未检视不能通过，模型推断不能代替实际证据。

### BR-009 真实隔离备份恢复

- 用例级别：L6
- 操作步骤：真实Windows节点生成历史/审批/共享附件，Web备份，快照后继续写；新隔离空目录恢复，检查SQLite完整性/外键、条目顺序版本、引用、审批审计/绑定。原生组件逐款固定版本一致导出或可证明静止，另在隔离身份根验证继续上下文。
- 预期结果：真实SQLite/文件系统ACL/附件租约/Web，原生继续上下文证据单列，未验证组件不包含；不自动启动Harness、交付旧审批、继承旧信任或切换生产；平台-only不能冒称原生恢复。

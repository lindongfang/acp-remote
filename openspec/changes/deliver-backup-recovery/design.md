## Goals / Non-Goals

平台配置与管理事实、原生数据分别备份并证明各自一致性；平台备份不恢复聊天，缓存不入历史备份。 原生读取、运行与平台管理存储分开；不引入未经授权的私有桥接，不操作实际用户数据库或原生数据。

## Decisions

### 1. 职责与权威

平台备份只涵盖配置及允许备份的管理事实，排除聊天缓存与认证密钥；原生会话、历史和上下文属于独立组件，不因平台备份成功而承诺可恢复。

### 2. 来源能力与接口

平台管理库用一致性快照与清单校验，不需要强刷聊天缓存或历史附件租约。原生组件只使用固定版本验证的一致性导出/备份或静止复制路径；无法排除外部写入则不声明成功。

### 3. 状态与失败

恢复只到隔离新目标，按规格“隔离恢复与校验”逐项核对清单中声明包含的组件。平台组件校验版本、摘要及内部管理关联；原生范围校验仅属于声明包含的原生组件。平台管理记录指向未备份原生对象时，保留不可执行、当前不可解析的引用，不为校验而连接实际原生存储。仅平台包可以报告平台组件恢复成功，仍明确历史和上下文未恢复；声明包含的原生组件缺失或损坏时报告分项失败及清单范围整体失败，不删改清单降为平台包。不覆盖实际数据，不自动生成密钥、激活旧客户端信任或旧审批，不启动外部工具。

### 4. 资源与安全

仅平台包可恢复管理事实，原生数据仍在时重新连接属于重新读取，不是从平台包恢复聊天。原生继续上下文另行真实验证；启用新目标需另行明确授权。

旧命令的签发期限、去重结果、节点请求代际和过期拒绝水位可以作为不可执行历史元数据恢复，但不能据较早备份推导原请求在当前仍有执行资格。新目标获授权启用时建立独立的新节点请求代际，旧请求直接拒绝；不复制原节点密钥以延长旧请求，也不自动为旧动作签发新身份。正常重启使用原完整管理库时继续保留原期限和去重事实，与隔离恢复分开；两条路径均不因记录缺失重放副作用。

## Risks / Trade-offs

- [来源能力不齐] → 各原生备份能力未验证，不承诺统一支持；原测试 BR 中历史、附件及租约预期需重基准。
- [旧证据失效] → 原固定版本证据仅按未改变范围复用，方案及用例重新独立检视，不把文本校验当产品通过。

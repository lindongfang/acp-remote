## Context

见 proposal.md、重设计§8。依赖删除/附件引用和平台库最终模式；编码前按上游最终合同重基准。当前没有真实库、原生备份接口或恢复证据，下面是待实施方案。

## Goals / Non-Goals

建立可检查的备份包与隔离恢复过程，不把文件副本称为一致性证明。不备份本机认证密钥，不恢复活跃进程、旧审批或工具副作用，不自动覆盖运行节点。

## Decisions

### 1. 本地目录包与版本清单

首期选择由可信操作者指定的本地受控目录包，包含manifest、SQLite快照及按摘要组织的附件；不新增远程存储、压缩或自制加密依赖。manifest含格式版本、模式版本、节点不透明ID、快照修订、组件版本、附件ID/大小/摘要、各原生范围包含状态及限制。先写随机临时包，全部校验后原子改名并写完成标志；没有标志或校验不符一律不可用。包含敏感历史，目录ACL限节点账户与操作者，Web不能任意浏览路径或下载密钥。

### 2. 平台一致性边界

备份操作先短暂停止变更命令受理，要求正在运行会话的有界缓存刷新；失败即中止备份，不把未提交数据混入快照。存储服务建立SQLite一致性只读快照并从该快照枚举附件引用，同时给这些字节建立备份租约，阻止回收。然后恢复命令受理；按快照清单复制不可变附件并校验摘要，完成后释放租约。使用数据库备份/快照机制而非复制正在写入的数据库和WAL。相比全程停机，此方式缩短平台写入暂停；快照与租约取得须在同一存储协调边界完成。

### 3. 原生存储是独立组件

默认包可只含平台数据，manifest明确上下文未备份。可选原生部分仅使用固定版本已验证的官方一致性导出或静止存储复制路径；先冻结对应操作并按已验证关闭语义释放全部相关实例，无法排除外部CLI写入或无法证明静止时拒绝该组件。原生部分采用独立范围、版本和校验清单，不推定三款均支持；ZCode未探测前该选项不开放。不将任意私有目录复制当成原生恢复证据。

### 4. 恢复只到新目标

目标须为不存在或经校验为空的专用目录，解析后不得与实际库、附件根、配置根、原生存储或密钥目录重叠，也禁止父子路径别名和重解析点逃逸。先校验manifest、大小、摘要、路径范围及版本，再解包到临时隔离根，执行SQLite完整性/外键检查、条目顺序与版本关系、附件引用及审批审计关联检查。原生绑定保留为历史标识，但将执行能力设为需重新验证；旧连接代际和审批失效，未终态Run记为中断/未知。恢复过程不得自动启动Harness或发命令。

### 5. 验证报告和后续启用

报告区分包校验、平台恢复及原生继续上下文的证据。默认恢复产物只属于离线只读检验资产，验证器不得进入daemon启动路径，也不把恢复目录注册为当前节点。恢复库即使含node_meta、clients和旧幂等事实，也不生成或替换密钥；沿用节点入口“有meta而缺key拒绝启动”的约束，不能通过恢复绕过。原nodeId仅是来源标识，不是新节点身份根；旧客户端信任、审批及旧命令事实只作为不可执行历史读取，不能凭旧信任接入。

原生恢复需在独立新建测试节点身份和隔离原生测试根按对应Harness能力单独执行真实继续输入测试，不能用恢复库中的旧信任或绑定存在代替。验证完成不自动切换生产；用户将来显式请求启用新目标时另立实施步骤：在新空根初始化新节点身份，隔离/移除旧认证信任的执行效力、重新配对，再经受控数据导入保留历史来源映射。不得在发现meta无key时静默换钥，不在本变更中自动转为可启动节点。涉及停机切换和覆盖实际数据的动作需最终明确授权。

## Risks / Trade-offs

- [巨大附件复制时间长] → 租约保留字节，快照后恢复写入，空间不足明确失败并释放租约。
- [原生状态无法一致导出] → 可交付平台备份，但原生组件明确未包含/不支持，不降低成功含义。
- [恶意包路径或压缩炸弹] → 首期目录包也校验总大小、单文件大小及路径，不执行包内程序或配置脚本。

## Migration Plan

引入版本化包格式与备份租约表，在隔离测试库模拟备份中断和回收并发。回滚停用备份入口，清理仅本操作拥有的临时包/租约；保留已完成包和实际数据不动。恢复不迁移旧系统；未来格式升级需显式转换副本，不能原地覆盖唯一备份。

## Implementation Gate

平台快照、附件租约竞态、路径保护、篡改包、缺失原生范围及旧审批失效必须独立验证；真实Harness原生备份能力未验证，不作统一支持承诺。

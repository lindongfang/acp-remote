# 交付一致性备份与恢复验证

## Why

节点接入与通用会话闭环已交付，一致性备份与隔离恢复验证尚未实现。为按重设计建立可独立验收的交付闭环，需要支持平台管理数据与原生数据分组件一致性备份及隔离恢复校验。

## Success Criteria

### 用户原始要求

> acp-remote还是不保存会话数据，以harness 数据为准
> 只提供原生删除，不保留隐藏功能。
> 查看时允许激活进程，不限制只读；查看本身不发送新输入或批准工具。

- **R2-003 确认**：较早备份中的旧请求期限、代际和过期水位在隔离恢复中只作不可执行历史元数据，不能变成新目标的执行资格；正常重启与隔离恢复分别处理。
- **SR-005 确认**：按备份清单声明包含的组件判断恢复成功；仅平台包无需连接原生存储，已声明但缺失或损坏的原生组件使清单范围整体失败，不静默降级。

### 硬约束与非目标

- 以[重设计 §5.1、§8、§10.1](../../../docs/HARNESS_CONTROL_PLANE_REDESIGN.md)与 `openspec/specs/` 长期规格为依据；采用新架构、不兼容旧系统。
- 不得以复制正在写入的文件冒充一致性备份；不得覆盖用户实际数据库、密钥和原生存储进行验收。
- 首期限定 Windows 节点 + Web，App 后续；当前处于需求与设计定义阶段，`tests/plan/tasks` 在正式启动本变更时基于真实代码树生成。

### 本 change 的成功判据

- SC1：平台配置与管理事实、原生数据分别备份并证明各自一致性；平台备份不恢复聊天，缓存不入历史备份。
- SC2：隔离恢复按清单逐项校验，旧请求资格不可在新目标复活，不自动激活旧客户端信任或旧审批。
- SC3：正式开工时基于当前规格生成 `tests/plan/tasks` 并通过编码前门禁、真实实现与集成交付验收。

## What Changes

- 提供平台配置/管理事实与原生数据的分组件一致性备份及清单摘要校验；聊天缓存与认证私钥不入历史备份。
- 实现到隔离新目标的恢复校验，区分平台-only 恢复与含原生组件恢复，隔离旧节点请求代际。

### Modified Capabilities

## Exploration

- **隔离恢复与请求代际（R2-003）**：隔离恢复中的旧请求资格只作历史元数据；另获授权启用新目标时建立独立的新节点请求代际，不复制原节点密钥或回退水位重放命令。正常重启继续保留原完整去重事实（引用 `session-execution`）。
- **按清单判定恢复结果（SR-005）**：仅平台包恢复成功时明确说明历史和上下文未恢复；清单声明包含的原生组件缺失或损坏时报告分项失败及整体失败，不删改清单伪装成纯平台包。
- **数据权威与重放兼容（Q-001 / RP-001）**：会话与历史以 Harness 为准；平台包恢复管理事实后，原生数据仍在时重新连接属于标准重读而非从平台包恢复聊天。
- **术语与 ADR 复核**：复用 [领域术语表](../../GLOSSARY.md) 中组件、清单、管理事实与请求身份定义，无新增独立 ADR。

# 交付一致性备份与恢复验证

状态：待实现文档齐备；独立方案结论见 review.md，产品未实施；上游真实交付和能力探测门禁仍需满足。

## Why

当前分支没有产品实现。为按重设计建立可独立验收的交付闭环，需要交付一致性备份与恢复验证，避免仅交付孤立模块而没有可观察结果。

### 硬约束与非目标

- 以[重设计 §5.1、§8、§10.1](../../../docs/HARNESS_CONTROL_PLANE_REDESIGN.md)为本闭环依据；采用新架构、不兼容旧系统，其他适用的全局约束仍然有效。
- 不得以复制正在写入的文件冒充一致性备份；不得覆盖用户实际数据库、密钥和原生存储进行验收。
- 本轮补齐待实现文档，不开始产品实现，不将规划或模拟结果写成已提供能力。首期限定 Windows 节点 + Web，App 后续。

### 本 change 的成功判据（待详细规格转成场景）

- SC1：区分平台数据库、附件及原生存储的备份范围，建立一致性备份、恢复检查和故障反馈。
- SC2：在隔离目标恢复并核对历史、附件、审批审计与原生绑定；仅平台数据备份不声称可恢复原生上下文，缺失或损坏明确失败。
- SC3：建立真实构建及适用检查，完成独立用例/方案检视和交付验收；记录未验证项及实质限制。

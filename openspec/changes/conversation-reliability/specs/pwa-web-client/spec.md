# Spec Delta

## ADDED Requirements

### Requirement: 提交输入立即可见且按身份替换

客户端 SHALL 在用户提交有效输入后立即显示该输入及必要附件信息，上传和受理等待 MUST 有反馈。正式正文到达后 SHALL 按可靠的请求及消息关联原位替换，MUST NOT 按相同文字推断重复。受理后执行失败或结果不确定 MUST NOT 使输入消失；受理前失败 SHALL 明确报错并保留可修正的输入。

#### Scenario: 老消息与本次文字相同
- **WHEN** 历史已有“继续”，本次又发送“继续”且尚未收到回显
- **THEN** 立即看到本次独立用户输入，旧消息不抵消它

#### Scenario: 附件正在上传
- **WHEN** 用户提交带附件的有效输入而上传尚未完成
- **THEN** 对话显示提交内容及上传等待，上传失败明确说明且不假装 Agent 已收到

### Requirement: 对话过程持续可见

客户端 SHALL 在等待、恢复、实际思考、工具执行、回复及失败各阶段提供与已知事实一致的反馈，并在事件到达后增量更新。MUST NOT 等完成再整批展示，MUST NOT 将“等待响应”写成 Agent 正在思考或编造思考正文。恢复和等待说明 SHALL 与设备连接状态及会话主状态分开，避免重复占行。

#### Scenario: Agent 长时间无首个输出
- **WHEN** 输入受理后 Agent 尚未提供任何内容
- **THEN** 输入和等待响应反馈可见，不出现无反馈的空白间隔

#### Scenario: 恢复完成后输出
- **WHEN** 会话恢复中随后开始返回思考和工具事件
- **THEN** 恢复反馈及时结束，实际思考与工具状态持续更新，失败则显示失败原因

### Requirement: 一个临时会话跨切换与刷新保留

同一标签页的当前已配对节点和设备下 SHALL 最多保留一个尚未转正的临时会话。切换已有会话、返回目录、刷新及再次点击新建 SHALL 保留并复用该临时会话及 ID、草稿和附件，准备资源过期 SHALL 优先同 ID 恢复。切换 Agent SHALL 替换准备目标并清理旧材料；更换目录 MUST 先显式放弃当前临时会话（确认后清理其草稿、附件与资源）再新建，MUST NOT 原位替换目录或把旧证明用于新目录。客户端 SHALL 在未转正临时会话页提供显式的「放弃新会话」动作，执行前须确认；普通返回目录 MUST NOT 触发放弃。转正后再次显式新建可分配新 ID。

#### Scenario: 切换后在已有会话刷新
- **WHEN** 创建临时会话 A 后切到正式会话 B 并刷新，再点击新建
- **THEN** 回到 A，ID、Agent、目录及已保存草稿不变，不分配另一个临时会话

#### Scenario: 资源恢复期间点击新建
- **WHEN** 当前临时会话资源正在恢复或暂不可用时再次点击新建
- **THEN** 仍进入原临时会话，不因它尚未就绪而另分配 ID

#### Scenario: 切换 Agent
- **WHEN** 用户明确选择其他 Agent
- **THEN** 旧临时会话被替换且不保留第二个，旧响应不能污染新目标

#### Scenario: 原目录之外点击新建
- **WHEN** 一个临时会话已存在，用户从另一目录点击普通新建入口
- **THEN** 回到现有临时会话及原目录，不静默改目录；要更换目录必须先显式放弃当前临时会话，再新建

#### Scenario: 显式放弃后再换目录
- **WHEN** 用户在临时会话页触发「放弃新会话」并确认，再从新目录发起新建
- **THEN** 旧临时会话的草稿、附件与资源被清理，新目标获得新 ID；普通返回目录或未确认放弃时，任何普通新建入口都不得改变目录

#### Scenario: 普通返回目录不放弃
- **WHEN** 用户从临时会话返回目录页但未触发「放弃新会话」
- **THEN** 临时会话、ID、草稿与附件保留，再次新建仍回到该会话

### Requirement: 对话样式按原型逐项验收

对话 SHALL 使用仓库桌面和移动原型的消息层级、思考折叠、工具卡片与吸底输入布局；必要的等待与恢复反馈 SHALL 在该布局中表达。结构化交互、失败、键盘操作、滚动锚点与上下文读取 MUST 保持可用。有意差异 SHALL 明确登记，MUST NOT 用截图代替行为验证。

#### Scenario: 流式工具与思考
- **WHEN** 桌面和窄屏接收思考、工具开始/更新/完成与回复
- **THEN** 原位更新且可展开详情，上读不被强制拉到底，底部阅读时持续跟随

## MODIFIED Requirements

### Requirement: 输入与提交支持协商内容且以终态为准

对话页 SHALL 支持文本及协商允许的附件和工作目录路径引用，整体提交规则遵循附件能力。输入 SHALL 区分可发送、执行中与不可用三种可用性：执行中可编辑但不可发送或排队；不可用 MUST 说明当前实际原因（如来源离线、提交进行中或附件能力未协商）。输入可用性 MUST NOT 由会话主状态推导，MUST NOT 存在「会话已关闭所以只读」的分支：三态主状态为 `idle`/`running`/`pending` 都不构成永久禁提交的理由。回车提交、Shift 加回车换行，不能提交时回车 MUST NOT 派发命令。提交在服务端终态前 SHALL 标为待确认，结果不确定 SHALL 显著保留。正式会话与 imported 会话的草稿及文件选择 SHALL 仅存页面内存；唯一例外是本机准备中、尚未首次提交的临时会话草稿，它 SHALL 经 `docs/FRONTEND_DESIGN.md` §7（本地数据边界）的 `PreparationDraftPort` 按标签页归属持久化，并在刷新、返回目录或重新认证后恢复。

#### Scenario: 回车提交、Shift 加回车换行

- **WHEN** 可提交的会话中用户按回车或 Shift 加回车
- **THEN** 分别提交完整消息或插入换行

#### Scenario: 不可提交时回车无副作用

- **WHEN** 输入区处于执行中或不可用状态时用户按回车
- **THEN** 不派发命令；执行中仍可编辑下一条草稿且不建立队列

#### Scenario: 附件不受支持被显式说明

- **WHEN** 当前端到端能力不支持某个已选附件
- **THEN** 明确说明并保留完整草稿，不静默删除附件后提交文字

#### Scenario: 提交不等于完成

- **WHEN** 消息已受理但尚未取得服务端终态
- **THEN** 标为待确认，不标为已发送、已排队或已完成

#### Scenario: 关闭的会话不可提交

- **WHEN** 历史曾被标为已关闭的会话升级为三态后，当前仍存在明确的不可提交原因（例如来源离线）
- **THEN** 输入按当前实际原因只读或禁用并说明原因，不派发命令；MUST NOT 仅凭旧关闭标签永久禁止提交

#### Scenario: 旧七态的关闭标签不再限制提交

- **WHEN** 历史曾被标为已关闭（旧七态）的会话升级为三态，且当前不存在任何明确的不可提交原因
- **THEN** 输入区按可发送处理；曾被关闭 MUST NOT 作为只读或永久禁提交的依据，界面也不得再呈现「已关闭」

#### Scenario: 不可用原因以当前事实为准

- **WHEN** 输入区因来源离线、附件能力未协商或提交进行中而不可用
- **THEN** 说明对应的当前原因；原因消失后恢复相应可用性，MUST NOT 以会话主状态代替该判定

#### Scenario: 来源离线的草稿不落盘

- **WHEN** 远程来源不可达而用户编辑草稿或选择附件
- **THEN** 草稿及选择仅留页面内存并标为未提交，不持久化

#### Scenario: 页面内切换与刷新

- **WHEN** 用户在正式会话间切换、打开文件查看后返回，或对本机准备中且尚未首次提交的临时会话刷新/返回目录
- **THEN** 正式会话的草稿及选择保持；临时会话 SHALL 恢复同一 ID、目录、Agent 与已保存草稿及附件；刷新或关闭页面前提示未发送内容。正式会话刷新 MUST NOT 承诺恢复或续传

### Requirement: 会话创建入口与载荷

客户端 SHALL 在目录内或目录列表顶部提供会话准备入口。协商准备能力后，入口只提交 Agent 标识与目录来源及必要的准备关联信息，MUST NOT 传入凭据或 MCP 配置；取得后端分配的最终 ID 后进入该会话页，但不持久创建会话。设备不再有创建权限这一维度，入口 MUST NOT 再以权限为由不可用，也 MUST NOT 出现「需要由电脑端授予」。准备中 SHALL 防重复，失败就地说明；首次保存成功或失败都留在同页同 ID，结果不明时由输入区保留说明且不自动重发。未协商时 SHALL 明确禁用新入口，不退回旧 `session.create`。当前标签页已有尚未转正的临时会话时，普通入口 SHALL 导航回该会话并复用其 ID，不因其尚未 ready 或入口所属目录不同而分配第二个临时会话；只有显式更换 Agent（或先显式放弃再新建）才替换准备目标。

#### Scenario: 提交载荷只含目录引用与 Agent 标识
- **WHEN** 用户在某目录内选择已配置的本机 Agent 并开始准备
- **THEN** 准备的业务选择只含该目录来源和 Agent 标识，关联材料不携带凭据或 MCP 配置，也不接受客户端自定正式 ID

#### Scenario: 入口不因权限不可用
- **WHEN** 已认证设备打开目录页或目录详情页且协商准备能力
- **THEN** 创建入口可用，不呈现「没有创建会话的权限」；资源或能力不可用时说明真实原因

#### Scenario: 创建中与终态分别呈现
- **WHEN** 准备或首次提交尚未得到确认
- **THEN** 各自呈现准备中或提交中且不重复操作；准备成功进入固定 ID 页，首条保存和派发结果在该页更新，不另跳新 ID

#### Scenario: 结果不确定显眼且不被自动消解
- **WHEN** 首次提交的结果被所属节点确认为不确定
- **THEN** 输入区保留该状态的说明，不自动判成功、重发或新建替代会话；会话页不另设顶部状态条

#### Scenario: 重复新建不分配第二个临时会话
- **WHEN** 当前标签页已有尚未转正的临时会话，用户从任意普通创建入口再次新建（包括准备恢复中或入口所属目录不同）
- **THEN** 客户端进入原临时会话并保留其 ID、Agent、目录、草稿与附件，MUST NOT 分配另一个准备 ID，也不因未 ready 重新创建

### Requirement: 目录项的创建入口

目录页每个目录项 SHALL 提供在该目录内准备新会话的入口，与详情页使用相同准备流程；业务选择只含目录来源和 Agent 标识。入口 MUST NOT 因权限原因不可用；未协商准备能力时 SHALL 说明能力不可用。任何入口都 MUST NOT 在首条提交前新增正式目录会话。已存在尚未转正的临时会话时，目录项入口 SHALL 导航回该临时会话，不按所点目录重新分配准备 ID；用户要换目录必须先显式放弃该临时会话。

#### Scenario: 从目录项直接创建
- **WHEN** 用户从目录项触发新建并选定已配置 Agent，且当前没有未转正临时会话
- **THEN** 同一准备流程取得后端 ID 并打开该页，输入中不包含凭据或 MCP 配置，正式会话列表不增加

#### Scenario: 创建中与终态的呈现沿用既有约定
- **WHEN** 从目录项发起的准备或首次提交未确认
- **THEN** 呈现明确阶段并阻止重复操作；准备失败就地说明，首次保存或执行失败保持原页与 ID，结果不明时保留输入区说明且不自动重发

#### Scenario: 已有临时会话时目录项不另建
- **WHEN** 当前标签页已有一个未转正的临时会话，用户点击另一个目录项的创建入口
- **THEN** 进入原临时会话及其原目录，不分配新 ID，也不把证明绑定到所点目录

### Requirement: 创建会话时可浏览节点上的目录（已记录标记）

当前标签页没有尚未转正的临时会话时，新建会话入口 SHALL 让用户指定目录，且 MUST 提供两条路径：选择本机已记录的目录，或在主机的文件系统上逐层浏览并选定一层。已有临时会话时，普通新建入口按「一个临时会话跨切换与刷新保留」导航回该会话，MUST NOT 打开目录选择或修改其目录。浏览 SHALL 从主机的根列表开始，提供面包屑与上一级，并在已记录的目录上标注它已被使用过。用户 SHALL 能在浏览过程中新建目录：「新建」与「选择此文件夹」是分开的动作，成功后目录已存在于主机上，选择器保持打开且不自动选择。用户 SHALL 能进入新目录继续创建下一层，再单独确认工作目录。不能浏览或不能独立新建时 MUST 明确说明缺少的能力，保留可用的已有目录选择，不退化为静默失败或延迟建目录。

#### Scenario: 从根逐层选定

- **WHEN** 用户打开浏览并逐层进入某一层后确认
- **THEN** 选定的路径进入新建会话的目录引用，且弹层回到新建会话自身

#### Scenario: 已记录目录被标注

- **WHEN** 浏览到的某一层已是本机记录过的目录
- **THEN** 该层标注为已被使用过，用户可据此识别既有目录

#### Scenario: 新建一层目录

- **WHEN** 用户在浏览的当前层输入目录名并点击「新建」
- **THEN** 客户端等待主机确认成功后刷新父层，从真实条目取得路径并自动进入新目录，清空本次名字输入，保持选择器打开；不自动确认工作目录、不自动创建会话

#### Scenario: 服务端不支持浏览

- **WHEN** 服务端未提供目录浏览能力
- **THEN** 入口明确说明该能力不可用，并保留选择已记录目录这条路径，MUST NOT 呈现一个必然失败的手工输入

#### Scenario: 先建立多级目录再选择

- **WHEN** 用户在主机目录下新建 `project`，进入后新建 `src`，再进入后新建 `api`
- **THEN** 每次成功都已经在磁盘建好对应的一层；只有用户进入目标层并点击「选择此文件夹」才关闭选择器并填写会话工作目录

#### Scenario: 独立新建失败或不确定

- **WHEN** 建目录尚未完成、明确失败或结果不确定
- **THEN** 创建中禁止重复点击；失败保留输入与当前层；不确定结果显式保留且不静默重发，MUST NOT 伪造成功目录

#### Scenario: 旧服务端没有独立新建能力

- **WHEN** 服务端支持浏览但未协商 `core.workspace-mkdir.v1`
- **THEN** 用户仍可浏览和选择已有目录；独立新建入口明确不可用，MUST NOT 用「会话提交时再建目录」冒充立即新建

#### Scenario: 新建后取消

- **WHEN** 用户新建目录成功后关闭选择器或取消会话创建
- **THEN** 目录保持存在，不创建会话，不启动 Agent，不自动删除目录

#### Scenario: 已有临时会话时不打开目录选择

- **WHEN** 当前标签页已有未转正临时会话，用户点击任一普通新建入口
- **THEN** 直接进入该临时会话，不打开目录浏览或选择器，也不改变其目录

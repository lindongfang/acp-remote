# Design

## Context

动机与用户确认要求见 [proposal.md](proposal.md)，行为规则见 `specs/session-transcript-cache/spec.md`、`specs/structured-history/spec.md`、`specs/native-session-recovery/spec.md`、`specs/session-resource-policy/spec.md` 与 `openspec/specs/` 长期规格。本变更当前处于需求与设计定义态，具体施工工作包与验收用例在正式开工时基于真实代码树建立。

## Goals / Non-Goals

**Goals:**
- 在与节点控制主库物理分离的独立存储中，按显式接入来源与原生会话标识持久化标准 ACP 结构化展示快照（含轮次边界、消息、思考、工具原位更新与已知父子步骤引用）。
- 实现冷会话“先秒开本地快照 + 后台自动拉取一次原生更新（Stale-While-Revalidate）”无感补齐体验、满额/异常降级快照直读，以及无重放（仅 `session/resume` 或纯内存）会话历史留存兜底。
- 提供可配置的默认 **30 天**滑动保留期与默认 **10 GiB** 磁盘容量上限自动回收机制，保护已加载活跃会话并支持删除即时擦除。

**Non-Goals:**
- 将展示快照拼成 Prompt 灌回 Harness 伪造模型上下文；解析 `~/.codex`、`~/.pi` 等厂商私有会话文件；将展示快照混入核心管理库 `acp-remote.sqlite` 或核心管理事实备份包。

## Decisions

### 1. 物理分库与故障隔离

在节点 `data_dir` 下建立独立的展示快照存储（例如独立 `transcript-cache.sqlite` 或带索引的分会话数据文件，与 `acp-remote.sqlite` 完全分离，继承同一 Windows owner 目录 ACL 保护）。展示快照写入采用异步非阻塞管道旁路落盘：实时接收、输入派发、严格权限审批及容量账本绝不等待快照刷盘锁；若快照库发生磁盘满或 I/O 异常，仅降级为内存当前连接视图并上报告警，不影响会话执行与安全控制。

### 2. 三档混合自适应读取与恢复路径

- **路径 A（未加载冷会话“秒开快照 + 后台自动同步” / Stale-While-Revalidate）**：
  - **第 1 步（首屏秒开）**：当客户端打开当前未在节点活跃加载的空闲会话且本地存在未过期展示快照时，节点立即返回本地展示快照渲染首屏（消除加载白屏等待），并标记后台校准状态；若会话已在节点处于活跃加载态，则直接返回当前内存共享实时视图，不重复发起重放。
  - **第 2 步（后台自动拉取补齐）**：若对端支持标准重放（ACP v1 `session/load` / ACP v2 `session/resume` + `replayFrom: {"type": "start"}`），节点无需用户手动点击，自动在后台按容量规则申请主会话名额并发起一次标准重放（并发打开同一会话共享同一在途重放）。重放收齐后以新代际原子更新展示快照库并推送前端：**当前序条目与已渲染快照前缀一致时，前端保持当前阅读滚动位置无闪烁地在末尾追加外部 CLI 新增的对话轮次**；若原生历史发生了上下文压缩或删改，则平滑更新为最新权威视图。若用户打开后仅浏览未发消息，该会话在重放完成后无受保护活动，按 `session-resource-policy` 可随时作为空闲淘汰候选让位给新会话。
  - **满额/异常优雅降级**：若 50 个主会话名额全部被运行中或待审批的受保护会话占满，或 Harness 暂时拉取失败，后台自动同步不中断已秒开的本地快照阅读，仅在状态栏轻提示“未完成最新原生同步（展示本地缓存历史）”并保留手动重试入口。
- **路径 B（接管恢复与上下文衔接）**：当主控客户端接管会话准备继续执行时：
  - 若会话已通过打开时的后台自动同步处于活跃加载态，直接校验/授予主会话控制权并继续派发新输入；
  - 若会话尚未加载（如满额释放后恢复，或对端仅支持轻量 `session/resume`），可调用 `session/resume` 恢复模型上下文并衔接本地展示快照与后续实时输出，也可由用户按需手动触发重新同步校准。
- **路径 C（无重放 / 纯内存 Harness 兜底）**：
  - 对仅支持 `session/resume`、不支持标准重放（或重放返回空）的 Harness，空闲回收或节点重启后打开时直接展示平台已记录的本地快照，明确提示“展示平台已记录历史（外部终端直接产生的变更不可见）”，接管恢复后可正常继续对话；
  - 对既不支持重放也不支持 `resume` 的纯内存会话，连接断开或回收后标记为不可继续执行，但保留本地展示快照供只读查阅直至到期或删除。

### 3. 30 天滑动保留与 10 GiB 容量淘汰策略

`acp-remote.toml` 支持配置快照保留天数（默认 `30` 天）与最大磁盘占用（默认 `10 GiB`）：
- **滑动过期**：每次会话产生新实时条目写入或完成有实质内容变化的原生重放同步时，刷新该会话快照的 `lastUpdatedAt`（纯读取快照，或后台自动重放比对确认原生无新增/变更时，不虚刷 30 天保留计时）；后台周期清理任务移除距今超过 30 天且当前未处于已加载活跃态的会话快照。
- **容量安全阀**：当展示快照总占用超过 `10 GiB` 时，排除当前已加载活跃会话（占用 50 名额中）及正在被客户端分块读取的快照代际，按 `lastUpdatedAt` 最早优先整会话淘汰非活跃快照，直至回到水位以下。
- **删除即时擦除**：当原生会话删除确认完成（或外部确认已不存在并由用户清理缓存）时，立即同步擦除该会话的全部本地展示快照字节。

## Risks / Trade-offs

- [打开支持重放的冷会话自动后台拉取会唤醒子进程] → 首屏由本地快照零等待承接；后台重放并发合并，完成后若无执行活动仍属可随时被满额淘汰的空闲候选；50 名额全忙时自动降级为纯本地快照只读浏览，兼顾外部更新自动可见与容量安全。
- [标准 ACP 重放返回完整历史导致页面重绘闪烁] → 节点以新代际原子更新快照库，前端对相同前序结构前缀执行无跳动差异补齐，仅将外部追加的新轮次平滑长出在末尾。
- [单轮产生极大工具输出快速消耗 10 GiB 预算] → 保持按需分块存储与淘汰水位保护，淘汰仅影响最旧冷会话的本地展示快照，绝不删除 Harness 原生存储数据。

## Migration Plan

独立新建展示快照库文件与配置项默认值（缺省即启用 30 天 / 10 GiB），无需迁移或改写既有 `acp-remote.sqlite` 核心表；旧版本已存在的原生会话在打开自动重放或新对话时自然建立本地展示快照。

# Design

## Context

动机与用户确认要求见 [proposal.md](proposal.md)，行为规则见 `specs/session-transcript-cache/spec.md`、`specs/structured-history/spec.md`、`specs/native-session-recovery/spec.md`、`specs/session-resource-policy/spec.md` 与 `openspec/specs/` 长期规格。本变更当前处于需求与设计定义态，具体施工工作包与验收用例在正式开工时基于真实代码树建立。

## Goals / Non-Goals

**Goals:**
- 在与节点控制主库物理分离的独立存储中，按显式接入来源与原生会话标识持久化标准 ACP 结构化展示快照（含轮次边界、消息、思考、工具原位更新与已知父子步骤引用）。
- 实现冷会话免唤醒直读、无重放（仅 `session/resume` 或纯内存）会话历史留存兜底，以及支持 `session/load` 时的显式原生重放校准。
- 提供可配置的默认 **30 天**滑动保留期与默认 **10 GiB** 磁盘容量上限自动回收机制，保护已加载活跃会话并支持删除即时擦除。

**Non-Goals:**
- 将展示快照拼成 Prompt 灌回 Harness 伪造模型上下文；解析 `~/.codex`、`~/.pi` 等厂商私有会话文件；将展示快照混入核心管理库 `acp-remote.sqlite` 或核心管理事实备份包。

## Decisions

### 1. 物理分库与故障隔离

在节点 `data_dir` 下建立独立的展示快照存储（例如独立 `transcript-cache.sqlite` 或带索引的分会话数据文件，与 `acp-remote.sqlite` 完全分离，继承同一 Windows owner 目录 ACL 保护）。展示快照写入采用异步非阻塞管道旁路落盘：实时接收、输入派发、严格权限审批及容量账本绝不等待快照刷盘锁；若快照库发生磁盘满或 I/O 异常，仅降级为内存当前连接视图并上报告警，不影响会话执行与安全控制。

### 2. 三档混合自适应读取与恢复路径

- **路径 A（冷会话浏览直读）**：当客户端打开未加载的空闲会话查阅历史且本地存在未过期展示快照时，节点直接从展示快照库返回结构化历史并标注快照同步时间与来源模式，**不启动 Harness 进程、不占用 50 主会话名额、不刷新 30 分钟空闲计时**。若该会话为外部新建且本地尚无快照，则按既有规则在支持 `session/load` 时按需触发原生重放并将结果写入展示快照库。
- **路径 B（接管恢复与显式原生校准）**：当主控客户端接管空闲会话准备继续执行时：
  - 若对端支持 `session/resume` 且本地已有完整展示快照、用户未请求强制重放外部变更，可优先调用轻量 `session/resume` 恢复模型上下文并直接衔接本地展示快照与后续实时输出；
  - 若对端支持 `session/load` 且用户点击“刷新同步原生历史”（或本地快照缺失/标记不完整），节点调用 `session/load` 获取最新原生权威历史，以新重放代际原子替换该会话的本地展示快照（消除外部 CLI 直接对话造成的差异）。
- **路径 C（无重放 / 纯内存 Harness 兜底）**：
  - 对仅支持 `session/resume`、不支持 `session/load`（或重放返回空）的 Harness，空闲回收或节点重启后再次打开时直接展示平台已记录的本地快照，明确提示“展示平台已记录历史（外部终端直接产生的变更不可见）”，恢复后可正常继续对话；
  - 对既不支持 `load` 也不支持 `resume` 的纯内存会话，连接断开或回收后标记为不可继续执行，但保留本地展示快照供只读查阅直至到期或删除。

### 3. 30 天滑动保留与 10 GiB 容量淘汰策略

`acp-remote.toml` 支持配置快照保留天数（默认 `30` 天）与最大磁盘占用（默认 `10 GiB`）：
- **滑动过期**：每次会话产生新实时条目写入或完成原生重放同步时，刷新该会话快照的 `lastUpdatedAt`；后台周期清理任务移除距今超过 30 天且当前未处于已加载活跃态的会话快照。
- **容量安全阀**：当展示快照总占用超过 `10 GiB` 时，排除当前已加载活跃会话（占用 50 名额中）及正在被客户端分块读取的快照代际，按 `lastUpdatedAt` 最早优先整会话淘汰非活跃快照，直至回到水位以下。
- **删除即时擦除**：当原生会话删除确认完成（或外部确认已不存在并由用户清理缓存）时，立即同步擦除该会话的全部本地展示快照字节。

## Risks / Trade-offs

- [外部 CLI 修改了会话导致本地快照暂时滞后] → 界面明确区分“本地快照视图”与“已从原生最新同步”，对支持 `session/load` 的会话提供一键原生刷新重读并以新代际原子替换旧快照，不猜测拼接。
- [单轮产生极大工具输出快速消耗 10 GiB 预算] → 保持按需分块存储与淘汰水位保护，淘汰仅影响最旧冷会话的本地免唤醒快照，绝不删除 Harness 原生存储数据。

## Migration Plan

独立新建展示快照库文件与配置项默认值（缺省即启用 30 天 / 10 GiB），无需迁移或改写既有 `acp-remote.sqlite` 核心表；旧版本已存在的原生会话在首次重放或新对话时自然建立本地展示快照。

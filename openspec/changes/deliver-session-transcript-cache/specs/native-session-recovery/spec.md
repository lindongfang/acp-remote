## MODIFIED Requirements

### Requirement: 原生绑定与按需恢复
系统 SHALL 按 Harness 原生范围及会话标识通过原生接口（`session/resume` 或 `session/load`）恢复原会话上下文，成功后才接受依赖该恢复的新输入；MUST 不静默创建替代会话，也 MUST NOT 将平台展示快照文本重灌给 Harness 伪造上下文。原生会话无法恢复时，未过期的本地展示快照仍可按只读历史展示，但不得宣称会话可执行。

异常执行的恢复还须满足 `session-execution` 的“异常后重新准入”，原生恢复成功本身不证明旧执行已停止，也不改变其未知结果。

#### Scenario: 原生状态缺失
- **WHEN** 已知原生会话在 Harness 侧无法恢复（无论独立展示快照库中是否仍有未过期只读快照）
- **THEN** 新输入或恢复操作明确失败且不可继续派发，管理审计与未过期本地只读快照可按各自边界查阅并明确标注原生会话不可恢复

### Requirement: 恢复与历史读取分离
系统 SHALL 分别管理与报告模型上下文恢复、当前连接实时内容、原生历史重放及本地展示快照状态；缺少标准重放不禁止实际可用的 `session/resume` 上下文恢复。支持 `session/resume` 的未加载会话在恢复时 SHALL 可直接衔接本地有效展示快照与后续新输出，同时如实区分“仅展示本地平台快照”与“已完成原生历史同步”；已通过打开时后台重放加载的会话可直接继续新输入，不保证工具、审批及子 Agent 从旧指令位置自动继续，也不重发输入。

#### Scenario: 无重放恢复
- **WHEN** 对端可 `session/resume` 恢复同一原生会话但不能重放历史
- **THEN** 允许恢复模型上下文并结合未过期的本地展示快照呈现平台既有历史与新输出，页面明确提示历史来自平台快照（不含外部直接变更）；若本地快照已过期清除则提示历史缺失

#### Scenario: 已准入连接选择无重放恢复
- **WHEN** 对端同时支持标准重放与 `session/resume`，此前打开时因容量满额等原因尚未完成重放同步，随后名额释放且主控端采用轻量 `session/resume` 配合本地展示快照恢复
- **THEN** 快速恢复可执行状态并衔接本地快照，不谎称已同步外部最新原生变更；用户也可随时手动重试原生重放校准

#### Scenario: 恢复重放旧消息
- **WHEN** 原生重放或恢复再次发出旧条目
- **THEN** 按可靠来源与读取代际更新视图及本地快照（前缀一致时前端无闪烁补齐新增轮次），不能证明连续性则整代替换并说明限制，不按文字去重或当作新回复

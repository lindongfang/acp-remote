# ZCode 接入配置与 ACP 兼容性验收

状态：待实现文档齐备；旧快照独立方案结论见 review.md，本轮修订检视另记总体报告，产品未实施；上游真实交付和能力探测门禁仍需满足。

## Why

当前分支没有产品实现。为按重设计建立可独立验收的交付闭环，需要接入 ZCode 原生会话闭环，避免仅交付孤立模块而没有可观察结果。

### 硬约束与非目标

- 以[重设计 §4.5、§6.3、§9–§10.2](../../../docs/HARNESS_CONTROL_PLANE_REDESIGN.md)为本闭环依据；采用新架构、不兼容旧系统，其他适用的全局约束仍然有效。
- 不重建 ZCode 工具或模型系统，不解析改写其私有会话文件充当日常恢复。
- 本轮补齐待实现文档，不开始产品实现，不将规划或模拟结果写成已提供能力。首期限定 Windows 节点 + Web，App 后续。

### 本 change 的成功判据（待详细规格转成场景）

- SC2：真实验证输入、结构化输出、审批、取消、释放恢复、压缩后平台历史保留及异常结果；不支持的能力明确呈现。
- SC3：建立真实构建及适用检查，完成独立用例/方案检视和交付验收；记录未验证项及实质限制。

## What Changes

- 复用通用 ACP 会话闭环（Codex 首验），本项只新增启动/认证引用配置、能力证据和兼容性验收，不另建厂商协议客户端、生命周期或页面流程。
- 按通用版本策略及协商能力验证 v1/v2 中该程序实际提供的组合，不要求每款都支持两版；必要能力不兼容时报告缺口、影响、证据和可选方案，由用户决策，不自行增加私有桥接或降低要求。
- 升级进行影响分析及兼容复验，不自动修改代码；旧版本证据保留，但不能作为新版本通过依据。

- 复用平台执行与历史合同，接入 ZCode 的实际 ACP 接入路径（需先核实），固定版本并验证恢复与重放隔离。
- 同步负责上述行为的设计、规范、测试、配置与操作文档；不复活旧系统合同。

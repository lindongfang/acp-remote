## 共用执行安排

- 首期 Windows 节点与受支持 Chromium 桌面 Web，不增加移动端门禁。仓库已有上游节点与 Web 开发实现及工程检查入口，本 change 仍待实现，不能把上游构建成功或规划齐备当成本 change 通过；开工前按上游实际交付、最终合同和固定版本重基准。
- 独立 tester 维护验收预期，coder 可补开发单元测试；独立 reviewer 检视用例/方案及交付证据，二者不继承 coder 对话。本次文本调整不是独立检视通过结论，旧 review 不覆盖新文本，修订后须重新检视。
- 在 D:/Project/acp-remote 按 README 和实际工程配置执行，固定提交或完整文件摘要及产品、Harness、适配器、协议版本；使用独立 owner、可信 Web 身份、专用配置/数据库/附件/原生根副本、端口、进程及浏览器 profile。真实 Web 验收使用受信 HTTPS。
- ZC-001–004 从现有工程命令和实现后登记到 README 的领域/合同/故障入口执行；L3/L4 允许明确标注边界的可控时钟、存储故障及协议 fixture（模拟输入），不替代真实数据库、平台或 Harness 验收。缺对应目标、入口、工具、环境、权限或真实对端记受阻/未执行，不以零测试、只启动或模型推断判通过。
- 其余行为用例从实际节点终端给出的 HTTPS 地址进入本 change 的 Web 管理入口，交互优先 ego-browser，必要时使用协议探针、数据库查询和资源观测程序；按各例步骤核对操作结果、持久化及资源断言，不仅检查截图。ZC-010 使用独立源码/证据检视和实际工具验证。
- ZC-009、ZC-011 必须使用真实 ZCode 程序及协议、原生存储、Windows 完整进程树、Web 和平台数据库；先核实官方程序、许可证、启动入口、固定版本/摘要与实际握手，未核实保持阻断。ZC-011–014 在验收及版本/配置变化时按需复验，只测实际可用的协议版本与能力组合；记录声明、协商、模拟及真实结果，不能用官方文档或模拟适配器冒充真实兼容证据。
- 成功、失败、取消均关闭本次拥有的连接、读取句柄、快照、订阅、任务和完整进程树，释放临时锁、端口及本操作持有的租约，只清理自有专用副本并保留脱敏证据；不删除用户实际数据库、原生会话、密钥或配置。
- 正式结果另存 testing/runs/integrate-zcode-harness/，按 plan 的报告分工记录版本、OS/工具/依赖、逐 ID 状态、命令、实际断言与执行数量、证据及问题闭环。同版本、同范围且环境符合要求的有效证据可复用，不要求用户重复操作；必需项失败、未执行或待确认均不能视为验收通过。归档前按能力同步长期 suite 并保留 ID。
- 当前没有已识别的工具无法验证且必须人工介入的场景，原 ZC-010 独立安全检视从 LX 调整为 L5，独立角色和安全范围保留。以后若确有必须由人判断的部分，只将该最小部分划入 LX，在步骤中说明具体原因；用户只需回答通过/不通过，Agent 记录 ID、受测版本和原始结论，未回复记待确认，不要求用户填写技术报告或代签。

## Cases

### ZC-001 真实构建及类型检查

- 用例级别：L1
- 操作步骤：在仓库根目录按 README 和 package.json 执行 npm run check、npm run build:rust；另执行 openspec.cmd validate integrate-zcode-harness --strict 与 git diff --check，分开记录规划检查和产品构建结果。核对构建目标是否实际包含本 change 的节点与 Web 实现。
- 预期结果：真实编译、Web 构建和类型检查成功，检查覆盖本 change 的实际目标；现有上游开发实现通过构建不证明本 change 通过。缺对应目标或入口记受阻/未执行，规划校验不能代替编译或功能验收。

### ZC-002 静态合同和供应链检查

- 用例级别：L2
- 操作步骤：在仓库根目录执行 npm run check、openspec.cmd validate integrate-zcode-harness --strict、git diff --check、npm audit --audit-level=high；对实际 BASE/HEAD 执行 npm run lint:commits -- --from BASE --to HEAD --verbose，按 .github/workflows/ci.yml 的 secrets 作业执行密钥扫描。核对本 change 的协议合同、依赖审查和锁文件是否纳入实际入口，缺专用合同入口记未执行。
- 预期结果：真实适用检查按工程配置执行；开发工具审计不等于产品供应链通过，无专用结构门禁，reviewer人工核对精确引用和覆盖。

### ZC-003 领域边界及异常状态

- 用例级别：L3
- 操作步骤：用明确标为fixture的协议载荷验证未验证/支持/不支持三态、未知扩展结构保留、缺少取消完成事实仍互斥、来源ID与加载代际映射；不得按文本/时间/哈希去重或套用Codex方法名。
- 预期结果：逐一断言spec中正常、异常、取消、重复与边界结果；状态/引用不串会话，不把未知写成成功，不弱化协议语义；局部模拟不替代真实验收。

### ZC-004 事务资源与并发协作

- 用例级别：L4
- 操作步骤：探测入口未知、版本改变、能力缺失时校验服务端拒绝与Web按钮一致；模拟断线、旧审批、共享实例释放、恢复重放无法关联和压缩输出，核对Command/Run/历史端口不重复、不改写已存记录。
- 预期结果：跨组件失败无假成功或半提交，幂等请求不重复副作用；取消和关闭有所有者，失败仍保留管理责任；模拟边界和实际断言另存报告。

### ZC-005 未核实程序

- 用例级别：L5
- 操作步骤：在已认证Web的本change管理入口，准备并操作以下情形：尚未确定 ZCode 实际程序或 ACP 路径。读取操作结果、页面、持久记录及受影响资源；对重复、取消、失败与边界分支逐项核实，不仅检查截图。
- 预期结果：系统标记接入未验证并拒绝执行，不展示为可用

### ZC-006 不支持的取消

- 用例级别：L5
- 操作步骤：在已认证Web的本change管理入口，准备并操作以下情形：固定版本不提供可确认的取消路径。读取操作结果、页面、持久记录及受影响资源；对重复、取消、失败与边界分支逐项核实，不仅检查截图。

### ZC-007 重放无法关联

- 预期结果：系统阻止该无损接管路径并报告能力阻断，不按文本相同去重

### ZC-008 仅有模拟通过

- 预期结果：接入仍标记未验证，不能标记真实兼容性通过

### ZC-010 独立安全及交互检视

- 用例级别：L5
- 操作步骤：由不继承 coder 对话的独立 reviewer 使用源码、配置、依赖审查、脱敏日志、浏览器和协议探针，核对设计权威与引用、页面状态及失败提示、敏感信息/权限边界、依赖维护许可与 Windows 支持、证据脱敏和限制展示；以实际 DOM、响应及执行证据核对行为。缺工具、环境、权限或入口记受阻/未执行，不自动转为用户手测。
- 预期结果：独立 reviewer 记录问题 ID、风险与结论；产品行为不擅改，未验证和错误不伪装成功，敏感信息不泄漏且权限边界成立。主执行自查不能代签独立检视通过，模型推断不能代替执行证据；独立角色要求不自动构成人工验收要求。

### ZC-011 通用标准路径接入与真实版本矩阵

- 用例级别：L5
- 操作步骤：固定真实程序、协议和适配器版本及启动/认证引用配置；实际可用组合运行原有 L6 的创建、输入、结构输出、审批、取消完成、释放恢复及异常闭环，核对通用轨迹和相同能力 Codex 首验合同。
- 预期结果：仅新增接入配置及兼容证据，不以厂商名新增标准语义、私有协议实现或专属页面；每个受测版本独立留取消/完成与未知结构证据，不假定同时支持双版，不用模拟替代真实通过。

### ZC-012 缺口报告与用户决策阻断

- 用例级别：L5
- 操作步骤：分别准备必需能力缺失、无共同版本、只能依赖未授权私有桥接三类接入；报告后用户未决定时尝试输入及恢复，观察其他兼容接入。
- 预期结果：报告程序/协议版本、缺口、影响、脱敏证据和选项；用户明确决定前受影响操作不可用，不自动桥接、不降级文本、不虚报支持、不派发有副作用输入，其他兼容接入不受影响。

### ZC-013 兼容升级影响分析与新证据

- 用例级别：L5
- 操作步骤：保留旧版通过记录，升级真实程序但保持标准兼容；分析程序、协议、扩展、配置及原生存储，重新协商并执行受影响合同及真实闭环，比较代码及证据差异。
- 预期结果：复验后新版才可用；兼容时仅需更新接入信息及证据，不强制改厂商代码；旧记录保留且不冒充新版通过，升级本身不意味着必须适配。

### ZC-014 不兼容升级保留旧事实并等待决策

- 用例级别：L5
- 操作步骤：由已留证旧版升级至必需能力或协议语义复验失败的新版本；尝试沿用旧结论、输入及恢复，用户未决定时复查两版历史。
- 预期结果：新版明确报告版本、缺口、影响、证据及选项并阻断；旧事实保留原版本归属，不充当新版通过；不擅自换会话、桥接、降要求或自动适配，等待用户决定。

### ZC-009 真实Windows与Web闭环

- 用例级别：L6
- 操作步骤：先在隔离配置根核实真实ZCode官方程序、启动路径、许可证、固定版本/二进制摘要与协议握手；门禁通过后真实Web创建会话、输入、结构工具、审批唯一决定、取消可靠完成、页面断开继续、释放并原生恢复继续上下文、压缩后历史保留、异常退出未知结果；缺必需能力出阻断报告，不能声称完整接入。
- 预期结果：通过真实可观察的本change闭环证明全部关联结果；ZCode实际程序和协议、原生存储、Windows进程树、Web与平台数据库均真实；未知入口或版本未固定时L6未执行，模拟适配器与官方文档均不是真实兼容性证据。模拟结果不能替代真实依赖，不声称未暴露或未实测能力。

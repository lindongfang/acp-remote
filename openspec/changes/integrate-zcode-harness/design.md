## Context

RP-001 当前重放边界（2026-10-30）：以本 change 当前 specs 和通用 harness-management/structured-history 为准，标准重放为基础准入；只做共用 ACP 版本与能力处理，不按厂商补读取适配。平台分页可在完整流式重放形成的有界可丢弃视图上提供；本文早期探测及下游未重基准记录不构成新版通过。实际实现、管理数据迁移与产品验收均保持暂停。

## Goals / Non-Goals

设计可执行的能力发现与接入门禁，而非编造具体协议。Windows 节点和 Web 继续复用平台服务；不修改私有会话文件，不以模型 API 包装器冒充 ZCode 原生 Harness。

## Decisions

### 0. 接入配置复用通用 ACP

PV-001：版本优先级统一引用 harness-management 的“优先最高共同可用协议”。同一程序支持多版时，新连接优先最高已实现版本的标准协商，不因旧探测使用低版而固定低版；对端合法低版选择、原因未提供及规范允许的回退如实呈现。不新增 ZCode 版本映射或私有探测，高版业务失败不自动降版重发；尚未核实的程序与协议组合保持未验证。

运行时操作准入统一引用 harness-management 的平台处理、当前能力和安全条件三项门槛，程序版本实测状态单独展示；本 change 的正式接入验收门禁不转化为终端用户运行时的版本白名单。原生目标、非输入 Run 的加载审批及当前连接视图均沿通用身份和操作模型。

2026-10-30 职责澄清：本 change 的 Harness 专项交付是能力调研、接入配置和实测验收。固定版本只限定证据，不固定运行时 ACP 版本。每次连接由通用 ACP 初始化流程协商并绑定该连接的版本策略及能力；不配置或硬编码“ZCode 只能使用某 ACP 版本”，重连后重新协商。

本项仅负责接入配置与兼容性验收。版本策略、公共客户端、扩展隔离及升级影响分析遵循上游 [通用 ACP 设计](../deliver-codex-session-loop/design.md) 的“通用 ACP 与多版本兼容边界”。启动入口与本机认证引用记录于 app/src/harnesses/zcode/；该目录不包含厂商协议实现。版本合同和能力夹具复用通用入口，不按厂商名称选择标准方法。v1/v2 仅验证实际可用组合，规范依据、草案/稳定状态与真实结果分别记录，未验证不得声明兼容。

必要能力缺失、语义不兼容、规范无法核实或需要私有桥接时，暂停受影响接入，向用户报告具体版本、缺口、影响、脱敏证据和可选方案，等待用户决定；不自行增加私有实现、重灌历史或降低产品要求。公共客户端违反已核实标准时回到通用闭环修复并重跑受影响回归；产品规则或桥接范围变化仍由用户决策。Web 使用通用能力及错误展示，不建立厂商特有页面流程。

升级先分析程序、协议、扩展、配置及原生存储影响，重新协商并执行受影响复验。旧证据保留为原版本结果，不视为新版本已通过；标准兼容且复验通过时仅更新配置及证据，不强制修改代码。

### 1. 先探测、再登记接入配置

把接入配置与验收拆成两个串行阶段。探测阶段在隔离配置根确定可执行文件、官方来源、许可证、发布版本、二进制摘要、启动方式与协议握手，保存脱敏能力记录。实际路径尚待探测是明确的实施输入门禁，不列为可安全忽略的问题。只有得到真实协议资料与握手记录才填写启动配置并核对通用版本策略的类型映射；探测失败产出阻断报告，不编写猜测接口。选此方案而非预填常见 ACP 方法，因为“名为ZCode”不能证明它是特定程序或支持相同扩展。

### 2. 每能力独立证据

能力记录包含声明来源、协商结果、真实测试结果及固定版本；支持状态为未验证/支持/不支持，失败原因保留结构码且脱敏。创建、输入、结构输出、审批、取消完成、释放及原生恢复是本闭环必需门禁；缺一项不得标记完整接入。历史读取、无重放恢复和子会话暴露分别检测，不从ACP支持推导。Web按钮按能力展示并保留说明，服务端仍逐命令校验，防止旧页面绕过。

### 3. 仅映射已证明语义

兼容验收核对通用客户端沿用上游Command/Run/审批与条目端口，来源字段保持原始值；未知扩展存带协议版本的原始结构并明确不支持。将恢复产生的消息放入独立加载代际，只有来源ID和边界可可靠对应时关联已有历史；否则阻断需要去重的路径。不使用正文哈希、时间邻近或源时间戳猜测身份。上下文压缩按原生实际读取结果展示，不保留平台旧正文对抗原生现状。

### 4. 资源与异常沿用节点所有权

由节点拥有协议连接及Windows进程树；页面断开不关闭连接。释放首先冻结会话命令、记录必要管理事实并协调执行，按探测所得关闭语义释放；共享实例只释放本会话。断线后失效旧审批并标记未知执行，不自动重发。接入阶段必须确定连接丢失是否自行清理后台资源；未知时实例仍受节点追踪，不凭连接关闭宣称资源已释放。

## Risks / Trade-offs

- [实际产品不提供必需原生能力] → 明确阻断并回报所缺能力；若必须改变产品范围，另行请求确认，不能悄然降级为文本聊天。
- [未来版本改变协议] → 版本和摘要绑定证据，升级重跑合同与真实验收。
- [重放缺跨加载稳定标识] → 沿通用处理重建读取代际及视图，不按文本合并；无法证明完成或当前内容范围时明确限制，不把临时位置冒充原生稳定 ID。缺标准重放本身仍拒绝接入。

## Migration Plan

定义登记不直接授予执行资格；每个运行时操作按通用准入判断。正式接入验收在隔离测试根取证，缺少某个程序版本报告不自动禁用符合通用条件的标准操作。无历史回填与旧系统迁移。回滚禁用ZCode新操作，协调其现有实例关闭并保留管理事实及原生绑定；不得改写原生文件以使旧版本可恢复。

## Implementation Gate

实际入口、受测版本、协议处理和Windows释放证据必须在正式接入验收签署前取得；本设计确定探测程序和拒绝策略，不代表这些未知已解决。tests/plan/tasks安排真实探测及独立检查，产品功能目前未验证。

## Context

见 proposal.md 和重设计§9。调研指出 DeepSeek ACP 有跨进程恢复、关闭及断线清理语义，且不支持session/load；这是调研信息，尚未绑定真实发布版本。平台合同来自通用 ACP 闭环（Codex 首验），实施前必须按最终上游规格重基准。

## Goals / Non-Goals

复用平台领域和Web，不建立DeepSeek专属会话生命周期。不从原生存储解析正文，不用恢复操作补齐平台漏存历史。

## Decisions

### 0. 接入配置复用通用 ACP

本项仅负责接入配置与兼容性验收。版本策略、公共客户端、扩展隔离及升级影响分析遵循上游 [通用 ACP 设计](../deliver-codex-session-loop/design.md) 的“通用 ACP 与多版本兼容边界”。启动入口与本机认证引用记录于 app/src/harnesses/deepseek/；该目录不包含厂商协议实现。版本合同和能力夹具复用通用入口，不按厂商名称选择标准方法。v1/v2 仅验证实际可用组合，规范依据、草案/稳定状态与真实结果分别记录，未验证不得声明兼容。

必要能力缺失、语义不兼容、规范无法核实或需要私有桥接时，暂停受影响接入，向用户报告具体版本、缺口、影响、脱敏证据和可选方案，等待用户决定；不自行增加私有实现、重灌历史或降低产品要求。公共客户端违反已核实标准时回到通用闭环修复并重跑受影响回归；产品规则或桥接范围变化仍由用户决策。Web 使用通用能力及错误展示，不建立厂商特有页面流程。

升级先分析程序、协议、扩展、配置及原生存储影响，重新协商并执行受影响复验。旧证据保留为原版本结果，不视为新版本已通过；标准兼容且复验通过时仅更新配置及证据，不强制修改代码。

### 1. 版本探测决定实际调用

实施先确定Windows实际程序、官方发布来源、版本/摘要、适配器与协议版本，在隔离原生根完成握手。把调研的list/resume/close作为待核验候选而非硬编码事实；以协商与真实行为确定类型映射。session/load默认不开放，只有未来固定版本证明支持才另行更新能力证据。相比用统一“load”封装全部路径，独立恢复/历史端口防止把无重放误解为没有历史。

### 2. 平台历史与原生恢复解耦

按原生范围和会话ID跨进程恢复；页面始终读取平台历史，无重放是预期分支。原生状态不存在则保留历史并拒绝继续输入，不新建替身或灌入提示词。压缩后继续保存新观察条目，原有历史不被摘要覆盖。若未来恢复发生重放，必须用可靠来源身份隔离，并重新验证该路径，不能按文字去重。

### 3. 节点长期拥有连接

协议连接归实例管理器而非Web订阅。页面关闭仅移除订阅；连接异常使所有相关审批代际失效，并将无终态Run记为中断或未知。调研的断线清理不能替代Windows资源确认；实例管理器仍检查拥有的Job Object和任务退出，共享实例影响逐会话记录。取消发出不释放前台锁，等待真实完成或异常事实处理。

### 4. 实证矩阵与升级

以程序版本、适配器版本、协议版本、配置根和测试环境形成一组证据，分别记录声明、协商、模拟与真实结果。必须验证跨进程继续上下文、唯一审批、旧审批失效、取消完成、页面断开、连接异常及进程树关闭；支持子身份和历史读取与否单独列出。升级按本设计通用接入原则进行影响分析及复验；旧证据仅适用于原版本，不因版本号变化自动改代码，也不凭版本号相近沿用通过结论。

## Risks / Trade-offs

- [无重放无法补救平台漏存] → 上游保存失败策略必须真实验证，恢复不被包装为补采。
- [断线清理范围可能跨共享会话] → 真实记录作用域，实例粒度按可证明隔离选择；无法隔离则不承诺单会话独立释放。
- [认证配置含密钥] → 复用本机凭据边界，不写审计、进程命令日志或测试快照。

## Migration Plan

新增接入配置及版本证据，不迁移旧系统数据。先在隔离原生根验证再开放可信Web操作；回滚停止新建，协调现有实例关闭，保留平台记录和原生绑定。版本不兼容时拒绝恢复，不能改写原生文件。

## Implementation Gate

固定版本探测、真实合同验证、依赖审查及独立方案检视尚待实施。本设计没有宣称DeepSeek在当前节点已安装或任何真实测试已通过。

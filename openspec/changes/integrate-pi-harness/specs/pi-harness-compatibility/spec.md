# Pi 接入兼容性

## Purpose

定义本机已安装的 Pi 通过外部 ACP 服务端接入本平台时的无版本绑定配置、协议交互与证据边界。明确节点单一启动入口与兼容性报告双组件观测记录的职责划分，防止将 Pi RPC、隐式脚本包装、文档声明或其他 Harness 结果冒充真实 ACP 兼容性。

## ADDED Requirements

### Requirement: Pi 接入身份与入口可追溯
系统 SHALL 为 Pi 接入保存单一 ACP 对端启动配置（原生可执行入口、独立参数与环境变量覆盖）及显式接入来源，并在每次连接时按 ACP 实际协商记录对端信息与能力。项目配置、探针与运行时 MUST 不绑定或锁定特定 Pi 版本，也不把 Pi RPC 或终端输出当成 ACP；单次兼容性报告 MUST 只读记录当次实测观察到的本机 Pi 与外部 ACP 服务端信息，来源与原生身份遵循 native-session-recovery。

#### Scenario: 通过外部 ACP 服务端接入
- **WHEN** 用户登记指向外部 ACP 服务端的原生可执行启动配置与显式来源并建立连接
- **THEN** 系统保存可追溯的单一启动配置与显式来源并按当前连接实际 ACP 协商结果处理，不要求配置固定 Pi 版本；兼容性报告分别记录当次实测观察到的外部 ACP 服务端与本机 Pi 信息

#### Scenario: 入口缺失或提供非 ACP 输出
- **WHEN** 启动配置中的可执行入口缺失、非绝对路径、属于需要隐式 Shell 解释的脚本，或对端输出不符合平台已实现的 ACP 协议
- **THEN** 系统明确报告启动或协议错误，不通过隐式 Shell 包装兜底、不静默安装或锁定 Pi、不改用 RPC 或模拟握手

### Requirement: Pi 能力按当前 ACP 连接处理
系统 SHALL 对 Pi 复用 harness-management 的版本协商、客户端空能力声明、标准能力与错误语义。对端反向调用平台未声明支持的客户端委托方法时，系统 MUST 按协议返回方法不支持错误；兼容性报告分别列出声明、实际协商及真实验证结果，不建立 Pi 版本白名单、私有替代或业务降版重发。

#### Scenario: 标准操作不支持
- **WHEN** Pi 的 ACP 入口未提供所请求的标准能力，或反向请求平台未声明支持的客户端文件、终端等委托操作
- **THEN** 系统对缺失的对端能力直接报告操作不支持，对未声明的客户端委托请求返回标准不支持响应；其他可用能力保持独立使用，不将其表述为整个接入不可用

#### Scenario: 程序或适配器升级
- **WHEN** 用户本机 Pi 或外部 ACP 服务端升级、更换版本后建立新连接
- **THEN** 系统无需修改项目配置或代码即可重新按通用规则协商；历史兼容性证据仅归属原受测组合，尚未复验的范围标记为未验证且不阻断运行时标准调用

### Requirement: Pi 内容保真与限制可见
系统 SHALL 按节点配置合同、structured-history 与 management-input-upload 保留 ACP 实际提供的结构化内容、会话启动配置及必要原始字段。通用 Web 表单尚未暴露的可选配置字段，以及外部适配器未传递的配置或遗漏的结构 MUST 分别明确记录为对应层限制，不伪造思考、差异或工具结构，也不通过文本转换掩盖不支持的输入类型。

#### Scenario: 收到结构化工具内容
- **WHEN** ACP 服务端提供工具更新、差异、思考或其他已实现结构
- **THEN** 通用视图保持结构及关联；未知结构按通用规则保留并明确限制，不静默丢弃

#### Scenario: 适配器存在结构丢失或输入降级
- **WHEN** 兼容性验证发现适配器忽略会话启动配置、遗漏必要结构、将不支持输入静默转为文本，或操作超出当前通用 Web 表单已暴露的字段范围
- **THEN** 报告明确区分适配器限制与通用表单范围并附证据，不签署未保真能力通过，不由平台伪造缺失内容

### Requirement: Pi 恢复与历史分别验收
系统 SHALL 对 Pi 的原生恢复、历史重放及外部会话可见范围分别验证。外部适配器的会话标识映射不等于完整原生会话目录；平台 MUST 不私读映射文件或原生正文补齐能力，也不重灌平台聊天副本。

#### Scenario: 恢复成功但无完整重放
- **WHEN** 同一来源的 Pi 会话可以恢复而历史不可完整重放
- **THEN** 恢复与可用执行保持独立，页面明显提示历史不完整及缓存丢失无法补回，不宣称历史同步完成

#### Scenario: 原生引用或适配器映射失效
- **WHEN** 已登记会话无法通过标准接口恢复
- **THEN** 报告失败及已知范围，不新建替代会话，不按正文、文件路径或时间猜测原生身份

### Requirement: Pi 权限与进程链受节点管理
系统 SHALL 按 permission-approvals 与 session-execution 管理 Pi 的实际权限请求和执行，按 native-session-recovery 管理释放。节点 MUST 管理其启动的 ACP 服务端及本机 Pi 子进程链，页面断开不停止执行，取消未确认不冒充停止或释放。

#### Scenario: 真实权限请求与页面断线
- **WHEN** Pi ACP 入口发出权限请求，随后页面断线或连接代际失效
- **THEN** 页面断线不撤销节点管理；批准仍须满足真实请求有效性和持久化规则，失效请求不重发、不默认批准；若对端在客户端空能力下不发出权限请求则如实记录该能力未提供

#### Scenario: 取消或关闭未确认
- **WHEN** 取消未取得可靠原生工作终态，或实例关闭未能证明所属进程链已收敛
- **THEN** 分别报告执行取消与实例关闭结果；取消已有可靠终态时允许常驻进程继续存在，关闭未收敛时保留清理责任，不误杀不属于本次启动的用户本机 Pi，不影响共享实例其他会话

### Requirement: Pi 兼容证据与用户数据隔离
Pi 兼容性验收 SHALL 使用明确隔离的会话、配置、工作区和进程，报告逐项区分真实、模拟及未执行结果并附当次只读观测到的组件版本；验收与运行时 MUST 不绑定、安装、升级或降级用户本机 Pi，不改写用户实际原生会话、认证或密钥，不在日志和报告泄漏凭据或敏感正文。

#### Scenario: 缺少本地路径或隔离环境
- **WHEN** 尚未确认本机 Pi 可调用入口、外部 ACP 服务端入口或安全隔离环境
- **THEN** 将相关真实用例记未执行，不自动安装或锁定特定 Pi 版本，不以文档调研、协议替身或 Codex 等其他 Harness 结果代替 Pi 验收

#### Scenario: 验证失败后清理
- **WHEN** 隔离验证失败或被取消
- **THEN** 清理本次拥有的完整进程树和临时资源，保留脱敏失败证据，不删除或修改用户本机 Pi 安装与会话数据

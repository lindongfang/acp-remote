# Pi 接入兼容性

## Purpose

定义 Pi 通过明确的 ACP 服务端接入本平台时的配置、证据及可观察边界。区分 Pi 本体、外部适配器和平台各自负责的能力，防止将 RPC、文档声明或其他 Harness 的验证结果冒充真实 ACP 兼容性。

## ADDED Requirements

### Requirement: Pi 接入身份与入口可追溯
系统 SHALL 为 Pi 接入记录明确的启动配置与接入来源，区分 Pi 程序和对外 ACP 服务端；兼容性报告 MUST 绑定两者的受测版本及环境，不把 Pi RPC 或终端输出当成 ACP。来源与原生身份遵循 native-session-recovery，不推断不同来源的物理存储等价性。

#### Scenario: 通过外部 ACP 服务端接入
- **WHEN** 用户登记 Pi 及外部 ACP 服务端的启动配置
- **THEN** 记录可追溯的程序链和显式来源，连接按 ACP 实际协商处理，报告分别标记两者的受测版本

#### Scenario: 入口缺失或提供非 ACP 输出
- **WHEN** 配置程序不可启动或输出不符合平台已实现的 ACP 协议
- **THEN** 明确报告启动或协议错误，不静默安装程序、改用 RPC、模拟握手或宣称已连接

### Requirement: Pi 能力按当前 ACP 连接处理
系统 SHALL 对 Pi 复用 harness-management 的版本协商、能力与错误语义。报告分别列出声明、实际协商及真实验证结果；缺历史报告不构成运行时白名单，操作不支持不触发私有替代或业务降版重发。

#### Scenario: 标准操作不支持
- **WHEN** Pi 的 ACP 入口未提供所请求的标准能力
- **THEN** 直接报告受影响操作不支持，其他能力独立使用，不将其表述为整个接入不可用

#### Scenario: 程序或适配器升级
- **WHEN** 任一组件升级后建立新连接
- **THEN** 重新按通用规则协商，旧结果仅属于旧版本组合；尚未复验的部分明确标记未验证

### Requirement: Pi 内容保真与限制可见
系统 SHALL 保留 ACP 实际提供的结构化内容和必要原始字段，按 structured-history 与 management-input-upload 处理输入和输出。适配器未提供的内容 MUST 明确记录为限制，不伪造思考、差异或工具结构，不通过文本转换掩盖不支持的输入类型。

#### Scenario: 收到结构化工具内容
- **WHEN** ACP 服务端提供工具更新、差异或其他已实现结构
- **THEN** 通用视图保持结构及关联；未知结构按通用规则保留并明确不支持，不静默丢弃

#### Scenario: 适配器存在结构丢失或输入降级
- **WHEN** 兼容性验证发现适配器遗漏必要结构或将不支持输入静默转为文本
- **THEN** 报告具体组件、受影响类型及证据，不签署该能力保真通过，不由平台伪造缺失内容

### Requirement: Pi 恢复与历史分别验收
系统 SHALL 对 Pi 的原生恢复、历史重放及外部会话可见范围分别验证。外部适配器的会话标识映射不等于完整原生会话目录；平台 MUST 不私读映射文件或原生正文补齐能力，也不重灌平台聊天副本。

#### Scenario: 恢复成功但无完整重放
- **WHEN** 同一来源的 Pi 会话可以恢复而历史不可完整重放
- **THEN** 恢复与可用执行保持独立，页面明显提示历史不完整及缓存丢失无法补回，不宣称历史同步完成

#### Scenario: 原生引用或适配器映射失效
- **WHEN** 已登记会话无法通过标准接口恢复
- **THEN** 报告失败及已知范围，不新建替代会话，不按正文、文件路径或时间猜测原生身份

### Requirement: Pi 权限与进程链受节点管理
系统 SHALL 按 permission-approvals 与 session-execution 管理 Pi 的实际权限请求和执行，按 native-session-recovery 管理释放。节点 MUST 管理其启动的 ACP 服务端及 Pi 子进程链，页面断开不停止执行，取消未确认不冒充停止或释放。

#### Scenario: 真实权限请求与页面断线
- **WHEN** Pi ACP 入口发出权限请求，随后页面断线或连接代际失效
- **THEN** 页面断线不撤销节点管理；批准仍须满足真实请求有效性和持久化规则，失效请求不重发、不默认批准

#### Scenario: 取消或关闭未确认
- **WHEN** 取消未取得可靠原生工作终态，或实例关闭未能证明所属进程链已收敛
- **THEN** 分别报告执行取消与实例关闭结果；取消已有可靠终态时允许常驻进程继续存在，关闭未收敛时保留清理责任，不误杀不属于本次启动的 Pi，不影响共享实例其他会话

### Requirement: Pi 兼容证据与用户数据隔离
Pi 兼容性验收 SHALL 使用明确隔离的会话、配置、工作区和进程，报告逐项区分真实、模拟及未执行结果。MUST 不改写用户实际原生会话、认证或密钥，不在日志和报告泄漏凭据或敏感正文。

#### Scenario: 缺少本地路径或隔离环境
- **WHEN** 尚未取得 Pi 与 ACP 入口的真实路径或安全隔离环境
- **THEN** 将相关真实用例记未执行，不以文档调研、协议替身或 OMP 结果代替 Pi 验收

#### Scenario: 验证失败后清理
- **WHEN** 隔离验证失败或被取消
- **THEN** 清理本次拥有的完整进程树和临时资源，保留脱敏失败证据，不删除用户数据

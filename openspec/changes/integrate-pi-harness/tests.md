# Tests

## 执行边界与需求映射

本文件基于修订后的 proposal、增量规格与 design 维护后续验收预期，不记录执行结果。本轮不安装、调用、升级或降级本机 `pi` 与外部适配器，不修改产品代码，且**项目任何配置、探针与脚本均不绑定或锁定特定 Pi 版本**。实施前须经独立 `tester` 与独立 `reviewer` 对照真实源码核对一致。

- 需求路径 `specs/pi-harness-compatibility/spec.md` 仅指本变更增量。下表列出精确 Requirement/Scenario；长期约束使用显式 `openspec/specs/...` 路径。
- 正式执行记录平台提交及文件清单摘要、Windows 环境、探针适配器自身锁文件摘要（不含 `pi` 本体）、配置版本及显式来源，并在 `testing/runs/integrate-pi-harness/` **只读记录当次实测观察到的本机 `pi` 与外部 ACP 服务端版本**用于证据归属，不硬编码校验特定 `pi` 版本；模拟通过不能填作真实通过。
- L4 使用真实配置解析/存储与 `OwnedProcess` 启动边界（含自有原生 PE 绝对路径回显进程及相对路径/`.ps1` 拒绝夹具）；L5 使用真实节点认证入口、存储与 ACP 传输，对端允许使用明确标记的合同替身；L6 的 Windows 节点、真实浏览器、本机已安装的 `pi`、外部 ACP 服务端、隔离原生会话及所属 Job 进程树必须全部真实。
- 仓库实际检查入口为根 `package.json` 的 `npm run check`、`npm run build:rust`；专项验收入口拟建于 `testing/probes/pi-harness/acceptance/run.ps1`，未建成或环境缺失记 `not-run`/受阻，不转为 LX。本次无必须人工主观判断的场景，不设 LX。
- 全部故障注入、会话映射损坏及进程清理仅作用于 `.tmp/` 下本次拥有的测试根与 Job Object 进程树；严禁扫描、改写或删除用户真实本机 `pi` 安装、原生会话、认证与密钥，严禁按进程名批量终止用户程序。

| 用例 | Requirement | Scenario |
|---|---|---|
| PI-004 | Pi 接入身份与入口可追溯 | 通过外部 ACP 服务端接入；入口缺失或提供非 ACP 输出 |
| PI-005 | Pi 能力按当前 ACP 连接处理 | 标准操作不支持 |
| PI-006 | Pi 能力按当前 ACP 连接处理 | 程序或适配器升级 |
| PI-007 | Pi 内容保真与限制可见 | 收到结构化工具内容；适配器存在结构丢失或输入降级 |
| PI-008 | Pi 恢复与历史分别验收 | 恢复成功但无完整重放 |
| PI-009 | Pi 恢复与历史分别验收 | 原生引用或适配器映射失效 |
| PI-010 | Pi 权限与进程链受节点管理 | 真实权限请求与页面断线 |
| PI-011 | Pi 权限与进程链受节点管理 | 取消或关闭未确认 |
| PI-012 | Pi 兼容证据与用户数据隔离 | 缺少本地路径或隔离环境；验证失败后清理 |
| PI-001–003、PI-013 | proposal.md `Success Criteria` | SC1–SC4；PI-013 复核以上场景的真实可达分支及逐能力限制 |

共用长期依据：`openspec/specs/harness-management/spec.md` 的“优先最高共同可用协议”“默认继承节点环境”“能力准入与证据状态分开”“调研证据不成为版本绑定表”；`openspec/specs/native-session-recovery/spec.md` 的“原生身份不依赖启动入口”“恢复与历史读取分离”“释放确认与管理事实”；输入、结构及审批分别遵循 `openspec/specs/management-input-upload/spec.md`、`openspec/specs/structured-history/spec.md`、`openspec/specs/permission-approvals/spec.md`，执行与取消遵循 `openspec/specs/session-execution/spec.md`。

## Cases

### PI-001 规划一致性与依赖证据可追溯

- 用例级别：L1
- 操作步骤：执行 `openspec validate integrate-pi-harness --strict` 和 `git diff --check`；逐项核对六类规划、精确 Requirement/Scenario 名称映射、`tasks.md` 到 `plan.md` 工作包完整引用、目录收敛（`testing/probes/pi-harness/`、`docs/implementation/`、`openspec/specs/`、`testing/suites/`）及“不绑定 `pi` 版本”约束与现有源码边界的一致性。实施前在 `WP1` 核查本机 `pi` 入口只读取证（不锁版本）、候选外部 ACP 服务端的许可证/维护/安全审查与探针依赖边界，以及空客户端能力下的实证结论。
- 预期结果：规划校验无错误，映射真实完整且无跨源码模型冲突；配置、探针与文档均未绑定或硬编码特定 `pi` 版本，未新增运行时版本白名单。未完成的 `WP1` 实证输入明确阻断后续产品实施，不将规划通过冒充实测兼容。

### PI-002 现有构建与回归入口覆盖集成结果

- 用例级别：L2
- 操作步骤：后续实施集成后，在冻结最终快照运行 `npm run check`、`npm run build:rust`；记录 Web/Rust 实际测试数量与退出码，核对配置解析、目录登记及 Web 专项测试已实际执行。若涉及新增产品断言，按 `docs/code-standards.md` 保存旧实现失败与新实现通过的 Red Check 证据。
- 预期结果：适用检查与构建全部通过且有非零有效断言约束改动；既有通用 ACP 行为无回归。缺环境或未执行项如实记录，不以静态检查通过或旧归档结果替代 Pi 验收。

### PI-003 Windows 启动配置与敏感数据边界

- 用例级别：L4
- 操作步骤：经真实 `format: 1` 配置入口发布无密钥、无 `pi` 版本绑定的 Windows 绝对路径原生 PE 可执行启动模板，用自有绝对路径原生 PE 回显进程验证空格、引号、首尾空白、非 ASCII 路径及环境变量默认继承与显式覆盖；分别将相对路径文件名和 `.tmp/` 下 `.ps1` 绝对路径填为 `executable`，验证 `OwnedProcess` 的绝对路径前置校验与无隐式 Shell `CreateProcessW` 拒绝行为，并测试未知字段、畸形配置、缺来源及未授权附加目录拒绝。注入合成凭据标记检查日志、错误与目录清单脱敏。
- 预期结果：原生 PE 绝对路径启动链完整保留独立 UTF-16LE 参数与显式来源，无隐式 Shell 拼接或包装兜底；相对路径可执行名与 `.ps1` 绝对路径均明确返回启动失败，未知字段、缺来源与越权目录明确拒绝；环境变量继承与覆盖按长期规格生效，合成凭据零泄漏，用户本机配置不被触碰。回显夹具不代签真实 `pi-acp`/`pi` 参数生效（由 `PI-013` 验证）。

### PI-004 ACP 接入链与错误入口

- 用例级别：L5
- 操作步骤：经节点认证管理入口登记指向外部 ACP 服务端的单一 Windows 绝对路径原生可执行启动配置与显式来源，建立连接并读取节点目录摘要及 ACP `initialize` 协商出的对端 `agentInfo` 与能力；由验收程序只读采集当次受测对端与本机 `pi` 版本写入报告。随后在独立来源中分别配置不存在的绝对路径可执行文件、`.ps1` 绝对路径脚本入口、仅输出 Pi RPC 的对端及交互终端输出对端，观察错误与进程退出；再用同来源两个不同启动配置访问同一原生会话标识核对协调互斥。
- 预期结果：节点系统保存单一可追溯启动配置与显式来源并记录当前连接协商信息，不要求扩充双组件目录字段，也不校验特定 `pi` 版本；兼容性报告完整记录当次观测到的双组件信息。同来源不同启动配置共享同一执行协调归属；错误入口明确返回启动或协议错误，无隐式 Shell 兜底、无自动安装或 RPC 转换，不把 JSON-RPC 2.0 记为 ACP v2。

### PI-005 不支持操作与其他能力独立

- 用例级别：L5
- 操作步骤：在平台初始化发送空客户端能力（`clientCapabilities: {}` / `capabilities: {}`）的真实传输路径上，用协议合同替身分别模拟：（1）对端缺少可选标准能力或对已支持操作返回不支持/业务失败；（2）对端声明平台未实现能力；（3）对端反向请求 `fs/*`、`terminal/*` 等平台未声明支持的客户端委托方法。随后在同一连接继续请求仍可用的普通输入或读取。
- 预期结果：明确区分对端不支持、平台未实现与实际业务失败；对非 `session/request_permission` 的未声明客户端委托请求按协议返回 `-32601 Method not found`，不崩溃、不伪报成功；仅受影响操作报错，其余可用标准能力继续独立工作，无私有兜底或业务降版重试。

### PI-006 组件升级后重新协商与证据失效

- 用例级别：L5
- 操作步骤：保持已登记的无版本绑定启动配置不变，在隔离环境用不同版本的合同替身（或组件更新前后）分别模拟本机 `pi` 版本变化、外部 ACP 服务端版本变化后重新连接；覆盖最高共同可用版本、规范允许回退、对端合法选低版且无原因、无共同版本及高版业务失败，核对新连接协商状态与报告版本归属。
- 预期结果：无需修改项目配置或代码即可在新连接自动重新协商最高共同可用版本；旧连接在途请求和审批不迁移重发，高版业务失败不自动降版重试。旧兼容性记录仅归属原观测版本组合，新组合未复验能力标记未验证且不阻断运行时标准调用。

### PI-007 输入与结构输出保真

- 用例级别：L5
- 操作步骤：分两层验证保真边界：（1）经底层 `format: 1` 配置文档配合声明对应能力位的合同对端提交非空 `mcp_servers`、`extra` 及精确参数，核对 `session/new`、`session/resume` 出站载荷保真与对端未声明能力时的标准拒绝；（2）经通用 Web 表单验证当前已暴露字段（含 `parseLaunchArgsLines` 行级 `trim` 边界）及文本/结构输入提交，核对合同对端发出的工具开始、多次原位更新、后续文字、晚完成、差异、思考流与未知结构；另注入适配器忽略启动配置、遗漏结构、将不支持输入静默转文本及包含主动 HTML/脚本/控制字符的场景。
- 预期结果：底层 `format: 1` 完整保留 `mcp_servers`、`extra` 与原始结构，通用 Web 表单未暴露 `mcpServers`/`extra` 的现状如实记录为表单范围限制，不混称底层协议不支持或页面已支持编辑；工具原位更新和消息顺序保持不变，主动内容安全隔离不执行，适配器配置忽略、结构丢失或输入降级明确记为限制而不签保真通过。

### PI-008 恢复与历史限制分别呈现

- 用例级别：L5
- 操作步骤：在同一来源建立会话后释放并按原生标识恢复，分别使用无重放、完整标准重放和重放中断合同；检查无重放时仍可输入、页面明显提示及节点缓存失效后的重开表现。分别请求列表与按标识读取，核对外部适配器仅暴露自身映射会话时的范围声明。
- 预期结果：恢复成功不冒充历史已同步；无重放明显提示历史不完整及缓存丢失无法补回，可用操作不被整体禁用。重放完整仅在协议完成事实到达后声明；列表、恢复、重放及外部会话可见范围分别记录，无私读映射文件或平台聊天副本补齐。

### PI-009 原生引用及适配器映射失效

- 用例级别：L5
- 操作步骤：对隔离会话分别模拟标准恢复报原生引用失效、外部 ACP 服务端重启及测试映射缺失；重试查看与恢复并核对原生标识、管理事实与出站请求。再以两个不同显式来源使用相同短原生标识，验证会话、缓存与权限隔离。
- 预期结果：恢复失败明确可观察且管理审计仍可查；不静默新建替代会话、不重灌历史、不按正文/路径/时间猜测身份。不同来源严格隔离不合并；平台不读取适配器私有映射或 Pi 原生会话文件，恢复成功亦不冒称未知旧活动已停止。

### PI-010 真实审批语义与页面断线

- 用例级别：L5
- 操作步骤：合同对端发出可验证的 `session/request_permission`，经 Web 分别测试允许与拒绝；等待期间断开原页面，由另一已授权页面查看并裁决。分别注入批准持久化失败、保存后原请求取消、连接换代及新连接复用相同短请求 ID，尝试重放旧批准、选择伪造选项及人工选择未知显示主题下的有效原选项。
- 预期结果：页面断线不中断节点托管；原选项与原始结构保留，裁决可靠持久化后才向仍有效的真实请求交付且最多一次。失效、伪造与旧代际批准一律拒绝交付、不默认允许；保存失败与交付未知分别呈现。若真实 `pi-acp` + 本机 `pi` 在客户端空能力下不产生权限请求，`PI-013` 须依据实测单列未提供说明，不借本替身宣称真实审批已支持。

### PI-011 取消竞态与完整进程树关闭

- 用例级别：L5
- 操作步骤：隔离长任务中分别取消待发送队列项、中断活动前台并等待可靠终态，再覆盖取消与自然完成交错、取消无响应、外部 ACP 服务端退出但子代 `pi`/工具孙进程仍驻留、节点关闭超时；捕获 Job Object 活动进程计数与进程树前后证据，并设置另一自有同名无关进程及共享实例第二会话作为保护对照。
- 预期结果：未发送项取消后零派发；执行中断按原生工作可靠终态确认，允许常驻进程在取消完成后继续存活，仅发出取消通知不等于已停止，已获正常终态不再死等重复取消响应。实例关闭与执行中断分开判定：关闭超时保留 cleanup/join 责任，直至所属 Job 全部后代进程收敛归零才报告实例释放完成；绝不按进程名误杀无关本机 `pi`，不影响共享实例其他会话，无法隔离时明确拒绝单会话释放。

### PI-012 缺环境、故障与取消后的证据及清理

- 用例级别：L5
- 操作步骤：验证本机 `pi` 可调用入口、外部 ACP 服务端入口或 `.tmp/` 隔离根缺失时的阻断报告；在隔离测试根外设置合成原生会话、认证与保护文件摘要对照，令验收中途失败及主动取消，检查所属 Job 进程树收敛、`.tmp/` 临时资源回收、报告脱敏及保护文件摘要（不读取用户真实密钥测试脱敏）。
- 预期结果：缺环境的真实分支如实记 `not-run` 并说明阻断原因，不自动安装或锁定特定 `pi` 版本，不借文档、替身或 Codex 等其他 Harness 结果代签。失败与取消后所属进程树清理收敛、保护数据摘要零变化、脱敏失败证据保留；未收敛清理明确保留责任，不把发出清理命令当成清理完成。

### PI-013 固定真实 Pi 组合的 Windows 与 Web 完整闭环

- 用例级别：L6
- 操作步骤：获得实施授权并满足 `Implementation Gate` 后，在 `.tmp/` 独立测试根连接**本机已安装的真实 `pi`**（不绑定或改动版本）与经审查的真实外部 ACP 服务端、真实 Windows 节点及真实浏览器；只读采集并固定本次受测运行时观察到的本机 `pi` 与适配器版本供本轮报告追溯。从 Windows 绝对路径原生 PE 启动配置登记、显式来源绑定、ACP 协商、创建/恢复隔离原生会话开始，实测文本与支持的结构输入、客户端空能力（`clientCapabilities: {}`）下的真实工具执行与委托行为、结构输出、真实审批（若对端提供）、页面断开后继续查看、取消、显式释放与 Job 完整进程树收敛、重连恢复及历史限制展示；分别核对底层 `format: 1` 配置（含 `mcp_servers`/`extra`）与通用 Web 已暴露表单的真实传递效果，并按 `PI-004`–`PI-012` 可安全复现分支逐项登记真实观察。
- 预期结果：真实链路每项操作均有可观察结果及当次观测版本证据，关键完成与进程树收敛事实不由替身提供；恢复、历史、列表、思考、工具、委托响应、审批、分层配置传递与后台范围各自独立给出结论。对端未提供的可选能力或当前通用表单未暴露字段如实记录实证依据，未触达分支记未验证，必要安全或进程树清理缺失直接阻断交付。独立 `tester`/`reviewer` 核对同一最终快照，用户本机 `pi` 安装、凭据及真实原生会话零改动。

# Tests

## 执行边界与需求映射

本文件由独立 tester 基于 proposal、增量规格和 design 编写，仅定义后续验收，不记录执行结果。本轮不安装、调用或升级真实 Pi/适配器，不修改产品代码。plan 生成后须再核对执行者、隔离资源、固定版本及证据位置；编码前还须通过独立 reviewer 的方案与用例检视。

- 需求路径 `specs/pi-harness-compatibility/spec.md` 仅指本变更增量。下表列出精确 Requirement/Scenario；长期约束使用显式 `openspec/specs/...` 路径。
- 正式执行固定平台提交及文件清单摘要、Windows 环境、Pi 与外部 ACP 服务端各自版本/摘要和来源、配置版本及显式来源。结果存入 `testing/runs/integrate-pi-harness/`，按 ID 分别记录 passed、failed、not-run、命令、断言及脱敏证据；模拟通过不能填作真实通过。
- L4 使用真实配置解析/存储及自有进程或故障夹具；L5 使用真实节点认证入口、存储和传输，协议对端允许使用明确标记的合同替身；L6 的 Windows 节点、Web、Pi、ACP 服务端、原生会话及所属进程树必须真实。各 L5 的真实分支集中在 PI-013 逐项追踪，不因替身覆盖而签署真实能力。
- 当前实际检查入口为根 `package.json` 的 `npm run check`、`npm run build:rust` 以及 README 的专项入口。Pi 专项验收脚本尚未存在，由实施任务交付并由 tester 核对实际断言数量；缺入口、环境、权限或真实依赖记受阻/未执行，不转为 LX。本次无必须人工判断且工具无法验证的场景，不设置 LX。
- 所有故障注入、会话映射损坏和清理仅作用于本次拥有的测试根及进程；不扫描、改写或删除用户真实会话、密钥和配置。不运行按程序名批量终止的清理。

| 用例 | Requirement | Scenario |
|---|---|---|
| PI-004 | Pi 接入身份与入口可追溯 | 通过外部 ACP 服务端接入；入口缺失或提供非 ACP 输出 |
| PI-005 | Pi 能力按当前 ACP 连接处理 | 标准操作不支持 |
| PI-006 | Pi 能力按当前 ACP 连接处理 | 程序或适配器升级 |
| PI-007 | Pi 内容保真与限制可见 | 收到结构化工具内容；适配器存在结构丢失或输入降级 |
| PI-008 | Pi 恢复与历史分别验收 | 恢复成功但无完整重放 |
| PI-009 | Pi 恢复与历史分别验收 | 原生引用或适配器映射失效 |
| PI-010 | Pi 权限与进程链受节点管理 | 真实权限请求与页面断线 |
| PI-011 | Pi 权限与进程链受节点管理 | 取消或关闭未确认 |
| PI-012 | Pi 兼容证据与用户数据隔离 | 缺少本地路径或隔离环境；验证失败后清理 |
| PI-001–003、PI-013 | proposal.md `Success Criteria` | SC1–SC4；PI-013 复核以上场景的真实可达分支及逐能力限制 |

共用长期依据：`openspec/specs/harness-management/spec.md` 的“优先最高共同可用协议”“默认继承节点环境”“能力准入与证据状态分开”；`openspec/specs/native-session-recovery/spec.md` 的“原生身份不依赖启动入口”“恢复与历史读取分离”“释放确认与管理事实”；输入、结构及审批分别遵循 `openspec/specs/management-input-upload/spec.md`、`openspec/specs/structured-history/spec.md`、`openspec/specs/permission-approvals/spec.md`，执行与取消遵循 `openspec/specs/session-execution/spec.md`。本专项不重复验收无关完整产品能力，也不改变这些规则。

## Cases

### PI-001 规划一致性与依赖证据可追溯

- 用例级别：L1
- 操作步骤：执行 `openspec validate integrate-pi-harness --strict` 和 `git diff --check`；人工逐项核对上述场景名、六类规划、tasks 到 plan 工作包映射及独立角色安排。实施前核对 Pi 和候选 ACP 服务端的固定来源、许可证、维护与安全审查、Windows 支持及依赖锁定证据；对照用户授权和 design 的 Implementation Gate。
- 预期结果：规划校验无错误，映射真实存在且无遗漏；结构校验不冒充场景覆盖。未定位的组件、隔离条件和清理办法明确阻断后续实施，不因本地已安装的陈述宣称版本兼容；依赖审查与运行能力证据分开，未新增运行时白名单。

### PI-002 现有构建与回归入口覆盖集成结果

- 用例级别：L2
- 操作步骤：后续实施完成后，在固定最终版本运行 `npm run check`、`npm run build:rust`；记录 Web/Rust 实际测试数量与失败信息，核对配置解析、目录登记及通用 Web 受影响测试是否执行。对新增行为断言按 `docs/code-standards.md` 保存旧实现失败和新实现通过的 Red Check 证据。
- 预期结果：适用检查和构建成功，非零有效断言约束改动；原有通用 ACP 行为无回归。缺依赖或未运行如实记录，不以工具安装、静态通过或旧归档结果替代 Pi 验收。

### PI-003 Windows 启动配置与敏感数据边界

- 用例级别：L4
- 操作步骤：从现有 format-one 配置入口发布隔离示例，经真实解析/存储读取独立 argv、原始字段和显式来源；用自有参数回显进程验证空格、引号、非 ASCII 路径及实际选用的 `.cmd`/`.ps1` 或可执行启动链。用合成环境标记验证默认继承与显式覆盖，设置合成凭据标记并检查日志、错误和报告。对畸形配置、缺来源及越权目录输入执行拒绝检查。
- 预期结果：参数边界和来源完整保留，无未转义 shell 拼接；缺来源或无效配置明确拒绝。继承和覆盖按长期规格生效，凭据标记不泄漏，失败不改写用户配置。夹具只证明平台启动路径，Pi 的真实参数/MCP/模型配置传递仍由 PI-013 验证。

### PI-004 ACP 接入链与错误入口

- 用例级别：L5
- 操作步骤：经节点认证管理入口登记 Pi 与外部 ACP 服务端的明确程序链、配置及来源，建立连接并读取实际协商信息；随后在独立来源中分别指定不存在的程序、仅输出 Pi RPC 的对端和交互终端输出对端，观察错误及进程退出。以同来源两个启动别名访问相同原生标识检查协调归属。
- 预期结果：成功路径区分 Pi 与 ACP 服务端身份、版本、连接及原生来源；同来源别名不绕过执行互斥。错误路径返回启动或协议错误，无模拟握手、自动安装或 RPC 兜底，不把 JSON-RPC 2.0 记为 ACP v2。

### PI-005 不支持操作与其他能力独立

- 用例级别：L5
- 操作步骤：合同对端分别声明缺少可选标准能力、声明平台未实现能力、对已支持操作返回不支持或业务失败；从 Web 请求对应操作，再请求仍可用的普通输入/读取。检查协议出站及管理结果，不发送破坏性能力探针。
- 预期结果：明确区分 Harness 不支持、平台未实现及实际业务失败；仅受影响操作失败，其他能力独立使用。无私有读取、替代会话、等待兼容裁决或业务降版重发，缺历史实测报告不成为运行时阻断。

### PI-006 组件升级后重新协商与证据失效

- 用例级别：L5
- 操作步骤：在隔离环境用两个固定组件组合或明确标记的版本合同替身，分别只变更 Pi、只变更 ACP 服务端后重连；覆盖最高已实现共同版本、规范允许回退、对端合法选择低版但无原因、无共同版本及高版业务失败。核对发起/实际版本、旧连接请求和报告归属。
- 预期结果：新连接重新协商，不继承旧低版缓存或热切旧连接；只在规范许可条件回退，原因未知则明示。旧请求和批准不移交重发，业务失败不降版重试。报告保留旧版本组合及证据，受影响未复验能力记未验证；模拟版本不冒充真实升级实测。

### PI-007 输入与结构输出保真

- 用例级别：L5
- 操作步骤：通过实际上传/输入入口提交文本及当前协议支持的结构输入，并对不支持类型请求观察明确拒绝；合同对端发出工具开始、多次更新、后续文字、晚完成、差异、未知结构和可区分的思考内容。对照 ACP 入站与 Web 视图；另用标记夹具模拟适配器遗漏结构、输入被转为文本及主动 HTML/终端控制字符。
- 预期结果：上传、受理、派发与执行结果分别呈现；工具关联、顺序和原始字段保留，未知内容说明限制，主动内容不执行。适配器缺失内容不能由平台凭空恢复；报告标明具体组件和类型，不签署该能力保真通过，不以文本显示成功掩盖输入降级。

### PI-008 恢复与历史限制分别呈现

- 用例级别：L5
- 操作步骤：在同一来源建立会话后释放并按原生标识恢复，分别使用无重放、完整标准重放和重放中断合同；检查无重放时仍可输入、页面提示及节点缓存丢失后的重开。分别请求列表与按标识读取，检查适配器只暴露自身映射会话时的范围声明。
- 预期结果：恢复成功不等于历史同步；无重放明确显示历史不完整及缓存丢失无法补回，可用能力不被整体拒绝。重放完整只在完成事实存在时声明；列表、恢复、重放及外部会话范围各自记录，无私有映射扫描或平台聊天副本补齐。

### PI-009 原生引用及适配器映射失效

- 用例级别：L5
- 操作步骤：对隔离会话分别模拟标准恢复报原生引用失效、ACP 服务端重启及测试映射不可用；重试查看/恢复并比较原生标识、管理事实及出站请求。再以两个不同来源使用相同短标识，检查会话、缓存与权限隔离。
- 预期结果：恢复错误可观察且管理事实仍可查；不创建替代会话、不重发历史、不按正文/路径/时间猜身份。不同来源不合并；平台不读取适配器私有映射或 Pi 会话文件，恢复成功亦不证明未知旧工作已停止。

### PI-010 真实审批语义与页面断线

- 用例级别：L5
- 操作步骤：合同对端产生可验证权限请求，经 Web 分别允许和拒绝；在等待期间断开一个页面，用另一有权页面查看和作答。分别注入批准持久化失败、保存后请求取消、连接换代以及新连接复用同样短请求标识；尝试旧批准与伪造选项。未知但有效选项仅用测试身份显式选择原选项。
- 预期结果：页面断开不终止节点管理；原选项及结构保留，决定可靠提交后才向仍有效请求交付，至多一个最终决定。失效、伪造和旧代际批准不交付，不默认允许；保存失败与交付未知分别报告。真实 Pi 未提供或无法触发权限请求时，PI-013 单列不支持/未验证依据，不借本夹具声称真实审批通过。

### PI-011 取消竞态与完整进程树关闭

- 用例级别：L5
- 操作步骤：隔离长任务中分别取消队列项、取消活动工作并等待可靠终态，再覆盖取消与自然完成交错、取消不响应、ACP 服务端退出但 Pi/孙进程仍存活、节点关闭超时。捕获所有权和进程树前后证据；准备另一自有无关同名进程及共享实例第二会话作为保护对照。
- 预期结果：未发送项取消后不派发；执行取消按可靠原生工作终态确认，ACP 服务端和 Pi 常驻进程可以继续存活，仅发取消不等于已停止，已证终态无需等待重复终态。未知活动阻止危险后继派发；实例关闭与执行取消分别判定，关闭超时保留 cleanup/join 责任，所有所属后代确认收敛才报告完整实例释放。不杀无关进程，不影响共享会话，无法隔离时明确拒绝单会话释放。

### PI-012 缺环境、故障与取消后的证据及清理

- 用例级别：L5
- 操作步骤：核验路径/固定版本/隔离根缺失时报告状态；在测试资源范围记录合成原生会话、认证配置及外部保护文件摘要，分别令验收中途失败和主动取消。检查所属树最终状态、临时资源清理、报告脱敏及保护文件摘要；不读取用户真实秘密验证脱敏。
- 预期结果：缺环境的真实分支记 not-run 并说明阻断，不借文档、替身、OMP 或旧 Harness 结果填通过。失败和取消保留脱敏证据，清理只涉及本次拥有资源，保护数据不变；清理尚未完成明确保留责任，不将清理请求发送当完成。

### PI-013 固定真实 Pi 组合的 Windows 与 Web 完整闭环

- 用例级别：L6
- 操作步骤：获得后续实施授权并满足 Implementation Gate 后，在独立测试根启动固定真实 Pi 与 ACP 服务端、真实 Windows 节点及 Web。从登记来源/配置、标准协商、创建或恢复隔离原生会话开始，完成文本和实际支持的结构输入、结构工具输出、有效审批（若提供）、页面断开后继续查看、取消、显式释放、重连恢复及历史检查；核对模型/MCP/Client 配置真实传递。按 PI-004–012 分支逐项登记真实观察，并在可安全实施范围重现升级、失效映射、错误入口和完整进程树清理。
- 预期结果：真实链路各操作有实际可观察结果及版本绑定证据，关键完成事实非替身提供；恢复、历史、列表、思考、工具、审批、配置传递和后台范围独立结论。Harness 未提供可选能力时记录实际不支持依据，不能制造该能力成功；未触达分支记未验证，必要清理或安全证据缺失阻断交付。独立 tester/reviewer 对同一最终版本核对结果，用户会话、凭据及原生文件不受改动。

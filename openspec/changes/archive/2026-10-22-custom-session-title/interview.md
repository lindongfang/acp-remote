# 审视决定（已完成）

## 已确认

- Q1：共享标题，不为每设备设置独立名称。
- Q2：不提供恢复 Agent 标题操作。
- Q3：远程导入会话统一支持改名。
- Q4：不增加额外编辑入口。
- Q5：顶部双击进入原地输入框；Enter 保存，Esc 取消，点击输入框外保存；输入法选词 Enter 不触发保存。
- Q6：去除首尾空白，空值拒绝，最多 512 个字符，超长报错不截断；技术计数以设计约定的 Unicode 标量值为准。
- Q7：Owner 后提交成功的值覆盖前值，不打断另一设备编辑中输入。
- Q8：离线禁止提交，不排队离线修改。
- Q9/Q13：两种标题均仅 Owner 保存。
- Q10：旧客户端也显示最终有效标题。
- Q11：保存失败显示错误，在当前编辑器保留输入。
- Q12：点击另一会话先为原会话尝试保存，再正常切换。
- Q16：允许保留连接信息；命令状态和收据最终由 Q20/Q21 确认为不保存。
- Q17：设备到当前节点断线影响应用；单个 Owner 离线只影响对应会话，其他 Owner 和本地会话仍可用。
- Q18：离线页面与存储改造独立立项；原先标题先做的顺序被 Q22 取代，两种标题仅 Owner 保存保持。
- Q19：当前页保存失败保留输入并提示；离页或进入离线页后放弃未保存输入，不保留跨页草稿。结果未知的已提交请求重连后查询，不换新请求自动重发。
- Q20：Access 不持久保存命令状态，当前客户端保留请求编号向 Owner 查询；刷新后重新读取当前标题，不恢复上次修改进度、不自动重发。
- Q21：Access 也不记录事件交付收据或转发进度；否决暂时保留收据的建议。
- Q22：先完成 Access 存储及恢复改造，再实现标题；离线页随后单独交付。用户明确同意并要求本轮把 spec 文档准备齐全。

## 最新原话及影响

Q14：“否，Access 不存储任何owner侧的数据，后面增加离线页面，离线状态直接跳转到离线页面”。不接受以断线后继续显示 Owner 缓存数据作为默认方案。具体边界已由 Q16–Q22 确认，详见各项记录与三个变更。

Q15 的失败离页边界已由 Q19 明确：不保留跨页草稿，不把自动提交视为保存成功。

Q16 的命令记录边界由 Q20 确认，收据边界由 Q21 确认：Access 仅保留连接资料，不持久保存 Owner 资源数据、命令状态或事件转发进度。Owner 仍负责命令防重复执行。在线接收、转发与页面渲染所必需的临时处理不是离线缓存能力。

最终实施顺序：access-owner-data-stateless → custom-session-title → scoped-offline-page。标题功能不得临时依赖已否决的持久化收据机制。

## 事实

会话摘要是标题、状态等概况记录，并非正文总结。现行 Access 存储合同允许部分 Owner 资源元数据和无正文交付记录；Q14 是对其进一步收紧，不能只按标题字段修改。真实 Agent 自动生成标题尚无仓库证据，ACP Remote 仅消费标题通知。

审视已完成，规划已按最终答案统一修订。架构取舍记录为 proposed ADR-0013，说明产品决定已确认、实现及合同迁移尚待执行。本轮只准备文档，不将计划描述为现有能力。

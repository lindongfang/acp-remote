# Proposal

## Why

当前 Web 新会话仍走临时的“准备式新建”：首条消息前不落库，而且这套准备机制引入了独立的会话身份、附件、凭据、存储和跨重启逻辑，与实际产品方向冲突。现在 Web 创建会直接取得一个已持久化的本机会话；没有产生任何会话内容的空会话在完整保留期结束后还应被静默清理，避免目录和数据库长期堆积无用记录。

## What Changes

- 用户原始要求：
  - 新建会话落库。
  - 新建后进入会话页面并激活该会话。
  - 切换会话时激活目标会话。
  - 到期回收时，空会话被清理，非空会话只回收运行资源并保留身份和历史。
- Web 新建入口直接调用 `session.create`，旧准备路径直接替换，不考虑兼容；创建成功后进入 `/session/<id>`，立即显示 `localActivity: active` 并建立查看租约。
- 创建仍遵守现有原子边界：受理阶段只写幂等记录；Agent 建立成功后才把正式会话行、ACP 会话标识、目录归属和命令终态在同一事务写入；失败不留下空会话。
- 为 owned 会话定义“空会话”：没有任何正式保存的消息、轮次、工具调用、终端记录、结构化历史或有效待处理交互。标题、模式、配置、正式会话行、浏览器草稿和未提交附件都不算内容。
- 收回“显式关闭会话”的产品入口。最后查看者离开且所有任务、排队输入和有效交互都解除后，开始完整保留期；默认 30 分钟，配置沿用 `sessions.idle_timeout_ms`。
- 保留期到期先向 Agent 发起真实 `session/close`，且只有 Agent 明确确认关闭或进程已退出后才继续清理。无法确认释放时保留会话记录与容量占位，并允许后续重试。
- 成功释放后的空会话 SHALL 被静默删除：删除正式会话记录、目录归属和 ACP Remote 历史，不通知用户；非空会话只释放资源，不删除身份或历史。
- 删除与激活在 Owner 上线性化：删除先提交时，迟到激活返回 `session.not_found`；激活先提交时，删除必须重新等待保护条件解除。
- 新增可持久化的会话删除结果和 `session.deleted` 事实事件。所有在线已认证客户端据此从目录、摘要缓存和当前页面投影中移除会话；宽限期内会话仍出现在目录和列表中，可进入、激活并发送第一条消息。
- 删除空会话时不删除 Agent 自身内部数据，也不删除已创建的宿主工作目录；只删除 ACP Remote 权威记录并释放受管运行资源。
- 移除整个 `core.session-preparation.v1`：包括 `session.preparation`、`session.start`、准备凭据、准备附件目标、浏览器准备草稿及相关 schema、fixture 和实现。正式会话数据保留；旧准备数据由存储迁移删除。
- 适用范围是所有本机 owned 会话，不限 Web 新建。Node Link imported 会话和 Access 节点不新增本地持久正文；它们只消费 Owner 的删除结果。
- **BREAKING** Sync/Node Link 不再提供准备式新建协议资产；Web 客户端也不再接受旧准备能力。创建命令本身继续保持 Sync 与 Node Link 的既有传输语义。

## Capabilities

### New Capabilities

无。本次变更扩展现有会话生命周期、创建、命令、事件、客户端和存储能力。

### Modified Capabilities

- `sync-session-create`: 创建完成的会话摘要直接投影为活跃；Web 直接采用 `session.create`，并保证宽限期内新建的合法空会话可正常进入、查看、激活和提交首条内容。
- `local-session-lifecycle`: 增加空会话判定、到期后先回收后删除、删除与激活的线性化、重启后的完整保留期、删除失败重试以及静默删除行为。
- `sync-command-handling`: 登记会话删除这一可重试 mutation 的接受、幂等、终态和 `session.not_found` 竞态分类，并移除准备式新建命令的处理面。
- `sync-event-delivery`: 下发持久化的 `session.deleted` 事实，使在线客户端移除目录与会话投影；快照与后续读取不得再返回已删除会话。
- `sync-event-projection`: 定义 `session.deleted` 的类型化最低视图，并要求删除事件可安全、重复地应用。
- `pwa-web-client`: 新建入口改为直接创建并导航，创建后立即激活；切换时激活目标；消费删除事件并清理列表、缓存和当前页；移除全部准备页和老准备草案逻辑。
- `web-session-preparation`: 整体移除该能力的全部要求，准备式新建不再是受支持的 Web 行为。
- `conversation-attachments`: 移除准备目标、准备附件上传、准备草稿恢复和准备转正规则，保留正式会话中的附件行为。
- `storage-schema-v2-migration`: 文件格式与 owned schema 推进到 v19，删除准备凭据、准备进度、浏览器准备草稿服务端映射及相关表；升级保留正式会话、历史、幂等和审计数据。

## Impact

- Core：新增空会话判定、删除候选、删除/激活互斥以及删除结果；移除准备模型、use case 和端口。
- Storage：新增会话删除事务和历史级联清理；移除 preparation DDL 与写入路径；增加 v19 migration 和升级测试。
- Sync 与协议合同：新增删除命令与 `session.deleted` 事件，移除 preparation 帧、`session.start`、相关 feature、错误码、schema 和 fixture；同步更新 Rust/TypeScript 镜像与兼容性矩阵。
- Daemon：资源回收成功后提交删除；删除结果持久化后广播。Agent 未确认释放时不得删除或释放容量占位。
- Web/PWA：创建、路由、激活、查看租约、删除投影和缓存失效接线；删除准备 UI、附件暂存分支和协议依赖。
- 文档与 ADR：以新 ADR 取代 ADR-0014 的 Web 默认准备式新建决定，保留其历史；同步产品、Sync、前端、核心端口与存储、配置和兼容性文档。
- 验证：需要真实 Daemon、真实构建后 PWA 与可控 Agent 的端到端覆盖；测试宽限期边界时可注入时钟，但不得以单元测试代替真实浏览器的目录、导航、激活和删除观察。

## Non-Goals

- 不新增用户可见的“关闭会话”按钮、菜单或确认弹窗。
- 不删除宿主工作目录、附件文件或 Agent 自身内部数据。
- 不向用户发送空会话即将删除或已经删除的通知。
- 不为 Node Link imported 会话新增 Access 本地持久化、删除索引或正文缓存。
- 不改变 Agent 真实能力门控、认证边界、单会话单 active turn 或命令不可自动重派的不变量。

## Success Criteria

- 点击 Web 新建后一次真实 `session.create` 成功即产生正式会话；目录、列表和服务端读取立即可见，页面直接进入该会话且无需经历 `idle → active` 闪现。
- 切换、刷新、重新可见和重连后都对目标会话执行 `session.view` 与 `session.resume`，复用可用资源或恢复原身份。
- 新建空会话在宽限期内可激活并提交第一条消息；满 30 分钟且 Agent 确认释放后才静默删除，目录和所有在线客户端同步移除。
- 非空会话经过同一保留期只回收资源，身份与历史仍可重新激活；删除失败不会丢失记录或容量计数。
- 删除先于激活提交时，迟到激活稳定得到 `session.not_found`；激活先于删除提交时，删除不会越过保护条件。
- 代码库、合同资产、权威文档和 migration 中不再存在准备式新建入口；升级后的正式会话和历史保持可用。

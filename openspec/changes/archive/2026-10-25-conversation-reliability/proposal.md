# Proposal

## Why

对话是产品核心。普通后续输入目前依赖 Agent 回显留下正文，本地即时显示又按正文匹配去重，不能保证刷新后完整可见；恢复与等待首个输出也可能出现没有过程反馈的空档。用户已确认前三项整改，并明确第 4 项按当前设计只存在一个临时会话。

## What Changes

- 每条已受理用户输入由 Owner 保存，首条及后续输入一视同仁；无 Agent 回显、刷新、重连和多端读取都不丢失。输入校验失败明确报错，执行失败不删除已保存输入。
- 本地即时显示与正式消息按稳定身份关联，不按文字相同推断；连续发送相同内容仍展示两次，重投同一请求只展示一次。
- 在对话中展示等待、恢复、实际思考、工具调用、回复及失败，收到事件持续更新，不等任务结束再整批显示。没有思考正文时不得伪造。
- 消息、思考折叠、工具卡片、输入区与桌面/移动原型核对，保留结构化交互和阅读位置。
- 当前标签页在当前已配对节点/设备下最多一个未转正临时会话；切换已有会话、刷新及再次新建保留并复用其 ID，只有切换 Agent 才替换 ID；更换目录必须先显式放弃再新建，不做原位替换。不同节点、身份和标签页不共享准备凭据。

## Capabilities

### New Capabilities

- `owned-input-history`: Owner 保存每条受理输入、稳定关联与回显保真、故障恢复后的可读性。

### Modified Capabilities

- `pwa-web-client`: 输入即时可见、过程连续反馈、原型核对及单一临时会话行为。

## Impact

预计涉及 core 的受理事务/消息值对象与端口、storage-sqlite 的 owned 消息写入/版本迁移、server 的 Sync 查询与投影、agent-host 的回显关联，以及客户端 feature/平台草稿/组件和 E2E。业务规则不放入 app；不改用户现有未提交的 `crates/app/src/compose.rs`。

实施时同步 INITIAL_DESIGN、CORE_PORTS_AND_STORAGE、MODULE_ARCHITECTURE、SYNC_PROTOCOL、FRONTEND_DESIGN、SECURITY_DESIGN 与 ACP 兼容矩阵；若稳定关联需要新增 wire 字段，必须先冻结 feature/schema/共享 fixture，旧端按未协商降级，不能继续按同文猜测。Access 不新增任何远程正文或命令落盘。

非目标：不构造 Agent 未公开的思考、不重发结果不确定的副作用、不扩展云服务、不支持多个临时会话、不改变配对和授权模型。目录属于准备证明绑定；换目录必须先显式放弃当前临时会话再新建，不将旧证明带到新路径。首条转正后允许下一次显式新建产生新临时会话。

成功判据：无回显的首条/第二条均可刷新读回；重复文字不误吞；工具/思考/恢复及时可见；切换和刷新不改变临时 ID；真实浏览器逐项断言及原型差异清单完成。现有 4 文件/89 项单元测试已通过，仅作为基线，不能作为上述缺口已解决的证据。

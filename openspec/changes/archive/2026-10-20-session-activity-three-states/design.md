# Design

## Context

动机与确认范围见 proposal.md。本文件描述待实现方案，不表示三态已落地。

已核实：`core/src/model/session.rs` 有 SessionState、TurnState、CommandStatus 三套枚举；前两套都使用 waiting_*，但它们不应同时被压缩。`broker.rs` 的交互请求落盘路径只追加交互，尚未完整推进等待状态；终态、派发失败和重启恢复路径仍会写会话 Failed。`resolve_locked` 先持久仲裁应答再派发，不能把“已抢到应答权”等同于“Agent 已确认解除”。`app` 的调度枚举依赖旧 queued/running/waiting_*，只改状态会导致排队任务饿死。`storage-sqlite/src/migrate.rs` 当前版本为 owned 11 / imported 4；后续变更落地后必须取实际最新版本加一，不能硬编码本文观察值为实施基线。

并行在途 `conversation-area-complete` 改动交互可恢复读取、输入和协议合同，且把 PWA 输入 requirement 重命名；本变更以其落地版本为前置基线，不能覆盖附件/表单规则。当前 delta 为主规范的完整块；实施前需对已同步的新 requirement 标题和全文重定基线，只消除会话关闭条件，不回退输入功能。

## Goals / Non-Goals

**Goals:** 一个权威计算规则贯穿 core、存储、同步与 UI；恢复和重放不丢失败/不确定结果；交互状态与摘要原子收敛。

**Non-Goals:** 不改变任务和命令状态词表，不开放忙碌时 PWA 发消息的新交互，不添加主动打断/steering，不实现 Agent 没有提供的撤回通知，不改变现有设备应答资格或远程正文缓存边界。

## Decisions

### D1. 会话主状态为持久化的活跃程度摘要

采用 `idle | running | pending`。在 core 中集中定义归约规则：有效未解决交互优先；其次未结束任务（含等待、排队和尚未确认停止的执行）；否则 idle。状态持久化是加速查询的权威摘要，由同一业务提交计算，不允许 UI、适配器或任意 SessionUpdate 写入者各自维护转换表。状态变化复用既有 `session.updated` 事件携带提交后的完整摘要，与任务/交互变化同事务落盘；状态不变不额外重复生成。端口保持 runtime-free，普通依赖不变。

TurnState 和 CommandStatus 保持语义，不能因 SessionState 只剩三态而把任务 failed/command uncertain 删除。等待原因从有归属的有效交互取得，单一会话可同时有授权与表单请求，不增加互斥的单值原因字段。目录只统计待处理会话数；交互细节仍按需读取，摘要不泄漏 options、表单正文或其他敏感内容。

替代方案“保留七态只改 UI”仍会保留失败会话的不可恢复限制，不满足确认范围。方案“每次 UI 统计任务”需要未交付明细、破坏离线元数据呈现，因此不采用。

### D2. 交互有轮次归属，仲裁不冒充完成

沿用 interactionId 与 turnId 建立所属轮次关系，OwnedCommit 支持成批结束该轮有效交互并更新摘要。请求创建、正式处理、失效与三态更新在同一 SessionStore 事务提交；提交后才广播可重放的状态变化。多请求剩余计数基于提交后的集合，不依赖单个事件覆盖布尔值。

应答的 first-writer-wins 仲裁沿用，但区分“应答已保留/正在派发”和“已确认处理”。前者阻止其他设备重复应答，但在后端确认前仍计入有效待处理；收到明确处理结果后才解除。派发失败、超时或崩溃不自动变成允许/拒绝，也不自动重发副作用；进入既有失败/uncertain 路径，并在任务确定结束时统一失效。若既有可恢复交互合同已提供相同阶段，复用其模型，不另造第二套。

明确撤回仅接收 adapter 确实可识别、带稳定请求关联的信号；当前 ACP 接入没有单个撤回处理，不宣告支持。Agent 普通输出、工具继续运行或新 prompt 都不是撤回证据。任务完成/失败/取消均清理本轮请求；待处理卡片保留失效原因，不伪造 ACP 授权回复。

### D3. 失败和恢复不再终结会话

统一修改 broker 终态、派发失败、放弃、超时及启动恢复的写入点。当前轮确定停止并完成落账后继续 FIFO 队列；队列策略与上限不变。app 调度以未结束任务/持久队列为依据，不再只筛选旧主状态；调度不可被 pending 主状态阻塞（交互应答仍需执行）。同会话最多一个 active turn 的不变量保持，排队 turn 不意味着第二个已派发执行。

崩溃结果无法确认的命令保留 uncertain；确认旧执行停止后终结旧 turn 并失效其交互，不重放它。无法证明停止的执行保留占位与运行阻塞，不升后续任务、不提前 idle。对后端不可用的已排队任务沿用明确失败/未派发结果，不默默删除或无限自动重试。

### D4. 三态合同必须协商，禁用双模型写入

拟在 feature 机器登记中给 Sync 与 Node Link 同时登记必需 `core.session-activity.v1`（required=true），新客户端也将它列入 requiredFeatures。缺失按现有 `protocol.feature_required` / `nodelink.protocol.feature_required` 拒绝；已选中前不得发送快照、事件或命令业务载荷。接入时两端都检查，覆盖新客户端/旧服务端与旧客户端/新服务端。PWA 静态资源与 Daemon 同批更新，旧页面提示更新后重连；不静默双写七态。

当前会话 DTO 严格只有三态。旧七态枚举仅允许在明确标识的历史读取边界出现，不能作为实时摘要解码的兼容后门。schemas/fixtures/Rust/TS 共享新合同；所有 sessionSummary 出现点（create/read/list/snapshot、事件视图、Node Link 目录与资源引用）逐一更新。迁移后的原始历史事件不改字节、不改 payloadDigest；历史旧状态视为带版本的过去事实，实时主状态从最新权威摘要获取，不能由旧标签覆盖。未知 ACP 扩展保真与既有至少一次投递不变。

替代方案直接向旧 peer 发送 pending 会突破封闭 enum；把 pending 映射回某个 waiting_* 会丢失多种交互原因并保留双模型，均不采用。

### D5. 新建、导航和连接不参与权威归约

创建成功为 idle；创建中/读取中是页面加载情况，不是第四个会话状态。导航无业务状态写入。离线沿用最后确认摘要并呈现既有过期来源提示；尚未加载不默认 idle。PWA 的可编辑/可发送状态独立按实际连接、提交中与既定忙碌策略判定；删除“会话 closed 所以只读”的分支，但不承诺 idle 一定可发送。Access 只消费 Owner 摘要，不持久化远程交互正文用于归约。

## Risks / Trade-offs

- 必需 feature 会拒绝旧版本连接 → 两端协调升级，明确错误与更新提示，不伪装兼容。
- 单一失败可能仍有外部执行 → 先确认停止再提升队列；uncertain 结果不自动重试。
- 应答仲裁与确认混用会让状态提前 running → 持久区分阶段，并覆盖崩溃窗口和重复应答测试。
- 历史旧状态覆盖新摘要 → 新实时 DTO 与历史版本读取分离，fixture 验证旧事件仍可读取但不改当前状态。
- 与在途对话改造冲突 → 前置串行合入；重定 delta 和版本基线，保留已有附件及可恢复应答行为。

## Migration Plan

1. 前置变更落地后，重新核对 schema 版本、PWA 被重命名 requirement 与交互持久阶段；更新本变更对应 delta，不重写其他在途文件。停止旧 Daemon 并按现有备份方式保存数据库及关联文件，禁止两个版本同时写同库。
2. owned/imported 各在其当前版本上按实际形状变化递增版本。重建会话状态 CHECK 并删除关闭时间语义；关闭时间属于已废弃摘要元数据，不转换成删除/归档，不改原始事件。涉及外键的表按现有迁移模式处理，保留索引、引用、序号及 sqlite_sequence。
3. 初始转换：idle→idle，queued/running→running，waiting_input/waiting_permission→pending，failed/closed→idle。此映射只是迁移暂存值，不能提前向客户端发布。随后在开放业务接入前执行恢复：校验本轮交互归属，失效已结束轮次的请求，按未结束任务和有效交互重算。对无法恢复归属的旧请求不猜测授权，按旧执行恢复确定失效并保留历史；不能确定时保留待确认及阻塞，不能假装恢复成功。
4. 新增交互 turn 归属需要版本化回填；优先用现有请求事件的可靠 turn 关联。不能仅按时间相邻推测。迁移结构变化、必要回填和版本写入在同事务；执行停止确认属于启动恢复，在恢复完成前不接受该会话新派发。恢复过程需可重复，不能重复生成终态或二次派发。
5. imported 摘要的旧值只作过期显示映射，不追加远程正文或在 Access 上终结 Owner 任务；联机后以 Owner 三态覆盖。旧交付索引与 cursor 保留。
6. 新快照建立后允许业务流，恢复的摘要与状态事件持久化顺序保持一致。保留全部事件原文、命令结果和幂等记录，旧历史标签的解释留在显式历史版本层。
7. 回滚使用升级前的完整备份及匹配旧二进制/PWA；不做有损反向 SQL。升级后新增历史不能靠恢复旧备份保留，因此回滚前先停止写入并保存升级后备份，明确备份时点之后的数据差异。

## Open Questions

无待确认产品决策。实际递增版本号与前置变更最终 requirement 标题由已确定的串行合入规则决定，不改变本变更行为与工作包边界。

# Spec Delta

## Purpose

定义由 ACP Agent 请求驱动的真实终端服务，包括任务启动、输出读取、等待退出、停止和释放，使对话区域能够呈现真实命令执行过程，并在断线、取消及进程退出时保持明确状态和可验证的资源清理。

## ADDED Requirements

### Requirement: 终端能力按真实服务宣告

系统 SHALL 仅在真实终端服务已接线时向 Agent 宣告终端能力，并支持已宣告的启动、输出、等待退出、停止与释放操作。终端服务 SHALL 绑定所属会话，工作目录与环境遵守现有 Agent profile 边界，MUST NOT 提供用户手动输入终端或借此绕过审批。

#### Scenario: Agent 请求终端任务
- **WHEN** Agent 在已宣告能力的会话中请求执行任务
- **THEN** 真实启动任务并返回对应终端标识，输出、退出状态与后续操作均属于该任务

#### Scenario: 跨会话访问终端
- **WHEN** Agent 请求操作其他会话的终端标识
- **THEN** 请求被拒绝且其他任务不受影响

### Requirement: 真实输出与退出结果

终端输出 SHALL 按实际接收次序交付并保留终端标识与分块次序；可区分来源时 SHALL 保留标准输出和错误输出来源。页面 SHALL 展示命令、持续输出、退出结果与截断说明；MUST NOT 将尚在运行误判为成功或模拟增量。超过输出保留预算时 MUST 明确标记缺失范围。

#### Scenario: 输出后非零退出
- **WHEN** 任务先输出内容再以非零状态退出
- **THEN** 页面保留已收到的输出并显示失败退出，重新进入后结果一致

### Requirement: 终端任务具有关闭与清理路径

终端任务 SHALL 有明确所有者、停止与释放路径；会话关闭、Agent 崩溃和 Daemon 关闭时 SHALL 按顺序回收关联进程树。停止请求未确认时 MUST NOT 显示任务已退出；停止与自然退出竞争 MUST 收敛为单一退出事实。

#### Scenario: Agent 崩溃留下子进程
- **WHEN** Agent 异常退出而终端任务仍在执行
- **THEN** 对应进程树被清理，状态明确记录，其他会话任务不受影响

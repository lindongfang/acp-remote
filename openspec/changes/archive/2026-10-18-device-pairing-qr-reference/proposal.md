# Proposal

## Why

设备配对二维码把完整 JSON 与公钥、秘密、来源重复编码为约 600 字符，可靠的实心终端绘制占据过大空间。用户要求完全替换为方案 C：二维码仅携带高强度取回凭据与公钥指纹；桌面和手机 PWA 都输入配对码，后续原生 App 才使用二维码。

## What Changes

- **BREAKING**：设备二维码改为明确版本的紧凑引用格式，不再生成或受理旧设备 `#data=` 完整载荷；节点配对协议与 `/node-link/pair` 不变。
- 新增同源 HTTPS 扫码资料取回端点：独立随机 32 字节凭据只在有效且尚未认领时可重复取回同一份完整资料；不创建设备信任，不延长有效期，不消耗网页配对码。
- 二维码另带完整 32 字节主机公钥指纹；原生消费方必须先匹配指纹，再沿用现有 claim/status、主机签名、本机确认和 WSS 身份认证。
- **BREAKING**：PWA 删除设备扫码认领入口；浏览器打开新短二维码立即清除片段并提示使用 App 或网页配对码，不兑换、不自动跳转、不自动认领。
- 网页 8 位配对码仍成功即消耗；扫码凭据与配对秘密独立生成、只存内存，认领后禁止取回，拒绝、失效、过期或重启后同样不可取回。
- 有效期默认且最多 5 分钟，允许缩短，任何读取与重试不续期。原生请求显式携带目标 canonical origin 对应的 Origin，不跨来源跳转，不新增无 Origin 模式。
- 定义暂时网络故障的有限重试、429 等待与不可重试的安全失败；原生 App 本体仍后续交付，本次以共享合同和模拟消费方验证，不声称已有原生扫码产品。

## Capabilities

### New Capabilities

无；扩展现有配对能力。

### Modified Capabilities

- `identity-pairing`：扫码取回凭据与配对生命周期、双入口争用和失效边界。
- `sync-pairing-http`：短二维码格式、取回接口、指纹固定、Origin、重试及错误边界。
- `local-admin-methods`：`device.pair.begin.pairingUrl` 改为新格式，返回键不变。
- `cli-commands`：设备终端输出面向 PWA 配对码与原生 App 短二维码，禁止完整秘密文本输出。
- `pwa-web-client`：设备配对仅使用配对码，短二维码浏览器指引与旧格式拒绝；保留节点展示入口。

## Impact

- Rust：`sync-protocol`、`identity-auth`、`server::sync`、`server::local_admin`、网络路由、`app` CLI 与组合根；TypeScript：协议解码、配对状态、路由、页面及测试。
- 同步维护 Sync/local-admin 的 schema、共享 fixture/manifest、错误词表与合同门禁；不改变 ACP 能力、业务命令、Node Link、SQLite schema 或 crate 依赖方向，不引入云服务。
- 实施时新增 ADR（预计 0012，落地前核对编号），修订 ADR-0010 的设备入口结论，以及产品、安全、Sync、本地管理、身份、前端权威文档和术语表；本提案阶段不改主规范或历史 ADR。
- 成功判据：测试地址的新 URL 不超过 150 ASCII 字节（含 43 字节地址前缀），相同纠错等级下矩阵明显小于旧格式；同一配对两入口至多一次认领；失效与重试不泄露材料；PWA 桌面/手机码配对正常且误扫不发请求；节点回归不变。
- 非目标：原生 App 相机、安装/深链、无 Origin 认证、旧设备 QR 双栈兼容、缩短公钥指纹、数据库迁移、PNG/HTML 敏感文件导出。
- 当前工作区存在前端主题与 CLI 二维码未提交修改；必须作为明确基线保留并在实施前复核，不能覆盖或替用户提交。

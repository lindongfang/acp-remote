# Design

## Context

动机和范围见 proposal.md。当前 schema 为 proposal/specs/design/plan/tasks；低风险允许自检且默认串行，缺少独立测试产物。现有 check:openspec 校验结构，不验证执行证据真假。

## Goals / Non-Goals

只修改开发工具链和文档，不影响 ACP Remote 运行时。使用当前工具可提供的独立会话和隔离 worktree；不绑定模型，不增设常驻角色，不引入浏览器框架或新的定时 CI。

## Decisions

1. 规则权威仍为 config.yaml 的 context/rules/operations；角色文件拥有各自职责，schema 拥有产物依赖，模板拥有结构。直接读取这些仓库文件即可执行，无需用户级技能安装。
2. 新增 tests artifact，依赖 specs/design；plan 依赖 tests，tasks 依赖 plan/tests，apply 必须具备 tests/plan/tasks。独立 tester 编写验收依据，coder 维护开发单元测试并可运行各级自测，但不得擅改验收预期。验收变化交 tester 判断、记录理由并由 reviewer 复核；需求变化先修正 specs。项目 design 指令与必产规则统一。
3. tests.md 使用固定 Markdown 字段；L1–LX 每级声明 required/not-applicable 和原因，用例采用稳定 ID。自动化入口、Agent 或人工步骤都明确；仅校验结构，不能以脚本通过冒充独立签字。
4. 长期用例按能力合并到 openspec/testing/suites，执行报告输出到被忽略的 openspec/testing/runs，plan 保留版本与结果摘要及问题ID。历史归档不追溯补齐新格式。
5. tester/reviewer 不继承开发对话，主执行者交接用户确认要求、仓库规则、基线、范围与验收判据。正式验收使用文件清单与 SHA-256 定义的快照或提交；仅有 HEAD 不能标识未提交改动。快照包括配置、脚本、角色、模板、用例及现行文档；plan中的执行结果/问题状态、tasks勾选和执行报告作为证据记录单列，不冒充受测内容；归档后的路径映射及新增记录独立复核。
6. 本次文档迁移与主配置修改写范围独立，方案检视通过后并行；独立 tester/reviewer 验收同一快照。只在本工作区集成，避免多执行者同时写文件。

## Risks / Trade-offs

- 自然语言无法自动可靠执行 → 命令或明确步骤与判据并存，不自动执行 Markdown 中任意命令。
- 规则存在但证据不足 → 独立角色实测和检视，不将结构门禁等同交付门禁。
- 路径迁移影响大量引用 → 只改现行链接，历史原样保留；检查迁移文件相对链接和合同漂移门禁。
- 文档变化会改变快照 → 明确受验收内容范围，报告文件不纳入内容摘要；归档移动后核对映射与差异。

## Migration Plan

迁移 ADR 时保持编号和决策内容，仅调整链接。新 tests 要求适用于活动变更，已归档变更不补写；本变更采用新格式。先独立验收与检视，再同步长期用例，归档前检查；归档本身的路径变化需复核。回滚通过撤销此变更及恢复原 ADR 路径完成，不涉及数据迁移。定时自动回归为第二阶段，本次提供可重跑入口及周期声明，不声称已接入调度。

## Decision Coverage

用户已逐项确认探索全覆盖、术语必维护/ADR按需、角色、并行、分级测试/独立验收、上下文隔离、工具选择、归档与两阶段实施。无阻断决策；周期自动调度明确延后。术语在共享 GLOSSARY.md 落实；本次无产品架构选择，不新增 ADR。

未来探索每轮列出问题及建议，等待用户回答后再推进依赖这些答案的分支；明确区分确认决定、建议与待确认项，沉默不是接受。结束时核对全部分支并由用户确认共同理解；文档/代码能够查证的事实不转嫁给用户。

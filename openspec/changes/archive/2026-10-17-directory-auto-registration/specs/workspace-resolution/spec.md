# Workspace Resolution 增量

## MODIFIED Requirements

### Requirement: 路径校验与规范化

系统 SHALL 要求路径为绝对路径、存在且为目录，并以 `canonicalize` 的结果作为权威值；相对路径与含 `..` 的输入 MUST 被拒绝。符号链接、junction、大小写与 `.` 差异 SHALL 被解析为同一权威值；UNC 或网络路径允许使用，但 SHALL 在解析时记录一次结构化警告而不改变授权模型。由规范化路径派生的目录标识 MUST 基于这一权威值计算，MUST NOT 基于客户端提交的原文。

#### Scenario: 规范化结果作为权威值

- **WHEN** 同一目录以符号链接路径与真实路径两种写法被使用
- **THEN** 解析得到的权威路径相同，会话创建使用该权威值，且两次得到同一个 `directoryId`

#### Scenario: 拒绝非绝对路径与父目录引用

- **WHEN** 客户端提供的目录是相对路径、不存在路径、非目录路径或含 `..` 的输入
- **THEN** 解析失败并返回具名错误，不产生会话行，也不把该路径写入任何持久化字段

### Requirement: 恢复时的目录复校验

恢复用例 SHALL 在调用会话后端之前，对持久化的创建时工作目录执行与创建时同口径的校验：必须是绝对路径、必须存在且为目录，且 `canonicalize` 的结果 MUST 与持久化取值相同。持久化取值为 `NULL`（该会话本就没有可恢复数据）时 MUST 与「能力不支持」走**同一条路径**（`nodelink.command.unsupported`）返回；其余校验失败（目录被删除、被替换为文件、规范化结果不同、无权限读取）时 MUST 返回服务端不可用类错误。两类失败都 MUST NOT 回退到按目录标识重新解析，也 MUST NOT 改用一个「最接近」的目录。

「它曾经合法」MUST NOT 被当作跳过校验的理由；每次恢复都重新校验一次。

本要求的校验对象与比较基准 MUST 始终是持久化取值与其 `canonicalize` 结果**本身**；发给 Agent 的工作目录参数是否经过形式转换（例如剥掉 Windows verbatim 前缀）MUST NOT 参与该校验，也 MUST NOT 因此改写持久化取值。

#### Scenario: 目录已被删除时返回不可用且不启动 Agent

- **WHEN** 一条会话的持久化创建时目录在恢复前被删除（或不可访问）
- **THEN** 恢复在调用后端之前失败并返回服务端不可用类错误，不启动 Agent 进程、不产生新会话，也不写入任何目录取值

#### Scenario: 规范化结果变化时拒绝恢复

- **WHEN** 持久化路径仍然存在，但 `canonicalize` 的结果与持久化取值不同（例如被换成指向别处的符号链接）
- **THEN** 恢复返回服务端不可用类错误，不使用新解析出的路径发送 `session/resume`

#### Scenario: 目录仍然有效时使用持久化取值

- **WHEN** 持久化目录仍然存在、是目录，且规范化结果与持久化取值一致
- **THEN** 恢复使用该持久化取值作为工作目录的来源，不按目录标识重新解析；出站参数的形式转换只影响发给 Agent 的字节，不影响本要求的校验与比较，也不改写持久化取值

## REMOVED Requirements

### Requirement: 解析归属与后端输入

**Reason**: 解析输入由「别名」改为「目录标识（`directoryId`）」或客户端提供的绝对路径；原要求的场景（未登记别名、后端只收到已解析路径）按新输入面重写。

**Migration**: 由新要求「解析归属与后端输入（目录标识）」承接；「解析发生在调用后端之前」「失败时不产生会话行」两条不变量不变。

### Requirement: 解析失败的分类

**Reason**: 失败分类的输入面从「别名是否在该 Export 的别名集合内」变为「标识是否在本节点目录表内」，原两条场景不再成立。

**Migration**: 由新要求「目录来源失败的分类」承接，保留「参数类 / 服务端不可用类」的区分与「参数类不触碰文件系统」。

### Requirement: 路径不泄漏

**Reason**: 该要求以「路径只在协商 `core.workspace-path.v1` 时下发」为前提；feature 撤销后路径随目录条目始终下发，且场景集合（未协商时任何输出都不含路径）不再成立。

**Migration**: 由新要求「路径可见面与派生展示路径」承接；工作区内相对化、工作区外标记、同名前缀判定三条场景原样保留。

### Requirement: 创建时别名的持久化与投影来源

**Reason**: 目录别名体系随人工登记一并删除；会话行改为持久化目录标识而不是别名原文。

**Migration**: 由新要求「创建时目录归属的持久化与投影来源」承接；窄写、三列同门、不反查、不推导四条不变量不变；存储迁移负责把既有别名回填为标识。

## ADDED Requirements

### Requirement: 解析归属与后端输入（目录标识）

系统 SHALL 在处理会话创建用例、调用会话后端之前完成「目录来源 → 本机规范化路径」的解析与校验；目录来源可以是本机目录表中的 `directoryId`，也可以是客户端提供的绝对目录（后者仅 Sync 面支持，Node Link 面 MUST NOT 接受）。会话后端 MUST 只接收已解析的规范化路径（使用 `directoryId` 时连同该标识），MUST NOT 自行查询存储或按约定拼接路径。

#### Scenario: 后端只收到已解析路径

- **WHEN** 一个会话创建命令携带本节点已记录的 `directoryId`，或携带一个客户端提供的合法目录
- **THEN** 会话后端收到已解析的规范化绝对路径，且解析发生在后端被调用之前

#### Scenario: 未记录标识在调用后端前失败

- **WHEN** 一个会话创建命令携带本节点没有记录的 `directoryId`，或携带形状非法的目录
- **THEN** 调用后端前就返回参数类错误，不产生任何会话行或后端进程，也不写入目录记录

#### Scenario: 客户端不能构造标识

- **WHEN** 客户端提交一个自造或从旧快照复用的 `directoryId`
- **THEN** 系统只按本节点目录表判定，不解析该值、不由它推导路径；未命中即参数类错误

### Requirement: 目录来源失败的分类

系统 SHALL 区分「目录标识不在本节点目录表内」与「标识已记录但本机解析失败」：前者 MUST 返回客户端可修正的参数类错误；后者 MUST 返回服务端不可用类错误，MUST 不得降级为参数错误。两类失败都 MUST NOT 创建会话、MUST NOT 启动进程。

#### Scenario: 未记录的标识报参数错误

- **WHEN** 请求携带的 `directoryId` 不在本节点目录表内
- **THEN** 返回参数类错误，且不尝试访问本机文件系统

#### Scenario: 已记录但目录消失报服务端错误

- **WHEN** `directoryId` 已记录，但其目录已被删除、被替换为文件或规范化失败
- **THEN** 返回服务端不可用类错误，错误分类与参数类错误可区分，且不产生会话行

### Requirement: 路径可见面与派生展示路径

解析得到的规范化路径 MUST NOT 出现在任何**客户端尚未知道该路径**的对端可见输出中，包括事件载荷、错误 `details`、`command.result` 与审计摘要的前像；客户端自己提供的目录不因此构成泄漏，但它 MUST NOT 被回显为对端可见的字段。本条的唯一例外是目录资源：快照的 `workspaces` 条目 SHALL 含已记录目录的规范化路径（口径见 `sync-workspace-catalog`）。日志、审计记录与错误 `details` MUST NOT 因此含任何路径。

由本机路径派生出的展示路径同样受该约束：系统 SHALL 只下发相对该会话工作目录根的展示路径，MUST NOT 下发工具或 Agent 报告的绝对路径。当被派生的路径经规范化后不位于该会话工作目录根之下时，系统 MUST 把该次派生标记为位于工作区之外，且其展示值 MUST NOT 包含回退层级或工作目录根的任何片段。位于工作区之外的判定 MUST 基于规范化后的前缀关系，MUST NOT 仅按字符串前缀判断。

#### Scenario: 事件与错误都不含路径

- **WHEN** 一次会话创建成功或失败后检查广播事件、错误载荷与审计记录
- **THEN** 其中只出现 `directoryId`（存在时），任何字段（含摘要计算的输入）都不包含本机规范化路径明文，客户端自己提供的目录也不被回显

#### Scenario: 已记录的目录路径随目录资源下发

- **WHEN** 一台设备接收快照
- **THEN** 快照的 `workspaces` 条目含已记录目录的规范化路径，而事件、命令结果与错误载荷中仍不出现路径

#### Scenario: 工作区内的派生路径只下发相对形式

- **WHEN** 某次由本机路径派生的展示路径经规范化后位于该会话工作目录根之下
- **THEN** 下发的展示值是该路径相对工作目录根的形式，不含工作目录根的任何片段，也不含回退层级

#### Scenario: 工作区之外的派生路径被标记且不回退

- **WHEN** 某次由本机路径派生的展示路径经规范化后不在该会话工作目录根之下
- **THEN** 该次派生被标记为位于工作区之外，下发的展示值只含该文件名称，不含回退层级或工作目录根的片段

#### Scenario: 同名前缀不构成工作区内

- **WHEN** 该会话工作目录根为某路径，而被派生的路径以该路径的字符串作为前缀但经规范化后并不位于其之下
- **THEN** 该次派生被判定为位于工作区之外，MUST NOT 因字符串前缀相同而被当作工作区内

### Requirement: 创建时目录归属的持久化与投影来源

系统 SHALL 在会话创建流程中把本次解析得到的目录标识与该次解析得到的规范化路径一起写入该会话行；客户端直接提供目录时，系统先按创建时口径记录该目录，再把其标识写入会话行。**目录标识与恢复所需的两列同门写入**：它们同属会话创建的那一次窄写提交，只有本次创建取得 Agent（ACP）侧会话标识时才一并落盘；未取得标识时三列同为 `NULL`，该会话按既有口径即「没有可用于恢复的数据」，其目录归属同样不落盘、会话呈现为未分组。恢复流程 MUST NOT 读写该标识。会话的目录归属投影 MUST 取自持久化的标识；读取路径 MUST NOT 按规范化路径反查目录表来补出归属。标识或路径任一为 `NULL` 时 MUST NOT 由另一项推导补齐。

#### Scenario: 创建写入目录标识与路径

- **WHEN** 一个会话创建请求携带已记录的 `directoryId` 且解析成功
- **THEN** 该会话行同时带有该标识与本次解析的规范化路径，二者独立保存

#### Scenario: 客户端提供的目录在成功后才被记录

- **WHEN** 一个会话创建请求携带客户端提供的绝对目录并成功
- **THEN** 该目录与本次会话在同一次提交里被记录，会话行携带由该路径派生的标识

#### Scenario: 未取得 ACP 会话标识时三列同为空

- **WHEN** 一次会话创建解析出了合法目录，但 Agent 侧没有回报 ACP 会话标识
- **THEN** 该会话行的目录标识、规范化路径与 ACP 会话标识三者同为 `NULL`，目录归属呈现为未分组；系统 MUST NOT 只写标识而留下另外两列为空

#### Scenario: 不按路径反查归属

- **WHEN** 一条会话行的持久化目录标识为 `NULL`，但其规范化路径当前能在目录表中匹配到某个目录
- **THEN** 该会话的目录归属仍为「无」（`null`），系统不据路径补出标识

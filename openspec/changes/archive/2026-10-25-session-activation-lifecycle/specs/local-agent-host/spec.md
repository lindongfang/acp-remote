# Spec Delta

## MODIFIED Requirements

### Requirement: 空闲回收与进程关闭顺序

系统 SHALL 按本机会话生命周期的查看、任务、交互保护与容量规则逐会话回收资源，保留原会话恢复身份。只有共享 Agent 下全部会话均可回收时才允许空闲关闭整个进程。超时 `0` SHALL 关闭按时间回收，但不关闭已明确配置的容量保护。进程关闭 MUST 顺序停止写入、结束未完成请求、等待关闭 grace（5 s）后强制终止完整进程树，并确保不遗留无所有者的后台任务。

#### Scenario: 无活动会话且超过空闲超时时关闭
- **WHEN** 会话空闲超时非零、Agent 下全部会话无人查看且无任务或交互，保留期均到期
- **THEN** 其进程树被关闭，旧活动映射不再复用；普通打开旧映射明确不可用，后续激活使用原身份恢复到新进程代；目录可用性仍只由命令和凭据可解析决定

#### Scenario: 零值不因空闲关闭
- **WHEN** 会话空闲超时为 `0`
- **THEN** 进程不因计时到期而关闭；显式关闭、Daemon 关闭、进程退出及满足安全条件的容量回收仍按各自规则执行

#### Scenario: 关闭顺序有界且不留后台任务
- **WHEN** 对一个仍有未完成请求的 Agent 执行关闭
- **THEN** 写入被停止、未完成请求以明确结果结束、超过 5 s grace 后进程树被强制终止，且没有遗留后台任务持有该进程

#### Scenario: 共享进程存在被查看的会话
- **WHEN** A 到期但同一 Agent 的 B 被查看或仍有任务或待处理请求
- **THEN** 不终止共享进程，A 的回收不得破坏 B

## ADDED Requirements

### Requirement: 恢复与卸载必须符合真实能力

系统 SHALL 仅在 Agent 实际宣告并支持时使用原生恢复或卸载能力；上下文恢复 SHALL 使用保存的原会话标识与工作目录。能力缺失或原会话丢失 SHALL 明确失败，不猜测扩展、不虚报能力、不新建替代，不重派历史任务。单会话卸载失败 SHALL 保留真实资源占用，不能以共享进程重启损害其他会话。

#### Scenario: 未宣告恢复能力
- **WHEN** 激活需要恢复，而 Agent 未宣告对应能力
- **THEN** 明确返回不支持，不发未经协商的方法，不创建新会话

#### Scenario: 同一会话同时激活
- **WHEN** 多个设备同时激活同一已回收会话
- **THEN** 至多建立一个可用原会话绑定，其余调用共享真实结果且不重复申请资源

#### Scenario: 卸载不等于本地关闭
- **WHEN** 本地端点关闭而外部 Agent 仍保留该会话资源
- **THEN** 系统不声称资源已释放，容量及活跃事实保持真实，验收明确记录未完成

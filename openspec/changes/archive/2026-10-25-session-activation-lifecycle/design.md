# Design

## Context

动机和用户确认边界见 [proposal.md](proposal.md)，行为以本变更五份增量规范为准。

现状核实：`agent-host::AgentHost` 按 AgentId 共享运行时，`open()` 仅重绑内存映射；找不到时的 `InvalidRequest` 被 Sync 泛化为 schema 错误。`Broker::resume_session` 及 Node Link 已有原身份恢复路径，但该 broker 入口尚不能直接视为并发合并或重复调用安全；Sync 明确不接受此命令。`Endpoint::close()` 只置本地关闭位并清理终端，不调用原生卸载。现有 idle sweep 以 Agent 整体空闲为条件，不能完成逐会话回收。`sessions.idle_timeout_ms` 默认 0。前端已有平台生命周期、命令状态机和历史读取，历史配置读取也已对缺少活动端点做降级，不能把它误列为完全未实现。

ACP 矩阵已登记 `session/resume`、`session/close` 与对应能力，但 close 当前明确不支持；`session/load` 同样尚未落地。本变更不能把 App Server 的其它接口直接当作 ACP 方法。`openspec/config.yaml` 的仓库画像部分滞后，范围以现有代码与权威文档为依据。

工作区已有用户未提交的分页、滚动和文件测试改动；本提案不覆盖它们。实施派发前需冻结基线或显式记录其依赖。

## Goals / Non-Goals

**Goals:** 在现有端口方向内建立 owned 生命周期，恢复与释放必须有外部 Agent 事实支持；多设备/多页并发只产生一个原会话绑定；将任务事实与资源事实分开投影，保证上下文和旧合同语义。

**Non-Goals:** 不扩展 Node Link/Access 远程资源管理；不改为每会话一个进程；不绕过 ACP 调用 Codex 私有接口；不在本变更中引入自动历史注入、内存硬限额或任务并发限制。

## Decisions

### D1. 原生恢复与关闭是实施前置门槛

选择能力门控的 ACP `session/resume` 与 `session/close` 路径，恢复参数只来自 owned 持久记录。首先用真实配置下的 Codex ACP adapter 核实：宣告能力、close 是否保留可恢复身份、resume 后上下文连续性、关闭是否释放 Agent 侧资源，以及同进程另一会话能否继续。协议 DTO 即便已存在也不代表 adapter 支持。

该探针失败则阻断依赖工作包，交付明确证据并修订设计；不能只写本地 closed 标志、伪造资源释放，不能自动切为一会话一进程或新建并回灌历史。停止整个共享进程只允许在所有会话均可回收时执行。单会话卸载不支持时安全保留资源和名额，报告未完成，不能把该降级当作成功验收。

替代方案：直接关闭端点无法证明卸载；每会话进程会改变共享拓扑和成本；重发历史会破坏语义和副作用边界，均不采用。实际能力是可验证前置条件，不列为可延期的 Open Question。

### D2. core 拥有 owned 生命周期决定，适配器只报告事实

在 core 增加纯类型运行期生命周期目录及用例，不引入 Tokio 或 wire DTO。纯状态区分 `inactive / activating / ready / reclaiming`，另附有语义的失败事实；任务与待处理事实仍由 SessionStore/Broker 提供。每个 session 的现有串行门与节点容量准入形成固定锁顺序；全局只短暂预占/确认名额，不能持全局锁等待 Agent I/O。目录记录资源代、查看租约、最后受保护时间及保留起点，时钟由端口注入。

server::sync 的每条连接声明查看者，认证撤销/断开主动通知 core。app 负责扫描调度、任务所有权和关闭顺序，不做回收业务判断。agent-host 新增有语义的单会话释放端口并执行真实 ACP close，停止本地终端、解除映射及 core 缓存端点；只有成功才能确认释放名额。关闭中/结果不确定的资源仍占位，禁止恢复与回收交错产生两个绑定。

同 session 的并发激活加入同一正在进行的操作；不同调用者仍各有合法命令收据和唯一终态。先查稳定请求标识，再判断 ready 复用或启动恢复。旧命令重试返回历史结果不等于当前资源 ready，资源已回收时新一次查看激活使用新请求标识；`uncertain` 的恢复不自动换标识重试，先核实状态，不能借页面激活重复派发未知副作用。

### D3. 任务三态不改义，本机生命周期另作显式投影

保留 `SessionState` / stored `idle|running|pending` 的任务含义与 Node Link 序列化。新增本机生命周期能力 `core.local-session-lifecycle.v1`（拟登记），协商连接的 owned 摘要扩展 `localActivity: idle|active|pending`；UI 将其作为本机会话主标签，“正在执行/排队”等细节仍读取任务事实。未协商连接和 imported 摘要不附字段。不给 Node Link 新增 active 枚举，不通过把任务伪造为 running 达到视觉效果。

归约：有效交互优先 pending；未结束任务、已确认 ready 的资源，以及从 ready 开始回收但尚未确认释放的资源均为 active；其余 idle。reclaiming 保持先前 active，关闭失败或结果不确定同样保留 active、容量占位及明确错误，只有确认资源释放后才转 idle。首次 activating 不因预占名额就提前显示 active；activating/reclaiming 的进度独立显示，不代表此时可发送。失败不覆盖真实任务或交互。发送依据实际 ready、任务/既有排队策略等事实，不依据 active 标签。

生命周期变化写 owned 持久事件 `session.activity.changed`（拟登记）后发布；事件保存当时事实，不作为重启后资源仍存活的凭据。当前活跃目录不持久化查看者/租约，owned 当前查询和快照读取同一代目录及任务事实。启动先执行既有 uncertain/任务恢复、确认旧进程停止并清空所有运行资源与查看租约，再为曾发布活跃且现已失效的 owned 会话提交状态收敛事件，完成后开放入站查询/订阅。重放与快照沿现有屏障和去重规则收敛。旧连接投影视图时剔除新字段，保留 ACP 原文，不能让新事件破坏旧解码器。

替代方案：全局将 running 改名 active 会污染 Node Link 与旧客户端合同；全由 UI 猜测则多设备不一致，均不采用。

### D4. 恢复用业务命令，查看用连接期控制帧

复用唯一命令名 `session.resume`，为 commands manifest 增加协商后的 Sync 传输支持，不另造激活同义命令。Sync owned payload 为 `{}`，会话引用放 envelope；首次受理及 command terminal、稳定 requestId、并发收口、关闭后的观察者取消，复用现有命令机制，结果投影为 Sync 本机摘要，不带 Node Link remoteSessionRef。未协商继续 `command.unsupported`，远程目标明确不支持。ready 复用同样记录合法受理/终态，但不触发 ACP 恢复。

新增连接期 `session.view` / `session.view.result` 控制帧（拟登记），同一认证连接最多声明一个当前会话，`sessionId: UUID|null` 表示选择/离开，附单调递增 `viewVersion`。同版本同载荷重试幂等，过期版本忽略而不复活旧页面。查看声明只续租/替换 viewer，不能自行启动 Agent；前端在同一连接先声明当前选择，再派发恢复命令，避免成功与租约创建之间无人保护的窗口。激活完成只看最新 viewer 集合，不因旧命令结果重新添加 viewer。

建议固定 v1 参数：可见页面每 10 秒续租，租期 30 秒；每连接最多一个 viewer；控制帧独立受每分钟 120 次上限保护，不计入持久命令速率，不持久化每次续租。时间只由服务端时钟决定，客户端时钟不可信。离页立即声明 null，断开/撤销立即清除，丢包靠有界租约兜底；普通 control.ping 不续租。所有输入受 schema、大小、session 归属、版本范围和认证校验，错误不含密钥、正文或任意路径。

新增常量、命令结果、feature 和必要错误类别在机器 manifest/Sync schemas/共享 fixtures 中唯一登记，Rust/TS 共用；有签名字段变化才更新 transcript 资产。本设计不新增长期 token 或设备权限集合。

### D5. 保留期与容量是一套节点规则

沿用 `sessions.idle_timeout_ms`，缺省候选值改为 1800000，显式 0 仅关闭按时间回收；新增拟定 `sessions.max_active_sessions`，正整数、候选默认 50，显式不可无限值。两者登记于 CONFIG_REFERENCE，旧配置显式 0 不被悄悄覆盖。保留起点为最后保护条件消失；恢复完成时若已无人查看从完成时开始，回到可见页面立即取消回收计时。

容量含 ready/activating/reclaiming 与其他尚占真实运行资源的 owned 会话；新建与恢复共用准入，待处理/任务占位也计入。不支持资源卸载时保留占位，不能释放假名额。创建失败但外部资源可能已建立的窗口按既有 uncertain 保留或核实资源，不盲目释放。

满额时选取未保护候选中最近一次查看/任务/交互保护结束时间最早者，稳定 ID 作同时间平局规则；读配置、网络心跳不刷新它。容量回收可早于保留期，显式 idle_timeout_ms=0 也不关闭容量策略。全受保护则返回资源已满，历史不受影响；没有自动排队等位或取消其他任务。运行期调低上限不强杀受保护会话，拒绝新增直到计数回落。

### D6. 前端通过现有层次接入

平台 adapter 提供可见性、pagehide、认证连接代信息，feature 层负责查看声明及激活请求，页面不直连 WebSocket 或存储。选择版本与连接代共同抑制旧续租/旧响应。恢复命令离页后由客户端命令跟踪收口，租约离页即撤；恢复中历史查询独立完成，失败保留草稿并允许显式重试，恢复成功不自动提交草稿。

## Risks / Trade-offs

- [Codex adapter 不支持可恢复卸载] → D1 实测门槛先行，失败阻断，不降级掩盖。
- [50 个长上下文内存过高或卸载不释放] → 记录真实硬件/版本/上下文、10/25/50 档进程树总内存及切页分位耗时，回收前后重复采样；不拿空会话压测替代长会话，不把当前宿主 Codex 内存当作产品数据。
- [保护规则使容量无法腾挪] → 明确容量错误和重试，保留历史；不承诺会话数是内存硬上限，不加未授权并发限额。
- [close 超时与迟到事件] → 使用资源代隔离、保留容量占位、确认无任务后才 close；不把旧代事件归入新恢复。
- [新增控制帧及 localActivity 漂移] → 显式协商、同 manifest 的 Rust/TS fixture、旧 peer/远程隔离和启动恢复测试。
- [租约丢包造成假离开] → 可见时重复续租及返回时立即激活；过期后仍有完整保留期，不立即杀会话。

## Migration Plan

1. 先完成真实 ACP 能力/上下文/释放探针并保存证据，通过后才推进合同和实现。
2. 登记协商能力、Sync resume 及控制帧、owned 投影/事件、配置规则、ACP close 支持矩阵和合同测试；保持 Node Link wire 不变。
3. 复用 owned 命令/事件表；运行资源、viewer 与租约不新增持久表。优先不改 DDL；若合同落地确认需要 owned 列，必须版本化迁移和旧库升级测试后再合入，禁止填入远程数据。
4. 先服务端、后前端接线；新客户端连接旧服务端明确降级为不支持自动激活，不发送新帧。旧客户端仍读任务三态，新字段通过能力投影隔离。50 候选值须完成实测才计为最终默认值；不支持时携证据重新确认。
5. 回滚先停止接入并正常收口任务，再撤销本机能力；不回滚或删除历史命令事件，不重派 uncertain。显式配置中的新键需在回退旧二进制前移除以避免未知键启动失败。未增加 DDL 时无需数据库降级；若实际引入迁移，按 migration 的回滚限制执行。

## Validation

行为场景映射见 plan/tasks。必须用真实 Codex ACP 配置验证“记住随机标记 → 确认记住 → close/回收或重启 → resume → 询问标记”，且恢复请求没有附带旧 prompt/标记文本；同时审计请求次数及工具副作用计数。自然语言回答只是一层证据，还需原 Agent 身份、请求参数、未发生新建及历史重派的协议证据。不得把 Agent 合法的自身上下文压缩承诺成逐字永久记忆。

真实资源释放按会话卸载前后及共享进程退出前后分别报告，内存分配器可能保留进程堆，不能只凭单次 RSS 不下降断定泄漏或凭本地对象被 drop 宣称成功；结合 Agent 载入会话计数/可用诊断和重复循环后的有界性。无法证明则保留为验收未通过。性能基准报告原始数据，不预先编造每会话 MB 或无依据的安全阈值。

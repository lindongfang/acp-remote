# Design

## Context

动机与用户约束见 proposal.md。现有 `domain/session-files.ts` 的来源为 all/git/session，默认 session；`features/client-store.ts` 的来源选择、打开文件、刷新分别包含 session 分支，并由 `buildSessionChangesModel` 汇总历史。`SessionFilesPanel`、`FileContentViewer` 和 `ConversationStream` 消费这些状态；`FileChangesPanel` 还作为未接线页面的回退，不能只删一个按钮。

主规范已有“变更文件的呈现边界”和“结构化条目的展开收起与右栏联动”。其余文件栏要求来自未归档的 `session-file-browser`。本增量沿用旧要求标题以便先旧后新同步；“文件栏提供三种来源”标题暂保留作精确匹配，正文改为两个来源，不另造平行能力。

## Goals / Non-Goals

Goals：让来源类型、组件与刷新调度一致收敛，清除无法到达的专属查看路径；保持时间线和文件查询原有边界。

Non-Goals：不删除 `file.changed` 的解码、投递、持久化、去重或时间线投影；不删除普通历史查询；不引入会话快照、Git 写操作、远程文件读取或新依赖。

## Decisions

1. **在来源入口归一化旧值，内部只保留 all/git。** 默认改 all，旧 session 选择及其专属打开状态回到全部文件/对话态，不恢复历史文件查看。现有状态主要在内存，无需新增持久化或数据库迁移。相比只隐藏选项，这能消除隐式默认与不可达分支；相比保留内部 session 来源，类型约束更准确。
2. **删除专属汇总和刷新，不动公共历史。** 移除文件栏会话记录归并、记录选择器、专属 `session.read` 刷新和已废弃回调；保留对话首次读取、历史分页、实时 file.changed 与目录/Git 事件驱动刷新。共享差异渲染仍由时间线使用的部分继续保留，不按组件文件名整文件删除。
3. **清理旧回退与自动联动。** `ConversationStream` 未接文件状态时不能重新显示旧文件变更清单；选中工具条目仍展开条目，不再切 session 来源。本次不新增目录定位、自动展开祖先或替代联动，既有显式文件路径打开能力沿用安全路径检查。
4. **原型与产品同批更新。** 原型删除来源按钮、默认 session 值、记录模式及脚本分支，保留两来源既有视觉。前端权威文档正文中旧的三来源、默认项、专属刷新及联动描述改为最终要求；历史修订/证据保留历史标识并指向本次更改。
5. **保留能力和安全边界。** 不更改 wire/schema/feature/catalog，也不修改 Rust 服务端；imported 与旧主机继续明确不可用，不因默认 all 而绕过门控。Git 提示明确覆盖整个工作目录。

## Risks / Trade-offs

- 删除共享差异渲染误伤时间线 → 检视组件调用方，并测试实时、重复事件与重新进入历史。
- 默认 all 增加首次目录查询 → 复用现有限流、并发合并与 capability/source 门控，失败不清空其他已加载状态。
- 在途变更互相覆盖 → 以当前工作区为基线，先收口 session-file-browser，再应用本变更；conversation-area-complete 的时间线要求继续有效，触及相同文件必须串行合入并重跑前端检查。
- 用户失去文件维度的会话记录聚合 → 已明确接受；逐事件工具差异和历史保留，不以 Git 结果冒充会话归属。

## Migration Plan

1. 固定已检视基线及在途文件清单，确保旧文件浏览实现可作为基线，不覆盖用户未提交修改。
2. 部署前端和原型调整，不迁移或删除服务端数据；旧来源值在边界回退 all，旧专属查看关闭，不新增存储。
3. 规范同步/归档顺序为 session-file-browser 在前、本变更在后；不得让旧增量重新覆盖为三来源，也不重写旧验收证据。本变更同步前确认旧增量新增的要求已进入主规范。
4. 回滚仅回退本次前端及设计资产补丁；后端事件和历史未改动，无数据恢复步骤。回滚后恢复旧界面只能作为版本回滚结果，不将旧行为称为本次目标。

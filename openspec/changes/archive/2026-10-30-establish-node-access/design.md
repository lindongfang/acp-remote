## Goals / Non-Goals

Goals：在单应用内分离身份领域、应用命令、客户端入口、存储和密钥操作；打通启动、Web 配对码认领、本机批准、认证、撤销和关闭。

Non-Goals：Harness执行、团队角色、跨节点协议、旧数据库迁移和移动客户端。用户后续明确首期 Windows + Web，App 与二维码后续实现，不作为本 change 验收门禁。

## Decisions

### 1. 本机命令持有配对管理权

采用用户指定流程：本机 `device pair` 创建一个限时请求，输出配对码并等待 Web 认领；认领后展示客户端名称、公钥指纹及到期时间，本机明确批准后提交信任；默认回车拒绝，Ctrl-C取消待处理请求。App 与二维码暂不实现。

不采用网络自助批准，也不让已配对远程客户端代替本机批准新设备。相比仅持码即信任，本机确认沿用用户要求参考的旧流程，降低码泄漏或被抢先认领直接取得管理权的风险。恶意抢领只能造成该次配对失败，用户取消后重新发起。

本机管理通道须验证操作系统用户身份，不能将loopback等同于可信。本机list/revoke入口保留恢复管理能力，避免最后一个远程客户端丢失后无法撤销。Windows采用限定当前用户访问的本机IPC；具体ACL和对端身份校验纳入平台验收。

### 2. Web 配对与临时材料

状态为待认领、待本机确认、已批准、已拒绝、已取消、已过期、已消费。它们是配对操作状态，不增加页面会话运行状态。有效期最多5分钟，时长由节点控制；进程重启使未完成请求失效。

Web输入码后通过同源请求换取配对资料，核对来源并验证节点证明。配对码不可用于管理认证，只保留于有界内存，失效即清理。认领时原子绑定一个持有对应私钥的客户端公钥。相同请求逐字重试返回相同结果，不同身份不能替换。全部字段、端点、状态和预算以 [接入合同](access-contract.md) 为本 change 唯一细节来源。

节点提交批准时原子保存客户端公钥、信任状态和必要安全审计；提交失败不得发布批准成功。客户端在验证节点身份并保存本地身份材料后，重新完成管理认证。批准结果短时可重取，不能因响应丢失重复建立身份。

### 3. 传输、节点身份与客户端身份分开

远程入口使用受信HTTPS/WSS；Tailscale只提供网络路径。首期选择节点直接TLS，加载用户提供的可信证书，不同时实现反代或移动原生入口。Web只接受配置同源，缺失Origin也拒绝；不信任客户端自报转发头。相比同时开放多种传输模式，该选择让首条闭环的信任边界可独立验证。

长期认证采用客户端公钥持有证明，每个连接使用新鲜且一次性的服务端挑战，绑定节点、客户端、连接、用途和协议版本。重放、跨节点及跨用途证明均拒绝。不会把配对码变为长期bearer凭据。

签名采用标准 JWS Compact/ES256，节点与浏览器通过成熟密码学库及WebCrypto实现，字段和防重放按接入合同；不复用旧Node Link与自定义transcript。合同有标准来源，不代表当前密码学或互操作已通过；固定向量及真实浏览器签验由实现交付，独立tester验证。

### 4. 领域与资源所有权

identity维护客户端信任及配对状态，policy判定管理资格，入口仅负责传输解析与转换；storage实现事务，keystore隔离私钥。以单应用逻辑模块起步，不按旧crate划分机械重建。

节点启动顺序：配置校验、进程/数据目录所有权、密钥存储、数据库、身份服务、监听及就绪。失败反向释放已取得资源。关闭顺序：停止受理、失效待配对、收敛在途命令、关闭订阅和连接、提交必要记录、关闭数据库与密钥句柄。任务均有节点或连接级所有者和取消路径；不使用无人管理的后台任务。

本change不启动Harness子进程，不能声称已验证其Windows进程树清理；后续执行change负责真实子进程树验收。

### 5. 撤销与持久化

信任和撤销只以数据库已提交状态为准；进程内索引为可重建缓存。撤销提交与请求受理通过同一身份协调边界确定顺序，提交后新请求不得越过旧缓存继续受理。连接注册表在提交后关闭目标连接和订阅；即使关闭通知尚未送达，每次新操作仍须检查有效身份。

若客户端自撤销，允许提交后直接断开；客户端随后重新连接被拒绝作为可观察结果，不能要求连接继续存活才能算撤销成功。先前已受理命令继续按实际结果收敛，不将撤销等同于取消或回滚。节点重启不复活已撤销身份。

普通数据库仅保存公钥、身份、信任及必要审计元数据。节点私钥进入系统密钥保护边界；客户端私钥各自保存，不能传给节点。日志和审计不保存完整凭据或配对载荷。

### 6. 实施边界与检查入口

接入合同已具体化首期 Windows x64 + Chromium Web 环境、JWS/ES256字段、限流、TLS、本机IPC、DPAPI与浏览器密钥保存、SQLite事务和初始化崩溃恢复。逻辑模块采用一个Rust应用工程 app/ 与一个Web工程 clients/web/，不按旧crate机械恢复；领域不依赖Win32或具体传输。

当前只有 openspec.cmd validate 和 git diff --check 可运行；产品编译/前端检查入口须由首个实施工作包建立，不能写成现已可执行。添加依赖前审查必要性、维护、许可证、平台支持与风险，并提交锁文件；本轮未添加依赖，具体库版本不能在尚无锁文件时冒称已冻结。

独立tester生成tests，主执行据此形成plan/tasks，reviewer检视方案和用例。设计问题按稳定ID修正复查；文档齐全、结构校验与独立方案通过分别记录。真实平台、依赖审查和产品验收属于实现交付证据，不能预先代签。

### 7. 应用审批边界的可执行接入

NodeRuntime 装配 ApplicationPolicy，复用同一 TrustStore 协调器和 PairingService 的一次性证明注册表；管理 WSS 使用该服务产生外部不可直接构造的认证上下文并重新核对当前资格。上下文绑定节点、客户端、公钥及认证代数。内部适配器通过该服务请求后续运行时能力，不增加网络 action 或页面。

运行时能力入口先验证当前资格，再检查独立审批依据，最后才可能派发副作用。当前没有审批颁发能力：缺资料、过期、未过期但不可验证来源的资料均拒绝，不制造默认批准或成功审批流程。有效期只是待验证资料，不能作为 bearer 凭据；假能力和 spy 派发器仅用于验收，不代表真实 Harness。策略弱引用配对服务，停机开始后不再签发或接受新挑战；内部挑战由独立随机作用域的 lease 持有，丢弃时取消。

配对 CLI 的批准输入采用 Windows 控制台事件非阻塞轮询，避免 Ctrl-C 取消后遗留不能取消的阻塞 stdin 线程。明确 y/yes 批准、默认回车拒绝及服务端取消语义保持合同不变。输入回显在调用方完成，平台适配器不持有后台读线程。

## Risks / Trade-offs

- 配对码可被旁观或猜测 → 短时有效、独立限流、原子认领和本机明确批准；失败不能泄漏配对是否存在的敏感细节。
- Web运行环境或本机恶意软件失陷 → 不承诺硬件级隔离或远程擦除已复制数据；通过密钥保护、最少敏感输出和撤销控制减少影响。
- 复用旧密码学编码带入架构和兼容包袱 → 仅按当前双入口流程提取必要部分，删去Node Link等不适用域并重新检视互操作。
- 规格CLI按文件存在判断specs完成 → 本change必须同时检查proposal列出的两份spec及其场景，不能以状态done作为覆盖或验收通过证明。

## Migration Plan

仅建立新数据目录和新schema，不读取或迁移旧产品数据库；检测到非本版本数据时明确拒绝，不清空或覆盖。首次启动只有在没有现有身份时生成新身份，已有身份不可读时失败关闭。

部署前在隔离环境验证启动失败、配对、认证、撤销及关闭；正式部署由用户指定数据目录与TLS材料。回滚保留数据和密钥，不自动降低schema或生成替代身份；尚无旧产品兼容承诺。备份和完整恢复属于后续change，本change不能冒充已具备该能力。

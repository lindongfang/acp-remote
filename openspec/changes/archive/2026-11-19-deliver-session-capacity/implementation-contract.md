后续运行时的队列冻结、已接收观察水位、首字节界限、三入口及调度见 [自动关闭运行时合同](automatic-release-runtime.md)。其中父子完整资源集合仍须补齐独立依据；内部模块测试不能替代生产自动回收及完整树验收。

标准初始活动依据为本轮固定的官方ACP v2 schema `StateUpdate`：new初始为idle，后续state覆盖；resume须在response之前给出当前state，response本身不证明idle。实现保存source/native级当前活动，覆盖Create-only及SourceOnly，不能只读有TargetFacts的已执行会话。只在未收到后续state时采用new的初始idle；重放旧正文只刷新计时。v1使用既有已验证加载/前台完成约束，不推导后台结束。

- 自动请求资格来自当前代际主树归属、已知前台/执行/审批/后台/子活动、关闭能力与必要管理状态。缺少未暴露的内部活动或原子窗口证明不阻断。未知前台、断线、已知活动未结束和账本未协调仍保护。
- 每个容量资源持有单调活动时钟和已知工作事实；实时活动及实际重放接收更新时钟，页面/缓存读取不更新。进入资格时重新计时。默认30分钟，扫描30秒；满额按最近活动、稳定身份排序，不等扫描。
- Create、执行加载及 SourceOnly Replay 三入口通过同一应用层容量准入触发一次候选释放，然后重试原子预留；并发仍由 SQLite 唯一账本限50。一次关闭失败不连续关闭其他树，无候选直接拒绝。
- 自动关闭沿原容量 owner、source/native/reservation/代际执行，不借用用户 actor 或伪造平台 target。内部系统操作在必要管理存储登记原始预留集合和原因（超时/容量），保持请求、物理关闭、协调返额的分离；只有原始集合确认关闭后原子提交完成并返额，失败/未知保额，重试不触及新代际。
- 复用已验证原生会话关闭与读取/审批收敛路径；不通过停止共享实例回收某树。自动发起前复核节点已知活动并封住本平台输入；仅在发送前可撤回的失败允许恢复准入，不撤销未知关闭的所有权。
- 调度任务纳入 runtime 所有权、stop 与 shutdown join；不产生无主循环或独立第二运行时。负载/读取失败和source关闭继续由既有所有者协调。
- 后台/子活动只取标准协议实际暴露的信息，保留未知字段和raw。已知父子关系用于共同主树名额，不增加子淘汰。没有可靠归属仍拒绝子加载。
- Web保留既有会话状态；说明自动发起关闭已启用及按已知活动判断，不承诺完整隐藏活动保护。请求失败、未知或管理未协调不得显示为空闲。
- 验收继续保持真实50树、实际30分钟及真实Harness路径，新增受测请求/结果边界；历史“原子安全窗口”断言由独立tester按授权替换，不把旧门通过当产品通过。

## 领域、应用、协议与持久化边界

1. 领域策略只接收来源身份、主树身份、资源代际、单调时间及已验证活动事实，产出预留、保护原因和候选；不执行协议IO，不接受客户端自报“安全”作为凭据。
2. 节点级应用所有者协调所有加载入口。尚无原生ID的新建以原始操作ID暂存预留，返回后绑定真实原生身份；同来源同树共享名额，未经验证的子目标不能猜测为主会话。
3. 协议适配器只提供当前版本实际支持的活动、关系和释放依据。完整观察范围及检查至关闭窗口保证是独立能力，不能从历史重放、前台完成或普通关闭推导。
4. 必要管理状态与账本协调须使用现有 SQLite owner/关闭责任。数据表、迁移版本及事务边界在写范围明确且独立检视通过后定稿；本轮不预写DDL或虚报已有容量表。
5. Web 通过现有认证管理通道读取限额、占用、保护/受限原因及释放结果；这些是资源事实，不新增会话生命周期状态。错误采用固定代码，不携带密钥或敏感正文。

## 自动回收所需的原始依据

自动回收至少需要同一目标及当前代际的以下事实：

- 已可靠识别主执行树，所有加载和在途资源均归同一所有者管理。
- 主/子、前台/后台工作及有效审批的覆盖范围完整，必要管理状态可靠。
- 检查到实际关闭之间的新工作竞态受到原生条件关闭或已验证运行约束保护。
- 隔离释放该树不会关闭共享实例的其他主树，释放结果和管理协调可确认。

当前源码 `domain/activity.rs` 将后台活动初始化为 `Unknown`；本轮检索未找到生产路径调用 `observe_background`。`NativeOwnershipGate` 是排他归属检查，不证明主树关系或后台活动完整性。现有普通 `session/close` 不携带本 change 所需的原生条件关闭依据。

因此目前只能确认这些依据尚未建立。不能以平台命令锁、两次 idle 查询、超时、先关闭再观察成功、杀进程或厂商私有探测补齐证明。完整编码门必须先有可执行的实现及取证路径；发现缺口本身不满足门禁。

## 计时、竞争与失败合同

- 计时使用单调时间；节点实际收到的重放按接收时刻刷新活动，历史消息时间不用于本次计时。缓存读取、心跳、页面打开不刷新。
- 进入安全状态重新计时；审批解除不抵扣此前等待时间。重放不形成工作保护；满额排序须使用最新活动，不能因每次重放而永久回避唯一安全候选。
- 预留及已加载资源共同受50名额约束。新建结果未知、加载结果未知、关闭失败、必要管理记录未协调均保留名额及所有权。
- 自动关闭前须重新核对候选与依据代际；平台冻结只解决平台输入竞争，不解决原生自发或外部输入竞争。
- 释放成功只在原始资源收敛与必要管理协调均确认后返还；实际关闭与管理保存失败分别呈现，不能提前把名额交给新加载。
- scheduler 必须由节点持有，有取消、等待关闭及失败后的清理路径；时钟边界可用可控时钟验证，真实30分钟验收仍须实际时长。

# Design

## Context

配对是系统里唯一建立长期信任的时刻。它现在有三处问题：**(1)** 设备侧对主机的验证只做了零件——协议要求「用配对载荷里固定的主机公钥验证认领响应里的主机证明」，而前端从未验过；状态查询的响应又**没有主机签名**，因此设备此后长期信任的那把主机公钥只能靠与载荷逐字节比对来确立，而这条比对也不存在。**(2)** SAS（短验证码）在本协议的流程里没有独立安全职责：信任锚是「配对载荷**带外**携带主机公钥与一次性配对秘密 + 认领阶段以配对秘密计算的 HMAC」，教科书里 SAS 所防的公钥替换已被它承担；而对"配对载荷在带外被整条替换"与"配对秘密泄露"这两种现实情形，SAS 完全无效。**(3)** 设备权限层与实际使用方式错配：不点名即零授权、`pack.create-session` 不进任何预设（照常理配对的人连上了却开不了会话），而只读设备、按设备降级这些表达力并未被用上。

## Goals / Non-Goals

**Goals:**
- 设备侧对主机的验证闭合：认领响应被验签、已批准响应里的主机公钥与载荷逐字节一致。
- 删掉两套 SAS（设备配对与节点配对）及其机器资产，并把「为什么不需要它」写进安全文档。
- 删除设备权限层：通过认证的设备可执行任何命令；配对确认仍必须由本机用户完成。
- Sync 面的会话创建允许客户端指定目录（Node Link 面维持"不得携带任意 Owner 路径"）。

**Non-Goals:**
- 不动跨节点的 `grant.*` / Export `scopes` / Access 侧 imports grants（那是"向哪个节点导出什么"的边界）。
- 不做「发起即批准」（配对仪式保持：发起 + 在电脑上按一次 y）。
- 不做命令级归因日志（由 `session-create-settle-order` 交付，本变更依赖它满足可见性诉求）。
- 不新增能力名。

## Decisions

**D1 删 SAS（设备 + 节点两套）。** 备选：保留但降级为"可选的人眼检查"（可选实现通常等于不实现，却仍给人「仪式已完成」的错觉）、由服务端下发（违反"双方各自计算"，等于把检查交给中间人可替换的通道）。删掉之后，设备侧剩余的信任判定全部是密码学的、不需要人参与。

**D2 补齐两条校验作为删 SAS 的前提。** L1：用配对载荷里的公钥验证认领响应的主机证明——协议早已要求，只是没有权威文档要求前端做，因此从未实现。L3：已批准响应的主机公钥必须与载荷里的逐字节相同——因为该响应没有任何主机签名。两条都落在 `pwa-web-client`。

**D3 删设备权限层。** 备选「保留机制、只改默认给全」能立刻达到同样效果且不动不变量，但整套 scope/preset 组合、前端门控与配对确认页的权限栏仍会留在仓库里，而默认零授权这个坑正是同一问题的另一半症状。

**D4 目录来源：Sync 面接受客户端提供的目录，别名保留为可选来源。** 实现取舍：浏览器**没有**获取宿主绝对路径的能力，因此"客户端提供目录"在 PWA 上自然是一次文本输入（可辅以已登记目录建议）；本变更只要求协议与能力允许，界面形态在 tasks 里定。Node Link 面不改——那条最贵的门拦的是**对端节点**，不是自己的设备。

**D5 文档与机器资产的连带面（本变更最大的一块）。** `AGENTS.md` §4 的「每个业务命令都要根据已认证设备及其 scope 授权」整条改写；`SECURITY_DESIGN.md` §10 授权表、§9.5 的 scope 缩减传播、§:241 确认页展示项、威胁模型里补"为什么不需要 SAS"；按 `AGENTS.md` §9 **修订 ADR-0001**（它把「Daemon 设备权限与撤销」写进了默认 Profile）；协议与前端文档、`transcripts` 域表与 fixture、`commands.json` 的 packs/presets、pairing/status schema 的 `scopes` 字段、设备记录的 `scopes` 列（删列走 migration，还是留作不再写入的历史列，在 tasks 里定）。

**D6 「前提消失」的要求用 REMOVED + ADDED 表达，而不是硬改旧要求。** 工具要求 `## MODIFIED Requirements` 的块保留原有场景标题，而 SAS/scope 相关场景的标题在新模型下会是假命题（例如「未持 scope 的设备被拒」）；因此这类要求整条删除并在同一 delta 里新增一条措辞准确的替代。本变更有较多 REMOVED，原因在此，不是顺手清账。

**D7 明确保留的边界**：设备认证与每连接挑战-应答、配对确认只能由本机用户完成、整台撤销立即生效、速率与各项上限、跨节点 Export/grant 交集。

## Risks / Trade-offs

- 这是仓库**第一次改写 `AGENTS.md` §4 的安全不变量**，改动面与审阅强度都是最大的一次。
- 与 `session-create-settle-order` 同时触碰 `SYNC_PROTOCOL.md` 与 `sync-session-create` / `sync-command-handling` 两份规格（落在不同要求块），合入必须串行。
- 不再拦截目录之后，"把会话开在敏感目录"的风险由用户承担；界面应给出提示，但它不再是服务端能拦的事——这条要在 tasks 里落成可观察的提示行为，而不是当作已经解决。
- `scopes` 列的处置牵动 `storage-sqlite` 的 migration 与 `CORE_PORTS_AND_STORAGE.md` §7 的合同漂移门禁。

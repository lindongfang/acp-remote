# Spec Delta

## MODIFIED Requirements

### Requirement: 变更文件的呈现边界

对话页 SHALL 在「文件」栏的「会话变更」中按文件合并当前会话 Agent 的改动，选中文件后在中间查看区按时间展示该会话的历次修改、每次修改的结构化统计与相对路径，并保留各事件的 ACP 原文诊断入口。客户端 MUST 不混入其他会话或手动修改，不把历次统计相加伪装累计净差异。已下发差异行 SHALL 逐行区分新增、删除与上下文，有 hunk 头时保留；未下发差异时 MUST 明确说明原因，不造占位，也不解析 ACP 原文补造差异。

#### Scenario: 只呈现有来源的统计

- **WHEN** 客户端收到一条带行数统计与展示路径的改动事件
- **THEN** 客户端在该文件对应修改记录中呈现这些统计与路径，未知统计不冒充零

#### Scenario: 有结构化差异行时逐行呈现

- **WHEN** 某处改动随事件下发了结构化差异行
- **THEN** 客户端以新增、删除与上下文样式及前缀呈现，有 hunk 头时保留，且行内容按不可信文本处理

#### Scenario: 没有差异行时明确说明

- **WHEN** 某处改动没有随事件下发差异行（未同步或超出单条上限）
- **THEN** 客户端明确说明原因，MUST NOT 渲染占位差异行使其看起来完整

#### Scenario: 原文是诊断入口而不是渲染源

- **WHEN** 用户想查看某处改动的完整 ACP 原文
- **THEN** 客户端把原文作为不可信文本在诊断视图里呈现，MUST NOT 把它解析后当作结构化差异渲染

#### Scenario: 同一个文件多次修改

- **WHEN** 当前会话对同一文件产生多条不同改动记录
- **THEN** 清单只列一个文件，打开后按时间查看全部已加载记录，重复投递同一事件不增加记录，不合成累计净差异

#### Scenario: 无法可靠确认是同一文件

- **WHEN** 两条事件只有相同文件名却不能证明是同一文件，或属于工作目录外的不同文件
- **THEN** 不仅凭文件名合并，不猜测路径或发出越界读取；已取得的事件记录仍可查看，并明确标注范围或来源限制

### Requirement: 结构化条目的展开收起与右栏联动

对话页 SHALL 让结构化条目（思考、工具调用、终端输出、计划）可展开与收起，且默认展开与否 MUST 由该条目的状态决定而 MUST NOT 由呈现顺序决定。用户对单条条目的显式操作 SHALL 覆盖默认值，且不改变其它条目的展开状态。条目携带文件标识时，选中它 SHALL 使「文件」栏切到「会话变更」并选中同一个文件；该联动 MUST NOT 自动替换对话区，用户点击文件后才打开文件内容。

#### Scenario: 进行中的条目默认展开

- **WHEN** 时间线上出现一条仍在进行中的工具调用
- **THEN** 该条目默认为展开，进行状态可读

#### Scenario: 显式操作只影响本条

- **WHEN** 用户收起一条默认为展开的条目
- **THEN** 只有该条目收起，其它同状态条目的展开状态不变

#### Scenario: 从条目联动到右栏

- **WHEN** 用户选中一条带文件标识的条目
- **THEN** 「文件」栏切到「会话变更」并选中该文件，对话区保持显示，点击文件后才打开内容

### Requirement: 对话页的宽窄两种形态

对话页 SHALL 在宽屏呈现三栏：同目录会话与目录上下文、中间对话或文件查看区、文件栏。三栏 SHALL 各自独立滚动；对话态保持会话头、内容来源提示、时间线与吸底输入区的既有布局。窄屏 SHALL 把同目录会话栏与文件栏降为可切换的次级视图；点击文件进入文件详情，关闭后返回原文件列表及滚动位置。两种形态 MUST 呈现同一信息集合，不因窄屏丢弃信息或改变判定。

#### Scenario: 窄屏不丢信息

- **WHEN** 同一会话分别在宽屏与窄屏形态下呈现
- **THEN** 两者呈现的信息集合一致，窄屏只是把两侧栏目改为按需切换的次级视图

#### Scenario: 切换次级视图不改变判定

- **WHEN** 用户在窄屏把次级视图从时间线切到文件再切回
- **THEN** 已提交命令、已呈现条目与各条目的展开状态都不改变

#### Scenario: 宽屏三栏各自滚动且输入区住在中栏

- **WHEN** 宽屏对话态下用户滚动时间线或任一侧栏
- **THEN** 只滚动该栏内容，其它两栏不随之移动；输入区保持在中栏底部，不横跨到左右栏

#### Scenario: 宽屏打开文件仍保留两侧

- **WHEN** 用户在宽屏点击文件
- **THEN** 中间区展示文件，左右侧栏保留且可独立滚动，关闭后恢复对话布局

#### Scenario: 手机关闭返回列表

- **WHEN** 用户在窄屏从已滚动的文件列表打开文件并关闭
- **THEN** 返回原选项、原展开目录与原滚动位置，不直接跳回对话顶部

### Requirement: 三页按设备宽度自适应

目录页、目录详情页与对话页 SHALL 按可用宽度自适应布局：窄屏下以单列呈现，宽屏下允许并排呈现更多信息。对话页窄屏时同目录会话栏与文件栏 MUST 改为可切换的次级视图。MUST NOT 因宽度不足而隐藏会话行、目录汇总、创建入口，也 MUST NOT 因宽度不足而改变任何判定结果。

#### Scenario: 窄屏

- **WHEN** 可用宽度小于断点
- **THEN** 三页均以单列呈现，会话行、三项汇总与创建入口仍然可见、可操作；对话页的两侧栏目经次级视图切换可达

#### Scenario: 宽屏

- **WHEN** 可用宽度不小于断点
- **THEN** 列表、详情与对话使用宽屏布局，呈现的信息集合与窄屏一致，不因宽度更大而少显示任何一项

## ADDED Requirements

### Requirement: 文件栏提供三种来源

对话页右栏标题和窄屏对应入口 SHALL 为「文件」，标题下 SHALL 提供「全部文件 / Git 变更 / 会话变更」，首次进入会话默认选中「会话变更」。三个选项 SHALL 以当前会话工作目录为范围，但来源分别为当前磁盘文件、Git 未提交状态与本会话 Agent 修改记录；不能互相冒充。

#### Scenario: 默认来源

- **WHEN** 用户首次进入某会话
- **THEN** 文件栏选中「会话变更」，没有记录时明确显示尚无已加载的会话变更，不表示目录或仓库为空

#### Scenario: 其他来源的修改

- **WHEN** 用户手动修改文件或另一会话修改了文件
- **THEN** 文件可出现在全部文件和 Git 变更，但不会仅因此加入当前会话变更

### Requirement: 全部文件逐层浏览与过滤

「全部文件」 SHALL 按文件夹层级浏览，默认显示隐藏及被 Git 忽略的文件，始终隐藏 `.git` 管理条目。客户端 SHALL 提供「隐藏忽略文件」按钮并可恢复全部显示；非 Git 目录禁用该按钮并说明原因。根外链接 SHALL 可见但不可打开。分页与加载失败 SHALL 明确呈现，不把部分结果冒充完整列表。

#### Scenario: 忽略规则可切换

- **WHEN** 用户切换「隐藏忽略文件」按钮
- **THEN** 根据 Git 有效忽略规则刷新当前目录，切回后恢复被忽略项，`.git` 始终不出现

#### Scenario: 根外链接

- **WHEN** 文件列表包含指向会话目录外的链接
- **THEN** 条目可见且说明不能打开，不能预览或下载目标

### Requirement: Git 变更的展示与不可用原因

「Git 变更」 SHALL 按文件展示所有范围内未提交修改，包括已暂存、未暂存与未跟踪文件，点击后展示相对 HEAD 的合并差异；新增文件展示全量新增，删除文件展示原内容删除。目录非 Git 仓库时 SHALL 显示「此目录不是 Git 仓库」，选项保留。Git 不可用、冲突、二进制差异和截断 SHALL 有明确说明。

#### Scenario: 新增修改删除

- **WHEN** 仓库有新增、暂存后继续修改及已删除的文件
- **THEN** 分别显示其状态，修改文件不重复列出，打开后取得对应基准的真实差异

#### Scenario: 干净仓库不等于不可用

- **WHEN** 查询成功且没有未提交改动
- **THEN** 显示没有 Git 变更；非仓库或查询失败不能使用这一空状态

### Requirement: 中间文件查看与关闭恢复

点击文件 SHALL 在中间对话区打开与来源对应的只读内容，右上角 SHALL 提供名称明确且可用键盘触发的关闭按钮。打开另一文件 SHALL 直接替换当前文件，不增加多页签；文件视图 SHALL 明确显示文件路径和来源。关闭后 SHALL 恢复对话滚动位置、输入草稿和条目展开状态；查看文件 MUST 不取消 Agent、暂停事件接收或清除命令状态。

#### Scenario: 三种内容对应来源

- **WHEN** 用户分别从全部文件、Git 变更和会话变更点击文件
- **THEN** 中间区分别显示当前内容、未提交差异和该会话历次修改，来源可辨认

#### Scenario: 关闭恢复草稿与位置

- **WHEN** 用户写了草稿并向上滚动对话，打开文件后点击右上角关闭
- **THEN** 对话回到原滚动位置，草稿及条目展开状态仍在，不强制跳至最新消息

#### Scenario: 查看文件期间 Agent 继续

- **WHEN** Agent 正在回复而用户打开文件
- **THEN** Agent 继续运行，事件和交互状态继续更新，关闭后可以看到期间收到的内容

#### Scenario: 切换文件时旧响应迟到

- **WHEN** 用户从文件 A 切换到 B 后，A 的读取响应才到达
- **THEN** 中间区仍展示 B，不被 A 覆盖；关闭或切换会话后的迟到响应也不能重新打开文件

### Requirement: 只读预览与主动下载

客户端 SHALL 以不可信内容展示文本，只预览常见安全栅格图片；其他二进制文件展示基本信息与用户主动下载入口。HTML、SVG 或可执行内容 MUST 不作为活动页面加载。超过预览预算 SHALL 明确提示截断或不可预览，不假装完整；下载 SHALL 经平台适配层执行，可取消且不将文件正文持久缓存，不以大内存拼接无限文件。

#### Scenario: 文本与图片

- **WHEN** 用户打开可预览文本或预算内支持的图片
- **THEN** 展示只读内容，文本中的脚本不执行，图片不加载额外远端资源

#### Scenario: 大文件与二进制

- **WHEN** 文件超出预览预算或格式不支持
- **THEN** 显示大小、原因和可用的下载入口，不能呈现空白冒充文件为空

### Requirement: 文件刷新与远程降级

客户端 SHALL 在进入文件来源视图时、用户手动刷新时及收到当前会话文件修改事件时刷新对应数据，不持续监控整盘。请求 SHALL 遵守限流，保留已有视图并显式呈现加载/失败。远程导入会话 SHALL 保留已收到的会话变更，全部文件与 Git 变更明确提示暂不支持且不查询本机目录；未协商新能力的主机同样明确降级，不影响既有会话记录。

#### Scenario: 事件驱动刷新

- **WHEN** 当前会话产生文件修改事件
- **THEN** 会话变更更新，已使用的文件与 Git 列表被刷新或标记待刷新；突发事件被合并，不能突破限流

#### Scenario: 手动刷新会话变更

- **WHEN** 已协商会话历史能力，用户在「会话变更」点击刷新
- **THEN** 通过既有 `session.read` 只重读最新历史页，按 eventId 去重合并，不清空旧记录、不替换聊天消息、不重置历史分页；在途时显示加载状态且不重复派发，失败保留原列表并显示原因

#### Scenario: 无法刷新时明确说明

- **WHEN** 连接离线或主机未协商当前来源的查询能力
- **THEN** 刷新按钮不可用且显示原因，不发出不支持的查询，不以静默无响应冒充刷新

#### Scenario: 远程会话保留已有能力

- **WHEN** 用户查看 imported 会话
- **THEN** 已取得会话修改记录可查看，另外两个选项明确暂不支持，不展示 Access 主机文件

#### Scenario: 部分历史尚未加载

- **WHEN** 会话变更只包含已加载的一部分历史记录
- **THEN** 明确标注范围并提供既有历史加载入口，不声称列表覆盖整个会话

### Requirement: 文件列表保留目录层级与变更标记

三种文件来源 SHALL 以文件夹图标和缩进区分目录与文件。Git 与会话变更 SHALL 按可靠相对路径保留每层目录且允许展开收起，不猜测未知路径的目录归属。新增、修改文件 SHALL 使用绿色文件名及尾随 `+`；删除 SHALL 使用红色文件名及尾随 `-`。未跟踪按新增展示，其他状态保留真实说明。会话标记 SHALL 取最新已加载记录，不随历史选择改变，不冒充净差异或行数统计。

列表 SHALL 采用无卡片边框的紧凑单行、目录引导线和右对齐标记/已下发统计；长文件名省略但保留完整打开路径。连续单分支目录 MAY 合并显示为 `a/b`，全部文件仅使用已成功完整加载的目录页，不额外预读。打开会话文件时，右栏 SHALL 保持紧凑，历次详情在中栏呈现；没有中栏打开能力时保留内联详情。未下发统计 MUST NOT 补造，多次记录 MUST NOT 累加为净差异。

#### Scenario: 不同目录有同名文件

- **WHEN** 变更包含 `src/ui/a.ts` 和 `tests/a.ts`
- **THEN** 两个文件分别置于各自目录层级，文件行显示尾段名称，打开时仍使用完整相对路径

#### Scenario: 文件最新记录为删除

- **WHEN** 会话某文件先修改后删除，用户选中较早的修改记录
- **THEN** 文件行仍显示红色与 `-`，历次记录及逐次统计继续可查

## Context

SQLite 已在成功的会话落账事务里写 owned_directory，Sync 快照从目录表提供标识与路径；创建完成结果只有 SessionSummary 中的目录引用。前端此前只补 sessions，workspaces 仍是旧快照，故无法分组。

## Goals / Non-Goals

补齐成功创建到目录清单的同步，刷新/重连后仍可见。无需新增目录写入接口或复制用户提交路径，不改变浏览/mkdir、Node Link、安全及持久化边界。

## Decisions

Feature 在创建完成且摘要目录未出现在清单时调用窄刷新端口。SyncClient 使用当前已认证连接发送 cursor=null 的 sync.subscribe，等待服务端 reset_required，再沿现有 snapshot_request/验证/原子替换路径获取资源。旧快照和去重/ACK 水位保留，业务渲染不发查询命令。SyncClient 合并在途刷新，期间再有创建保留一次后续刷新；关闭后保留意图，重连追平再执行。对同一完成回复按 requestId 去重。

## Risks / Trade-offs

快照结束后的帧在异步摘要校验完成前按到达顺序暂存，避免后续事件/追平游标先于快照提交而让新目录快照被判回退。暂存最多 256 帧和 4M UTF-16 字符，超限关闭并从持久游标恢复；连接关闭后丢弃暂存，不提交迟到快照。只有快照验证与本轮追平均完成后才启动合并的后续刷新。

新目录创建需要一次完整快照；只在缺目录时触发，重复完成不会造成请求循环。刷新失败或断线保留原清单，依现有恢复流程重试。路径只能来自已验证快照，不能取自提交输入。

## Migration Plan

无数据/协议迁移；已有服务端提供全部必要能力，更新前端即可。旧提示与较早主规范存在历史漂移，修正与当前已实现的目录持久化规则直接相关的条文。

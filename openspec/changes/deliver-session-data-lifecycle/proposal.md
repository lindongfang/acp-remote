# 交付原生会话删除与自有缓存清理

## Why

节点接入与通用会话闭环已交付，获授权的原生会话删除与平台自有缓存/元数据安全清理尚未实现。为按重设计建立可独立验收的交付闭环，需要实现严格绑定范围的原生删除与自有缓存回收。

## Success Criteria

### 用户原始要求

> acp-remote还是不保存会话数据，以harness 数据为准
> 只提供原生删除，不保留隐藏功能。
> 查看时允许激活进程，不限制只读；查看本身不发送新输入或批准工具。

- **SR-002 确认**：删除授权固定目标集合，范围变化须重新确认；原生机制无法限制实际影响范围时拒绝删除，不用平台锁掩盖外部竞态。
- **R2-002 / R2-003 确认**：删除派发前管理记录失败时不调用原生删除，派发后结果写入失败时保留已知事实且不重发；管理元数据清理与聊天缓存清理分离，保护有效去重、审批交付与过期拒绝依据。

### 硬约束与非目标

- 以[重设计 §4.4、§7.1–§7.2、§8](../../../docs/HARNESS_CONTROL_PLANE_REDESIGN.md)与 `openspec/specs/` 长期规格为依据；采用新架构、不兼容旧系统。
- 只提供原生删除，不增加平台侧“隐藏会话”功能；不以删平台记录或直接删厂商私有文件冒充原生删除。
- 首期限定 Windows 节点 + Web，App 后续；当前处于需求与设计定义阶段，`tests/plan/tasks` 在正式启动本变更时基于真实代码树生成。

### 本 change 的成功判据

- SC1：只提供获授权且能力已验证的原生删除，保留最小不含正文审计；仅清理平台拥有的缓存及临时上传。
- SC2：故障下不重发危险删除副作用，管理元数据清理不破坏去重、资源责任或客户端身份/撤销事实。
- SC3：正式开工时基于当前规格生成 `tests/plan/tasks` 并通过编码前门禁、真实实现与集成交付验收。

## What Changes

- 实现绑定固定目标集合摘要的原生删除授权、执行停止与资源释放前置协调及最小结果审计。
- 实现平台自有视图缓存/临时上传回收，以及遵守通用保留策略的管理元数据安全清理器。

## Exploration

- **固定范围删除授权（SR-002）**：命令记录确认时的原生范围、目标集合及摘要并在派发前复核；集合变化使旧授权失效。原生接口无法保证影响范围不扩大时保持禁用。
- **删除故障与元数据清理边界（R2-002 / R2-003）**：管理记录未可靠提交前禁止发出原生删除；管理元数据清理引用 `management-audit` 与 `session-execution` 期限策略，保留不可回退的过期拒绝依据，身份与撤销事实绝不自动清理。
- **只删原生、无隐藏功能（Q-001）**：原生接口不支持删除时直接呈现不可用，外部删除在刷新后按原生事实自然消失。
- **术语与 ADR 复核**：复用 [领域术语表](../../GLOSSARY.md) 中原生范围、命令与管理事实定义，无新增独立 ADR。

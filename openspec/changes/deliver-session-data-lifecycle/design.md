# Design

## Context

动机与用户确认要求见 [proposal.md](proposal.md)，行为规则见 `specs/session-data-lifecycle/spec.md` 与 `openspec/specs/` 长期规格。本变更当前处于需求与设计定义态，具体施工工作包与验收用例在正式开工时基于真实代码树建立。

## Goals / Non-Goals

**Goals:**
- 提供范围受控、获明确授权且能力已验证的原生会话删除，并记录不含正文的最小审计。
- 分离回收无引用的平台自有缓存/临时上传与满足收敛条件的过期管理元数据。

**Non-Goals:**
- 提供会话隐藏/取消隐藏；直接删除厂商私有磁盘文件替代标准原生接口；自动清理客户端身份或撤销记录。

## Decisions

### 1. 职责与权威

只提供原生删除，原生接口未验证支持时禁用删除入口。外部工具直接删除的会话在刷新重读后按原生事实呈现不存在，不用平台索引复活。

### 2. 来源能力与接口

删除命令记录确认时的原生范围、目标集合及其摘要，阻止相关新执行并协调未决审批、取消和资源释放后再调用。原生适配器须提供可验证的范围约束保证（如原子条件删除或原生排他机制），无法限制实际影响范围的接口保持不可用，不用平台内存锁掩盖外部竞态。

### 3. 状态与失败

删除属于危险副作用：受理及派发前置记录不能可靠提交时不调用原生删除；原生已删除而管理结果写入失败时，保留已知原生删除事实与记录故障告警，绝不自动重发。故障安全取消和容量回收路径均不允许调用原生删除。

### 4. 资源与安全

只回收平台自有、无活动读取引用的视图缓存和临时上传分块。管理元数据清理统一引用 `management-audit` 与 `session-execution` 期限策略：核对请求不可再执行、工作及审批交付已终结、未知结果核验与资源名额责任已收敛，并保留不可回退的过期拒绝依据后，再在单事务内清理到期记录。

## Risks / Trade-offs

- [部分 Harness 无标准会话删除接口] → 诚实禁用删除按钮并说明协议能力限制，不退化为删本地文件。
- [元数据清理误伤去重防线] → 严格保留代际与过期拒绝水位，确保清理后旧重放请求仍被确定性拒绝。

## Migration Plan

开工前盘点当时管理审计与请求登记表结构，增量添加删除状态与清理水位约束时不破坏现有身份、信任、管理记录与原生数据。

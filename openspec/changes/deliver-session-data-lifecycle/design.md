## Context

见 proposal.md、重设计§8。依赖导入唯一绑定、容量释放及可靠父子身份；编码前按上游最终合同重基准。本设计细化未定父子/审计规则，保持普通删除不删原生的确认边界。

## Goals / Non-Goals

明确删除作用域与失败恢复。不建立自动历史保留窗口，不清理用户实际原生文件，不承诺跨平台库与外部Harness的原子删除。

## Decisions

### 1. 保守默认与显式批量

默认仅删选中平台会话，不级联。Web先显示影响范围；删除执行树必须显式列出被选子会话，服务器将选择集合与关系版本绑定，范围变化则拒绝并要求刷新。保留子会话仍可独立浏览，不制造新原生父身份。只有可浏览的Session链接可空，并显示“原父会话已不可用”；AgentParticipant的parent/root身份链不得清空或改成伪根。被删侧参与者保留最小无正文墓碑（不透明ID、原生范围、原parent/root身份及会话不可用标记），不保留提示词、工具正文或附件。委派保留自身来源关联并将已删Session浏览链接标记不可用。多层关系重启后仍须无环、同原生范围并可追溯原根；这些身份事实由agent-session-tree负责，删除只改变Session可浏览性。相比隐式级联，这减少未选数据丢失，且未改变已有已确认行为；此规则是设计细化，不称为用户逐项确认。

### 2. 操作所有权与删除事务

删除Command保存固定目标集合、请求身份及步骤结果，按稳定会话ID顺序取得操作锁，阻止新输入/导入/恢复。先失效待审批并协调取消完成、保存与释放；失败退出删除流程并保留会话管理和可见错误，不让“删除中”成为额外页面生命周期。资源确认释放后，单事务删除平台条目/轮次/目标会话、处理关系并移除附件引用，同时保存最小删除审计和原Command结果。进程在事务前崩溃可重试协调，事务后重复返回结果；不自动重发外部未知副作用。

### 3. 原生删除分阶段

请求必须显式区分平台删除与原生删除。若原生选项不支持则在任何删除前拒绝整个请求，避免用户以为全部成功。支持时先完成平台释放，再按固定原生绑定执行一次原生删除并记录独立结果；外部结果未知时停止并报告，不能自动重发。平台删除只有在其事务提交后才算成功；两部分不能原子完成，响应逐部分给出事实。普通删除解除绑定但不改写原生存储。

### 4. 引用驱动附件回收

附件记录使用内容摘要识别字节，引用记录关联条目或导入批次。事务移除引用后将零引用附件标为可回收；回收器在同一附件锁下重新检查零引用及代际，先标记deleting，原子移到受控垃圾目录，再删除并提交结果。新增引用必须拒绝deleting对象并重新提供/校验字节，防止检查与删除之间误删。失败保留回收任务重试，不回滚已提交平台删除。路径由附件ID解析且校验受控根，不接受用户任意路径。

### 5. 最小删除审计

保留Command与AuditRecord的目标不透明ID、操作者、时间、明确范围、请求摘要和分步骤结果，默认不自动清理，直到未来显式审计保留规则。不得保留提示词、工具正文、附件字节或凭据；已删会话不作为列表对象复活。审计访问沿用可信客户端授权。

## Risks / Trade-offs

- [外部删除与平台事务无法原子] → 分项结果及未知状态显式呈现，不自动重试副作用。
- [保留子会话失去父上下文] → 明确不可用父链接，保留子自身历史，不伪造父摘要。
- [磁盘删除失败] → 逻辑删除完成与物理回收分开反馈，后续安全重试。

## Migration Plan

在隔离副本建立引用表、回收任务和最小删除事实存储，核对已有附件全部有来源引用后才启用回收。回滚关闭删除入口及回收器，不回填已删除正文；若需恢复只从独立备份恢复到隔离目标。验收禁止使用用户实际数据。

## Implementation Gate

默认不级联是本设计选定的详细规则；若后续要求改变该默认或审计保留边界须另行确认。真实运行中删除、共享附件竞态、原生能力和故障窗口均未验证。

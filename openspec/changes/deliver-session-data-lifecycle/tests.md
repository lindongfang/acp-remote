## Cases

### DL-001 真实构建及类型检查

- 用例级别：L1
- 操作步骤：在仓库根目录按 README 和 package.json 执行 npm run check、npm run build:rust；另执行 openspec.cmd validate deliver-session-data-lifecycle --strict 与 git diff --check，分开记录规划检查和产品构建结果。核对构建目标是否实际包含本 change 的节点与 Web 实现。
- 预期结果：真实编译、Web 构建和类型检查成功，检查覆盖本 change 的实际目标；现有上游开发实现通过构建不证明本 change 通过。缺对应目标或入口记受阻/未执行，规划校验不能代替编译或功能验收。

### DL-002 静态合同和供应链检查

- 用例级别：L2
- 操作步骤：在仓库根目录执行 npm run check、openspec.cmd validate deliver-session-data-lifecycle --strict、git diff --check、npm audit --audit-level=high；对实际 BASE/HEAD 执行 npm run lint:commits -- --from BASE --to HEAD --verbose，按 .github/workflows/ci.yml 的 secrets 作业执行密钥扫描。核对本 change 的协议合同、依赖审查和锁文件是否纳入实际入口，缺专用合同入口记未执行。
- 预期结果：真实适用检查按工程配置执行；开发工具审计不等于产品供应链通过，无专用结构门禁，reviewer人工核对精确引用和覆盖。

### DL-003 领域边界及异常状态

### DL-004 事务资源与并发协作

- 用例级别：L4
- 操作步骤：运行中删除同时输入/导入/恢复/审批；在取消完成、保存、释放、删除事务前后崩溃、原生删除结果丢失处注入故障；附件零引用复核到移动垃圾目录间新增引用、磁盘删除失败重试、路径越界输入；确认不误删共享字节、不回滚已提交逻辑删除、不重发未知原生副作用。
- 预期结果：跨组件失败无假成功或半提交，幂等请求不重复副作用；取消和关闭有所有者，失败仍保留管理责任；模拟边界和实际断言另存报告。

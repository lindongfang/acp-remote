### DL-012 确认集合变化使旧删除授权失效

- 用例级别：L5
- 操作步骤：展示并确认原生范围内父目标及固有级联集合 A；在确认后、派发前通过外部客户端新增子目标，另覆盖目标移出或改挂导致集合不一致。重试原请求并观察派发计数；重新展示当前集合，以新请求确认，另在新确认前取消。核对原授权与新请求的范围摘要及原生范围。
- 预期结果：集合或原生范围变化后不按旧授权派发，不自动把新增目标纳入动态子树授权；必须重新展示并等待新请求确认，取消确认不执行。新确认仍须满足原生影响范围约束，不因用户再次确认绕过接口安全缺口。

### DL-013 最后一次查询不能消除删除竞态

- 用例级别：L5
- 操作步骤：在派发前查询与授权集合一致后设置屏障，让外部客户端有机会新增级联目标；分别使用无法约束实际级联的接口合同，以及有已验证原子条件删除或覆盖全部相关写入的原生排他机制。前者即使冻结平台输入并反复查询也尝试操作；后者在范围条件失效时观察原生拒绝及实际受影响集合。替身仅用于危险窗口合同，不实际删除用户数据。
- 预期结果：无原生范围保证的路径在派发前拒绝，明确不能保证授权范围；一次校验、再次查询及平台锁均不足。具有原生约束的路径只能在授权集合内删除或安全拒绝，外部新增目标不被未授权删除；不能证明原生约束的版本不获得支持标记。

### DL-014 受原生约束的固定集合删除与重复结果

- 用例级别：L5
- 操作步骤：选用已验证可限制实际影响范围的原生路径，确认固定目标集合和固有级联；协调执行、审批及释放，注入一次释放失败并确认零删除，再重新发起获授权请求。成功分支记录原生约束、派发及确认，刷新真实列表，重试同请求；核对集合外另一会话及最小审计。所有操作仅在专用原生根执行。
- 预期结果：释放失败保留管理责任且不删除；成功仅影响已确认集合，不由平台额外级联。原生确认后才报告删除完成并失效缓存，同请求返回原结果、不再调用删除；审计保留范围及分步事实而无聊天、工具或附件正文。

### DL-015 删除交付未知后范围变化仍不重发

- 用例级别：L5
- 操作步骤：在原生删除可能已经接收、平台确认尚未到达时断开实际连接；外部随后改变关系集合。分别重试同请求、重连刷新及再次打开确认界面，观察删除调用次数；有核验能力时读取真实状态，无能力时保留未知。对照尚未派发即发现集合变化的分支。
- 预期结果：已交付或结果未知的原请求保留原事实，不因范围变化、再次确认界面或连接恢复自动重发；可按能力核验，无法证明则明确未知。未派发的旧授权失效后须由新请求确认新范围；清缓存和页面消失均不能作为原生删除成功证据。

### DL-016 真实原生删除范围约束及隔离验证

- 用例级别：L6
- 操作步骤：在隔离原生根用真实 Harness/接口建立父子集合，通过真实 Windows 节点及 Web 展示并确认；外部客户端在确认后新增目标，验证旧授权不派发。另用真实已验证范围约束路径在查询后引入并发变化，核对实际删除或条件拒绝；在稳定集合上取得新确认完成安全删除，并核对重复请求、结果查询、审计和集合外会话。缺真实安全删除能力时记录正向删除未执行，不能以平台隐藏或私有文件删除补位。
- 预期结果：真实外部变化不扩展旧授权，原生约束实际阻止超范围删除；稳定授权集合可按真实能力删除或明确失败，结果未知不重发。集合外数据及其他共享会话受保护，真实原生结果与平台受理/交付/确认分开，模拟竞态证据不代替本例。

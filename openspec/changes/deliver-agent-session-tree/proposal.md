# 交付子 Agent 身份与父步骤展开

## Why

节点接入与通用会话闭环已交付，子 Agent 身份与父步骤内展开能力尚未实现。为按重设计建立可独立验收的交付闭环，需要基于原生可靠身份、父子关系和委派建立可重建的子会话视图，并与受管展示快照库（`deliver-session-transcript-cache`）及主会话根树客户端控制权继承（`deliver-session-control-takeover`）协同对齐。

## Success Criteria

### 用户原始要求

> acp-remote还是不保存会话数据，以harness 数据为准
> 只提供原生删除，不保留隐藏功能。
> 查看时允许激活进程，不限制只读；查看本身不发送新输入或批准工具。
> 父子会话不是独立分页，而是子会话作为父会话的一步，点击可以展开子会话（展开区域正序分页，轮数由前端传入、默认10，父会话倒序分页）。

- **CT-001 / TC-001 对齐（2026-11-19）**：子会话不设立独立客户端控制锁，一律继承所属根主会话的客户端控制权状态（只读客户端与主控客户端均可展开浏览子步骤，涉及子会话审批裁决或控制动作时仅限根主会话当前控制端）；平台已观测的可靠父子步骤引用与子会话结构化展示内容可在独立展示快照库（默认 30 天滑动保留、10 GiB 上限）内受控缓存，显式原生同步以最新 Harness 事实覆盖，不建立无期限永久正文档案或厂商私有读取器。

### 硬约束与非目标

- 以[重设计 §4.1–§4.4、§6–§7.3、§10.2.5](../../../docs/architecture/overview.md)与 `openspec/specs/` 长期规格为依据；采用新架构、不兼容旧系统。
- 基础执行链保留实际暴露的结构化子 Agent 载荷；不建立厂商私有读取器、不建立无期限永久聊天档案、不拼回快照文本冒充子会话原生上下文。
- 首期限定 Windows 节点 + Web，App 后续；当前处于需求与设计定义阶段，`tests/plan/tasks` 在正式启动本变更时基于真实代码树生成。

### 本 change 的成功判据

- SC1：从原生可靠身份、父子关系和委派建立可重建视图与受管展示快照，在父步骤内展开可读子历史（父倒序、子正序、默认 10 轮），命中有效本地快照时零子进程展开，不建立无期限永久档案。
- SC2：验证原生来源和实际能力、显式原生同步刷新子关系与快照代际、主树控制权继承及历史不可用边界；外部操作不伪造为平台命令或审批。
- SC3：正式开工时基于当前规格生成 `tests/plan/tasks` 并通过编码前门禁、真实实现与集成交付验收。

## What Changes

- 从原生可靠身份、父子关系和委派建立可重建视图与受管展示快照关联，在父步骤内按需展开可读子历史（父倒序、子正序、默认 10 轮）。
- 对齐主会话根树客户端控制权继承（展开查看不要求控制权，子级审批或写控制严格继承根主会话 `controllerClientId` / `controlEpoch`）。
- 区分关系/摘要展示与完整子历史分页展开的能力条件，缺子历史读取时仅限制展开而不禁用整体接入。

## Capabilities

### New Capabilities

- `agent-session-tree`：稳定子身份、父子关系、委派及父步骤内展开。对应文件为 `specs/agent-session-tree/spec.md`。

### Modified Capabilities

（无；开工前若需调整已归档长期能力，按实际精确路径补充增量规格。）

## Impact

- 依赖：[deliver-history-navigation](../archive/2026-11-21-deliver-history-navigation/proposal.md)、[deliver-session-transcript-cache](../archive/2026-11-20-deliver-session-transcript-cache/proposal.md)、[deliver-session-control-takeover](../archive/2026-11-20-deliver-session-control-takeover/proposal.md) 和基础原生身份/读取端口；各 Harness 按自身已接入能力独立验收，跨 change 依赖见[能力地图](../../../docs/architecture/capability-map.md)。
- 影响范围：子身份关系映射、受管快照子步骤引用、分页展开协议、主树控制权继承校验及 Web 展示组件；具体写范围在开工阶段 `plan.md` 定义。

## Exploration

- **混合展示快照与原生权威（Q-001 / TC-001）**：子会话模型上下文与原生事实以 Harness 为权威；已观测子历史在物理隔离的展示快照库有效期内支持零子进程离线展开，显式原生同步时按最新 Harness 关系刷新快照代际，不创建厂商专用读取器或无期限永久档案。
- **关系展示、加载归属与根树控制继承（SR-003 / SR-004 / CT-001）**：仅有关系或摘要时保留父步骤展示；完整分页展开复用 `history-navigation`；实际子目标原生加载遵循 `session-resource-policy` 主树名额规则，写控制与子级权限审批严格继承根主会话控制权状态。
- **父步骤内分页交互**：子会话作为父会话中的一步原位展开、不跳转独立子页；展开区域正序分页（前端传参、默认 10 轮），父会话倒序分页。
- **术语与 ADR 复核**：复用 [领域术语表](../../GLOSSARY.md) 中展示快照库、会话控制权接管、重放读取代际与原生会话身份定义，无新增独立 ADR。

# 交付子 Agent 身份与父步骤展开

## Why

节点接入与通用会话闭环已交付，子 Agent 身份与父步骤内展开能力尚未实现。为按重设计建立可独立验收的交付闭环，需要基于原生可靠身份、父子关系和委派建立可重建的子会话视图，避免仅交付孤立模块而没有可观察结果。

## Success Criteria

### 用户原始要求

> acp-remote还是不保存会话数据，以harness 数据为准
> 只提供原生删除，不保留隐藏功能。
> 查看时允许激活进程，不限制只读；查看本身不发送新输入或批准工具。
> 父子会话不是独立分页，而是子会话作为父会话的一步，点击可以展开子会话（展开区域正序分页，轮数由前端传入、默认10，父会话倒序分页）。

### 硬约束与非目标

- 以[重设计 §4.1–§4.4、§6–§7.3、§10.2.5](../../../docs/HARNESS_CONTROL_PLANE_REDESIGN.md)与 `openspec/specs/` 长期规格为依据；采用新架构、不兼容旧系统。
- 基础执行链保留实际暴露的结构化子 Agent 载荷；不建立厂商私有读取器或永久平台聊天历史档案。
- 首期限定 Windows 节点 + Web，App 后续；当前处于需求与设计定义阶段，`tests/plan/tasks` 在正式启动本变更时基于真实代码树生成。

### 本 change 的成功判据

- SC1：从原生可靠身份、父子关系和委派建立可重建视图，在父步骤内展开可读子历史，不持久保存子正文或关系档案。
- SC2：验证原生来源和实际能力、外部更新后重新读取、缓存失效及历史不可用边界；外部操作不伪造为平台命令或审批。
- SC3：正式开工时基于当前规格生成 `tests/plan/tasks` 并通过编码前门禁、真实实现与集成交付验收。

## What Changes

- 从原生可靠身份、父子关系和委派建立可重建视图，在父步骤内按需展开可读子历史（父倒序、子正序、默认 10 轮），不持久保存子正文或关系档案。
- 区分关系/摘要展示与完整子历史分页展开的能力条件，缺子历史读取时仅限制展开而不禁用整体接入。

## Capabilities

### New Capabilities

- `agent-session-tree`：稳定子身份、父子关系、委派及父步骤内展开。对应文件为 `specs/agent-session-tree/spec.md`。

### Modified Capabilities

（无；开工前若需调整已归档长期能力，按实际精确路径补充增量规格。）

## Impact

- 依赖：[deliver-history-navigation](../deliver-history-navigation/proposal.md) 和基础原生身份/读取端口；各 Harness 按自身已接入能力独立验收，跨 change 依赖见[能力地图](../../../docs/REBUILD_CAPABILITY_MAP.md)。
- 影响范围：子身份关系映射、分页展开协议、节点共享视图及 Web 展示组件；具体写范围在开工阶段 `plan.md` 定义。

## Exploration

- **数据权威与重放兼容（Q-001 / RP-001）**：会话与历史以 Harness 为准；复用通用八份长期规格，缺历史重放不再整体禁用接入，允许标准流式重放后在有界视图分页，不创建厂商专用读取器或永久聊天档案。
- **关系展示与加载归属（SR-003 / SR-004）**：将关系展示与完整子历史分页展开的能力条件分开——仅有关系或摘要时保留父步骤展示；完整分页展开依赖可靠轮次及有界读取；实际子目标加载遵循 `session-resource-policy` 主树资源归属与名额规则。
- **父步骤内分页交互**：用户确认子会话作为父会话中的一步原位展开、不跳转独立子页；展开区域正序分页（前端传参、默认 10 轮），父会话倒序分页。
- **术语与 ADR 复核**：复用 [领域术语表](../../GLOSSARY.md) 中主执行树、读取代际与原生历史定义，无新增独立 ADR。

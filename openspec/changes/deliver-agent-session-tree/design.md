## Context

见 proposal.md。依赖历史导航与三款Harness接入；上游目前均属规划，实施前须逐一读取最终能力记录和数据合同重基准。原始结构从首次接入已必须保留，本变更增加可靠关系模型和父步骤内展开，不承担补造未暴露历史。

## Goals / Non-Goals

分清AgentParticipant（执行参与者）、Session（内容容器）、Delegation（一次委派）。不把工具调用ID当子会话ID，不统一父子全局排序，不控制Harness内部调度。

## Decisions

### 1. 三类实体及来源唯一键

参与者以Harness原生范围+原生参与者ID识别，会话以原生范围+原生会话ID识别，委派以来源范围+可靠委派ID识别；三者均有独立平台ID。不以显示名、工具名称、正文或时间猜身份。委派保存父会话、父条目/Run、参与者、可选子会话及来源载荷；未知字段保留而不补全。无原生委派ID但有可靠来源条目ID时，仅在该条目范围建立委派关联，不能声称跨恢复稳定身份。

### 2. 关系事务与冲突处理

同一来源事件的参与者、子会话、委派及父条目引用在一个事务更新；外键阻止悬空引用。关系指向已存在会话时校验原生范围、授权边界及无环，来源冲突或循环保留异常原始载荷并报告，不覆盖已有可靠关系。多个委派可关联同一子会话；父子关系以来源事实建立，不能用重复消息拆分或合并。参与者持久保存parent/root身份，使子可追溯原根；Session可浏览链接与该身份链分开。后续删除Session只使浏览链接不可用，参与者以无正文墓碑保留最小ID、原生范围及parent/root链，不把子提升为伪根；重启、多层链及多次委派仍服从原身份事实。

### 3. 浏览投影与安全

父条目按实际委派显示步骤摘要、名称、状态及展开入口，点击后在该步骤内展示子历史，折叠后保留步骤位置与摘要；不跳转子页；展开区域正序分页，前端传pageSize，默认10轮，父会话则按其前端参数倒序分页、默认10轮。复用history-navigation的同一分页参数/校验、父步骤展开合同与共享字节预算、页内块续取、代际及重连规则，子翻页不改变父分页。独立Session/条目是数据来源身份，不等于独立页面。每次展开、续取和订阅校验父步骤到目标的可靠关系、客户端身份及目标权限；历史读取不加载原生资源，折叠不影响子执行和保存。

同一子会话的多个委派步骤各自保留父位置、Run与来源引用，展开引用同一可靠子身份及已观察历史，不复制为多份子Session；只有来源能证明每次委派的历史边界时才按该范围过滤，未知则明确“范围未区分”，不按时间或正文猜测。同一子历史在多个展开区域出现是引用视图而非重复持久化消息。嵌套关系逐层原位展开，不预读整树；加载失败、关联已不可用或仅有工具结果时保留已知结构和限制，不虚构可展开完整历史。

### 4. 能力驱动转换

每款固定版本列出参与者身份、子会话ID、独立历史、委派关联及活动信号的实际暴露证据。只有工具载荷时保留于父条目并显示“未暴露独立子会话”，不创建伪实体。不能根据Codex能力推定ZCode/DeepSeek支持。缺少可靠活动信号也不能在后续容量策略中把执行树当作安全空闲。

## Risks / Trade-offs

- [历史载荷缺少身份] → 不追溯猜测补关系，保留原条目与限制说明。
- [子会话很大] → 独立来源索引与父步骤内有界分块读取，按前端参数在展开区域正序分页，逻辑页内有界分块，不预读全部正文。
- [来源关系冲突] → 拒绝有歧义的关联并记录诊断，不能让同名合并泄漏其他会话内容。

## Migration Plan

新增参与者/委派关系记录和来源唯一约束。只从已保存可靠结构回填可证明映射，其余保持未知；在隔离副本验证后逐步启用树形入口。回滚关闭关系浏览但保留原始载荷和关系表，不删除子历史。无旧系统迁移。

## Implementation Gate

三款实际暴露矩阵、重启关联、重复事件、关系冲突、父步骤展开、嵌套与多次委派需真实验证；当前没有证据说明三款均能提供完整子会话。

## Goals / Non-Goals

从原生可靠身份、父子关系和委派建立可重建视图，在父步骤内展开可读子历史，不持久保存子正文或关系档案。 原生读取、运行与平台管理存储分开；不引入未经授权的私有桥接，不操作实际用户数据库或原生数据。

## Decisions

### 1. 职责与权威

主接入按通用逐能力规则可用，关系展示及子历史展开各自判断；分页遵循history-navigation，结构及当前连接视图遵循structured-history。缺少子历史读取只限制对应展开，不使整个接入不可用，不增加厂商读取器。

参与者、会话及委派以原生可验证身份及关系为权威，不永久保存关系或子正文档案。平台只保留可失效、可重建的视图。

### 2. 来源能力与接口

关系校验原生范围、无环和目标权限；同一子身份多次委派保留不同来源步骤，不按名字或时间合并。无法证明独立子历史则保留当前原生工具结构并说明限制。

### 3. 状态与失败

父步骤内按需展开，子正序、父倒序、默认10轮，嵌套逐层请求。每次重开及节点重启重新校验原生关系，原生缺历史时不伪造永久子档案。

### 4. 资源与安全

原生关系变化使缓存关联失效，已删除父目标不由平台墓碑关系重建为原生事实；管理审计中的不透明目标引用与浏览关系分开。查看激活遵循通用所有权与审批规则。

每层展开独立核对读取和分页能力；实际子目标加载遵循 session-resource-policy 的主树归属、名额及释放规则。父历史通过无加载查询取得，不意味着随后子目标也可以无名额加载。根已删除或主树归属不明时仅使用无需加载且有权的查询，不从缓存猜测资源归属。

## Context

RP-001 当前重放边界（2026-10-30）：以本 change 当前 specs 和通用 harness-management/structured-history 为准，标准重放为基础准入；只做共用 ACP 版本与能力处理，不按厂商补读取适配。平台分页可在完整流式重放形成的有界可丢弃视图上提供；本文早期探测及下游未重基准记录不构成新版通过。实际实现、管理数据迁移与产品验收均保持暂停。

2026-10-30 根据用户确认的原生会话权威方案重基准；见 proposal.md 和当前 specs。实现暂停，旧 tests/plan/tasks 仅作待迁移规划，旧 review 不覆盖本版。

## Goals / Non-Goals

从原生可靠身份、父子关系和委派建立可重建视图，在父步骤内展开可读子历史，不持久保存子正文或关系档案。 原生读取、运行与平台管理存储分开；不引入未经授权的私有桥接，不操作实际用户数据库或原生数据。

## Decisions

### 1. 职责与权威

主接入先满足通用标准重放准入，关系展示与子历史展开再按各自条件交付。history-navigation 提供有界重放视图及轮次分页合同；子目标只有标准全量重放且可证明轮次时同样可以展开，不要求原生分页。只有关系或摘要、缺子重放或缺轮次时保留父步骤并说明限制，不伪造完整子历史。逐接入验证，不等待其他厂商；当前无重放的接入不计为本功能已支持，也不要求为其新增厂商读取器。

参与者、会话及委派以原生可验证身份及关系为权威，不永久保存关系或子正文档案。平台只保留可失效、可重建的视图。

### 2. 来源能力与接口

关系校验原生范围、无环和目标权限；同一子身份多次委派保留不同来源步骤，不按名字或时间合并。无法证明独立子历史则保留当前原生工具结构并说明限制。

### 3. 状态与失败

父步骤内按需展开，子正序、父倒序、默认10轮，嵌套逐层请求。每次重开及节点重启重新校验原生关系，原生缺历史时不伪造永久子档案。

### 4. 资源与安全

原生关系变化使缓存关联失效，已删除父目标不由平台墓碑关系重建为原生事实；管理审计中的不透明目标引用与浏览关系分开。查看激活遵循通用所有权与审批规则。

每层展开独立核对读取和分页能力；实际子目标加载遵循 session-resource-policy 的主树归属、名额及释放规则。父历史通过无加载查询取得，不意味着随后子目标也可以无名额加载。根已删除或主树归属不明时仅使用无需加载且有权的查询，不从缓存猜测资源归属。

## Risks / Trade-offs

- [来源能力不齐] → 真实三款范围各自验证，缺原生关系或历史不承诺完整树；原测试 AT 系列尤其重启一致场景需重基准。
- [旧证据失效] → 原固定版本证据仅按未改变范围复用，方案及用例重新独立检视，不把文本校验当产品通过。

## Migration Plan

不执行实现或数据迁移。后续先盘点实际模式、未提交改动及本 change 写范围；保留身份、信任、管理与原生数据。取消的旧历史表、索引或租约方案不自动删除已存在数据，部署和回滚须在新合同及独立检视后实施。

## Implementation Gate

真实三款范围各自验证，缺原生关系或历史不承诺完整树；原测试 AT 系列尤其重启一致场景需重基准。 用户本轮三个分支已确认；实际程序能力、详细合同、独立用例和方案检视未完成，不恢复实现。

## 既有修订依据

### 父步骤原位展开修订依据

依据2026-10-29用户纠正及本变更最新proposal/specs/design，保留原ID并修正旧独立子分页/跳转预期；独立Session是数据来源身份，不等于独立页面。最新要求改为前端传pageSize、父DESC子ASC且均默认10；子在父步骤内独立分页，再对当前逻辑页有界分块。此前“不提供子分页”及固定10断言由本轮要求取代。AT负责真实身份/委派映射及完整Harness父步骤展开，复用HN已交付的有界展开合同，不用HN fixture证据替代真实关系验收。当前只定义待实现验收，不运行产品测试；缺实现、工具或所需真实能力在独立testing/runs报告记not-run。

### 自定义分页与保存透明修订依据

依据2026-10-29最新用户确认及本变更spec/design修订，所有旧ID保留；前端指定pageSize、默认10，父轮次DESC子轮次ASC，轮内条目仍ASC；子在父步骤内独立分页而不跳转新页面。正常页面不展示保存状态/提交版本，仅保存失败或异常缺失/完整性无法确认时报错，内部持久化及提交事实不变。pageSize公开有界上限须实施前按预算确定，测试从最终接口取得，不编造常量。AT继续承担真实身份/委派及完整父步骤分页验收。当前仅文档，产品用例not-run，结果另存testing/runs。

### AT-001 真实构建及类型检查

- 用例级别：L1
- 操作步骤：在仓库根目录按 README 和 package.json 执行 npm run check、npm run build:rust；另执行 openspec.cmd validate deliver-agent-session-tree --strict 与 git diff --check，分开记录规划检查和产品构建结果。核对构建目标是否实际包含本 change 的节点与 Web 实现。
- 预期结果：真实编译、Web 构建和类型检查成功，检查覆盖本 change 的实际目标；现有上游开发实现通过构建不证明本 change 通过。缺对应目标或入口记受阻/未执行，规划校验不能代替编译或功能验收。

### AT-002 静态合同和供应链检查

- 用例级别：L2
- 操作步骤：在仓库根目录执行 npm run check、openspec.cmd validate deliver-agent-session-tree --strict、git diff --check、npm audit --audit-level=high；对实际 BASE/HEAD 执行 npm run lint:commits -- --from BASE --to HEAD --verbose，按 .github/workflows/ci.yml 的 secrets 作业执行密钥扫描。核对本 change 的协议合同、依赖审查和锁文件是否纳入实际入口，缺专用合同入口记未执行。
- 预期结果：真实适用检查按工程配置执行；开发工具审计不等于产品供应链通过，无专用结构门禁，reviewer人工核对精确引用和覆盖。

### AT-003 领域边界及异常状态

- 用例级别：L3
- 操作步骤：构造同名不同原生身份、同子身份两次委派、重复事件、无ID仅工具结果、不同原生范围同ID、循环/悬空/冲突关系；断言参与者/会话/委派平台ID独立及来源唯一键，不按名称/正文猜关联。
- 预期结果：逐一断言spec中正常、异常、取消、重复与边界结果；状态/引用不串会话，不把未知写成成功，不弱化协议语义；局部模拟不替代真实验收。

### AT-004 事务资源与并发协作

- 用例级别：L4
- 操作步骤：在参与者、子会话、委派、父引用事务每步注入失败并重试；父子并发输出和重启，验证不半提交、不覆盖可靠映射；展开、块续取和订阅逐次校验父步骤关联与目标授权，撤销身份或仅有父权限时拒绝子正文；折叠/重开后注入旧代际响应，按可靠载荷回填而不补造关系。
- 预期结果：跨组件失败无假成功或半提交，幂等请求不重复副作用；取消和关闭有所有者，失败仍保留管理责任；模拟边界和实际断言另存报告。

- 预期结果：父步骤保留实际工具结构、委派输入及结果，明确缺少可靠子身份/子历史；可展开已知工具载荷但不创建伪子Session，不提供冒充完整子历史的展开入口。

### AT-006 同子身份多次委派

- 用例级别：L5
- 操作步骤：在已认证Web的本change管理入口，准备并操作以下情形：同一可靠子身份收到两次不同委派。读取操作结果、页面、持久记录及受影响资源；对重复、取消、失败与边界分支逐项核实，不仅检查截图。
- 预期结果：两次委派独立保留并关联同一可靠身份，各父步骤、Run和来源引用不覆盖或合并；分别原位展开引用同一子Session，不复制子历史为新会话，无法证明各次范围时明确标注范围未区分。

### AT-007 父子交替输出

- 用例级别：L5
- 操作步骤：准备父子各25轮，边界父轮含可靠子步骤；默认父DESC25→16，子ASC1→10再11→20；父子交替输出时分别自定义pageSize、翻子页、折叠/重开及续父页，核对目标、游标、轮内条目和更新路由。
- 预期结果：父步骤保持父首次位置，子内容仅在所属展开区域按ASC分页更新；父按自身pageSize倒序读取，两者默认10而非固定10，子页参数与进度不增加父轮次或改父边界、不跳子页。各轮内部仍首次位置ASC，不按时间混排父子正文或声明全局执行顺序。

### AT-008 重启后浏览子会话

- 用例级别：L5
- 操作步骤：保存可靠子身份、委派引用及已观察历史后停止Harness并重启节点；从父步骤原位展开同一子历史，检查平台数据源与parent/root链；结合后续删除验收核对父Session不可浏览时的墓碑身份链。
- 预期结果：父步骤仍可靠关联原子Session并可原位展开已保存历史，查询不启动或恢复Harness；若关联不可用明确报错，不伪造完整子历史。后续删除验收中浏览引用可失效，但participant原parent/root由无正文墓碑保留，多层和多次委派重启仍追溯原根，不将子提升为伪根。

### AT-010 独立安全及交互检视

- 用例级别：L5
- 操作步骤：由不继承 coder 对话的独立 reviewer 使用源码、配置、依赖审查、脱敏日志、浏览器和协议探针，核对设计权威与引用、页面状态及失败提示、敏感信息/权限边界、依赖维护许可与 Windows 支持、证据脱敏和限制展示；以实际 DOM、响应及执行证据核对行为。缺工具、环境、权限或入口记受阻/未执行，不自动转为用户手测。
- 预期结果：独立 reviewer 记录问题 ID、风险与结论；产品行为不擅改，未验证和错误不伪装成功，敏感信息不泄漏且权限边界成立。主执行自查不能代签独立检视通过，模型推断不能代替执行证据；独立角色要求不自动构成人工验收要求。

### AT-011 多次委派分别展开同一子历史

- 用例级别：L5
- 操作步骤：同一可靠子Session由两个不同父步骤委派，分别原位展开并以不同pageSize/边界正序续页；一组来源有委派历史范围、另一组没有；互换两步骤游标、重复来源事件、更新子条目并检查两区域和数据库身份数。
- 预期结果：两个父步骤/Run及来源分别保留，引用同一可靠子Session而不重复持久化；各步骤ASC分页进度独立，游标不能串用，父位置不变。证实范围按来源展示，未知明确范围未区分，不按文本/时间猜裁剪、不合并步骤或拆新会话。

### AT-012 嵌套子步骤逐层原位展开

- 用例级别：L5
- 操作步骤：建立真实可证明的多层关系，每层含长历史；先只展开第一层，再点其中下一层步骤并折叠祖先/重开，记录各层来源、顺序、查询量与未展开分支请求。
- 预期结果：逐层在所属步骤内按前端pageSize正序分页并按需展开，默认10；每层源身份/内部顺序保留，不预读整树、不伪造全局时间线；共享上游块预算，子分页不跳页或改祖先分页位置。祖先折叠释放所属展开读资源，不取消子执行或停止保存。

### AT-013 父子交替时折叠及父页边界

- 用例级别：L5
- 操作步骤：真实父会话超过20轮，边界轮中含子步骤；父子并行输出时展开/折叠并翻父页，折叠期间继续输出与提交，重开交错返回旧基线和新缓存；检查执行/保存及父轮次集合。
- 预期结果：父按有效pageSize倒序分页、默认10，子展开内按自己的pageSize正序分页；子输出不额外计父轮或混为平级条目，子翻页不改父边界。折叠不停止执行保存或恢复Harness；重开按源ID/版本合并，不重复、不被旧版本覆盖，正常同步无保存状态，异常失败或完整性无法确认才错误；不声明父子全局先后。

### AT-014 重启展开重新校验权限与关联

- 用例级别：L5
- 操作步骤：保存可靠关系后重启节点，不恢复Harness；从父步骤展开历史，随后分别撤销客户端身份/子目标权限、使关联不可用，并在续取/订阅及重开时重试，检查其他有权限父步骤。
- 预期结果：正常重启展开仍引用原子身份及平台历史；各次展开/续取/订阅按design§3重新验证关系与目标权限，不依父权限放行，不泄漏新正文；关联或权限失败保留父步骤位置并明确错误，其他有权限父历史仍可读，不创建替身、不伪造完整子历史。

### AT-015 真实子展开区域自定义正序分页

- 用例级别：L5
- 操作步骤：使用真实可靠子身份与25轮已观察历史，在父步骤前端传5，依次子1→5、6→10；省略默认10，下一页可改有效pageSize。父另传自定义大小DESC；同子多次委派分别续页、尝试串用游标，折叠/重开与正常重连后再续，撤销目标权限再取页/块。
- 预期结果：子分页ASC留在原父步骤，两者共用默认10、合法参数和预算规则而独立进度；父位置与页边界不动，轮内首次顺序ASC。不同委派步骤游标不串用，不复制历史、不预读整树；失效/越权明确拒绝，重开验证来源权限且旧代际不盖新。正常保存/完整同步透明，只有保存失败或异常缺失/完整性无法确认才错误；真实Harness证据不能由HN fixture替代。

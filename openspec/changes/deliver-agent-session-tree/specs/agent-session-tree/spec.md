## Purpose

定义 Harness 实际暴露的子 Agent 身份、父子会话及多次委派之间的关系，使子会话作为父历史中的步骤点击展开、在受管展示快照有效期内支持离线查看并在原生同步后保持可靠关联，同时明确根主会话控制权继承及仅有工具载荷时无法证明的内部执行边界。

## ADDED Requirements

### Requirement: 子树能力按接入独立交付
系统 SHALL 在主接入具备相应操作能力后，分别判断可靠关系展示、子历史重放或已观测展示快照及可证明轮次的能力，并对满足相应条件的接入独立交付，不以其他计划中 Harness 接入完成为前提。子历史分页展开遵循 history-navigation 与 session-transcript-cache 的展示快照、重放、分页及当前连接规则；MUST 不将原生按页读取作为必要条件，未支持子分支不伪造完整子树，也不阻塞有权父内容。

#### Scenario: 其他接入尚未就绪
- **WHEN** 一款满足相应操作条件的 Harness 能提供可靠子身份、关系及可证明轮次的标准重放，另一款尚未接入或不具备所需能力
- **THEN** 可对已满足条件的接入交付并验收子步骤展开，另一款明确未验证或不支持，不将前者结果外推后者

#### Scenario: 子历史通过展示快照或全量重放分页
- **WHEN** 子身份和关系可靠，子历史存在有效本地展示快照或可标准全量重放并证明轮次，但没有原生分页接口
- **THEN** 通过同一套通用快照/重放及分页规则在父步骤内正序分页，不增加厂商专用适配，不因缺原生分页拒绝展开

#### Scenario: 关系可读但子历史不可重建
- **WHEN** 已准入接入提供可靠子关系，但子目标既无已观测结构化快照也不能重放所需内容，或无法证明轮次边界
- **THEN** 保留有权父步骤、关系及原生摘要并说明子展开限制，不猜测完整子历史，不阻断其他父内容

### Requirement: 可靠身份才建立子会话
系统 SHALL 只根据可靠原生身份与来源范围建立子会话及父子关联，分别呈现原生参与者身份、会话和委派；仅暴露工具调用、摘要或结果时 MUST 保留原结构并标记限制，不伪造子会话。

#### Scenario: 仅有工具结果
- **WHEN** Harness只发出委派工具调用及结果而无稳定子会话身份
- **THEN** 父历史保留工具结构和实际输入/结果并标记缺少子历史，不生成可展开完整历史的虚构子会话

### Requirement: 多次委派不等于多个身份
系统 SHALL 保留同一参与者的多次委派与各自来源关联，不因显示名相同合并不同身份，也不因重复委派拆分同一可靠身份。

#### Scenario: 同子身份多次委派
- **WHEN** 同一可靠子身份收到两次不同委派
- **THEN** 两次委派独立保留并关联同一身份，不覆盖第一次

### Requirement: 父步骤内展开子会话与根控制权继承
系统 SHALL 将有可靠关联的子会话作为父轮次中的委派步骤，在该子目标满足展示快照或重放兼容及轮次条件时，允许任意有读取权限的客户端（含只读客户端与主控客户端）点击后在步骤内展开子历史；分页方向和参数统一遵循 history-navigation，子分页不增加父页轮次或改变父页边界。子会话 MUST 继承所属根主会话的客户端写控制权状态（`session-control-takeover`），不设立独立子控制锁，涉及子会话权限审批裁决或控制指令仅限根主会话当前控制客户端执行。父步骤位置由父条目决定，MUST 不将父子正文混排或声明跨会话全局执行顺序；展开命中有效本地展示快照时不拉起子进程，需要触发实际原生加载时遵循 session-resource-policy 的“子目标加载归属主执行树”。

#### Scenario: 父子交替输出与只读客户端同步观察
- **WHEN** 父子会话并行产生内容，且主控客户端与只读客户端同时展开查看
- **THEN** 父步骤保持其父会话位置，子内容仅在所属步骤内按子顺序更新和正序分页；只读客户端可实时观察但无法裁决子会话触发的待决审批

#### Scenario: 展开区域自定义正序分页
- **WHEN** 子会话有25轮，前端在父步骤内传入每页5轮后继续翻页
- **THEN** 依次正序读取第1至5轮、第6至10轮等，省略轮数按 history-navigation 默认参数处理，不跳转子页或改变父分页位置

#### Scenario: 多次委派展开同一子会话
- **WHEN** 两个不同父委派步骤可靠关联同一子会话，用户分别点击展开
- **THEN** 两个父步骤及其来源引用分别保留，展开沿用同一可靠子身份，不复制子历史作为新会话，也不将多个步骤合并；无法证明每次委派的子内容范围时明确标注，不猜测裁剪

#### Scenario: 嵌套子步骤
- **WHEN** 已展开的子历史包含可靠关联的下一层子会话步骤
- **THEN** 用户可在该步骤内继续展开，保持逐层来源和各层内部顺序，不伪造全局时间线或预读整棵树

#### Scenario: 子步骤展开受限
- **WHEN** 用户点击子步骤但客户端读取权限已撤销或可靠关联已不可用
- **THEN** 保留父步骤及其有权读取的摘要，明确展示限制且不返回子正文，不将父历史权限视为已撤销客户端的子目标授权

### Requirement: 原生关系、受管快照与重启读取
系统 SHALL 以 Harness 可验证身份、关系及子历史为原生权威，独立展示快照库仅在默认 30 天滑动保留与 10 GiB 上限内缓存已观测子步骤展示视图；显式原生同步或无快照重启加载时从 Harness 重新读取，MUST 不以无期限永久子正文或关系副本替代原生权威，也不将展示快照拼回充当子 Agent 模型上下文。

#### Scenario: 重启后命中本地快照或重读浏览子会话
- **WHEN** 节点重启后再次展开子步骤
- **THEN** 若本地存在未过期有效子展示快照则零子进程直接展开并标注快照来源；若快照不存在/已淘汰或用户显式请求原生同步，则重新校验来源并从 Harness 标准读取，无法读取时如实说明限制

#### Scenario: 外部客户端更新子关系后显式同步
- **WHEN** 显式原生同步时 Harness 返回外部新增、变化或不可用的子关联
- **THEN** 以最新原生事实刷新关系视图与展示快照代际，不用旧快照索引覆盖原生事实

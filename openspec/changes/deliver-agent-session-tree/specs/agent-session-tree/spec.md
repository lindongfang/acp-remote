## Purpose

定义 Harness 实际暴露的子 Agent 身份、父子会话及多次委派之间的关系，使子会话作为父历史中的步骤点击展开并在重启后保持可靠关联，同时明确仅有工具载荷或摘要时无法证明的内部执行边界。

## ADDED Requirements

### Requirement: 子树能力按接入独立交付
系统 SHALL 在主接入满足标准重放门禁后，分别判断可靠关系展示、子历史重放和可证明轮次的能力，并对满足相应条件的接入独立交付，不以其他计划中 Harness 接入完成为前提。子历史分页展开遵循 history-navigation 的重放兼容及有界视图规则；MUST 不将原生按页读取作为必要条件，未支持子分支不伪造完整子树，也不阻塞有权父内容。

#### Scenario: 其他接入尚未就绪
- **WHEN** 一款已满足重放准入的 Harness 能提供可靠子身份、关系及可证明轮次的标准重放，另一款尚未接入或不具备所需能力
- **THEN** 可对已满足条件的接入交付并验收子步骤展开，另一款明确未验证或不支持，不将前者结果外推后者

#### Scenario: 子历史通过全量重放分页
- **WHEN** 子身份和关系可靠，子历史可标准全量重放并证明轮次，但没有原生分页接口
- **THEN** 通过同一套重放兼容和有界视图在父步骤内正序分页，不增加厂商专用适配，不因缺原生分页拒绝展开

#### Scenario: 关系可读但子历史不可重建
- **WHEN** 已准入接入提供可靠子关系，但子目标不能重放所需内容或无法证明轮次边界
- **THEN** 保留有权父步骤、关系及原生摘要并说明子展开限制，不猜测完整子历史，不阻断其他父内容

### Requirement: 可靠身份才建立子会话
系统 SHALL 只根据可靠原生身份与来源范围建立子会话及父子关联，分别呈现原生参与者身份、会话和委派；仅暴露工具调用、摘要或结果时 MUST 保留原结构并标记限制，不伪造子会话。

#### Scenario: 仅有工具结果
- **WHEN** Harness只发出委派工具调用及结果而无稳定子会话身份
- **THEN** 父历史保留工具结构和实际输入/结果并标记缺少子历史，不生成可展开完整历史的虚构子会话

### Requirement: 多次委派不等于多个身份
系统 SHALL 保留同一参与者的多次委派与各自来源关联，不因显示名相同合并不同身份，也不因重复委派拆分同一可靠身份。

#### Scenario: 同子身份多次委派
- **WHEN** 同一可靠子身份收到两次不同委派
- **THEN** 两次委派独立保留并关联同一身份，不覆盖第一次

### Requirement: 父步骤内展开子会话
系统 SHALL 将有可靠关联的子会话作为父轮次中的委派步骤，在该子目标满足重放兼容及轮次条件时，点击后在步骤内展开子历史并按前端传入轮数正序分页，默认10轮；父会话按前端参数倒序分页，默认10轮，子分页不增加父页轮次或改变父页边界。父步骤位置由父条目决定，MUST 不将父子正文混排或声明跨会话全局执行顺序；不满足条件的子目标保留步骤并说明限制。展开所需实际加载遵循 session-resource-policy 的“子目标加载归属主执行树”，不因父历史仅查询而免除子资源的所有权及名额管理。

#### Scenario: 父子交替输出
- **WHEN** 父子会话并行产生内容
- **THEN** 父步骤保持其父会话位置，子内容仅在所属步骤内按子顺序更新和正序分页，父分页仍按指定轮数倒序读取，不受子分页参数及进度影响

#### Scenario: 展开区域自定义正序分页
- **WHEN** 子会话有25轮，前端在父步骤内传入每页5轮后继续翻页
- **THEN** 依次正序读取第1至5轮、第6至10轮等，省略轮数时默认10轮，不跳转子页或改变父分页位置

#### Scenario: 多次委派展开同一子会话
- **WHEN** 两个不同父委派步骤可靠关联同一子会话，用户分别点击展开
- **THEN** 两个父步骤及其来源引用分别保留，展开沿用同一可靠子身份，不复制子历史作为新会话，也不将多个步骤合并；无法证明每次委派的子内容范围时明确标注，不猜测裁剪

#### Scenario: 嵌套子步骤
- **WHEN** 已展开的子历史包含可靠关联的下一层子会话步骤
- **THEN** 用户可在该步骤内继续展开，保持逐层来源和各层内部顺序，不伪造全局时间线或预读整棵树

#### Scenario: 子步骤展开受限
- **WHEN** 用户点击子步骤但子目标权限不足、已撤销或可靠关联已不可用
- **THEN** 保留父步骤及其有权读取的摘要，明确展示限制且不返回子正文，不将父历史权限视为子目标访问授权

### Requirement: 原生关系与重启读取
系统 SHALL 以 Harness 可验证身份、关系及子历史为来源，平台仅持有可重建视图和缓存；重启后重新读取，MUST 不以永久保存子正文或关系副本替代原生权威。三款实际暴露范围分别报告。

#### Scenario: 重启后浏览子会话
- **WHEN** 节点重启后再次展开子步骤
- **THEN** 重新校验来源及目标权限，从 Harness 读取可用子历史；关系或历史无法读取时明确限制，不伪造可恢复历史

#### Scenario: 外部客户端更新子关系
- **WHEN** Harness 返回外部新增、变化或不可用的子关联
- **THEN** 刷新关系视图，不用平台旧索引覆盖原生事实

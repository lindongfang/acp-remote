# Spec Delta

## MODIFIED Requirements

### Requirement: 会话创建入口与载荷

客户端 SHALL 在目录内或目录列表顶部提供会话准备入口。协商准备能力后，入口只提交 Agent 标识与目录来源及必要的准备关联信息，MUST NOT 传入凭据或 MCP 配置；取得后端分配的最终 ID 后进入该会话页，但不持久创建会话。设备不再有创建权限这一维度，入口 MUST NOT 再以权限为由不可用，也 MUST NOT 出现「需要由电脑端授予」。准备中 SHALL 防重复，失败就地说明；首次保存成功或失败都留在同页同 ID，结果不明先核实。未协商时 SHALL 明确禁用新入口，不退回旧 `session.create`。

#### Scenario: 提交载荷只含目录引用与 Agent 标识
- **WHEN** 用户在某目录内选择已配置的本机 Agent 并开始准备
- **THEN** 准备的业务选择只含该目录来源和 Agent 标识，关联材料不携带凭据或 MCP 配置，也不接受客户端自定正式 ID

#### Scenario: 入口不因权限不可用
- **WHEN** 已认证设备打开目录页或目录详情页且协商准备能力
- **THEN** 创建入口可用，不呈现「没有创建会话的权限」；资源或能力不可用时说明真实原因

#### Scenario: 创建中与终态分别呈现
- **WHEN** 准备或首次提交尚未得到确认
- **THEN** 各自呈现准备中或提交中且不重复操作；准备成功进入固定 ID 页，首条保存和派发结果在该页更新，不另跳新 ID

#### Scenario: 结果不确定显眼且不被自动消解
- **WHEN** 首次提交的结果被所属节点确认为不确定
- **THEN** 页面显眼保留该状态直到用户处理，不自动判成功、重发或新建替代会话

### Requirement: 创建入口的副作用说明

目录内的准备入口 SHALL 说明准备可能在电脑上启动或使用 Agent 资源，以取得模式和配置；首条提交前尚未保存正式会话。MUST NOT 声称准备完全没有副作用，或声称仅打开页面就已持久保存会话。

#### Scenario: 副作用提示
- **WHEN** 用户在目录详情页看到新建入口
- **THEN** 说明临时准备会使用电脑上的 Agent 资源，首次发送后才保存正式会话

### Requirement: 目录项的创建入口

目录页每个目录项 SHALL 提供在该目录内准备新会话的入口，与详情页使用相同准备流程；业务选择只含目录来源和 Agent 标识。入口 MUST NOT 因权限原因不可用；未协商准备能力时 SHALL 说明能力不可用。任何入口都 MUST NOT 在首条提交前新增正式目录会话。

#### Scenario: 从目录项直接创建
- **WHEN** 用户从目录项触发新建并选定已配置 Agent
- **THEN** 同一准备流程取得后端 ID 并打开该页，输入中不包含凭据或 MCP 配置，正式会话列表不增加

#### Scenario: 创建中与终态的呈现沿用既有约定
- **WHEN** 从目录项发起的准备或首次提交未确认
- **THEN** 呈现明确阶段并阻止重复操作；准备失败就地说明，首次保存或执行失败保持原页与 ID，结果不明先核实

### Requirement: 新目录会话创建后同步目录清单

客户端 SHALL 在原 `session.create` 完成，或新准备流程的首条消息被持久接受且引用本地清单尚无的目录时，复用当前连接请求完整快照，仅从验证成功的快照取得目录路径与标识。浏览、单独新建文件夹和未提交准备 MUST NOT 登记目录。旧清单 SHALL 保留直到新快照验证通过，MUST NOT 从候选路径伪造目录；首条保存后即使 Agent 后续失败，目录与正式会话仍 SHALL 可见。

#### Scenario: 新目录创建成功后返回
- **WHEN** 在新目录保存首条消息后返回目录页
- **THEN** 新快照展示该目录与会话，不需手工刷新或重新认证，也不等待 Agent 执行成功

#### Scenario: 刷新或重连
- **WHEN** 首条已保存的页面刷新，或目录快照刷新期间断线恢复
- **THEN** 同一会话与目录从服务端恢复，未完成刷新意图不丢失，地址 ID 不变

#### Scenario: 重投与并发创建
- **WHEN** 同一保存确认重复投递，或快照刷新期间另一目录也接受首条消息
- **THEN** 同一结果不重复发起刷新，并发刷新合并且后一个目录最终可见

#### Scenario: 未完成或失败
- **WHEN** 仅浏览目录、独立新建文件夹、准备未提交，或首条保存失败
- **THEN** 不将候选路径添加为正式会话目录；原创建流程仍不因 accepted/failed/uncertain 结果擅自登记

## ADDED Requirements

### Requirement: 准备页刷新恢复与同页转换

准备页 SHALL 复用会话页面交互，以后端 ID 表示地址，按当前标签页恢复文字、设置及附件。首条保存前不依赖正式快照中已有会话；保存后 SHALL 读取正式状态且不跳页。不能把正式会话草稿或 imported 正文纳入新增浏览器准备存储。

#### Scenario: 快照没有准备会话不误跳转
- **WHEN** 当前标签页有合法准备上下文，但最新正式快照没有对应 ID
- **THEN** 仍呈现准备页及真实设置，不当成会话不存在

#### Scenario: 保存后切换数据来源不重建页面
- **WHEN** 原准备 ID 的首条消息被接受
- **THEN** 同页面使用正式状态，清理准备草稿前确认已保存完整内容，不切换到另一个 URL 或丢失失败状态

#### Scenario: 恢复结果明确为已提交
- **WHEN** 保存响应丢失后恢复准备，服务端返回 `committed` 及首次/当前请求关联
- **THEN** 保持同页同ID读取正式会话、查询当前请求，不把该结果当失败重试、不重传已认领附件，也不自动再次start

### Requirement: 不存在会话地址返回目录页

无当前标签页准备上下文的会话地址 SHALL 经所属节点权威查询确认；只有明确不存在才替换到目录页 `/`。连接、认证、快照等待或服务失败 SHALL 显示真实状态，MUST NOT 冒充不存在。陌生地址 MUST NOT 自动创建任何准备。

#### Scenario: 陌生 ID
- **WHEN** 用户输入不存在的 `/session/<id>`，已认证服务端确认不存在
- **THEN** 替换到 `/`，不留反复返回失效页的历史条目，不启动 Agent

#### Scenario: 服务离线
- **WHEN** 服务不可达，无法确认该 ID 是否存在
- **THEN** 留在原页显示连接问题，不丢输入，也不以不存在为由跳目录

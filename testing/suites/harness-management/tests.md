## Cases
### CL-005 能力未证实

- 用例级别：L5
- 操作步骤：登记 Harness 与目录；当前身份权限、请求去重、真实原生请求及资源安全条件满足时，分别给出仅缺程序实测报告但标准能力可用、Harness 明确声明不支持、标准调用返回不支持错误，以及平台尚未实现协议版本或操作的组合；查看实际 ACP 声明、调用与错误归属。另保安全条件不满足的拒绝对照。
- 预期结果：仅缺该程序实测报告不阻止已实现标准路径，证据仍标未实测；Harness 不支持直接呈现 ACP 声明或实际错误，平台未实现则明确报平台尚不支持并保留对端声明，不混称 Harness 不支持。不另建平台能力准入矩阵、兼容验证或等待用户决定流程，不私有兜底、不创建替代会话、不伪报成功；权限、去重、真实请求及资源安全仍独立执行，不冒额外 ACP 能力证明。登记不自动运行有副作用探针，不泄露配置凭据。

### CL-006 页面断开

- 用例级别：L5
- 操作步骤：真实节点执行中关闭/断网/退订页面，再用另一可信客户端查看已保留输出和有效审批；观察节点所有者及调用。
- 预期结果：客户端断开不取消工作或 Harness 连接，节点继续管理；退订只影响该订阅，不清空共享视图，不承诺已交网络栈数据收回。

### CL-007 共享实例释放

- 用例级别：L5
- 操作步骤：同实例两个自有会话并行，对一个显式释放；在可隔离及不可隔离两分支核对另一会话与资源树。
- 预期结果：可隔离则只释放目标，不能隔离则明确拒绝并保留责任；不强杀其他会话，不凭缓存清空判释放。

### CL-032 相同标准合同不按厂商分流

- 用例级别：L5
- 操作步骤：两个不同名称的协议合同对端使用相同标准版本与能力，运行同组执行/审批/取消/重放；若有两款真实程序再分别记录。
- 预期结果：共用标准合同、不按厂商分流；合同对端不标真实跨款通过，真实范围单独记录，缺第二款不虚报。

### CL-033 逐版本完成取消与互斥合同

- 用例级别：L4
- 操作步骤：按已核实 v1/v2 规范分别构造完成、插入确认、取消发送/权限取消、自然完成及错版控制值，逐步尝试普通输入。另执行 CL-072–074 边界。
- 预期结果：v1 可靠 prompt 终态与 v2 插入/前台状态不混用；发送取消或重放快照不等于活动完成，取消按该版请求范围处理；idle 无 pending 不等协议未要求通知。

### CL-034 逐版本结构与未知载荷保真

- 用例级别：L3
- 操作步骤：逐版本输入结构更新、工具字段省略/null/patch、未知扩展和未知主题/选项提示；验证原 optionId 人工选择与伪造 optionId 拒绝，对照原始字段及安全投影。
- 预期结果：按实际版本保留语义，不通用深合并或跨版解释；未知结构惰性保留，未知审批可安全展示和人工选原选项但不自动允许；不以正文持久化验证保真。

### CL-035 无共同版本拒绝与零派发

- 用例级别：L4
- 操作步骤：对端仅提供无共同支持或未实现/无法核验版本，尝试产品创建、恢复和输入，统计调用。
- 预期结果：版本缺口明确且零业务派发，不猜格式/静默换版或创建替代会话。

### CL-036 协商回退不得重复副作用

- 用例级别：L4
- 操作步骤：核验合法高版 offer→低版 selected 的响应 ID/schema，另给未知/超 offer 选择、错响应 ID、错 selected 形状和网络/业务失败。
- 预期结果：仅规范允许的协商结果生效，按 selected 解析并绑定连接；错误不重新试发副作用，不按厂商猜版本，不将网络/认证/业务失败作为降版证据。

### CL-037 版本规范依据与平台未支持说明

- 用例级别：L5
- 操作步骤：核对实际协议版本标识及平台已实现范围，分别给尚未实现的版本、无法按标准识别当前版本，以及只有程序历史实测证据缺失但标准路径可用的情况；另检查官方规范修订、稳定/草案与实测结果的呈现归属。
- 预期结果：未实现版本报平台协议不支持，无法识别报协商或协议错误；不把 SDK 或 JSON-RPC 号当 ACP 版本，不进入等待用户决定兼容方案的流程。缺历史实测证据如实说明但不额外阻断已实现标准操作；草案不等于无规范，协商不等于真实执行通过，不擅自降低双版目标。

### CL-038 兼容升级沿标准路径且证据分版本

- 用例级别：L5
- 操作步骤：保留旧报告，登记未在报告中的兼容升级程序，按 ACP 重新协商并直接请求其已实现标准能力；请求前不提供平台兼容复验结论或用户兼容裁决，再独立记录开发/验收按影响复验的版本与范围。
- 预期结果：当前 ACP 标准能力及各自安全条件满足即沿标准路径使用，不因缺程序历史报告或平台兼容复验而先禁用，不强制增加厂商实现。旧报告只属原版本，未复验范围如实标注；标准调用结果不冒完整兼容性验收，证据追溯不成为运行时能力门槛。

### CL-039 升级后的不支持或协议错误如实报告

- 用例级别：L5
- 操作步骤：升级后的连接分别返回 Harness 不支持当前标准操作、与声明不符的业务错误和协议错误；尝试借用旧报告宣称新版通过，保留同连接的其他可用标准操作及其他兼容连接，并对照可能已有副作用但结果未知。
- 预期结果：如实呈现实际不支持或错误；协议错误按该版处置，可能已发生的副作用不自动重发。一次操作不支持不自动停用其他标准操作，不另建按厂商/程序版本停用能力的补偿规则、私有兜底或等待用户决定兼容方案的流程；旧证据保持原版本归属，不以旧报告伪称新版成功。

### CL-040 标准操作不支持直接报错且无平台兜底

- 用例级别：L5
- 操作步骤：对平台已实现的恢复或其他标准操作，分别给 Harness 声明不支持和实际返回不支持错误，检查立即响应及原生调用；另给仅无重放但输入/审批满足标准与安全条件的连接，并对照平台尚未实现该协议或操作。
- 预期结果：Harness 不支持则直接报告 ACP 所表达的不支持或实际错误，不等待用户兼容裁决、不另建平台准入/复验流程、不私有桥接、不改走替代会话、不伪报成功；平台未实现则明确报平台尚不支持，保留实际声明。其他标准能力独立使用；仅无重放提供当前连接模式及历史不完整/缓存丢失无法补回提示，权限、请求和资源安全规则仍成立。

### CL-041 版本矩阵不以模拟冒充真实

- 用例级别：L5
- 操作步骤：建立程序×协议×能力矩阵，对文档声明、运行协商、合同夹具、真实完整验收分别登记；核对 CL-030 的 Codex 首验。
- 预期结果：各证据不混称，未执行为 not-run；不假设每程序支持双版，不用旧探测或模拟代替真实执行/重放/恢复/树清理。

### CL-047 无标准重放时仅发现能力且零产品派发

- 用例级别：L5
- 操作步骤：合同对端不提供标准历史重放，但分别满足创建、输入、审批和无重放恢复的标准与安全条件；从 Web/认证入口调用各自能力并统计实际 writer。另对照平台未实现能力。
- 预期结果：具备条件的操作实际派发，当前连接聊天可用；明显提示历史不完整及缓存丢失后无法补回。未实现能力单独拒绝，不扫描私有文件、不拼审计历史。标题“零产品派发”为保留追踪的历史语义，已被本断言替换。

### CL-048 相同标准能力共用路径且不设程序白名单

- 用例级别：L5
- 操作步骤：两不同名称/程序版本的合同对端在当前身份权限、请求去重、原生请求和资源安全条件满足时，提供相同已实现协议/标准能力且无程序历史报告；对照协议必备方法未额外广告、Harness 声明或响应不支持，以及对端声明平台尚未实现的能力。检查实际标准调用和未提供副作用探针。
- 预期结果：可用标准能力共用 ACP 路径，不要求程序版本白名单、额外平台能力准入矩阵/验证流程或协议未要求的可选标志；证据仅说明未实测范围。Harness 不支持直接报实际错误，平台未实现明确报平台尚不支持并保原声明；不私有兜底、不等待兼容裁决、不以输入/批准/删除等副作用探测能力，也不把安全条件包装为额外 ACP 能力证明。

### CL-053 重连失去重放能力保留旧事实与资源责任

- 用例级别：L5
- 操作步骤：已有命令、未知工作与资源后重连，新连接失去重放但其他能力仍满足；分别在旧活动未收敛及已可靠收敛时请求入队/继续，重试原 ID 并读旧审批。
- 预期结果：报告明显历史限制，其他能力独立可用；活动未收敛仅阻派发，资源责任及旧事实保留，旧ID只返回原事实且无统一期限，旧审批不跨连接复用。

### CL-054 真实标准重放到有界 Web 视图

- 用例级别：L6
- 操作步骤：真实 Harness 在专用来源创建结构/轮次历史，经 Windows/Web 标准重放，核对来源、顺序、完成及基本页参数；历史超过旧视图/缓存阈值但真实系统可处理，无原生分页分支优先。
- 预期结果：真实重放及基本视图成立，无旧平台正文容量截断/淘汰，首次成本随总历史增长；标题“有界”不再规定内容容量。下游缓存外任意定位不冒称本期已交付；缺真实组合记未执行。

### CL-055 默认环境继承覆盖且不增加环境准入门槛

- 用例级别：L5
- 操作步骤：节点环境放非敏感测试哨兵，启动自有观测对端，先默认继承再部分同名覆盖，含 Windows 大小写同名及特殊继承条目；故障时仅布尔检查合成秘密是否泄漏。
- 预期结果：未覆盖值继承、覆盖值生效，无白名单/环境指纹门禁且不污染他配置；日志/审计/错误无凭据值，资源可收敛。

### CL-058 新连接优先高版并如实呈现合法协商结果

- 用例级别：L5
- 操作步骤：合同入口平台具有高低版已实现处理，分别给共同高版、规范允许低版、合法低版无原因、未知未来版、仅未来版及网络/认证失败；旧报告/缓存仅低版或当前程序无历史报告，核对实际发起/选择版本和高版独有已实现结构。
- 预期结果：新连接优先最高已实现版，合法选择遵守规范并分开展示 offer/selected/依据或原因未提供；高版能力不压低版交集，无共同版本明确拒绝。平台未实现的协议明确报平台尚不支持而非伪称 Harness 不支持；不因缺程序报告额外拦截或固定低版，不以网络/认证失败降版。

### CL-059 重连重新优先且高版失败不降版重发

- 用例级别：L5
- 操作步骤：旧低版连接有效时不热切；条件支持高版后重连，高版输入/审批可能发送后失败/超时，另给只缺重放的连接；重试旧登记ID及旧审批。
- 预期结果：新连接重新优先最高已实现版并绑定能力；业务失败不降版重派，仅缺重放提示限制不整体封锁。旧ID返回原事实而无统一截止，旧审批不复用；实际活动未知继续阻派发。

### CL-060 真实新连接和重连的高版优先路径

- 用例级别：L6
- 操作步骤：固定真实平台/程序/适配器与规范，在真实共同高版组合新连，验证高版实际结构；有先低后高真实条件时显式重连并核对旧操作不重发。
- 预期结果：真实新连/重连优先最高共同已实现版，旧连接不热切，证据绑定实际版本；缺真实高版特性/升级组合记未执行，不为本例安装升级或用模拟代签。

### CL-069 交互准入与自动回收能力分别呈现

- 用例级别：L5
- 操作步骤：对端能标准执行但无完整后台观测/安全自动关闭窗口，分别提供有无重放条件；查独立能力，提交输入、审批与显式释放，并对照资源满额。
- 预期结果：交互按自身条件可用，自动回收明确受限，不从重放/idle/关闭方法推全观测；未知活动保护，资源满额按所属策略拒绝，不把输入队列三项混同主树容量。

### CL-106 真实无重放接入及当前连接模式

- 用例级别：L6
- 操作步骤：若有已实现标准处理且真实无重放Harness，固定版本在自有Windows/Web运行创建/当前连接输入/真实审批及可用恢复；换端共享内容，释放/重连后查看；记录能力与历史提示。
- 预期结果：无重放不整体禁用，历史不完整及缓存丢失无法补回明显可见，审批决定与历史完整独立；不造前文、不厂商私有读取。无真实无重放组合列未执行，不用合同对端冒充。

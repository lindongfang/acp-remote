## Cases
### CL-001 真实构建及类型检查

- 用例级别：L1
- 操作步骤：按 README、根 package.json 与 clients/web/package.json 执行 npm run check、npm run build:rust；Windows 测试按 testing/ci/windows-owner.ps1 准备实际 owner 环境。另执行 openspec.cmd validate deliver-codex-session-loop --strict、git diff --check。记录各入口实际测试数量、退出码和快照。
- 预期结果：编译、Web 类型/测试/构建、Rust 格式/clippy/测试及文档检查分别有结果；零测试、仅静态通过或旧合同测试通过不视为 Q-001 功能通过。

### CL-003 领域边界及异常状态

- 用例级别：L3
- 操作步骤：确定性模型覆盖节点登记去重、共享三个等待项、入队/编辑/取消/发送先后、正常优先中断、失败挂起旧项与新输入优先、点击继续恢复、受理后撤销、独立原生活动及早到终态；另执行CL-043–045/056/066/067/072–074/100和110–113的模型分支。
- 预期结果：数量、队列身份、可执行/失败挂起状态、前台与插入事实独立；并发结果对应节点顺序，新输入成功不恢复挂起旧项，继续不重复受理或抢占当前工作；模型只证明其输入前提下规则。

### CL-004 事务资源与并发协作

- 用例级别：L4
- 操作步骤：用自有全新库及 schema1/2/3/4 一致性副本，对编码前独立检视通过的新迁移合同逐事务注入失败并核对原身份、信任、撤销、管理及旧正文摘要；在必要登记、审批保存和派发交接前后崩溃。并发相反裁决与连接失效交错，检查正文/编辑旧版本未落盘。
- 预期结果：迁移原子且失败回滚，未知/残缺库拒绝不重建；旧数据保留，新入口不读写旧正文；必要事实可靠后方可派发，队列正文不恢复，可能发送不补发，裁决唯一。当前尚未冻结的新 DDL 不预设 schema5 或宣布可执行，缺合同/入口记录受阻。

### CL-017 断线后重复提交

- 用例级别：L5
- 操作步骤：节点已登记输入，在响应丢失、浏览器重连及等待超过一天后用同 ID 同内容重试；分别让其仍排队、已发送、已完成及节点重启失去未发正文。查询节点事实及实际派发次数。
- 预期结果：重复返回原事实，不重复入队/派发；无统一期限。重启旧项不靠重试恢复正文，元数据仍防重；主动追加同文字须新登记身份，未发送与可能发送分别处理。

### CL-018 请求身份冲突

- 用例级别：L5
- 操作步骤：使用已登记 ID 改目标、动作或内容提交；同内容合法表达对照。另以有权 B 的新操作编辑原等待项并重试编辑操作，再用原提交 ID 携带编辑内容。
- 预期结果：登记 ID 内容冲突拒绝，原队列不被偷换；合法重复只返回原事实。编辑是新验权操作，保留项身份/位置并记录内容版本和实际操作者；不要求独立每动作签名、截止或时间水位。

### CL-019 并发输入

- 用例级别：L5
- 操作步骤：同来源同原生 ID 当前前台活动时，A/B 跨入口同时提交四条普通输入，再释放当前工作；对照不同会话共享目录并行，期间处理审批和中断。
- 预期结果：最多三个等待项全客户端共享，满额明确拒绝且不覆盖；前台至多一个，可靠成功后 FIFO 逐条派发。忙碌可入队但不派发，目录不建立锁，控制不排在普通输入后。

### CL-020 取消未完成

- 用例级别：L5
- 操作步骤：活动前台或已发送待插入输入存在时中断，只给取消发送/适用权限响应而无可靠终态；再提交普通输入，并对照空闲无 pending 分支。
- 预期结果：不把中断发送当已结束，不解除旧工作派发阻挡；剩余名额可排队，不向 Harness 发下一条。满额拒绝；空闲无 pending 按 CL-072 不新增额外等待。

### CL-021 派发后异常退出

- 用例级别：L5
- 操作步骤：输入可能已接收并产生副作用后断线/节点退出，无可靠终态，重启并重试旧登记ID；重新登记新输入并在需要时取得原生恢复，观察入队/派发及资源责任。
- 预期结果：已知发送与未知结果分开，不补发可能发送项，旧登记不因重启复活；所需恢复按当前能力校验，名额内可受理项与旧活动阻派发分别呈现，未知不改未发生，不从管理事实拼原生消息。

### CL-022 一轮完成

- 用例级别：L5
- 操作步骤：真实完成一轮但保留资源，再确认显式释放；另让关闭未确认，比较 Web 的前台结果与资源状态。
- 预期结果：一轮完成单独显示，资源仍加载时页面运行中；仅释放及管理协调确认才空闲，断线/idle 不替代释放。

### CL-030 真实Windows与Web闭环

- 用例级别：L6
- 操作步骤：固定真实Codex/适配器、规范、摘要与实际ACP版本，在专用Windows数据/原生根和可信Web完成登记、创建、输入、结构工具、真实审批、中断、跨端查看、释放、同原生身份恢复及重启；加入共享队列、A撤销后旧受理交付、失败挂起后新输入优先/成功不恢复旧项/显式继续、编辑取消，逐分支核对自有树。
- 预期结果：节点/Web/SQLite/Harness/原生数据/Job全链路真实；无重复副作用，历史按真实重放或当前连接模式呈现并有提示，不设旧内容预算。失败挂起只约束旧项，新输入仍按互斥/资源条件派发。未产生的真实分支列未执行，不用握手、截图或替身补签。

### CL-043 旧执行未证明停止时重连仍拒绝输入

- 用例级别：L5
- 操作步骤：先以独立模型入口演算，再用实际节点+协议对端复现：前台已派发无终态，依次断连、超时、新握手及仅中断已发送；每步在剩余名额内提交普通输入，对照无 Run 的 foreground unknown，并保留另一共享会话。
- 预期结果：旧活动/未知阻止下一条派发，但剩余名额可入队；不因新握手、超时或无 Run 解锁，不改变另一会话归属。标题中的“拒绝输入”历史含义替换为禁止派发；模型不替代节点或 L6。

### CL-044 资源收敛后仅显式新请求可继续

- 用例级别：L5
- 操作步骤：先模型后实际节点+协议对端：依次提供旧工作收敛、原生身份、唯一归属及必要恢复，逐一缺项尝试下一条派发；保留可证未发送旧项、可能发送项及失败挂起状态，另提交新输入。全部条件满足后分别在继续前/后观察。
- 预期结果：缺重新准入条件不派发；安全收敛后可证未发项遵循当前调度，挂起旧项须点击继续，新输入可独立优先。可能发送旧项不重发，旧结果未知不改成功、旧审批不复活。标题“仅显式新请求”不排除已受理且恢复可执行的未发送项。

### CL-046 真实异常退出到新一轮的 Windows 与 Web 路径

- 用例级别：L6
- 操作步骤：固定真实Windows/Harness/Web，输入后中断传输，旧资源仍存时另提交新输入；确认自有资源收敛、同原生身份、唯一归属及恢复后观察可证未发新项，并对失败挂起旧项显式继续，重试旧请求/审批。对照仍可能活动及资源不可核验。
- 预期结果：可入队不等于可派发；真实收敛后新输入按互斥/资源条件执行，挂起旧项须继续，可能发送项不重发、旧审批不复活。完整自有树清理且共享会话不强杀，缺真实依据记未执行。

### CL-066 无平台 Run 的原生前台与后台事实独立

- 用例级别：L5
- 操作步骤：先独立模型再实际节点+对端：无平台Run时报告可靠原生 active，提交队列项并处理真实审批/中断；前台结束后分别保留后台 active/unknown，对照前台 unknown、idle及平台Run组合。
- 预期结果：active/unknown阻下一条派发但名额内可入队，审批/中断独立校验，不造Run。前台结束不清后台事实，不从Run结束推全部停止或可回收；纯模型不代节点/L6。

### CL-072 可靠空闲取消不建立额外前台等待

- 用例级别：L5
- 操作步骤：先以 独立纯模型入口执行 L3 子范围，再在真实节点和协议合同对端重复以下全部分支并记录实际派发/请求/资源归属；纯模型通过只签该子范围，完整本例仍待 L5 验证。构造 v2 可靠 idle 且无待确认输入，有有效后台权限请求；捕获当前目标发起取消，处理协议适用的权限取消响应但不再发送额外 idle。随后显式提交新输入，并交错旧取消回报与新真实 active。
- 预期结果：取消不创建 Run、假完成或等待协议未要求 idle 的阻挡；审批按适用范围处理，不宣称后台已全部停止。新输入按当前自身事实准入，新 active 不被旧取消回报结算。 实际节点入口须满足同一预期；CL-086 不替代本例 L5 义务，真实 Harness 能力由对应 L6 用例另验。

### CL-073 空闲不清除未确认插入输入

- 用例级别：L5
- 操作步骤：先模型再实际节点+对端：foreground idle但已发送输入插入结果未知，中断后只给idle/取消发送；保持有名额队列，分别给对应可靠拒绝或迟到插入响应并保留先前终态，对照其他工作回报。
- 预期结果：不因idle或取消发送清pending，不重发；可入队但不得派发下一条。可靠对应事实才解除阻挡，早到终态须保留，不永久等第二次idle；其他工作不能结算该输入。

### CL-074 取消与自然完成竞态不结算下一轮

- 用例级别：L5
- 操作步骤：先以 独立纯模型入口执行 L3 子范围，再在真实节点和协议合同对端重复以下全部分支并记录实际派发/请求/资源归属；纯模型通过只签该子范围，完整本例仍待 L5 验证。对同一旧工作以两种顺序交错取消请求和可靠正常终态，不提供 cancelled；随后新一轮开始，再交付旧取消/终态回报。另令旧目标连接换代后同 native ID 开始新工作。
- 预期结果：保留正常完成及取消未证实，不等第二个终态或改写已取消；旧回报不能结算新一轮或新连接工作。活动与取消命令状态分开，不能把前台结束显示为资源释放。 实际节点入口须满足同一预期；CL-086 不替代本例 L5 义务，真实 Harness 能力由对应 L6 用例另验。

### CL-075 受理派发前管理提交失败禁止副作用

- 用例级别：L5
- 操作步骤：真实节点/SQLite 对输入、创建、恢复加载与其他已实现危险动作在受理/派发必要记录提交前失败或提交未知，重试同身份；正常无故障对照。
- 预期结果：没有可靠必要提交时零新原生副作用，不虚报受理；重试先核验不重复，缓存故障不进入此规则，原事务无部分事实。

### CL-076 原生完成后管理结果失败不重派

- 用例级别：L5
- 操作步骤：已可靠完成的动作在结果提交失败/未知后查询及重启；对照可能已发送但未有完成事实，观察原生调用与所有权。
- 预期结果：原生已知完成与管理记录故障分别表达，未知不改未发生；不重发，重启先核验，未协调资源不复用名额。

### CL-079 节点签发请求固定截止与待派发到期

- 预期结果：各分支分别沿负责规格的成功推进、可靠失败暂停、已停止暂停及未知核验规则；未知不伪装已停止/成功/失败，不自动重发。v2 聚合成功/失败也不凭空完成某 Run，v1 RemoteError 不推零发送或可靠前台失败；原始原因和实际证据层次可区分。

### CL-122 立即发送所选项的取消结束例外

- 用例级别：L4、L5
- 操作步骤：正常队列 X/Y/Z，B 按“中断与立即发送”选择已有 Y，实际旧前台可靠取消结束后检查 Y 和余项；对照仅取消通知已写、旧前台未知、Y 被先行编辑/取消导致版本失效、资源换代、中断失败及满额未入队新草稿。Y 派发后分别以后继成功、失败和普通取消结束，再交付旧取消回报；全程核对 X/Z 是否被自动派发或恢复。
- 预期结果：旧工作保取消原因，只允许原已选且仍有效的 Y 在全部围栏满足后派发一次；X/Z 保持原相对顺序及暂停状态。仅取消通知、旧前台未知或中断失败不派发，保留 Y 并明确提示未进入派发；Y 版本失效、资源换代或中断未确认时不派发且不回退到 X/Z，保留 Y 或失效选择对应的剩余项并提示选择已失效。Y 后继成功、失败或取消均不自动恢复 X/Z，余项仍须有权用户显式继续。满额新草稿不获第四等待位，本例不把例外扩大到普通中断或其他队列项。

### CL-123 真实非成功结束与继续操作闭环

- 用例级别：L6
- 操作步骤：固定真实 Windows 节点、可信 Web A/B、SQLite、Harness/适配器及专用原生来源，实际可产生时分别取得 token 上限、请求轮数上限、拒绝和普通取消的可靠结束，保留原始协议原因和 Run 关联依据；验证旧项停止暂停、新输入优先及手动继续，再执行已有项立即发送的中断例外。复用同版有效成功/失败对照证据或实际执行，关闭并核完整自有 Job 树及共享会话隔离。
- 预期结果：真实结果/原因、队列和原生调用符合 CL-117–122 的相应分支；受控协议夹具不代签。程序不能真实产生的原因、早终态或未知组合分别保留未执行范围，不为本例安装升级、访问凭据或用模拟结果补齐真实证据；未执行必需分支不宣布完整闭环通过。

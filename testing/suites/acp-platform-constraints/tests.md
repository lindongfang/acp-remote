## Cases
### CL-002 静态合同和供应链检查

- 用例级别：L2
- 操作步骤：按 .github/workflows/ci.yml 执行依赖审计与密钥扫描，检查产品依赖审查/锁文件，真实 BASE/HEAD 用 npm run lint:commits -- --from BASE --to HEAD --verbose；逐项核对本文件场景引用与实施合同。
- 预期结果：供应链、提交和静态合同检查分别可追溯；上游或开发工具审计不代替产品依赖审查，无专用脚本时人工核对而非虚报机器验证。

### CL-026 持续保存故障

- 用例级别：L5
- 操作步骤：持续流式输出跨越旧视图、实体、节点缓存与快照阈值；慢订阅暂停消费，随后恢复并核对已接收输出。并行审批、中断和队列操作，另注入真实展示故障及必要管理存储故障。
- 预期结果：不以旧输出容量驱逐、截断或间接正文限额，慢客户端不堵协议接收及控制；实际展示故障准确报告且不取消原生执行。必要管理故障按 CL-075–078，附加审计故障按 CL-094。

### CL-049 完整历史流式传输与所有保留缓冲有界

- 用例级别：L5
- 操作步骤：无原生分页的对端全量流式重放超过旧视图/实体/节点/快照阈值的结构历史；混慢订阅、并发读取和页面参数，核对条目总数、原结构、完成边界及实际资源观测。
- 预期结果：全历史传输成本如实呈现，无旧内容上限拒绝、截断或淘汰；完成前不冒称完整，完成后来源/顺序真实，不写永久正文。标题“所有保留缓冲有界”不再要求平台内容预算，工程数量交接边界不能变相限正文。

### CL-092 受理后节点交付与原提交者撤销

- 用例级别：L5
- 操作步骤：A受理X后分别断线、凭证自然过期、被撤销，再由节点发送X；A尝试新输入/编辑/取消/继续/读取，B有权时可显式取消尚未发送的X。
- 预期结果：已受理X继续节点规则，不取原actor锁或交付再验权；A的新交互/读取按当前权限拒绝，断线不丢项；B取消若先处理则X不发，不能称撤销自动取消。

### CL-095 删除正文输出及间接缓存容量门槛

- 用例级别：L5
- 操作步骤：用合成非敏感载荷测试旧输入单体、32MiB自设帧、16/128MiB视图/缓存、4096/32768条实体、快照/租约总量边界两侧及以上；协议对端明确可处理。大输入只占一等待项，检查实际writer、接收条目、结构及慢订阅恢复。另给真实Harness/协议拒绝。
- 预期结果：不因旧输入/输出/实体/解析预算拒绝、截断或淘汰，不能以多对象租约变相封顶；只按三项数目限队列。实际限制或分配/传输故障如实标来源，不承诺无限物理资源，不将附件读取独立安全预算一并删除。

### CL-103 额外限制依据及新旧规则证据核对

- 用例级别：L5
- 操作步骤：独立核对限制清单及实际拒绝：历史、输入/挂起名额、审批、正文缓存、来源、资源和读取安全；从可见原因追溯负责spec/确认/合同/验证。对照旧累计4096请求寿命、统一暂停新输入、TTL、正文预算或actor派发再验权。
- 预期结果：额外限制可追溯且单一来源，无依据列实现差异、不称ACP必需。Q-002删除的是连接累计寿命，真实请求来源/单响应/重复ID及同时未决保护保留；旧实现/报告/模型和结构检查不证明新规则交付。

### CL-107 真实重放审批并发与协议乱序边界

- 用例级别：L6
- 操作步骤：在真实Harness/适配器/Windows/Web的专用来源启动实际重放，在真实权限请求等待期间中断并观察reader；通过受控传输窗口而非替换Harness制造写等待及早终态/迟插入可达顺序，核对配置字段与资源退出。
- 预期结果：真实可达组合有原始帧/配置/调用及树清理证据，控制不形成锁循环，插入不混前台终态。真实程序不能产生的顺序明确未执行；CL-100/101的合同证据单独保留，不外推真实保证。

### CL-108 双版长连接超过累计4096请求仍可用

- 用例级别：L4
- 操作步骤：以实际公共ACP Connection入口及可控流对端分别协商v1/v2，同一连接依次发送并完成至少8193个不同类型化ID的合法Harness请求，包含真实权限请求与其他请求的现有处理路径（未知方法按标准不支持响应，不虚报支持）；逐次记录4095/4096/4097/8193边界、响应ID/数量，随后再完成一项正常请求。仅协议对端替身，不运行节点/Web/Harness。
- 预期结果：第4097及更后请求仍处理，连接不因累计次数失效，不以更大固定寿命阈值替代4096；每个响应只对应原请求、仅一次，响应结束后后续仍可用。真实执行/审批owner/资源能力不从此夹具推断。

### CL-109 删除累计上限后重复来源及同时未决保护

- 用例级别：L4
- 操作步骤：沿CL-108完成超过4096个请求后，在各自独立连接分支重放已答复旧ID、重复未答复ID、使用数字与同形字符串ID，伪造句柄/其他连接owner并重复响应。另用两条全新连接测试现有同时未决边界：一条保留64个未决且不接收第65个，排空后再收新请求；另一条保留64个未决再接收第65个，捕获Capacity及连接失效、真实writer事实。
- 预期结果：累计次数上限删除不清除真实已见ID防重，不复活已答复请求；待答同ID不创建第二请求，每请求最多一个实际响应，类型化身份及owner边界保留。第一条从未超限，排空后新请求可用；第二条沿既有Capacity及poison/关闭语义，不要求超限同连接恢复。现有同时未决64保护保留，不把该阈值称ACP统一规定。

### CL-116 长连接累计边界后节点审批与控制集成

- 用例级别：L5
- 操作步骤：后续在实际认证节点和真实SQLite、审批owner及ACP连接上使用受控Harness对端，连续产生并处理超过4096个不同真实请求；混入当前支持的其他Harness请求路径，在边界后由Web A/B裁决有效权限请求并再中断/查询，另发已见ID和失效原请求。
- 预期结果：节点连接和审批处理不因累计次数失效；真实来源、唯一决定/单响应、失效抑制及当前读取/操作验权仍成立。累计寿命端口改动不能替代此节点集成；节点/owner未实现则记未执行，协议对端不是真实Harness验收。

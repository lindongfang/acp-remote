## 范围和独立执行方式

- 本文是现有 `tests.md` 的 L3 子阶段补充，保留 CL 主 ID/标题。`.Qnn` 仅为独立脚本内子断言标识，不改现有 L5/L6 用例的级别、标题或义务。
- 只通过库的公开 API 构造合成目标、已受理输入、队列快照、可信活动/资源事实，执行状态转换。禁止 include 私有源码、改生产可见性、写私有字段或通过反射绕过边界。若内部极值只能私有测试，必须分列为未动态验证。
- 所有正文为合成内容；使用自有外部副本和 `CARGO_TARGET_DIR`。本阶段不启动节点、SQL、WSS、Web、ACP 连接或 Harness，不访问用户库、凭据、原生会话，不外发审计，不新增依赖。
- 接受两个语义入口：受理后的内存等待/直接归属转换，以及当前有效事实约束下的派发归属。这里“接受已受理输入”不证明请求已登记、身份或权限真实。
- 不把纯值对象中调用者提供的 idle、资源有效或可靠失败视为真实 ACP 证据。领域 API 消费这些事实，WP3 才证明事实来源与关联。
- 本阶段最大可证明：共享数量、排序、项身份及版本竞争、单个派发归属、挂起/继续规则、当前事实阻挡、无内置 TTL/正文封顶。不能证明跨客户端认证/刷新同步、持久去重/重启不补发、真实 writer 零字节、节点 actor 撤销、终态归属、资源树清理。

## 依据与八份规格的相关边界

## 公共观测合同所需信息

以下是语义要求，尚未指定 Rust 名称。实际合同必须将每项映射到公开方法/返回值：

1. 目标键、等待项 ID、当前内容版本、正文、原提交归属和最后编辑归属、稳定相对顺序、可执行/挂起状态。
2. 等待数量（包含挂起）、派发预留/所有权、待插入与前台事实分离。快照不能把“已取出”直接显示成“原生已插入/完成”。
3. 具可识别分类的容量满、项不存在、版本冲突、已发送/已交接、当前阻挡、旧代际/旧 token 错误；拒绝后可公开对照没有状态变化。
4. 不可复用的当前派发句柄，或具有等价围栏的显式 ID/版本；应可验证第二次消费、旧句柄与跨目标回报不会修改当前工作。
5. 如果本阶段提供锁/注册表，保证同 NativeSessionKey 复用一个协调对象；若仅提供 `&mut` 单会话值，则明确唯一 owner 由 application 保证，不声称已经验证多线程原子性。

## Cases

### CL-087 节点共享三项与最后名额竞争

- 用例级别：L3 子范围。
- 操作步骤：Q01：前台 active、无平台 Run，受理 X/Y，再按 A→B、B→A 两种处理顺序竞争 Z/W；Q02：保留当前派发或待插入项后再入 X/Y/Z；Q03：同来源同原生 ID 经两个别名取得协调对象，另给不同来源同短 ID、同来源不同原生 ID。
- 预期结果：最后位仅一项成功，另一明确满额且不改已有正文/顺序；活动/待插入阻派发但不占三个等待位；独立目标各有三位，同目标不能因别名取得第二队列。如果无并发公共容器，本阶段只证明两种线性顺序，真实屏障争抢仍待 CL-087 L5。

### CL-088 跨客户端编辑取消与优先操作

- 用例级别：L3 子范围。
- 操作步骤：Q01：已受理 X/Y/Z，由代表已验权 B 的命令编辑 Y；Q02：以 Y 旧版本再编辑、取消和优先操作，对照当前版本；Q03：取消 X 后再读、再取消 X，随后加入 W。
- 预期结果：成功编辑保 item ID/位置/数量，正文及编辑归属更新；旧版本不能覆盖/移除新版本，拒绝后状态不变；成功取消释放一位，不把后续取消自动转中断。新操作实际鉴权和请求重试去重不由本夹具证明。版本推进与 no-op 规则须先冻结。

### CL-089 可靠成功后FIFO串行发送

- 用例级别：L3 子范围。
- 操作步骤：Q01：正常 X/Y/Z，注入当前工作可靠成功，依次获取派发，保持 X 待插入、已插入但前台 active、unknown 三种状态，各尝试下一项；Q02：可靠允许后完成 X、Y、Z；Q03：另一目标在本目标被阻挡时派发。
- 预期结果：仅 X→Y→Z，不能一个推进动作同时取得多个派发归属；X 任一阻挡未解除不得发 Y；拒绝不把未发送 Y 标为结果未知。不同目标互不串行。插入与前台状态输入的真实关联不在本阶段证明。

### CL-090 立即发送确认中断及满额新草稿拒绝

- 用例级别：L3 子范围。
- 操作步骤：Q01：正常 X/Y/Z、旧工作活动，优先选 Y；仅提交“中断已请求”时尝试派发，再给可靠旧工作结束；Q02：分别给中断失败和未知；Q03：正常满额新草稿 D 尝试普通及优先提交；Q04：旧中断完成回报在新归属创建后迟到。
- 预期结果：仅确认旧工作结束并满足其他条件后可选 Y，其余 X/Z 相对顺序不变；中断请求本身不解除活动；失败/未知保留项且不派发；新 D 不成为第四等待项；旧回报不结束新工作。选择保留、取消选择及失败后的顺序规则见待冻结参数。

### CL-091 失败暂停与显式继续边界

- 用例级别：L3 子范围。
- 操作步骤：Q01：当前工作可靠失败，旧 X/Y 挂起；刷新快照、重复调度、资源恢复；Q02：提交新 D，D 成功后新 E；Q03：D 活动时继续，再尝试调度；Q04：当前前台 unknown 时继续。
- 预期结果：等待与资源恢复都不自动恢复 X/Y；D/E 可按新输入路径执行，成功不自动恢复旧项；继续只改变挂起可执行性、不抢占 D；unknown 仍阻挡发送。新继续操作的鉴权不由领域值证明。

### CL-092 受理后节点交付与原提交者撤销

- 用例级别：L3 子范围。
- 操作步骤：Q01：以原 actor A 的已受理项 X 构造队列，后续派发只提供当前目标/资源/状态，不提供 A 的在线状态、凭据或 gate；Q02：由代表已验权 B 的当前命令取消 X，再尝试派发。
- 预期结果：领域派发无需重新证明 A 当前权限，原归属仅作追溯；取消先处理则 X 不再可派发。若公开派发 API 必须传当前 A 或旧 credential，则记录为合同缺口。真实撤销及所有新操作/读取权限仍须 L5。

### CL-095 删除正文输出及间接缓存容量门槛

- 用例级别：L3 子范围。
- 操作步骤：Q01：在同一等待项写入非敏感 UTF-8/多行/非 BMP 内容并逐字比较；Q02：用 32MiB+1 合成正文入队及编辑，正常三位容量独立验证；失败时记录真实分配/接口故障，不改成固定平台上限。
- 预期结果：正文不截断/散列替换/因旧正文预算拒绝，巨大正文仍只占一位；项数限制不变。本阶段不验证输出/视图缓存、ACP 帧传输或真实 Harness 容量，不从一次大正文接受推导无限资源。

### CL-096 节点时间排序与校时独立等待

- 用例级别：L3 子范围。
- 操作步骤：Q01：按节点处理顺序 X/Y/Z 入队，时间字段使用相反顺序、过去/未来和回拨值（仅若 API 接受节点记录时间）；Q02：编辑/快照/继续反复观察顺序。
- 预期结果：队列只依已处理顺序和显式优先/取消动作变化，时间字段不重排/过期或锁死。若 API 无时间字段则确认其结构性不依赖时钟，不声称实际节点校时测试已执行。

### CL-097 队列无期限与原凭证到期

- 用例级别：L3 子范围。
- 操作步骤：Q01：若提供时间输入则跨一天和更长时间推进，再读/编辑/派发；若无时间输入则核对所有公开转换不要求 expiresAt 或凭据期限，以大量无副作用观察后保持项作补充。
- 预期结果：无队列 TTL、旧正文自动清理、原 credential 到期门槛。无实时时间入口时不通过 sleep 模拟证成期限规则，也不把 API 缺期限当节点全链路已达成。

### CL-098 重启不恢复队列正文且无专门丢失提示

- 用例级别：L3 子范围。
- 操作步骤：Q01：独立创建实例、入队并编辑，丢弃该领域实例；创建新实例，读取其初始队列及返回状态。
- 预期结果：新实例等待项为空、没有自行恢复或专门生成队列丢失事件。仅验证内存值生命周期；不能证明进程重启、SQL/临时文件无正文、旧 ID 拒绝和可能发送不重发。

### CL-099 取消编辑与发送的节点串行交接

- 用例级别：L3 子范围。
- 操作步骤：Q01：cancel→claim 与 claim→cancel；Q02：edit(v1→v2)→claim(v1/v2) 与 claim(v1)→edit(v1)；Q03：如果 API 区分预留与发送提交，则预留后取消/编辑、资源换代再提交旧句柄；Q04：第二次消费句柄、跨目标/旧代际/旧项版本回报。
- 预期结果：取消先成功则不能取得同项发送归属；发送已线性化后取消/编辑按合同明确拒绝，不自动中断；成功派发正文是当前版本；旧句柄不能修改或发送新版本/新工作。Q03 的可修改区间、发送线性化点和回退算法必须冻结后才可编码断言。纯模型无 writer，不宣称已观测零字节。

### CL-110 失败挂起旧项与后续新输入直接优先

- 用例级别：L3 子范围。
- 操作步骤：Q01：当前工作可靠失败，将 X/Y/Z 挂起；在可靠 idle、无待插入、资源有效时提交 D；Q02：完成 D 成功后再提交 E；Q03：编辑 X、反复读取快照及尝试普通调度。
- 预期结果：旧三项内容/ID/相对顺序保留并计三位；D/E 获得独立直接派发归属，不作为第四等待项；D/E 成功、编辑或读取均不恢复旧项；直接归属必须同时堵住第二项派发。

### CL-111 失败后新输入等待优先且成功不恢复旧项

- 用例级别：L3 子范围。
- 操作步骤：Q01：挂起 X/Y，分别以 active、unknown、待插入、资源不可用阻挡新 D，D 进入唯一剩余位；尝试 E，再可靠解除阻挡；Q02：D 成功；Q03：独立分支 D 可靠失败。
- 预期结果：D 占第三位，E 满额；确定没有发送时不标 delivery-unknown；解除条件后 D 优先于挂起项；D 成功不恢复 X/Y，D 失败保留 X/Y 挂起及 D 的真实结果，不自动把失败 D 重新入队。失败时同时存在其他可执行新项的挂起集合规则须冻结。

### CL-112 显式继续恢复旧项不抢占新输入不重复入队

- 用例级别：L3 子范围。
- 操作步骤：Q01：X/Y 挂起、D 活动时继续两次，分别尝试调度；D 结束后逐项派发；Q02：D 结束后才继续；Q03：unknown 或待插入时继续；Q04：新 D 已在等待位时继续，记录总数与完整顺序。
- 预期结果：不复制 X/Y，不改变项 ID/正文，不抢占 D；可靠允许后 X 先 Y，各只取得一次归属；继续不绕过 unknown/待插入。操作请求重试的身份去重留给 Node 登记阶段。Q04 跨“旧恢复项/新等待项”的排序在合同冻结后补精确 oracle，不以猜测当用户确认。

### CL-113 挂起满额时直接发送与并发新输入边界

- 用例级别：L3 子范围。
- 操作步骤：Q01：三项挂起、全部直接条件有效，以 D→E、E→D 两种处理顺序提交；Q02：分别 active、unknown、待插入、资源不可用，尝试 D；Q03：正常未挂起三项满额，即便前台可靠可用仍尝试新草稿 D；Q04：若公开容器线程安全，以 barrier 实际争抢直接归属。
- 预期结果：Q01 仅首项取得直接归属，后项无法即派且等待满额须拒绝，旧三项不丢/不清空/不挪作假活动；Q02 一律不绕过阻挡且不新增第四等待项；Q03 不能利用直发清空正常满队列规则。没有公共线程安全入口时 Q04 明确未执行，节点原子集成义务保留。

### CL-115 多客户端挂起项编辑取消及继续授权

- 用例级别：L3 子范围。
- 操作步骤：Q01：挂起 X/Y，以已验权 B 编辑 X、取消 Y，提交新 D，再在 D 活动时继续 X；Q02：分别 cancel(X,version)→resume/claim 与 resume/claim→cancel，加入旧版本编辑/优先命令。
- 预期结果：编辑保身份/位置及挂起状态，取消释放名额，D 不自动恢复 X；继续不复制、不抢占，取消与发送不会同报成功；版本冲突不改状态。只读 B、撤销 A 与新继续鉴权留给 L5；纯领域不接受“未授权=true”模拟来签权限通过。

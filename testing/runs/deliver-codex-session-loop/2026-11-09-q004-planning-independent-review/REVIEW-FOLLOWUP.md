**Q-004 复查**
范围：仅将 proposal、session-execution 规格、CL-117–123、design、implementation contract、plan 和 tasks 作为同一规划系统审阅。未执行产品代码或真实 Harness；结构校验 11/11 与 `git diff --check` 按给定结果采信。本结论不构成产品验收。

**结论**
`BLOCKED`。`Q4-RV-001`、`003`、`004`、`005` 已关闭；`Q4-RV-002` 仍有关闭缺口，并新增 `Q4-RV-006`。

**关闭情况**
- `Q4-RV-001`：**已关闭**。design 的 Context、Goals 和 Implementation Gate 已明确 Q-003 仅属历史授权，Q-004 独立复核及用户放行前不得恢复实现或验收。
- `Q4-RV-002`：**仍未完全关闭**。见下。
- `Q4-RV-003`：**已关闭**。implementation contract §6 已覆盖 CL-117–123、停止原因、取消通知、早终态/迟插入、继续重试及 L4/L5/L6 边界。
- `Q4-RV-004`：**已关闭**。`plan` 的 WP2–WP6 与 `tasks` 6.8–6.10 已分别覆盖共享队列与失效项、协议终态、Web 交互、独立验收和复查。
- `Q4-RV-005`：**已关闭**。规格已为“继续”定义稳定请求身份、同身份同内容返回原事实、不同内容拒绝及不重复恢复或派发。

**未闭合发现**
- `Q4-RV-002` **P2，仍开放**。文件：`cl117_to_cl123` 的 CL-122、`tasks` 6.8–6.9。证据：规格已要求“中断失败或未知时保留输入并提示”，失效选择还应“保留剩余项并提示该选择失效”；CL-122 只断言不派发、不回退及 X/Z 保持暂停，未断言保留 Y 和用户提示；6.8–6.9 的判据也未包含这两项。修复：在 CL-122 预期结果及任务判据中加入可观察的“保留 Y/剩余项并提示”断言，同时保留现有“无回退、X/Z 暂停、Y 结束后不自动恢复”断言。
- `Q4-RV-006` **P2，新发现**。文件：`cl117_to_cl123` 开头“单一行为来源”段。证据：该段仍称非成功结束 Requirement 有“三个 Scenario”，实际规格现有五个；被漏计的两个正是立即发送选择失效及 Y 结束后 X/Z 继续暂停。修复：改为引用全部相关五个 Scenario，或删除数量表述并明确两个立即发送例外场景属于单一行为来源。

其余指定语义一致：`Completed` 不等同成功；取消通知不是可靠结束；限额、拒绝、普通取消、失败和未知分开处理；早终态与迟插入独立；未知不猜测 Run；真实、夹具和未执行边界明确。除上述两项外，CL、工作包和任务引用未见新的语义冲突。

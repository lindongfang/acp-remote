# Q-004 独立评审报告

**范围**  
仅审阅提供的规划包：proposal、session-execution 规格、CL-117–123、design、implementation contract、plan 和 tasks。未检查或执行产品代码，不构成产品验收。

**结论**  
`BLOCKED`。无 P0；发现 2 个 P1、3 个 P2。核心停止语义大体一致，但规划闭环、CL-122 行为边界及下游追溯仍不完整。

**发现**
- `Q4-RV-001` **P1 — 实施授权与 Q-004 暂停要求冲突。** 文件：`design` 的 Context/Goals 和 Implementation Gate。证据：proposal 明确本轮不恢复实现、迁移或真实 Harness 验收；design 却称“先修订 Q-003……再继续已授权的增量实现”，并要求 Q-003 核对后“恢复已授权实现”。修复：用 Q-004 门槛取代该表述，明确 Q-003 仅属历史授权，Q-004 规划闭环及用户再次放行前不得恢复实现或验收。
- `Q4-RV-002` **P1 — CL-122 未闭合“只推进原已选有效项”的语义。** 文件：`specs/session-execution/spec.md` 的“立即发送的中断按已选项继续”；`cl117_to_cl123` 的 CL-122；`tasks` 6.9。证据：task 6.9 要求“立即发送例外仅推进已选有效项”，但规格和 CL-122 只断言 Y 成功派发一次及 X/Z 顺序保持，未明确 Y 成功后 X/Z 仍暂停、不自动派发、仍需显式继续；Y 失效时也未明确不得回退到 X/Z。CL-122 虽包含中断失败/未知分支，预期结果未明确断言 Y 被保留并提示用户。修复：在规格、CL-122 和任务中统一规定并断言“仅 Y 可推进；无回退；X/Z 保持暂停；中断失败/未知时保留 Y 并提示；Y 成功后不自动恢复 X/Z”。
- `Q4-RV-003` **P2 — implementation contract 的验证入口遗漏 Q-004 用例。** 文件：`implementation_contract` §6。证据：该节仍只列 CL-087 起、失败暂停等检查，未列 CL-117–123，也未覆盖停止原因分类、早终态/迟插入、取消通知、立即发送例外和显式继续。修复：将 CL-117–123 及所需 v1/v2、L4/L5 与 L6 边界加入合同检查清单，并与 tasks 6.8–6.10 对齐。
- `Q4-RV-004` **P2 — CL-122 的工作包归属和引用不一致。** 文件：`plan_excerpt` WP2/WP3/WP4、Q-004 映射段；`tasks` 6.8/6.9。证据：WP2 仅核验 CL-117–121，task 6.8 仅列 CL-117–119/121；CL-122 只落到 WP4/task 6.9。但“原项版本、资源条件、无回退、队列不自动恢复”属于共享队列和派发所有者，不能仅由 Web/最终装配工作包承担。修复：WP2/task 6.8 增加 CL-122 的队列与失效项断言；WP3 承担取消/终态序列；WP4 保留显示和集成操作；WP5/WP6 独立验收。
- `Q4-RV-005` **P2 — CL-120 的“重试继续身份”缺少规范依据。** 文件：session-execution 的“非成功结束”与“执行失败暂停队列”；`cl117_to_cl123` CL-120；`implementation_contract`。证据：CL-120 要求重试原继续身份且不得重复派发，但规范只规定点击继续后恢复，未定义继续操作的请求身份、重复请求返回原结果还是无操作，也未说明是否适用现有输入幂等规则。修复：在规格和合同中明确继续操作的稳定身份与幂等语义，或删除该测试断言。

其余明确检查项未见新增冲突：`Completed` 不得等同成功、取消通知不等于可靠结束、限制/拒绝/普通取消/失败/未知分离、早终态与迟插入独立、未知不猜测 Run、停止后新输入优先及旧项显式继续，在 proposal、规格及 CL-117–121/123 中基本一致。

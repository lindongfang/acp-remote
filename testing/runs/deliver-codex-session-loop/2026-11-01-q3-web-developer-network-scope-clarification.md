# Web 开发网络证据范围勘误

原查看器候选 `a01662c0…` 的开发日志及 frozen HANDOFF 保持原字节。其“请求零次”表述只由当时收集的 `Fetch.requestPaused` 和自有页面 canary 计数支持：相关开发轮次的 HTTP 拦截尝试及脚本、弹窗、锚点导航、提交计数均为零。脚本没有完整分类其余 CDP 网络事件，因此不能从这些日志推出浏览器全部网络事件或 WebSocket 帧为零。此前开发进度中的“零资源请求”按此范围理解，不用作完整网络安全验收。

原独立 tester 在授权后的新空间 2 记录到一条 `Network.webSocketFrameSent`，并从可信静态加载阶段的同一 requestId、`@vite/client` initiator、仅自有回环地址和 `vite-hmr` 协议确认这是 Vite 测试基础设施的既有连接 ping。该证据属于新的独立浏览器版本，不能倒推原空间 1 当时存在或不存在该事件；也不能将这条非零事件改记为全网零次。`hmr: false` 的服务器配置本身不证明没有实际 HMR 连接。

独立验收继续按原用例收集、分类完整事件；未知事件不能用汇总 clean 字段盖过。纯静态、无 WebSocket 的测试基础设施目前只是待检视提案，不是已执行能力。本勘误不修改产品、原用例、旧日志或旧候选，也不签 WD19、视觉、完整 Web28 或父项通过。

### Browser fetch regression found and fixed

The first real Chromium pairing attempt stopped with:

```text
TypeError: Failed to execute 'fetch' on 'Window': Illegal invocation
```

The saved `globalThis.fetch` function was being called later as an object method, changing its receiver. `clients/web/src/pairing/api.ts` now calls `globalThis.fetch(...args)` and stores an ordinary wrapper function. `clients/web/tests/api.test.ts` includes a receiver-sensitive regression test. The Web suite increased from 30 to 31 tests.

### Shutdown test race found and fixed

One complete Rust run exposed an intermittent shutdown-order failure:

```text
local IPC failed: local request failed: 管道正在被关闭。 (os error 232)
```

The test could start shutdown before the owner IPC task observed the stop request. The test in `app/src/node.rs` now starts the stop task, waits for `control.stop_received`, and only then starts the 250 ms shutdown. Ten consecutive targeted runs and the complete Rust suite passed. This is a test reliability correction, not a change to the product shutdown semantics.

The earlier `send_replace` and pre-`select!` state check in `app/src/ipc.rs` remain necessary so an immediate stop/shutdown request is not lost before an IPC receiver subscribes.
